## 1. 手写 EventEmitter（发布订阅）

**题目：** 实现 `EventEmitter`，支持 `on`、`once`、`off`、`emit`，并处理：

- 同一事件多个监听器，按注册顺序执行；
- `once` 只触发一次，且 `off` 能移除它；
- `emit` 时监听器抛错不能影响其他监听器；
- 返回取消订阅函数（可选，现代 API 常用）。

**数据结构选型：**

| 方案 | 查找 | 添加 | 备注 |
| --- | --- | --- | --- |
| 数组 `listeners[event] = [fn, ...]` | O(n) | O(1) | 简单，`once` 需要包装 |
| `Map<event, Set<fn>>` | O(1) | O(1) | 天然去重，推荐 |
| `Map<event, Map<fn, wrapped>>` | O(1) | O(1) | 能保存 `once` 的包装映射，`off` 可直接移除 |

**实现：**

```js
class EventEmitter {
  constructor() {
    // event -> Map<原始监听器, 实际执行的监听器>
    this.events = new Map();
  }

  on(event, listener) {
    return this.#add(event, listener, false);
  }

  once(event, listener) {
    return this.#add(event, listener, true);
  }

  #add(event, listener, once) {
    if (!this.events.has(event)) this.events.set(event, new Map());
    const listeners = this.events.get(event);

    // once：包一层，执行前先移除自己
    const wrapped = once
      ? (...args) => {
          this.off(event, listener);
          listener.apply(this, args);
        }
      : listener;

    listeners.set(listener, wrapped);

    // 返回取消订阅函数，避免调用方记住 event 名称
    return () => this.off(event, listener);
  }

  off(event, listener) {
    if (!listener) {
      this.events.delete(event); // 不传 listener：清空该事件
      return this;
    }
    const listeners = this.events.get(event);
    if (!listeners) return this;
    listeners.delete(listener);
    if (listeners.size === 0) this.events.delete(event); // 防止空 Map 堆积
    return this;
  }

  emit(event, ...args) {
    const listeners = this.events.get(event);
    if (!listeners) return false;

    // 复制一份再遍历：监听器里可能 on/off，直接遍历原集合会出问题
    for (const wrapped of [...listeners.values()]) {
      try {
        wrapped.apply(this, args);
      } catch (error) {
        // 单个监听器出错不能中断其他监听器
        console.error(`[EventEmitter] listener error on "${event}":`, error);
      }
    }
    return true;
  }

  // 只触发一次，但保留全部监听器（用于 ready 场景）
  emitOnce(event, ...args) {
    if (!this.events.has(event)) return false;
    this.emit(event, ...args);
    this.off(event);
    return true;
  }
}
```

**关键点：**

1. **为什么 `Map<fn, wrapped>` 而不是数组**：`once` 包装后，调用方手里的仍是原函数，`off(event, 原函数)` 必须能找到包装函数，映射表解决了这个问题。
2. **遍历前复制**：`emit` 过程中监听器执行 `off`，直接遍历 `Map.values()` 会导致迭代器行为不确定。
3. **异常隔离**：Node 原生 `EventEmitter` 对没有 `error` 监听的 `error` 事件会抛错，其他事件抛错则直接冒泡；浏览器端通常需要隔离，避免一个坏监听器拖垮整条链路。
4. **内存泄漏**：长期存在的 emitter（全局总线）如果只 `on` 不 `off`，组件销毁后监听器仍持有组件引用。现代框架里应在 `onUnmounted` / `useEffect` 清理函数里取消订阅。

**面试怎么答：** 先写 `on/emit` 骨架，再补 `once` 与 `off` 的映射关系，最后主动提「emit 时复制监听器数组」和「组件卸载必须取消订阅」——这两点是追问高发区。

**易错点：**

- `once` 里用 `wrapper` 存进数组，但 `off` 用原函数查不到。
- `emit` 里 `listeners.forEach` 时监听器移除自己，导致跳过下一个。
- `off` 后不删除空 Map，长生命周期对象上事件名不断增长。
- 用普通对象 `{}` 存事件名，`__proto__`、`constructor` 等键会命中原型链，必须用 `Object.create(null)` 或 `Map`。

## 2. 手写 LRU 缓存

**题目：** 实现 `LRUCache`，支持 `get(key)` 与 `put(key, value)`，容量满时淘汰**最久未使用**的项，两个操作都要求 O(1)。

**核心思路：哈希表 + 双向链表**

```
Map<key, node>  ──►  node { key, value, prev, next }
                      ↑ 最近使用                     ↑ 最久未使用
head ⇄ node ⇄ node ⇄ node ⇄ tail
put/get 命中：把节点移到 head
容量满：删除 tail.prev
```

**方案 A：利用 `Map` 的插入顺序（面试首选，代码短）**

`Map` 迭代顺序就是插入顺序，删除再插入即可把 key 移到「最新」。

```js
class LRUCache {
  constructor(capacity) {
    this.capacity = capacity;
    this.map = new Map();
  }

  get(key) {
    if (!this.map.has(key)) return -1;
    const value = this.map.get(key);
    // 删除后重新插入，移动到末尾（最新）
    this.map.delete(key);
    this.map.set(key, value);
    return value;
  }

  put(key, value) {
    if (this.map.has(key)) this.map.delete(key);
    this.map.set(key, value);

    if (this.map.size > this.capacity) {
      // Map 的第一个 key 就是最久未使用的
      const oldestKey = this.map.keys().next().value;
      this.map.delete(oldestKey);
    }
  }
}
```

**方案 B：双向链表 + Map（面试官要求「不用 Map 的顺序」时）**

```js
class Node {
  constructor(key, value) {
    this.key = key;
    this.value = value;
    this.prev = null;
    this.next = null;
  }
}

class LRUCacheLinked {
  constructor(capacity) {
    this.capacity = capacity;
    this.map = new Map();
    // 哨兵节点，省去 head/tail 判空
    this.head = new Node(null, null);
    this.tail = new Node(null, null);
    this.head.next = this.tail;
    this.tail.prev = this.head;
  }

  #remove(node) {
    node.prev.next = node.next;
    node.next.prev = node.prev;
  }

  #addToHead(node) {
    node.next = this.head.next;
    node.prev = this.head;
    this.head.next.prev = node;
    this.head.next = node;
  }

  get(key) {
    const node = this.map.get(key);
    if (!node) return -1;
    this.#remove(node);
    this.#addToHead(node);
    return node.value;
  }

  put(key, value) {
    let node = this.map.get(key);
    if (node) {
      node.value = value;
      this.#remove(node);
      this.#addToHead(node);
      return;
    }

    if (this.map.size === this.capacity) {
      const oldest = this.tail.prev;
      this.#remove(oldest);
      this.map.delete(oldest.key);
    }

    node = new Node(key, value);
    this.map.set(key, node);
    this.#addToHead(node);
  }
}
```

**复杂度：** 两方案 `get` / `put` 都是 O(1)，空间 O(capacity)。

**面试追问：**

| 追问 | 回答 |
| --- | --- |
| 为什么链表节点要存 key？ | 淘汰尾节点时需要通过 `node.key` 删除 Map 中的条目 |
| 为什么用哨兵？ | 省去头尾为 null 的分支判断，代码更稳 |
| 怎么支持过期时间？ | 节点加 `expireAt`，`get` 时惰性删除；再加定时器或轮询清理 |
| 分布式 LRU 怎么做？ | 本地 LRU + Redis 做二级缓存；Redis 用 `allkeys-lru` 近似 LRU |

**易错点：**

- `put` 更新已有 key 时忘记移动位置，导致它仍按旧时间被淘汰。
- 淘汰时只删链表节点、忘删 Map，内存泄漏。
- 容量为 0 时没有特判，`keys().next().value` 为 `undefined`。
- 以为 Map 方案「不是真 LRU」：`Map` 迭代顺序确实是插入顺序，删除重插等价于移到最新，语义正确。

## 3. 手写 compose 与 pipe

**题目：** 实现 `compose(...fns)` 与 `pipe(...fns)`，把多个单参数函数组合成一个。

**方向（最容易写反）：**

```
compose(f, g, h)(x) === f(g(h(x)))   // 从右到左，数学复合
pipe(f, g, h)(x)    === h(g(f(x)))   // 从左到右，数据管道
```

**实现：**

```js
function compose(...fns) {
  if (fns.length === 0) return (x) => x;
  if (fns.length === 1) return fns[0];

  return fns.reduce(
    (acc, fn) =>
      (...args) =>
        acc(fn(...args)),
    // reduce 没有初值时，第一项作为初始 acc
  );
}

function pipe(...fns) {
  return compose(...fns.reverse());
}
```

**等价写法（更易读）：**

```js
const compose = (...fns) => (x) => fns.reduceRight((acc, fn) => fn(acc), x);
const pipe = (...fns) => (x) => fns.reduce((acc, fn) => fn(acc), x);
```

**扩展：支持多参数与 this**

```js
function composeWithContext(...fns) {
  return function (...args) {
    let result = fns[fns.length - 1].apply(this, args);
    for (let i = fns.length - 2; i >= 0; i--) {
      result = fns[i].call(this, result);
    }
    return result;
  };
}
```

**异步 compose：**

```js
const composeAsync = (...fns) => (x) =>
  fns.reduceRight((p, fn) => p.then(fn), Promise.resolve(x));
```

**易错点：**

- `reduce` 与 `reduceRight` 搞反，导致执行顺序相反。
- 忘记处理空函数列表，`compose()(x)` 报错；返回恒等函数更稳。
- 认为 `compose` 只能处理单参数：第一个执行的函数（最右/最左）通常需要接收多参数，需要用 `apply`。
- 在 React/Redux 中使用时混入 `this`，箭头函数拿不到调用者上下文。

## 4. 手写 memoize

**题目：** 实现 `memoize(fn, resolver?)`，缓存函数结果；相同参数再次调用直接返回缓存。

**基础实现：**

```js
function memoize(fn, resolver) {
  const cache = new Map();

  return function (...args) {
    const key = resolver ? resolver.apply(this, args) : args[0];

    if (cache.has(key)) return cache.get(key);

    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}
```

**必须讨论的四个问题：**

| 问题 | 方案 |
| --- | --- |
| 多参数怎么生成 key？ | `JSON.stringify(args)`（注意顺序、`undefined`、函数会丢）；或让调用方传 `resolver` |
| 对象参数怎么缓存？ | 用 `WeakMap` 以对象为 key（不阻止 GC）；或多参数 `WeakMap` 嵌套 |
| 缓存无限增长？ | 加 `max` 限制 + LRU，或加 `ttl` 过期 |
| 异步函数怎么缓存？ | 缓存的是 **Promise**，并发调用可共享同一个请求（请求合并） |

**进阶：带 TTL 与容量的 memoize**

```js
function memoizeAdvanced(fn, { resolver, ttl = 0, max = Infinity } = {}) {
  const cache = new Map(); // key -> { value, expireAt }

  return function (...args) {
    const key = resolver ? resolver.apply(this, args) : JSON.stringify(args);
    const now = Date.now();
    const hit = cache.get(key);

    if (hit && (hit.expireAt === 0 || hit.expireAt > now)) {
      // 命中后重新插入，维持 LRU 顺序
      cache.delete(key);
      cache.set(key, hit);
      return hit.value;
    }

    const value = fn.apply(this, args);
    cache.set(key, { value, expireAt: ttl ? now + ttl : 0 });

    if (cache.size > max) {
      cache.delete(cache.keys().next().value);
    }
    return value;
  };
}
```

**异步请求合并（面试高频追问）：**

```js
function memoizeAsync(fn) {
  const cache = new Map();
  return function (...args) {
    const key = JSON.stringify(args);
    if (!cache.has(key)) {
      // 缓存 Promise 而不是结果：并发调用只发一次请求
      const promise = fn.apply(this, args).catch((error) => {
        cache.delete(key); // 失败不缓存，允许下次重试
        throw error;
      });
      cache.set(key, promise);
    }
    return cache.get(key);
  };
}
```

**易错点：**

- 直接 `cache[args]`：所有对象都变成 `"[object Object]"`，全部命中同一条。
- 缓存 Promise 后失败也缓存，用户重试永远拿到同一个失败。
- `this` 丢失：返回的包装函数必须用 `function` 而非箭头函数，才能拿到调用者 `this`。
- 递归函数 memoize 时，内部递归调用的是原函数而不是包装函数，缓存不生效。
- 缓存无上限，长列表/大对象场景会持续吃内存。

## 5. 手写 once

**题目：** 实现 `once(fn)`，保证函数最多执行一次，后续调用返回第一次的结果。

**实现：**

```js
function once(fn) {
  let called = false;
  let result;

  return function (...args) {
    if (!called) {
      called = true;
      result = fn.apply(this, args);
    }
    return result;
  };
}
```

**三个细节：**

1. `called = true` 必须在调用 `fn` **之前**，否则 `fn` 内部再次调用包装函数会无限递归。
2. 如果 `fn` 抛错，按上面的写法 `called` 已经是 `true`，后续调用返回 `undefined`。若希望「失败可重试」，要在 catch 里回滚：

```js
function onceRetryable(fn) {
  let called = false;
  let result;
  return function (...args) {
    if (called) return result;
    try {
      result = fn.apply(this, args);
      called = true;
      return result;
    } catch (error) {
      throw error; // called 仍为 false，下次可重试
    }
  };
}
```

3. 异步函数：`once` 返回的仍是 Promise，但内部只执行一次；并发调用会拿到同一个 Promise。

**应用场景：**

- 支付/下单按钮防重复提交；
- 只初始化一次的 SDK / 埋点；
- Node 中 `once` 包装事件回调，避免 `error` 与 `end` 同时触发导致回调执行两次。

**易错点：**

- 用 `result !== undefined` 判断是否执行过：`fn` 返回 `undefined` 时会重复执行。
- 忘记 `apply(this, args)`，调用者上下文丢失。
- 认为 `once` 等于防抖：防抖是「延迟 + 只执行最后一次」，`once` 是「首次执行后永久锁定」。

## 6. 链式调用与惰性求值

**题目：** 实现 `add(1)(2)(3)` 返回 6，且支持无限链式 `add(1)(2)(3)(4)...`。

**核心：函数也是对象，靠 `valueOf` / `toString` 触发隐式转换。**

```js
function add(...initial) {
  let sum = initial.reduce((a, b) => a + b, 0);

  function inner(...args) {
    sum += args.reduce((a, b) => a + b, 0);
    return inner; // 继续返回函数，支持无限调用
  }

  // 参与运算 / 打印时触发
  inner.valueOf = () => sum;
  inner.toString = () => String(sum);

  return inner;
}

console.log(add(1)(2)(3) + 0);     // 6（valueOf）
console.log(`${add(1)(2)(3)}`);    // "6"（toString）
console.log(add(1, 2)(3, 4) + 0);  // 10（支持多参数）
```

**为什么 `+ 0` 不能省？** `console.log` 打印函数对象时，Node 会调用 `inspect`，通常显示 `[Function: inner]`；显式 `+ 0` 或模板字符串才会触发转换。

**变体：惰性求值（Lazy）**

要求：每次调用只收集参数，**直到取结果时才真正计算**，并且能缓存。

```js
function lazyAdd(...initial) {
  const args = [...initial];

  const chain = (...next) => {
    args.push(...next);
    return chain;
  };

  chain.getValue = () => args.reduce((a, b) => a + b, 0);
  chain.valueOf = chain.getValue;
  chain.toString = () => String(chain.getValue());

  return chain;
}

const calc = lazyAdd(1)(2)(3);
console.log(calc.getValue()); // 6
```

**变体：链式调用 + 延迟执行（类似 jQuery / Promise）**

```js
class Query {
  constructor(tasks = []) {
    this.tasks = tasks;
  }
  map(fn) {
    return new Query([...this.tasks, (arr) => arr.map(fn)]);
  }
  filter(fn) {
    return new Query([...this.tasks, (arr) => arr.filter(fn)]);
  }
  value(arr) {
    // 只有调用 value 才真正执行
    return this.tasks.reduce((acc, task) => task(acc), arr);
  }
}

const result = new Query()
  .map((x) => x * 2)
  .filter((x) => x > 4)
  .value([1, 2, 3]); // [6]

console.log(result);
```

**面试怎么答：** 普通链式调用靠返回自身；要「拿到最终值」有三条路——`valueOf/toString` 隐式转换、显式 `.getValue()`、以及 Promise 式的 `.then()`。能说出「隐式转换会和 `+`、模板字符串、`==` 产生意外交互」是加分项。

**易错点：**

- `inner` 用箭头函数，`arguments` 不可用；用 rest 参数。
- 每次调用返回新函数但丢失累计值（闭包变量必须在外层）。
- `valueOf` 返回字符串，`+` 会变成字符串拼接。
- 用 `add(1)(2)(3) === 6` 判断：函数对象永远不等于数字，必须显式转换。
