## 1. Go 的错误处理机制

**核心前提：`error` 是一个普通接口。**

```go
type error interface {
    Error() string
}
```

任何实现了 `Error() string` 的类型都是错误。因为它是**值**而不是语言层面的异常，所以可以返回、存储、包装、比较、聚合、序列化，也可以被测试断言——这是 Go 错误哲学的起点：**Errors are values（错误即值）**。

**四种失败表达手段：**

| 手段 | 典型写法 | 适用场景 | 代价与风险 |
| --- | --- | --- | --- |
| 返回 `error` | `func f() (T, error)` | 一切**可预期**的失败：参数非法、资源不存在、网络超时 | 调用方可能忽略；需要逐层传递 |
| `panic` / `recover` | `panic(v)` + `defer func(){ recover() }()` | **编程错误**、不可恢复状态：数组越界、空指针、初始化失败 | 开销大、栈信息噪声、跨 goroutine 无法 recover |
| 哨兵错误 | `var ErrNotFound = errors.New("...")` | 少数**固定分支**的失败，调用方需要精确判断 | 无法携带上下文；暴露包内部细节 |
| 自定义错误类型 | 实现 `Error()`，可附带字段 | 需要**结构化信息**：字段名、SQL、重试状态码 | 调用方需 `errors.As`；类型进入公开 API |

**为什么 Go 不用异常做常规控制流：**

1. **控制流显式**：`if err != nil` 让失败路径在代码里「看得见」，阅读时不需要脑内维护一张可能抛出异常的调用表。
2. **调用方必须做决策**：错误交到调用点，由它决定重试、降级、包装上抛还是记录后忽略，而不是让某层「统一捕获」。
3. **性能可控**：异常模型需要栈展开和异常表；Go 的 `panic` 要遍历 defer 链、抓取栈快照，单次成本远高于返回一个接口值，不能用于高频分支。
4. **可组合**：错误可以被包装成链、用 `errors.Is` 判断、用 `errors.Join` 聚合，也可以作为普通参数传给日志与监控。
5. **goroutine 隔离**：`panic` 只影响当前 goroutine，**不会**传播给父 goroutine，父 goroutine 的 `recover` 也接不住；用「异常向上冒泡」的直觉写并发代码必然出错。
6. **与 `defer` 的语义简单**：defer 只负责清理，不承担「捕获异常」的职责，二者解耦。

```go
package main

import (
	"errors"
	"fmt"
)

// 哨兵错误：包级别定义，调用方用 errors.Is 精确判断
var ErrNotFound = errors.New("用户不存在")

// 自定义错误类型：携带结构化字段
type ValidationError struct {
	Field string
	Value string
}

func (e *ValidationError) Error() string {
	return fmt.Sprintf("字段 %s 的值 %q 不合法", e.Field, e.Value)
}

// 手段一：返回 error（最常见的失败表达）
func findUser(id int) (string, error) {
	if id <= 0 {
		return "", fmt.Errorf("findUser(%d): %w", id, ErrNotFound)
	}
	return "alice", nil
}

// 手段二：自定义错误类型，供上层提取细节
func validate(name string) error {
	if name == "" {
		return &ValidationError{Field: "name", Value: name}
	}
	return nil
}

// 手段三：panic 只用于编程错误
func mustPositive(n int) int {
	if n <= 0 {
		panic("mustPositive: n 必须为正数")
	}
	return n
}

// 手段四：在边界（HTTP handler、goroutine 入口、任务调度）统一 recover
func safeRun(fn func()) (err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("panic recovered: %v", r)
		}
	}()
	fn()
	return nil
}

func main() {
	if _, err := findUser(0); errors.Is(err, ErrNotFound) {
		fmt.Println("命中哨兵错误:", err)
	}

	err := validate("")
	var ve *ValidationError
	if errors.As(err, &ve) {
		fmt.Printf("结构化错误: field=%s value=%q\n", ve.Field, ve.Value)
	}

	fmt.Println(safeRun(func() { mustPositive(-1) }))
	fmt.Println(safeRun(func() { mustPositive(1) }))
}
```

**易错点：**

- `recover()` 必须**直接在 defer 的函数里调用**才有效；包一层 `func(){ recover() }()` 再调用，返回值是 `nil`，捕获不到。
- `recover()` 只能捕获**当前 goroutine** 的 panic；子 goroutine 里 panic 会直接让进程崩溃，必须在子 goroutine 内部自己 defer recover。
- Go 1.21 起 `panic(nil)` 会被包装成 `*runtime.PanicNilError`，`recover()` 不再返回 `nil`，早期版本则会出现「panic 了但 recover 判定为没 panic」的诡异现象。
- 用 `:=` 在 `if` 里声明 `err` 会**遮蔽外层 `err`**，导致函数返回时外层 `err` 仍为 `nil`，是「错误被吞掉」的头号原因。
- 不要用 `err.Error()` 做字符串匹配来判断错误类型，一旦上游改文案就全崩；必须用 `errors.Is` / `errors.As`。

## 2. errors 包与错误包装

**错误链的本质：**被包装的错误实现 `Unwrap() error`（或 `Unwrap() []error`），`errors` 包沿着这条链逐层查找。

```text
service.Load: repo.Get(0): not found
└────────────┬──────────────┘
             └─ 每层都是 fmt.Errorf("...: %w", err)
                errors.Unwrap 剥一层，errors.Is/As 递归到底
```

**四个 API 的职责：**

| API | 作用 | 判断依据 |
| --- | --- | --- |
| `errors.New(msg)` | 创建一个只带文本的错误 | 返回 `*errors.errorString` |
| `fmt.Errorf(format, ...)` | 格式化错误，`%w` 会建立包装关系 | 有 `%w` 才产生 `wrapError` |
| `errors.Is(err, target)` | 判断链上**是否存在**某个错误 | `==` 相等 → 调用 `Is(target)` → `Unwrap` 递归 |
| `errors.As(err, target)` | 把链上**某个类型**提取到 target | 类型断言 → 调用 `As(target)` → `Unwrap` 递归 |
| `errors.Unwrap(err)` | 手动剥一层，返回被包装的错误 | 无包装时返回 `nil` |

**`%w` 与 `%v` 的区别（高频考点）：**

| 格式 | 是否保留错误链 | `errors.Is/As` 能否穿透 | 典型用途 |
| --- | --- | --- | --- |
| `%w` | **是** | 能 | 需要调用方判断根因、做分支处理 |
| `%v` | 否，只拼字符串 | 不能 | 只想展示/记录，不想暴露内部实现 |
| `%s` | 否 | 不能 | 同 `%v`，等价于 `err.Error()` |
| 多个 `%w`（Go 1.20+） | 是，等价于 `errors.Join` | 能 | 一次包装多个独立错误 |

> 设计原则：**包内向上传递用 `%w`，跨越模块边界（尤其对外 API）用 `%v` 或转换成领域错误**，避免把数据库驱动、文件路径等内部细节泄露给调用方。

```go
package main

import (
	"errors"
	"fmt"
)

// 哨兵错误：包级别定义，调用方可以精确判断
var ErrNotFound = errors.New("not found")

// 自定义错误类型：携带结构化上下文，并实现 Unwrap 参与错误链
type QueryError struct {
	SQL string
	Err error
}

func (e *QueryError) Error() string { return "查询失败: " + e.SQL + ": " + e.Err.Error() }
func (e *QueryError) Unwrap() error { return e.Err }

func repo(id int) error {
	switch {
	case id == 0:
		return fmt.Errorf("repo.Get(%d): %w", id, ErrNotFound)
	case id < 0:
		return &QueryError{SQL: "SELECT * FROM users WHERE id = ?", Err: errors.New("connection reset")}
	default:
		return nil
	}
}

func service(id int) error {
	if err := repo(id); err != nil {
		return fmt.Errorf("service.Load: %w", err)
	}
	return nil
}

func main() {
	err := service(0)
	fmt.Println(err)                         // service.Load: repo.Get(0): not found
	fmt.Println(errors.Is(err, ErrNotFound)) // true：穿透两层包装
	fmt.Println(errors.Unwrap(err))          // repo.Get(0): not found：只剥一层

	err = service(-1)
	var qe *QueryError // 注意：目标必须是指针类型
	if errors.As(err, &qe) {
		fmt.Println("SQL =", qe.SQL)
		fmt.Println("根因 =", errors.Unwrap(qe))
	}

	// errors.Join（Go 1.20+）：把多个独立错误聚合为一个
	joined := errors.Join(fmt.Errorf("校验失败: %w", ErrNotFound), errors.New("字段 b 超长"))
	fmt.Println(joined)                         // 逐行输出两个错误
	fmt.Println(errors.Is(joined, ErrNotFound)) // true：Join 会被 Is 递归遍历
	fmt.Println(errors.Unwrap(joined))          // <nil>：Join 类型没有实现 Unwrap
}
```

**自定义 `Is` / `As` 方法（进阶）：**当错误类型无法直接比较，或希望「一个错误匹配多个哨兵」时，可以实现：

```go
type HTTPError struct {
	Code int
	Msg  string
}

func (e *HTTPError) Error() string { return fmt.Sprintf("%d: %s", e.Code, e.Msg) }

// 让 errors.Is(err, ErrNotFound) 在 404 时也成立
func (e *HTTPError) Is(target error) bool {
	return target == ErrNotFound && e.Code == 404
}
```

**易错点：**

- `errors.As` 的 target 必须是「**指向实现了 error 的类型的指针**」：`var qe *QueryError; errors.As(err, &qe)`。传 `qe` 或 `&QueryError{}` 都会 panic。
- `errors.Is` 用 `==` 比较的是**错误值的身份**；`fmt.Errorf` 不加 `%w` 时，即使文案一样也不相等。
- `errors.Unwrap` 只剥一层，且对 `errors.Join` 返回 `nil`；判断聚合错误里的成员要用 `errors.Is`/`errors.As`。
- 一个 `fmt.Errorf` 里写多个 `%w` 需要 Go 1.20+；早期版本只有第一个 `%w` 生效，其余按 `%v` 处理。
- 包装时别丢掉原始错误：`fmt.Errorf("load failed: %v", err)` 会让上层彻底失去判断能力。

## 3. 泛型的使用

Go 1.18 引入**类型参数（type parameter）**，核心是「用约束描述一组类型，让同一份代码适配多个类型，且保持编译期类型安全」。

**四个基本概念：**

1. **类型参数**：`func F[T any](x T) T`，`T` 在调用时由编译器推断或显式指定。
2. **约束（constraint）**：写在方括号里的接口，描述 `T` 必须满足的能力。
3. **类型推断**：能从实参推出 `T` 时不必显式写 `F[int](...)`。
4. **泛型类型**：`type Stack[T any] struct{...}`，方法接收者写作 `*Stack[T]`。

**约束写法对比：**

| 约束 | 含义 | 可否用于 `==` / map 键 | 备注 |
| --- | --- | --- | --- |
| `any` | 任意类型，等价 `interface{}` | 否 | 只能用 `T` 的零值与赋值 |
| `comparable` | 支持 `==` `!=` 的类型 | 是 | 不含 slice、map、func |
| `int` | **仅** `int` 本身 | 是 | 自定义类型 `type MyInt int` 不满足 |
| `~int` | 底层类型为 `int` 的**所有**类型 | 是 | `~` 表示「底层类型」，泛型最常用 |
| `~int \| ~string` | 联合约束 | 是 | 用 `\|` 连接多个类型项 |
| `interface{ Foo() }` | 具备该方法的类型 | 视具体类型 | 方法约束可调用该方法 |

```go
package main

import (
	"fmt"
	"slices"
)

// 约束：接受底层类型为 int / int64 / float64 的类型
type Number interface {
	~int | ~int64 | ~float64
}

func Sum[T Number](xs []T) T {
	var s T
	for _, x := range xs {
		s += x
	}
	return s
}

// comparable：只有可比较类型才能作为 map 的键
func Unique[T comparable](xs []T) []T {
	seen := make(map[T]struct{}, len(xs))
	out := make([]T, 0, len(xs))
	for _, x := range xs {
		if _, ok := seen[x]; ok {
			continue
		}
		seen[x] = struct{}{}
		out = append(out, x)
	}
	return out
}

// 泛型类型：一个可复用的栈
type Stack[T any] struct {
	items []T
}

func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }

func (s *Stack[T]) Pop() (T, bool) {
	var zero T
	if len(s.items) == 0 {
		return zero, false
	}
	v := s.items[len(s.items)-1]
	s.items = s.items[:len(s.items)-1]
	return v, true
}

// 自定义类型：底层是 int，因此满足 ~int
type MyInt int

func main() {
	fmt.Println(Sum([]int{1, 2, 3}))      // 6，T 自动推断为 int
	fmt.Println(Sum([]float64{1.5, 2.5})) // 4
	fmt.Println(Sum([]MyInt{1, 2}))       // 3，~int 让 MyInt 通过

	fmt.Println(Unique([]string{"a", "b", "a"}))

	var st Stack[string]
	st.Push("x")
	st.Push("y")
	v, ok := st.Pop()
	fmt.Println(v, ok)

	// 标准库泛型工具：slices / maps（Go 1.21+）
	fmt.Println(slices.Contains([]int{1, 2, 3}, 2))
	fmt.Println(slices.Max([]int{3, 1, 2}))
}
```

**什么时候不该用泛型（面试常追问）：**

| 场景 | 原因 | 更合适的做法 |
| --- | --- | --- |
| 只有一种具体类型 | 泛型没有收益，反而增加阅读成本 | 直接写具体类型 |
| 需要按类型执行**不同逻辑** | Go 泛型不做特化，没有 C++ 模板的编译期分支 | 接口 + 多实现，或类型断言 |
| 需要**动态**类型（运行时才确定） | 泛型是编译期的，运行时不保留类型参数 | `any` + 类型断言/反射 |
| 需要泛型方法 | Go **不支持**方法自带类型参数 | 写成泛型函数，或让类型参数属于接收者 |
| 需要在 `T` 上调用任意方法 | 约束只能声明已知方法 | 定义方法约束接口 |
| 追求极致性能 | 实现走 GC shape stenciling + 字典，可能不如具体类型直接 | 先 benchmark，再决定 |

> `slices`、`maps`、`cmp` 三个标准库泛型包从 Go 1.21 起进入标准库，日常优先用它们，而不是自己造轮子。

**易错点：**

- `comparable` **不包含** slice、map、func，用它们做泛型实参会编译失败。
- `int` 约束不接受 `type MyInt int`，必须写 `~int`；这是「底层类型」与「类型本身」的区别。
- 泛型类型的方法不能再引入新的类型参数（`func (s *Stack[T]) Map[U any](...)` 非法）。
- 不能在函数体内声明「只在运行时确定」的类型参数，也不能用类型参数做类型开关（`switch T` 不存在）。
- 类型推断不会「跨函数返回值反推」所有场景，必要时显式写 `F[int](...)`。

## 4. 单元测试与表驱动测试

**表驱动测试（table-driven tests）**是 Go 社区的事实标准：把用例写成**数据表**，用同一个循环执行断言，新增用例只需加一行数据。

**三层结构：**

| 写法 | 优点 | 缺点 |
| --- | --- | --- |
| 一个函数一个断言 | 直观、调试简单 | 用例一多就大量重复 |
| 表驱动（无子测试） | 增删用例只改数据 | 失败时只看到行号，不知道是哪条用例 |
| 表驱动 + `t.Run` | 失败信息带用例名，可用 `-run` 过滤 | 多一层缩进 |
| 表驱动 + `t.Run` + `t.Parallel` | 大幅缩短耗时 | 共享状态、环境变量必须隔离 |

**常用能力：**

| API | 作用 |
| --- | --- |
| `t.Run(name, fn)` | 创建子测试，失败信息带层级 |
| `t.Parallel()` | 标记并行，与其它并行子测试同时跑 |
| `t.Helper()` | 标记辅助函数，报错行号指向调用处 |
| `t.Cleanup(fn)` | 注册清理，子测试结束时执行（LIFO） |
| `t.TempDir()` | 自动清理的临时目录 |
| `t.Setenv(k, v)` | 设置环境变量并在测试结束后恢复，**不能与 `t.Parallel` 同用** |
| `TestMain(m)` | 包级 setup/teardown，需自行调用 `m.Run()` |

**被测代码 `calc.go`：**

```go
package calc

import (
	"errors"
	"strings"
)

var ErrDivByZero = errors.New("除数不能为 0")

func Add(a, b int) int { return a + b }

func Div(a, b int) (int, error) {
	if b == 0 {
		return 0, ErrDivByZero
	}
	return a / b, nil
}

func Normalize(s string) string { return strings.ToLower(strings.TrimSpace(s)) }
```

**测试代码 `calc_test.go`：**

```go
package calc

import (
	"errors"
	"testing"
)

func TestAdd(t *testing.T) {
	t.Parallel()

	tests := []struct {
		name string
		a, b int
		want int
	}{
		{name: "正数", a: 1, b: 2, want: 3},
		{name: "含负数", a: -1, b: 2, want: 1},
		{name: "全零", a: 0, b: 0, want: 0},
	}

	for _, tt := range tests {
		tt := tt // Go 1.22 起循环变量每轮独立，这行可以省略
		t.Run(tt.name, func(t *testing.T) {
			t.Parallel()
			if got := Add(tt.a, tt.b); got != tt.want {
				t.Errorf("Add(%d, %d) = %d, want %d", tt.a, tt.b, got, tt.want)
			}
		})
	}
}

func TestDiv(t *testing.T) {
	t.Parallel()

	tests := []struct {
		name    string
		a, b    int
		want    int
		wantErr error
	}{
		{name: "整除", a: 6, b: 3, want: 2},
		{name: "有余数", a: 7, b: 3, want: 2},
		{name: "除零", a: 1, b: 0, wantErr: ErrDivByZero},
	}

	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			got, err := Div(tt.a, tt.b)
			if !errors.Is(err, tt.wantErr) {
				t.Fatalf("Div(%d, %d) err = %v, want %v", tt.a, tt.b, err, tt.wantErr)
			}
			if err == nil && got != tt.want {
				t.Errorf("Div(%d, %d) = %d, want %d", tt.a, tt.b, got, tt.want)
			}
		})
	}
}

func TestNormalize(t *testing.T) {
	t.Parallel()
	if got := Normalize("  GoLang "); got != "golang" {
		t.Fatalf("Normalize = %q, want %q", got, "golang")
	}
}
```

```bash
go test ./...                       # 运行所有测试
go test -run 'TestDiv/除零' ./...   # 只跑某个子测试（层级用 / 分隔）
go test -race ./...                 # 开启数据竞争检测
go test -count=1 -v ./...           # 禁用缓存并输出明细
go test -coverprofile=cover.out ./... && go tool cover -html=cover.out
```

**易错点：**

- `t.Parallel()` 的子测试会**先暂停**，等父测试函数返回后才继续；不要把需要顺序的断言放进并行子测试。
- Go 1.22 之前，循环变量在所有迭代中复用，`t.Parallel` + 闭包会读到同一个 `tt`，必须写 `tt := tt`。
- `t.Setenv` 与 `t.Parallel` 互斥，运行时会直接报错；需要环境隔离就老老实实串行。
- 在子 goroutine 里调用 `t.Fatal` 只会退出该 goroutine，测试函数仍会继续，必须用 channel 把错误传回主 goroutine。
- 测试函数签名必须是 `func TestXxx(t *testing.T)`，`Xxx` 首字母大写，否则不会被识别。

## 5. 基准测试与性能分析

**基准测试函数签名：**`func BenchmarkXxx(b *testing.B)`，框架会自动调整 `b.N`，让被测代码运行足够长的时间以获得稳定结果。

**关键 API：**

| API / 参数 | 作用 |
| --- | --- |
| `b.N` | 框架给定的迭代次数，**必须**用它做循环上界 |
| `b.ResetTimer()` | 重置计时，用于跳过昂贵的初始化 |
| `b.StopTimer()` / `b.StartTimer()` | 暂停/恢复计时 |
| `b.ReportAllocs()` | 输出每次操作的分配字节数与次数（等价命令行 `-benchmem`） |
| `b.SetBytes(n)` | 声明单次处理的数据量，输出 MB/s |
| `b.RunParallel(fn)` | 并行基准，用 `pb.Next()` 控制迭代 |
| `b.Run(name, fn)` | 一个基准里跑多组子基准 |

**命令行参数：**

| 参数 | 含义 |
| --- | --- |
| `-bench .` / `-bench=BenchmarkX` | 运行哪些基准（正则匹配） |
| `-benchmem` | 输出 `B/op` 与 `allocs/op` |
| `-benchtime=1s` | 每个基准的运行时长；也可写 `-benchtime=1000x` 固定次数 |
| `-count=10` | 重复运行 10 次，配合 `benchstat` 做统计对比 |
| `-cpu=1,4,8` | 用不同的 `GOMAXPROCS` 各跑一遍 |
| `-run=^$` | 跳过普通单元测试，只跑基准 |
| `-cpuprofile` / `-memprofile` | 同时产出 profile 文件 |

**被测代码 `concat.go`：**

```go
package bench

import (
	"strconv"
	"strings"
)

func ConcatNaive(n int) string {
	s := ""
	for i := 0; i < n; i++ {
		s += strconv.Itoa(i)
	}
	return s
}

func ConcatBuilder(n int) string {
	var sb strings.Builder
	sb.Grow(n * 3)
	for i := 0; i < n; i++ {
		sb.WriteString(strconv.Itoa(i))
	}
	return sb.String()
}
```

**基准代码 `concat_test.go`：**

```go
package bench

import (
	"strconv"
	"testing"
)

// sink 防止编译器把无副作用的调用优化掉
var sink string

func BenchmarkConcatNaive(b *testing.B) {
	b.ReportAllocs()
	b.SetBytes(190) // 0..99 拼接后的字节数
	for i := 0; i < b.N; i++ {
		sink = ConcatNaive(100)
	}
}

func BenchmarkConcatBuilder(b *testing.B) {
	b.ReportAllocs()
	b.SetBytes(190)
	for i := 0; i < b.N; i++ {
		sink = ConcatBuilder(100)
	}
}

// 子基准：一次比较三种规模
func BenchmarkConcatBuilder_Size(b *testing.B) {
	for _, n := range []int{10, 100, 1000} {
		b.Run(strconv.Itoa(n), func(b *testing.B) {
			b.ReportAllocs()
			for i := 0; i < b.N; i++ {
				sink = ConcatBuilder(n)
			}
		})
	}
}

// 并行基准
func BenchmarkConcatBuilderParallel(b *testing.B) {
	b.ReportAllocs()
	b.RunParallel(func(pb *testing.PB) {
		for pb.Next() {
			sink = ConcatBuilder(100)
		}
	})
}
```

```bash
go test -bench . -benchmem -run '^$' -count=5
```

**结果解读（数值为示意）：**

```text
BenchmarkConcatNaive-8          1532    781000 ns/op    48016 B/op    99 allocs/op
BenchmarkConcatBuilder-8       19284     62000 ns/op      256 B/op     2 allocs/op
```

- `-8`：`GOMAXPROCS=8`，与 CPU 核数相关，跨机器对比时必须对齐。
- `ns/op`：单次操作耗时，**越小越好**；跨版本对比看相对倍数，不看绝对值。
- `B/op`、`allocs/op`：单次操作分配的内存与对象数，直接影响 GC 压力，通常是优化重点。
- 单次运行噪声大，正确做法是 `-count=10` 后用 `benchstat old.txt new.txt` 看中位数与波动。

```bash
go install golang.org/x/perf/cmd/benchstat@latest
go test -bench . -count=10 -run '^$' > old.txt
# 修改代码后
go test -bench . -count=10 -run '^$' > new.txt
benchstat old.txt new.txt
```

**易错点：**

- 忘记使用 `b.N`（写成固定的 1000 次）会让框架的自动调参失效，结果无意义。
- 在循环里做初始化（建连接、读文件）会把开销算进去；应放在循环外并调用 `b.ResetTimer()`。
- 结果没被使用会被编译器优化掉，必须写入包级变量或 `b.ReportAllocs()` 之外的 sink。
- `b.SetBytes` 只影响吞吐量展示，不影响 `ns/op`；单位是字节。
- 并行基准里共享可变状态会引入锁竞争，测到的是锁而不是业务。

## 6. pprof 的使用

pprof 是 Go 自带的采样剖析工具，分两种接入方式：

| 方式 | 导入 | 适用场景 | 采集入口 |
| --- | --- | --- | --- |
| HTTP 方式 | `import _ "net/http/pprof"` | 长期运行的服务，可远程触发 | `/debug/pprof/*` |
| 代码方式 | `import "runtime/pprof"` | 命令行工具、单元测试、短生命周期进程 | `StartCPUProfile` / `WriteHeapProfile` |

**五类 profile 各自能查什么：**

| profile | 采集内容 | 能定位的问题 | 开启方式 |
| --- | --- | --- | --- |
| `cpu` | CPU 时间采样（约 100Hz） | 热点函数、死循环、重复计算、锁自旋 | 默认可用，`?seconds=30` |
| `heap` | 堆内存**分配**采样（默认每 512KB 采样一次） | 内存泄漏、大对象、分配热点 | 默认可用 |
| `goroutine` | 当前所有 goroutine 的调用栈 | goroutine 泄漏、阻塞在哪一行 | 默认可用 |
| `block` | 阻塞操作（channel、select、锁等待） | 谁在等 channel、谁在等锁 | 需 `runtime.SetBlockProfileRate(1)` |
| `mutex` | 互斥锁竞争 | 热点锁、临界区过长 | 需 `runtime.SetMutexProfileFraction(1)` |

**方式一：HTTP 服务接入**

```go
package main

import (
	"fmt"
	"log"
	"net/http"
	_ "net/http/pprof" // 匿名导入，自动向 DefaultServeMux 注册 /debug/pprof/*
)

func main() {
	// 单独开一个只监听本机的端口，避免业务端口暴露调试接口
	go func() {
		log.Println("pprof:", http.ListenAndServe("127.0.0.1:6060", nil))
	}()

	mux := http.NewServeMux()
	mux.HandleFunc("/work", func(w http.ResponseWriter, r *http.Request) {
		buf := make([]byte, 1<<20) // 制造可观测的堆分配
		_ = buf
		fmt.Fprintln(w, "ok")
	})
	log.Println("业务服务:", http.ListenAndServe(":8080", mux))
}
```

```bash
# CPU：默认采样 30 秒
go tool pprof -http=:8000 'http://127.0.0.1:6060/debug/pprof/profile?seconds=30'

# 堆：查看当前存活对象（inuse_space）
go tool pprof -http=:8000 http://127.0.0.1:6060/debug/pprof/heap

# 堆：查看累计分配（alloc_space），排查「分配多但不一定泄漏」
go tool pprof -http=:8000 -alloc_space http://127.0.0.1:6060/debug/pprof/heap

# goroutine：文本形式看全局阻塞情况
curl -s 'http://127.0.0.1:6060/debug/pprof/goroutine?debug=1' | head -50

# 锁与阻塞（需先在程序里打开采样率）
go tool pprof -http=:8000 http://127.0.0.1:6060/debug/pprof/block
go tool pprof -http=:8000 http://127.0.0.1:6060/debug/pprof/mutex
```

**方式二：代码内采集（适合 CLI / 测试）**

```go
package main

import (
	"log"
	"os"
	"runtime"
	"runtime/pprof"
)

func main() {
	// 打开阻塞与锁采样（生产环境慎用，有额外开销）
	runtime.SetBlockProfileRate(1)
	runtime.SetMutexProfileFraction(1)

	f, err := os.Create("cpu.pprof")
	if err != nil {
		log.Fatal(err)
	}
	defer f.Close()

	if err := pprof.StartCPUProfile(f); err != nil {
		log.Fatal(err)
	}
	defer pprof.StopCPUProfile()

	// 被测逻辑放在这里
	sum := 0
	for i := 0; i < 1e7; i++ {
		sum += i
	}
	log.Println("sum =", sum)

	// 堆快照：也可用 pprof.Lookup("heap").WriteTo(f, 0) 取得内置 profile
	heapFile, err := os.Create("heap.pprof")
	if err != nil {
		log.Fatal(err)
	}
	defer heapFile.Close()
	if err := pprof.WriteHeapProfile(heapFile); err != nil {
		log.Fatal(err)
	}
}
```

```bash
go tool pprof -http=:8000 cpu.pprof
go tool pprof -top -cum cpu.pprof     # 按累计耗时排序，看调用链
go tool pprof -list 'main.main' cpu.pprof  # 逐行标注热点
```

**易错点：**

- 生产环境把 `net/http/pprof` 挂在公网端口等于开放「性能与内存快照」，必须独立内网端口 + 鉴权，或按需临时开启。
- `heap` 是**采样**，默认 `runtime.MemProfileRate = 512 * 1024`，小对象多的场景会低估；排查泄漏时可临时调低采样间隔（有性能代价）。
- `inuse_space` 看「当前占用」，`alloc_space` 看「累计分配」；判断泄漏用前者，优化 GC 用后者。
- `block` 与 `mutex` 默认关闭，不调用 `SetBlockProfileRate` / `SetMutexProfileFraction` 只会看到空结果。
- CPU profile 默认只采 30 秒，短于采样窗口的请求可能完全采不到，测试时要循环打流量。

## 7. Go Modules 依赖管理

**三个核心文件：**

| 文件 | 作用 | 是否提交 |
| --- | --- | --- |
| `go.mod` | 声明模块路径、Go 版本、直接与间接依赖的最低版本要求 | 必须 |
| `go.sum` | 记录每个模块版本的**内容哈希**，防篡改与可复现 | 必须 |
| `go.work` | 多模块工作区，把多个本地模块临时组合成一个构建单元 | 视团队约定（库项目通常不提交） |

**`go.mod` 指令：**

| 指令 | 作用 |
| --- | --- |
| `module` | 模块路径，也是包的导入前缀 |
| `go` | 语言版本，同时决定默认的 GODEBUG 行为（如 1.22 的循环变量语义） |
| `toolchain` | 建议的工具链版本（Go 1.21+，配合 `GOTOOLCHAIN=auto` 自动下载） |
| `require` | 依赖模块及其**最低**版本要求 |
| `exclude` | 排除某个具体版本 |
| `replace` | 把某个模块替换为其它路径或版本（仅对当前主模块生效） |
| `retract` | 声明自己发布的某个版本作废，提示使用者升级 |

**最小版本选择（MVS）：**Go 不做「求最新」，而是「**满足所有约束的最低版本中取最高者**」。

```text
A requires C v1.2.0
B requires C v1.4.0
→ 最终选择 C v1.4.0（能同时满足两者的最低版本）
```

这与 npm 的「尽量装最新 + 嵌套多版本」完全不同：Go 的构建列表里**每个模块只有一个版本**，依赖图更扁平、可复现性更强。

**典型工作流：**

```bash
go mod init example.com/demo         # 初始化
go get github.com/gin-gonic/gin@v1.10.0   # 添加/升级到指定版本
go get github.com/gin-gonic/gin@latest    # 升到最新（谨慎）
go mod tidy                          # 增删依赖、清理 go.sum
go mod download                      # 只下载到模块缓存
go mod verify                        # 校验模块内容未被篡改
go mod graph                         # 打印依赖图
go mod why -m github.com/some/module # 解释某依赖为何被引入
go list -m all                       # 列出最终选定的所有模块版本
go list -m -u all                    # 列出可升级的模块
```

**`replace` 的两种用法：**

```bash
# 1) 替换成另一个版本（临时验证修复）
go mod edit -replace example.com/lib@v1.0.0=example.com/lib@v1.0.1

# 2) 替换成本地目录（联调私有库）
go mod edit -replace example.com/lib=../lib
```

```go
// go.mod
module example.com/demo

go 1.22

require (
	example.com/lib v1.0.0
	github.com/google/uuid v1.6.0
)

replace example.com/lib => ../lib
```

> 关键限制：`replace` **只对主模块的 `go.mod` 生效**，不会被传递给你的使用者。发布库时不要依赖 replace 来「修好」依赖。

**vendor：把依赖复制进仓库**

```bash
go mod vendor          # 生成 vendor/ 与 vendor/modules.txt
go build -mod=vendor   # 强制使用 vendor
```

- 当项目根目录存在 `vendor/` 且 `go` 版本 ≥ 1.14 时，`go build` **默认**使用 vendor。
- 适合：离线构建、构建环境无法访问代理、需要审计第三方源码。
- 代价：仓库体积变大，升级依赖必须重新 `go mod vendor` 并提交。

**多模块工作区 `go.work`（Go 1.18+）：**

```bash
go work init ./app ./lib
go work use ./tools     # 追加模块
go work sync            # 把工作区的版本约束同步回各模块的 go.mod
```

```go
// go.work
go 1.22

use (
	./app
	./lib
	./tools
)
```

`go.work` 让多个本地模块互相引用时**无需 replace**，改动即时生效。注意：CI 中若不想让工作区干扰构建，可设置 `GOWORK=off`。

**代理与校验相关环境变量：**

| 变量 | 作用 |
| --- | --- |
| `GOPROXY` | 模块代理，如 `https://proxy.golang.org,direct` 或国内镜像 |
| `GOPRIVATE` | 匹配私有模块路径，跳过代理与校验和数据库 |
| `GONOSUMDB` | 指定不校验 `go.sum` 的路径前缀 |
| `GOSUMDB` | 校验和数据库地址，默认 `sum.golang.org` |
| `GOFLAGS` | 全局默认参数，如 `-mod=vendor` |
| `GOMODCACHE` | 模块缓存目录 |

**易错点：**

- `go.sum` 必须提交，且不要手改；内容不一致时 `go mod verify` 会失败，正确做法是 `go mod tidy` 重新生成。
- 主版本 ≥ 2 时模块路径必须带 `/v2` 后缀，否则使用者无法导入，`go get` 会报「major version mismatch」。
- `go get -u ./...` 会升级**所有**直接与间接依赖，风险极高；生产项目应逐个升级并跑测试。
- `replace` 指向本地相对路径后，其他人拉代码会直接构建失败（路径不存在），只适合临时联调。
- `vendor/` 与 `go.work` 混用时行为容易混乱，CI 里建议显式指定 `-mod=mod` 或 `-mod=vendor`。

## 8. JSON 序列化与反序列化

Go 的 `encoding/json` 基于**反射 + struct tag** 工作，规则不算多，但细节坑极多。

**struct tag 常用选项：**

| tag 写法 | 作用 |
| --- | --- |
| `json:"name"` | 指定字段名 |
| `json:"-"` | 完全忽略该字段 |
| `json:"name,omitempty"` | 值为「空」时省略：`false`、`0`、`nil`、空串、长度 0 的 slice/map/array |
| `json:"name,omitzero"` | Go 1.24+，零值即省略，类型可实现 `IsZero() bool` 自定义判定 |
| `json:"name,string"` | 把数字/布尔编码成 JSON 字符串（如 `"123"`） |
| `json:",inline"` | **不存在这个选项**，嵌入请用匿名字段 |

**字段可见性规则：**

| 字段形式 | 是否参与序列化 |
| --- | --- |
| 导出字段（首字母大写） | 是 |
| 未导出字段（小写开头） | **否**，永远被忽略 |
| 匿名字段（嵌入） | 其导出字段会被「提升」到外层 |
| `json:"-"` | 否 |

**`omitempty` 与 `omitzero` 的差别（高频坑）：**

| 值 | `omitempty` | `omitzero` |
| --- | --- | --- |
| `0` / `false` / `""` / `nil` | 省略 | 省略 |
| 零值 struct（如 `time.Time{}`） | **不省略** | 省略 |
| 空数组 `[0]int{}` | 省略 | 省略 |
| 自定义 `IsZero` | 不生效 | 生效 |

```go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"time"
)

type Address struct {
	City string `json:"city"`
}

type User struct {
	ID        int64           `json:"id"`
	Name      string          `json:"name"`
	Nickname  string          `json:"nickname,omitempty"`
	Age       int             `json:"age,omitzero"`   // Go 1.24+，零值省略
	Internal  string          `json:"-"`              // 永不输出
	password  string          // 未导出字段，解码时也不会被赋值
	Meta      json.RawMessage `json:"meta,omitempty"` // 原样透传，延迟解析
	CreatedAt time.Time       `json:"created_at"`     // 默认 RFC3339Nano
	Address   Address         `json:"address"`
}

func main() {
	raw := []byte(`{
		"id": 1,
		"name": "alice",
		"nickname": "",
		"age": 0,
		"password": "should-be-ignored",
		"meta": {"role": "admin", "tags": ["vip"]},
		"created_at": "2024-05-01T10:00:00Z",
		"address": {"city": "上海"}
	}`)

	var u User
	if err := json.Unmarshal(raw, &u); err != nil {
		panic(err)
	}
	fmt.Printf("%+v\n", u)
	fmt.Println("password 未被赋值:", u.password == "")

	// RawMessage 可以延迟到需要时再解析
	var meta struct {
		Role string   `json:"role"`
		Tags []string `json:"tags"`
	}
	if err := json.Unmarshal(u.Meta, &meta); err != nil {
		panic(err)
	}
	fmt.Println("meta:", meta.Role, meta.Tags)

	out, err := json.Marshal(u)
	if err != nil {
		panic(err)
	}
	fmt.Println(string(out))

	// 严格解码：遇到未知字段直接报错
	dec := json.NewDecoder(bytes.NewReader([]byte(`{"id":2,"name":"bob","extra":1}`)))
	dec.DisallowUnknownFields()
	var u2 User
	fmt.Println("严格解码结果:", dec.Decode(&u2))

	// 大整数精度：前端 JS 的 Number 只能精确到 2^53
	type Payload struct {
		ID int64 `json:"id,string"` // 编码为字符串，避免精度丢失
	}
	b, _ := json.Marshal(Payload{ID: 9007199254740993})
	fmt.Println(string(b))
}
```

**时间格式：**`time.Time` 的 `MarshalJSON` 固定输出 RFC 3339（带纳秒，如 `2024-05-01T10:00:00Z`），反序列化也只接受 RFC 3339。要输出 `2006-01-02 15:04:05` 这类格式，必须自定义类型：

```go
type CustomTime struct{ time.Time }

func (c CustomTime) MarshalJSON() ([]byte, error) {
	return []byte(`"` + c.Format("2006-01-02 15:04:05") + `"`), nil
}
```

**易错点：**

- `omitempty` 不会省略零值 struct，`time.Time{}` 依然会输出 `"0001-01-01T00:00:00Z"`；要省略请用 `omitzero` 或改成指针。
- nil slice 会编码成 `null`，空 slice 编码成 `[]`，前端判空逻辑要区分。
- `json.Unmarshal` 默认**忽略未知字段**，也**大小写不敏感**地匹配键名；要严格必须 `DisallowUnknownFields`。
- 未导出字段既不输出也不会被解码，`password` 即使出现在 JSON 里也进不来。
- `omitzero` 需要 Go 1.24+；在更早版本里它会被当成未知选项**静默忽略**，零值字段照样输出。
- `json.Marshal` 默认会转义 `<`、`>`、`&` 为 `\u003c` 等；需要原样输出时用 `Encoder.SetEscapeHTML(false)`。
- 用 `map[string]any` 解码数字时全部变成 `float64`，大整数会失真；改用 `Decoder.UseNumber()` 或具体 struct。

## 9. 标准库 HTTP 服务

标准库的 HTTP 栈由四层组成：`Listener` → `Server` → `ServeMux`（路由器）→ `Handler`（业务）。理解这四层，才能答好「不用框架能不能写服务」。

**核心类型：**

| 类型 | 作用 |
| --- | --- |
| `http.Handler` | 接口：`ServeHTTP(w, r)`，中间件与业务的最小契约 |
| `http.HandlerFunc` | 函数适配器，让普通函数变成 `Handler` |
| `http.ServeMux` | 路由器，Go 1.22 起支持方法与路径通配符 |
| `http.Server` | 持有监听、超时、TLS 等配置 |
| `http.Client` | 客户端，**必须**显式设置超时 |

**Go 1.22 起的路由模式：**

| 模式 | 匹配 |
| --- | --- |
| `GET /users/{id}` | 仅 GET，`{id}` 匹配单段，用 `r.PathValue("id")` 取值 |
| `POST /users` | 仅 POST |
| `GET /files/{path...}` | `{path...}` 匹配剩余全部路径 |
| `/static/` | 以 `/` 结尾表示**子树匹配** |
| `GET /users/{id}/posts/{postID}` | 多段通配 |

> 下面的示例使用 Go 1.22+ 的方法与通配符路由；在 1.21 及更早版本中需退回 `mux.HandleFunc("/users/", ...)` 并手动解析路径。

**服务端超时配置（生产必配）：**

| 字段 | 覆盖阶段 | 防什么 |
| --- | --- | --- |
| `ReadHeaderTimeout` | 读取请求头 | Slowloris 慢速攻击 |
| `ReadTimeout` | 读取整个请求（头 + 体） | 慢速上传请求体 |
| `WriteTimeout` | 写响应 | 客户端长时间不读 |
| `IdleTimeout` | keep-alive 连接空闲 | 连接长期占用不释放 |

```go
package main

import (
	"context"
	"encoding/json"
	"errors"
	"log"
	"net/http"
	"os"
	"os/signal"
	"syscall"
	"time"
)

type ctxKey string

const reqIDKey ctxKey = "reqID"

// 中间件：注入请求 ID
func withRequestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		ctx := context.WithValue(r.Context(), reqIDKey, r.Header.Get("X-Request-ID"))
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

// 中间件：兜底 recover，避免单个请求 panic 打挂整个进程
func withRecover(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				log.Printf("panic: %v", rec)
				http.Error(w, "internal error", http.StatusInternalServerError)
			}
		}()
		next.ServeHTTP(w, r)
	})
}

func main() {
	mux := http.NewServeMux()

	mux.HandleFunc("GET /healthz", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	})

	mux.HandleFunc("GET /users/{id}", func(w http.ResponseWriter, r *http.Request) {
		reqID, _ := r.Context().Value(reqIDKey).(string)
		id := r.PathValue("id")
		w.Header().Set("Content-Type", "application/json; charset=utf-8")
		_ = json.NewEncoder(w).Encode(map[string]string{
			"id":     id,
			"req_id": reqID,
		})
	})

	// 限制请求体大小，防止恶意大包打爆内存
	mux.HandleFunc("POST /echo", func(w http.ResponseWriter, r *http.Request) {
		r.Body = http.MaxBytesReader(w, r.Body, 1<<20) // 1MB
		var body map[string]any
		if err := json.NewDecoder(r.Body).Decode(&body); err != nil {
			http.Error(w, "bad request", http.StatusBadRequest)
			return
		}
		_ = json.NewEncoder(w).Encode(body)
	})

	handler := withRecover(withRequestID(mux))

	srv := &http.Server{
		Addr:              ":8080",
		Handler:           handler,
		ReadHeaderTimeout: 5 * time.Second,
		ReadTimeout:       10 * time.Second,
		WriteTimeout:      10 * time.Second,
		IdleTimeout:       60 * time.Second,
	}

	go func() {
		if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			log.Fatalf("listen: %v", err)
		}
	}()

	// 优雅关闭：先停止接收新连接，再等待在途请求完成
	stop := make(chan os.Signal, 1)
	signal.Notify(stop, syscall.SIGINT, syscall.SIGTERM)
	<-stop

	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	if err := srv.Shutdown(ctx); err != nil {
		log.Printf("shutdown: %v", err)
	}
	log.Println("服务已退出")
}
```

**易错点：**

- `http.Server` 默认**没有任何超时**，不设置就等于给慢速攻击留门；`ReadHeaderTimeout` 必须配。
- `http.Get` / `http.DefaultClient` 默认**无超时**，生产必须构造带 `Timeout` 的 `http.Client`。
- handler 里用 `r.Context()` 能感知客户端断开；但若把请求传给后台任务，请求结束后 ctx 会被取消，必须用 `context.WithoutCancel`（Go 1.21+）或新建 ctx。
- `WriteHeader` 只能调用一次；先 `Write` 再 `WriteHeader` 会失效并打印日志。
- `http.Error` 会设置 `Content-Type: text/plain` 并结束响应，不要再叠加业务 JSON。

## 10. database/sql 与连接池

**最重要的一句话：`sql.DB` 不是一条连接，而是一个连接池的句柄。**

它本身是并发安全的，**整个进程只应创建一次**（通常在 `main` 或依赖注入容器里），并在进程退出时 `Close`。

**连接池三个参数：**

| 方法 | 默认值 | 作用 |
| --- | --- | --- |
| `SetMaxOpenConns(n)` | `0`（不限制） | 最大打开连接数（使用中 + 空闲） |
| `SetMaxIdleConns(n)` | `2` | 空闲池中保留的最大连接数 |
| `SetConnMaxLifetime(d)` | `0`（永不过期） | 连接最长存活时间，避免被中间件/数据库单方面断开 |
| `SetConnMaxIdleTime(d)` | `0`（永不过期） | 连接空闲多久后被关闭（Go 1.15+） |

**调优经验：**

1. `MaxOpenConns` 不是越大越好，要与数据库的最大连接数、实例数一起算：`单实例连接数 × 实例数 < 数据库上限`。
2. `MaxIdleConns` 建议设成与 `MaxOpenConns` 接近，否则高并发后连接被频繁关闭又重建。
3. `ConnMaxLifetime` 必须小于负载均衡/数据库的 `wait_timeout`（常见 30 分钟以内），否则会拿到已被服务端断开的「死连接」。
4. `MaxOpenConns` 打满时，新请求会**阻塞等待**，直到有连接归还或 ctx 超时——这也是「服务突然整体变慢」的常见原因。

**三种执行方法：**

| 方法 | 返回 | 适用 |
| --- | --- | --- |
| `db.Exec` | `sql.Result` | INSERT / UPDATE / DELETE / DDL |
| `db.Query` | `*sql.Rows` | 多行查询，**必须** `Close` 并检查 `rows.Err()` |
| `db.QueryRow` | `*sql.Row` | 至多一行，未查到返回 `sql.ErrNoRows` |

```go
package main

import (
	"context"
	"database/sql"
	"errors"
	"fmt"
	"log"
	"time"

	_ "modernc.org/sqlite" // 纯 Go 的 SQLite 驱动：go get modernc.org/sqlite
)

type User struct {
	ID   int64
	Name string
}

func main() {
	// sql.DB 只是句柄，第一次使用时才真正建立连接
	db, err := sql.Open("sqlite", "file:demo.db")
	if err != nil {
		log.Fatal(err)
	}
	defer db.Close()

	db.SetMaxOpenConns(20)
	db.SetMaxIdleConns(10)
	db.SetConnMaxLifetime(30 * time.Minute)
	db.SetConnMaxIdleTime(5 * time.Minute)

	ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
	defer cancel()

	if _, err := db.ExecContext(ctx,
		`CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, name TEXT NOT NULL)`); err != nil {
		log.Fatal(err)
	}

	// 占位符 + 参数绑定：驱动负责转义，杜绝 SQL 注入
	if _, err := db.ExecContext(ctx,
		`INSERT OR REPLACE INTO users (id, name) VALUES (?, ?)`, 1, "alice"); err != nil {
		log.Fatal(err)
	}

	// Prepare：同一 SQL 复用，省去重复解析；记得 Close
	stmt, err := db.PrepareContext(ctx, `SELECT id, name FROM users WHERE id = ?`)
	if err != nil {
		log.Fatal(err)
	}
	defer stmt.Close()

	var u User
	err = stmt.QueryRowContext(ctx, 1).Scan(&u.ID, &u.Name)
	switch {
	case errors.Is(err, sql.ErrNoRows):
		fmt.Println("用户不存在")
	case err != nil:
		log.Fatal(err)
	default:
		fmt.Printf("单行查询: %+v\n", u)
	}

	rows, err := db.QueryContext(ctx, `SELECT id, name FROM users ORDER BY id`)
	if err != nil {
		log.Fatal(err)
	}
	defer rows.Close()

	for rows.Next() {
		var x User
		if err := rows.Scan(&x.ID, &x.Name); err != nil {
			log.Fatal(err)
		}
		fmt.Println("多行查询:", x)
	}
	// 必须检查 Err()：遍历中途出错时 Next 只会返回 false
	if err := rows.Err(); err != nil {
		log.Fatal(err)
	}

	// 事务：defer Rollback + 显式 Commit
	tx, err := db.BeginTx(ctx, nil)
	if err != nil {
		log.Fatal(err)
	}
	defer tx.Rollback() // Commit 之后再 Rollback 返回 ErrTxDone，可安全忽略

	if _, err := tx.ExecContext(ctx, `UPDATE users SET name = ? WHERE id = ?`, "alice2", 1); err != nil {
		log.Fatal(err)
	}
	if err := tx.Commit(); err != nil {
		log.Fatal(err)
	}
	fmt.Println("事务提交成功")
}
```

**SQL 注入对比：**

| 写法 | 是否安全 | 说明 |
| --- | --- | --- |
| `"SELECT * FROM users WHERE name = '" + name + "'"` | **否** | 拼接字符串，`' OR '1'='1` 直接绕过 |
| `db.Query("... WHERE name = ?", name)` | 是 | 占位符由驱动转义 |
| `fmt.Sprintf("... WHERE name = %q", name)` | 否 | 只是加引号，不处理转义细节 |
| `"ORDER BY " + col` | **否** | 标识符不能用占位符，必须**白名单校验** |

**易错点：**

- `sql.Open` 不会真正连接数据库，也不会校验 DSN；要验证连通性用 `db.PingContext`。
- 每次请求 `sql.Open` 一个 `sql.DB` 会创建新的连接池，导致连接数暴涨；应全局复用。
- `rows` 不 `Close` 会泄漏连接，最终把连接池耗尽，表现为请求全部卡在等连接。
- `Scan` 到 `NULL` 必须用 `sql.NullString`、`sql.NullInt64` 或指针类型，否则报错。
- 占位符语法因驱动而异：MySQL 用 `?`，PostgreSQL 用 `$1`，SQLite 两者都支持。
- 长事务会长时间占用连接，且放大锁冲突；事务里不要做 HTTP 调用等外部 IO。

## 11. 日志与结构化日志

**从 `log` 到 `log/slog` 的演进：**

| 维度 | `log`（标准库） | `log/slog`（Go 1.21+） | zap / zerolog |
| --- | --- | --- | --- |
| 结构化 | 不支持，只能拼字符串 | 支持键值对 | 支持 |
| 级别 | 无（需自己封装） | Debug/Info/Warn/Error | 支持 |
| 输出格式 | 固定文本 | Text / JSON，可自定义 Handler | JSON / 二进制 |
| 性能 | 一般（有锁） | 中等 | 极高（零分配） |
| 依赖 | 标准库 | 标准库 | 第三方 |
| 生态 | 简单场景 | 逐步成为默认 | 成熟（采样、轮转、hook） |

**slog 的四个核心概念：**

1. **Logger**：入口，`slog.New(handler)` 创建；带 `With` 派生携带固定字段的子 logger。
2. **Handler**：决定「写到哪里、写成什么格式」，内置 `TextHandler` / `JSONHandler`。
3. **Attr**：键值对，`slog.String`、`slog.Int`、`slog.Duration`、`slog.Any` 等构造。
4. **Level**：`Debug=-4`、`Info=0`、`Warn=4`、`Error=8`，可通过 `HandlerOptions.Level` 控制最低输出级别。

```go
package main

import (
	"context"
	"errors"
	"log/slog"
	"os"
)

type ctxKey string

const traceKey ctxKey = "trace_id"

func main() {
	handler := slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
		Level:     slog.LevelInfo,
		AddSource: true, // 输出文件与行号，定位问题方便，但有性能开销
	})

	// With 派生：所有日志自动带上 service 字段
	logger := slog.New(handler).With("service", "order")

	// InfoContext：把 ctx 一并传入，便于自定义 Handler 提取链路信息
	ctx := context.WithValue(context.Background(), traceKey, "trace-123")
	logger.InfoContext(ctx, "创建订单", "order_id", 1001, "amount", 99.5)

	logger.Warn("库存不足", slog.Int("sku", 42), slog.String("warehouse", "sh-01"))

	// WithGroup：把一组字段收进同一个 JSON 对象
	dbLogger := logger.WithGroup("db").With("table", "orders")
	dbLogger.Error("查询失败", "err", errors.New("connection reset"))

	// 设置默认 logger，让第三方库里的 slog 调用也走同一套输出
	slog.SetDefault(logger)
	slog.Info("全局 logger 已生效")
}
```

**输出示例（每行一条 JSON）：**

```json
{"time":"2026-10-23T10:00:00.000+08:00","level":"INFO","source":{"function":"main.main","file":"main.go","line":26},"msg":"创建订单","service":"order","order_id":1001,"amount":99.5}
{"time":"2026-10-23T10:00:00.000+08:00","level":"WARN","source":{...},"msg":"库存不足","service":"order","sku":42,"warehouse":"sh-01"}
{"time":"2026-10-23T10:00:00.000+08:00","level":"ERROR","source":{...},"msg":"查询失败","service":"order","db":{"table":"orders","err":"connection reset"}}
```

**日志规范建议：**

| 建议 | 理由 |
| --- | --- |
| 用键值对而不是 `fmt.Sprintf` 拼字符串 | 保留结构化，便于检索与聚合 |
| 统一字段名（`err`、`user_id`、`trace_id`） | 跨服务查询一致 |
| 用 `logger.With` 携带请求级字段 | 避免每条日志重复传参 |
| 错误用 `"err", err` 而非 `"err", err.Error()` | 保留错误类型，部分 Handler 能展开链 |
| 日志级别可配置 | 生产默认 Info，排查时临时开 Debug |
| 敏感信息脱敏 | 密码、token、身份证号禁止落盘 |

**易错点：**

- 每个请求 `slog.New(...)` 新建 logger 会丢掉 `With` 的公共字段，也增加分配；应在启动时创建一次并注入。
- `slog` 默认级别是 `Info`，`Debug` 日志不会输出，误以为「代码没执行」。
- `context` 里的 trace id 不会自动出现在日志中，需要自定义 Handler 或在入口处 `With("trace_id", id)`。
- 标准库 `log` 与 `slog` 是两套输出；混用时最好 `slog.SetDefault` 并用 `slog.NewLogLogger` 桥接。
- `slog` 不做日志轮转，写文件需要配合 `lumberjack` 等库或交给容器/采集侧。

## 12. 配置管理与环境变量

**配置的来源与优先级（12-Factor 风格）：**

```text
命令行参数 > 环境变量 > 配置文件 > 代码内默认值
```

| 方式 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- |
| 硬编码 | 简单 | 改配置要重新编译 | 常量、不随环境变化的值 |
| 配置文件（YAML/TOML） | 结构清晰、可版本化 | 需要解析库、易与密钥混放 | 复杂静态配置 |
| 环境变量 | 容器友好、易注入密钥 | 全是字符串、层级表达差 | 部署差异、密钥 |
| 命令行参数 | 优先级最高、临时覆盖方便 | 参数多时难管理 | 调试、一次性覆盖 |
| 配置中心（etcd/Nacos） | 动态生效 | 引入外部依赖与复杂度 | 大规模微服务 |

**读取环境变量的两种 API：**

| API | 未设置时 | 空字符串时 | 用途 |
| --- | --- | --- | --- |
| `os.Getenv(k)` | `""` | `""` | 无法区分「没设」与「设为空」 |
| `os.LookupEnv(k)` | `ok=false` | `ok=true, v=""` | 需要区分两种情况时用 |

```go
package main

import (
	"fmt"
	"os"
	"strconv"
	"time"
)

type Config struct {
	Addr         string
	ReadTimeout  time.Duration
	MaxOpenConns int
	LogLevel     string
	Debug        bool
}

// Load：默认值 → 环境变量覆盖 → 校验，一次性完成
func Load() (Config, error) {
	cfg := Config{
		Addr:         ":8080",
		ReadTimeout:  10 * time.Second,
		MaxOpenConns: 20,
		LogLevel:     "info",
	}

	if v, ok := os.LookupEnv("APP_ADDR"); ok {
		cfg.Addr = v
	}

	if v, ok := os.LookupEnv("APP_READ_TIMEOUT"); ok {
		d, err := time.ParseDuration(v)
		if err != nil {
			return Config{}, fmt.Errorf("APP_READ_TIMEOUT 非法: %w", err)
		}
		cfg.ReadTimeout = d
	}

	if v, ok := os.LookupEnv("APP_MAX_OPEN_CONNS"); ok {
		n, err := strconv.Atoi(v)
		if err != nil {
			return Config{}, fmt.Errorf("APP_MAX_OPEN_CONNS 非法: %w", err)
		}
		cfg.MaxOpenConns = n
	}

	if v, ok := os.LookupEnv("APP_LOG_LEVEL"); ok {
		cfg.LogLevel = v
	}

	if v, ok := os.LookupEnv("APP_DEBUG"); ok {
		b, err := strconv.ParseBool(v)
		if err != nil {
			return Config{}, fmt.Errorf("APP_DEBUG 非法: %w", err)
		}
		cfg.Debug = b
	}

	// 校验放在启动阶段，快速失败而不是运行到一半才炸
	if cfg.MaxOpenConns <= 0 {
		return Config{}, fmt.Errorf("APP_MAX_OPEN_CONNS 必须为正数")
	}
	switch cfg.LogLevel {
	case "debug", "info", "warn", "error":
	default:
		return Config{}, fmt.Errorf("APP_LOG_LEVEL 只能是 debug/info/warn/error")
	}
	return cfg, nil
}

func main() {
	cfg, err := Load()
	if err != nil {
		fmt.Fprintln(os.Stderr, "配置加载失败:", err)
		os.Exit(1)
	}
	fmt.Printf("%+v\n", cfg)
}
```

```bash
APP_ADDR=:9000 APP_READ_TIMEOUT=5s APP_DEBUG=true go run .
```

**第三方库的定位：**

| 库 | 能力 |
| --- | --- |
| `spf13/viper` | 多格式配置、环境变量、远程配置、watch，功能全但依赖重 |
| `kelseyhightower/envconfig` | 用 struct tag 直接映射环境变量，轻量 |
| `caarlos0/env` | 同上，支持默认值与自定义解析 |
| `knadh/koanf` | 模块化设计，比 viper 轻 |

**易错点：**

- 环境变量永远是字符串，`"false"` 转 `bool` 要用 `strconv.ParseBool`，直接 `!= ""` 判断会把 `"false"` 当成真。
- `os.Getenv` 无法区分「未设置」与「设为空」，需要「空值合法」的语义时用 `os.LookupEnv`。
- 在 `init()` 或包级变量里读配置，会让测试无法替换、也让启动顺序变得隐式；应显式调用 `Load()` 并注入。
- 配置校验失败要在**启动阶段**直接退出，不要带着非法配置运行到第一个请求。
- 密钥只从环境变量或密钥管理服务读取，不要写进仓库的配置文件，更不要打进日志。

## 13. 命令行工具与 Cobra

**Cobra 的定位：**Go 生态最主流的 CLI 框架，`kubectl`、`hugo`、`docker`（部分）都用它。核心由三部分组成：

| 概念 | 作用 |
| --- | --- |
| `cobra.Command` | 一个命令（含子命令树），通过 `AddCommand` 组装 |
| `Flags` | 参数：`PersistentFlags` 对本命令及所有子命令生效，`Flags` 仅本命令 |
| `Run` / `RunE` | 执行体；`RunE` 返回 error，便于统一错误处理与退出码 |

**与其它方案对比：**

| 方案 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- |
| 标准库 `flag` | 零依赖、简单 | 不支持子命令、长短选项写法受限 | 小工具 |
| `spf13/pflag` | 支持 `--long` / `-s`、Posix 风格 | 仍需自己组织命令树 | 需要 GNU 风格参数 |
| `spf13/cobra` | 子命令、补全、帮助、文档生成 | 依赖较多、抽象偏重 | 中大型 CLI |
| `urfave/cli` | API 简洁、内置功能多 | 生态与扩展性弱于 cobra | 中小型 CLI |

```bash
go mod init demo
go get github.com/spf13/cobra@latest
```

```go
package main

import (
	"fmt"
	"os"

	"github.com/spf13/cobra"
)

var (
	port    int
	verbose bool
)

func newRootCmd() *cobra.Command {
	root := &cobra.Command{
		Use:           "demo",
		Short:         "演示 Cobra 的命令行工具",
		Long:          "demo 是一个用于演示 Cobra 子命令、参数与错误处理的示例程序。",
		SilenceUsage:  true, // 业务错误时不打印用法，避免噪声
		SilenceErrors: true, // 由 main 统一打印错误
	}

	// 持久化参数：所有子命令都能用
	root.PersistentFlags().BoolVarP(&verbose, "verbose", "v", false, "输出详细日志")

	root.AddCommand(newServeCmd(), newVersionCmd())
	return root
}

func newServeCmd() *cobra.Command {
	cmd := &cobra.Command{
		Use:   "serve",
		Short: "启动 HTTP 服务",
		Args:  cobra.NoArgs, // 不接受位置参数
		RunE: func(cmd *cobra.Command, args []string) error {
			if port <= 0 || port > 65535 {
				return fmt.Errorf("端口 %d 不合法，应在 1-65535 之间", port)
			}
			fmt.Fprintf(cmd.OutOrStdout(), "启动服务 port=%d verbose=%v\n", port, verbose)
			return nil
		},
	}
	// 本地参数：只有 serve 能用
	cmd.Flags().IntVarP(&port, "port", "p", 8080, "监听端口")
	return cmd
}

func newVersionCmd() *cobra.Command {
	return &cobra.Command{
		Use:   "version",
		Short: "打印版本号",
		Args:  cobra.NoArgs,
		Run: func(cmd *cobra.Command, args []string) {
			fmt.Fprintln(cmd.OutOrStdout(), "demo v1.0.0")
		},
	}
}

func main() {
	if err := newRootCmd().Execute(); err != nil {
		fmt.Fprintln(os.Stderr, "错误:", err)
		os.Exit(1)
	}
}
```

```bash
go run . --help
go run . serve --port 9090 -v
go run . version
go run . serve extra   # 报错：unknown command "extra" for "demo serve"
```

**参数校验器：**

| 校验器 | 含义 |
| --- | --- |
| `cobra.NoArgs` | 不接受位置参数 |
| `cobra.ExactArgs(n)` | 必须正好 n 个 |
| `cobra.MinimumNArgs(n)` / `MaximumNArgs(n)` | 数量区间 |
| `cobra.RangeArgs(min, max)` | 闭区间 |
| `cobra.ArbitraryArgs` | 任意数量 |

**易错点：**

- 用 `Run` 而不是 `RunE` 时无法把错误交给 `Execute`，退出码与错误输出都要自己管；推荐 `RunE`。
- `SilenceUsage` 不设置，业务错误也会打印一整页帮助信息，体验很差。
- 子命令同时定义 `PersistentPreRun` 会**覆盖**父命令的同名钩子，需要链式调用 `cmd.Parent().PersistentPreRunE(...)`。
- 用 viper 绑定时必须在 flag 定义**之后**调用 `BindPFlag`，否则拿到的是零值。
- Cobra 会自动注入 `help` 与 `completion` 子命令，做命令数量断言时要排除它们。

## 14. 代码规范与静态检查

**工具分层：**

| 层级 | 工具 | 检查内容 |
| --- | --- | --- |
| 格式化 | `gofmt` / `goimports` / `gofumpt` | 缩进、空格、导入分组与排序 |
| 官方检查 | `go vet` | printf 格式串、锁拷贝、不可达代码、struct tag、context 取消泄漏 |
| 社区检查 | `staticcheck` | 未使用代码、低效写法、可疑逻辑（SA/S/ST/QF 系列） |
| 聚合器 | `golangci-lint` | 并行运行几十个 linter，统一配置与输出 |
| 安全 | `gosec`、`govulncheck` | 硬编码密钥、弱随机、已知漏洞依赖 |
| 竞态 | `go test -race` / `go run -race` | 数据竞争 |
| 覆盖率 | `go test -cover` | 行覆盖率与未覆盖代码 |

**常用 linter 及其职责：**

| linter | 检查内容 |
| --- | --- |
| `errcheck` | 未处理的 error 返回值 |
| `govet` | 官方 vet 的全部检查 |
| `staticcheck` | 综合静态分析 |
| `ineffassign` | 赋值后从未使用的变量 |
| `unused` | 未使用的函数、变量、字段 |
| `revive` / `golint` | 命名与注释风格 |
| `bodyclose` | HTTP 响应体未关闭 |
| `sqlclosecheck` | `rows` / `stmt` 未关闭 |
| `noctx` | 使用未带 context 的请求方法 |
| `errorlint` | 用 `==` 比较错误、`%v` 包装等错误链问题 |
| `gosec` | 安全规则扫描 |
| `misspell` | 英文拼写错误 |

**`.golangci.yml`（golangci-lint v2 格式）：**

```yaml
version: "2"

linters:
  default: standard   # errcheck、govet、ineffassign、staticcheck、unused
  enable:
    - bodyclose
    - errorlint
    - gosec
    - misspell
    - noctx
    - revive
    - sqlclosecheck
  exclusions:
    rules:
      - path: _test\.go
        linters:
          - gosec
          - noctx

formatters:
  enable:
    - gofmt
    - goimports

issues:
  max-issues-per-linter: 0
  max-same-issues: 0
```

> 若还在用 golangci-lint v1，配置结构是顶层的 `linters:` 列表 + `linters-settings:`，升级到 v2 需要执行 `golangci-lint migrate` 自动转换。

```bash
gofmt -l -w .                 # 列出并就地格式化
goimports -l -w .             # 同时整理 import 分组
go vet ./...                  # 官方静态检查
staticcheck ./...             # 更严格的社区检查
golangci-lint run ./...       # 聚合检查（读取 .golangci.yml）
golangci-lint run --fix ./... # 自动修复可修复项
govulncheck ./...             # 扫描依赖中的已知漏洞
go test -race -cover ./...    # 竞态 + 覆盖率
```

**Makefile 统一入口：**

```makefile
.PHONY: fmt lint test build

fmt:
	gofmt -l -w .
	goimports -l -w .

lint:
	golangci-lint run ./...

test:
	go test -race -coverprofile=cover.out ./...

build:
	CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o bin/app ./cmd/app
```

**CI 中落地（GitHub Actions）：**

```yaml
name: CI
on: [push, pull_request]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.22'
          cache: true
      - name: 格式检查
        run: test -z "$(gofmt -l .)"
      - name: 静态检查
        uses: golangci/golangci-lint-action@v6
        with:
          version: latest
      - name: 测试
        run: go test -race -cover ./...
      - name: 漏洞扫描
        run: go run golang.org/x/vuln/cmd/govulncheck@latest ./...
```

**易错点：**

- `golangci-lint` 默认只开一小部分 linter，`default: standard` 之外的能力需要显式 `enable`。
- 滥用 `//nolint` 会掩盖真实问题；必须写原因，如 `//nolint:errcheck // 关闭失败不影响主流程`。
- 本地 `gofmt` 版本与 CI 不一致会产生「本地没问题、CI 挂」；应在 CI 固定 Go 版本。
- `go vet` 的 `copylocks` 会拦住「拷贝含 `sync.Mutex` 的 struct」，这不是误报，通常说明值接收者用错了。
- 缓存（`actions/cache` 或 `GOCACHE`）配置错误会让 CI「秒过」，实际根本没跑检查；失败时先看步骤耗时。
