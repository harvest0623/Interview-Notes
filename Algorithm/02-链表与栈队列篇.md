## 1. 反转链表与区间反转

**题目：** ① 反转整个单链表并返回新头节点，要求迭代 O(1) 空间、递归各写一版。② 反转区间 `[m, n]`（1 ≤ m ≤ n ≤ 长度），要求一趟扫描完成。

**示例：**

```js
reverseList(buildList([1, 2, 3, 4, 5]));        // [5, 4, 3, 2, 1]
reverseBetween(buildList([1, 2, 3, 4, 5]), 2, 4); // [1, 4, 3, 2, 5]
```

**思路：**

- 迭代：三指针 `prev / cur / next`。先用 `next` 保存后继，再让 `cur.next = prev`，最后整体后移。
  - 为什么必须临时保存 `next`：改完 `cur.next` 就丢失后继，链表断裂。
  - 为什么是 O(n)/O(1)：每个节点访问一次，只用了三个指针。
- 递归：先递归反转 `head.next` 得到新头，再让 `head.next.next = head`、`head.next = null`；栈空间 O(n)，面试通常要求迭代版本。
- 区间反转：哑节点 `dummy` +「头插法」。`prev` 停在 `m - 1` 位置，`start` 是 `m` 位置；反复把 `start` 后面的节点插到 `prev` 之后。
  - 为什么用头插而不是逐段断开重接：一趟完成且不用记录 `n` 之后的节点，`then` 始终指向待搬运节点。
  - 为什么需要 `dummy`：`m = 1` 时头节点会变，哑节点让「前驱」永远存在。

**代码：**

```js
class ListNode {
    constructor(val = 0, next = null) {
        this.val = val;
        this.next = next;
    }
}

function buildList(arr) {
    const dummy = new ListNode();
    let tail = dummy;
    for (const v of arr) {
        tail.next = new ListNode(v);
        tail = tail.next;
    }
    return dummy.next;
}

function toArray(head) {
    const res = [];
    while (head) {
        res.push(head.val);
        head = head.next;
    }
    return res;
}

function reverseList(head) {
    let prev = null;
    let cur = head;
    while (cur) {
        const next = cur.next;   // 先保存后继，否则断链
        cur.next = prev;
        prev = cur;
        cur = next;
    }
    return prev;
}

function reverseListRec(head) {
    if (head === null || head.next === null) return head;
    const newHead = reverseListRec(head.next);
    head.next.next = head;       // 让后继指回自己
    head.next = null;            // 断开正向指针，防止成环
    return newHead;
}

function reverseBetween(head, m, n) {
    const dummy = new ListNode(0, head);
    let prev = dummy;
    for (let i = 1; i < m; i++) prev = prev.next;   // prev 停在 m - 1
    const start = prev.next;
    let then = start.next;
    for (let i = 0; i < n - m; i++) {               // 头插法搬运 n - m 次
        start.next = then.next;
        then.next = prev.next;
        prev.next = then;
        then = start.next;
    }
    return dummy.next;
}

// 验证
console.log(toArray(reverseList(buildList([1, 2, 3, 4, 5]))));        // [5,4,3,2,1]
console.log(toArray(reverseListRec(buildList([1, 2]))));              // [2,1]
console.log(toArray(reverseBetween(buildList([1, 2, 3, 4, 5]), 2, 4))); // [1,4,3,2,5]
```

**复杂度：** 反转整表迭代 O(n)/O(1)、递归 O(n)/O(n)（栈）；区间反转 O(n)/O(1)，只遍历一趟。

**边界与坑：**

- 空链表返回 `null`；单节点反转后仍是自己，循环不执行。
- 递归版本最后必须 `head.next = null`，否则原头节点与第二个节点互相指向，形成环。
- `m = 1` 时头节点改变，必须返回 `dummy.next` 而不是 `head`。
- `m = n` 时头插循环执行 0 次，应原样返回。

**面试怎么答：** 先写迭代版并解释「保存 next → 反向 → 后移」三步，再补递归版并说明栈开销。区间反转讲「哑节点 + 头插」，重点解释 `then` 为什么每次都取 `start.next`：搬运后 `start` 的后继已经变成原 `then` 的后继。

**易错点：**

- 迭代版先 `cur.next = prev` 再保存 `next`，链表断裂。
- 递归版忘记 `head.next = null`，结果成环。
- `reverseBetween` 的循环次数写成 `n - m + 1`，多搬一个节点。

## 2. 环形链表检测与入口

**题目：** ① 判断链表是否有环。② 若有环，返回入环的第一个节点，否则返回 `null`。要求 O(1) 额外空间。

**示例：**

```js
hasCycle(buildCycle([3, 2, 0, -4], 1));      // true，尾节点连到下标 1
detectCycle(buildCycle([3, 2, 0, -4], 1));   // 值为 2 的节点
```

**思路：**

- 哈希表：遍历并把节点存入 `Set`，第一次重复出现的节点就是入口，O(n)/O(n)。最直观但不是最优空间。
- Floyd 判圈：慢指针走 1 步、快指针走 2 步。
  - 为什么一定有环时必相遇：快指针每轮相对慢指针靠近 1 步，环内距离必然归零。
  - 为什么无环时退出：`fast` 或 `fast.next` 为 `null`，说明走到了尽头。
- 找入口的数学：设头到入口距离 `a`，入口到相遇点距离 `b`，环长 `c`。相遇时慢走 `a + b`，快走 `a + b + k*c`，且快是慢的两倍：
  `2(a + b) = a + b + k*c` → `a = k*c - b = (k - 1)*c + (c - b)`。
  即「从头走 `a` 步」与「从相遇点走 `c - b` 步」同时到达入口。所以相遇后让一个指针回到头部，两指针同速前进，再次相遇处就是入口。
  - 为什么 `k` 不影响结论：多绕的整圈可以忽略，位置等价。

**代码：**

```js
function hasCycle(head) {
    let slow = head;
    let fast = head;
    while (fast && fast.next) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow === fast) return true;
    }
    return false;
}

function detectCycle(head) {
    let slow = head;
    let fast = head;
    while (fast && fast.next) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow === fast) {
            let p = head;                 // 一个指针回到头部
            while (p !== slow) {          // 同速前进，相遇即入口
                p = p.next;
                slow = slow.next;
            }
            return p;
        }
    }
    return null;
}

function buildCycle(arr, pos) {
    const head = buildList(arr);
    if (pos < 0 || head === null) return head;
    let tail = head;
    while (tail.next) tail = tail.next;
    let entry = head;
    for (let i = 0; i < pos; i++) entry = entry.next;
    tail.next = entry;
    return head;
}

// 验证
console.log(hasCycle(buildCycle([3, 2, 0, -4], 1)));              // true
console.log(detectCycle(buildCycle([3, 2, 0, -4], 1)) === null); // false
const c = detectCycle(buildCycle([3, 2, 0, -4], 1));
console.log(c ? c.val : null);                                    // 2
console.log(detectCycle(buildList([1, 2])));                      // null
```

**复杂度：** 时间 O(n)（判圈最多 n 步，找入口再走 a 步），空间 O(1)。哈希表法为 O(n)/O(n)。

**边界与坑：**

- 空链表、单节点无环：返回 `false` / `null`，循环条件 `fast && fast.next` 已覆盖。
- 单节点自环（`pos = 0`）：`slow === fast` 在第一次迭代成立，之后 `p` 从头部出发立即相遇。
- `while (fast && fast.next)` 的顺序不能反，`fast.next.next` 需要 `fast.next` 非空。
- 找入口时必须用「相遇点」而不是「相遇时的慢指针值」继续走，否则逻辑混乱。
- 只判环不找入口时不要用 `Set`，面试明确要求 O(1) 空间。

**面试怎么答：** 先给判圈结论「快慢指针必相遇」，再推公式 `a = (k - 1)c + (c - b)`，最后说「相遇后一个指针回头，同速走，相遇即入口」。被追问证明时画一个三段的环图比背公式更有效。

**易错点：**

- 快指针也从头走 1 步（`fast = fast.next`），永远不会相遇。
- 入口判定写成 `slow === head`，忽略了头节点本身就在环上的情况。
- 在找入口的循环里让两个指针走不同速度，结论失效。
- 认为 `Set` 解法也是 O(1) 空间。

## 3. 合并两个或多个有序链表

**题目：** ① 合并两个升序链表为一个升序链表（要求原地拼接，不新建节点）。② 合并 k 个升序链表。

**示例：**

```js
mergeTwo(buildList([1, 2, 4]), buildList([1, 3, 4])); // [1,1,2,3,4,4]
mergeKLists([buildList([1, 4, 5]), buildList([1, 3, 4]), buildList([2, 6])]);
// [1,1,2,3,4,4,5,6]
```

**思路：**

- 两两合并暴力：每次取较小头节点接到结果尾部，O(m + n)/O(1)。
  - 为什么用哑节点：新链表的头可能是任意一个入参，哑节点省去特判。
  - 为什么最后直接接剩余段：剩余部分本身有序，逐个搬运是多余工作。
- k 个链表暴力：反复两两合并，总代价 O(kN)（N 为节点总数），k 大时退化。
- 最优：分治合并。把 k 个链表两两配对，合并后再递归/迭代。
  - 为什么是 O(N log k)：每层把所有节点处理一次，共 log k 层。
  - 为什么比「依次合并」好：依次合并会让早期链表被重复扫描 k 次，分治让每个节点只参与 log k 次。
- 另一种解法是小顶堆存 k 个头节点，每次取最小并补入其后继，同样 O(N log k)/O(k)，流式场景更合适。

**代码：**

```js
function mergeTwo(l1, l2) {
    const dummy = new ListNode();
    let tail = dummy;
    while (l1 && l2) {
        if (l1.val <= l2.val) {
            tail.next = l1;
            l1 = l1.next;
        } else {
            tail.next = l2;
            l2 = l2.next;
        }
        tail = tail.next;
    }
    tail.next = l1 || l2;      // 剩余段整体接上
    return dummy.next;
}

function mergeKLists(lists) {
    if (lists.length === 0) return null;
    if (lists.length === 1) return lists[0];
    const mid = Math.floor(lists.length / 2);
    return mergeTwo(mergeKLists(lists.slice(0, mid)), mergeKLists(lists.slice(mid)));
}

// 验证
console.log(toArray(mergeTwo(buildList([1, 2, 4]), buildList([1, 3, 4]))));
// [1, 1, 2, 3, 4, 4]
console.log(toArray(mergeKLists([
    buildList([1, 4, 5]),
    buildList([1, 3, 4]),
    buildList([2, 6]),
]))); // [1, 1, 2, 3, 4, 4, 5, 6]
```

**复杂度：**

| 题 | 时间 | 空间 |
| --- | --- | --- |
| 合并两个 | O(m + n) | O(1)（只改指针） |
| 分治合并 k 个 | O(N log k) | O(log k) 递归栈 |
| 小顶堆合并 k 个 | O(N log k) | O(k) |

**边界与坑：**

- 任一为空直接返回另一个，`tail.next = l1 || l2` 已覆盖。
- 相等时取 `l1`（`<=`）才能保持稳定；取 `l2` 也行，但要说明稳定性差异。
- `lists` 中可能含 `null`，分治仍能正确处理，无需过滤（但 `length === 1 && lists[0] === null` 返回 `null` 正确）。
- 递归分治在 k 很大时栈深度 O(log k)，安全；`mergeTwo` 不要写成递归，否则长链表会栈溢出（尾递归在 JS 也不保证优化）。
- 拼接后原链表结构被改变，若调用方还要用原链表需先复制。

**面试怎么答：** 两两合并讲「哑节点 + 比较头部 + 接剩余段」。k 个链表先承认依次合并是 O(kN)，再给分治的 O(N log k) 并解释「每个节点只参与 log k 层」。最后补一句「流式或 k 很大用堆」，展示方案取舍。

**易错点：**

- `tail.next = l1 || l2` 之后又继续循环，导致尾部重复接链。
- 用 `while (l1 || l2)` 但循环体里没有正确推进指针，死循环。
- 分治时 `mid = k / 2` 未取整（JS 下标为小数），`slice` 行为异常。
- 认为分治合并的空间是 O(1)——递归栈是 O(log k)。

## 4. 删除倒数第 N 个节点

**题目：** 给定链表，删除倒数第 `n` 个节点并返回头节点，要求一趟扫描。

**示例：**

```js
removeNthFromEnd(buildList([1, 2, 3, 4, 5]), 2); // [1, 2, 3, 5]
removeNthFromEnd(buildList([1]), 1);             // []
```

**思路：**

- 暴力：先遍历求长度 `L`，再从头走 `L - n` 步删除，两趟 O(n)。
- 最优：快慢指针保持 `n + 1` 的间距。`fast` 先走 `n + 1` 步，然后两指针同步前进，`fast` 到 `null` 时 `slow` 正好停在待删节点的前驱。
  - 为什么是 `n + 1` 而不是 `n`：需要停在前驱才能执行 `slow.next = slow.next.next`；多走一步正好让间距覆盖哑节点。
  - 为什么要哑节点：删除头节点（`n` 等于长度）时前驱是哑节点，统一处理。
  - 为什么是一趟：只扫描一次，长度信息通过指针间距隐式获得。

**代码：**

```js
function removeNthFromEnd(head, n) {
    const dummy = new ListNode(0, head);
    let fast = dummy;
    let slow = dummy;
    for (let i = 0; i <= n; i++) {   // fast 先走 n + 1 步
        fast = fast.next;
    }
    while (fast) {                   // 同步前进，保持间距
        fast = fast.next;
        slow = slow.next;
    }
    slow.next = slow.next.next;      // slow 停在待删节点的前驱
    return dummy.next;
}

// 验证
console.log(toArray(removeNthFromEnd(buildList([1, 2, 3, 4, 5]), 2))); // [1, 2, 3, 5]
console.log(toArray(removeNthFromEnd(buildList([1]), 1)));             // []
console.log(toArray(removeNthFromEnd(buildList([1, 2]), 1)));          // [1]
```

**复杂度：** 时间 O(n)（一趟），空间 O(1)（哑节点与两个指针）。

**边界与坑：**

- `n` 等于链表长度：删除头节点，`dummy.next` 指向第二个节点，返回 `dummy.next` 正确。
- 链表只有一个节点且 `n = 1`：返回 `null`，即空链表。
- `n` 大于长度属于非法输入：`fast` 会在预跑阶段变成 `null` 并抛错，需要按题面约束处理或加校验。
- 返回 `head` 而不是 `dummy.next`，删头时返回已删除节点。
- 预跑循环写 `i < n`（少走一步），`slow` 会停在待删节点本身，删错。

**面试怎么答：** 一句话讲清「快指针先走 n + 1 步，两指针间距固定，快指针到头时慢指针在前驱」。强调哑节点解决「删头」这个唯一需要特判的场景，最后说明一趟扫描与 O(1) 空间。

**易错点：**

- 忘记哑节点，删除头节点时需要单独写分支。
- 预跑步数算成 `n`，最后 `slow` 指向待删节点，`slow.next = slow.next.next` 删的是下一个。
- `while (fast.next)` 而不是 `while (fast)`，会少走一步。
- 删除后没有释放引用（JS 有 GC，面试提一句即可）。

## 5. 链表相交与回文链表

**题目：** ① 给定两个单链表，返回它们相交的第一个节点，不相交返回 `null`。② 判断链表是否回文，要求 O(n) 时间、O(1) 空间。

**示例：**

```js
// 两条链在值为 8 的节点处相交
getIntersectionNode(a, b);   // 返回值为 8 的节点
isPalindrome(buildList([1, 2, 2, 1])); // true
isPalindrome(buildList([1, 2]));       // false
```

**思路：**

- 相交暴力：对 A 的每个节点遍历 B，O(mn)。用 `Set` 存 A 的节点再查 B 是 O(m + n)/O(m)。
- 相交最优（路径拼接）：指针 `p` 走完 A 后跳到 B 的头，`q` 走完 B 后跳到 A 的头。两者总步数都是 `m + n`，若相交必然在交点相遇；不相交则同时变成 `null`。
  - 为什么成立：设 A 独有部分长 `a`、B 独有部分长 `b`、公共部分长 `c`，两个指针都走 `a + c + b` 步。
  - 为什么不需要求长度：长度差被「换轨道」自动抵消。
- 回文暴力：把值复制到数组后双指针判断，O(n)/O(n)。
- 回文最优：快慢指针找中点 → 反转后半段 → 双指针比较 → 恢复链表。
  - 为什么反转后半段而不是前半段：从中间向两端比较更自然，且奇偶长度可用同一个循环（`while (p2)`）。
  - 为什么找中点的条件是 `fast.next && fast.next.next`：让 `slow` 停在「前半段的最后一个节点」，偶数长度时后段正好是后半，奇数长度时中间节点归前半段、不参与比较。

**代码：**

```js
function getIntersectionNode(headA, headB) {
    let p = headA;
    let q = headB;
    while (p !== q) {
        p = p === null ? headB : p.next;   // 走完 A 换到 B
        q = q === null ? headA : q.next;   // 走完 B 换到 A
    }
    return p;                              // 交点或 null
}

function append(head, tail) {
    if (head === null) return tail;
    let p = head;
    while (p.next) p = p.next;
    p.next = tail;
    return head;
}

function isPalindrome(head) {
    if (head === null || head.next === null) return true;
    let slow = head;
    let fast = head;
    while (fast.next && fast.next.next) {
        slow = slow.next;
        fast = fast.next.next;
    }
    let second = reverseList(slow.next);   // 复用第 1 题的反转
    let p1 = head;
    let p2 = second;
    let ok = true;
    while (p2) {
        if (p1.val !== p2.val) {
            ok = false;
            break;
        }
        p1 = p1.next;
        p2 = p2.next;
    }
    slow.next = reverseList(second);       // 恢复原链表，保持入参不变
    return ok;
}

// 验证
const common = buildList([8, 4, 5]);
const a = append(buildList([4, 1]), common);
const b = append(buildList([5, 6, 1]), common);
console.log(getIntersectionNode(a, b).val);              // 8
console.log(getIntersectionNode(buildList([1]), buildList([2]))); // null
console.log(isPalindrome(buildList([1, 2, 2, 1])));      // true
console.log(isPalindrome(buildList([1, 2])));            // false
```

**复杂度：** 相交 O(m + n)/O(1)；回文 O(n)/O(1)（反转与比较都是线性，只用了常数指针）。

**边界与坑：**

- 任一链表为空：相交返回 `null`；单节点回文返回 `true`。
- 两条链完全不相交：两个指针最终同时为 `null`，`while` 结束返回 `null`，不会死循环。
- 相交节点是 A 或 B 的头节点：路径拼接依然正确。
- 回文比较循环用 `while (p2)` 而不是 `while (p1 && p2)`：后段更短或等长，以它为终止条件即可。
- 面试若要求「不允许修改链表」，恢复那一步必须写；否则会被认为破坏了入参。

**面试怎么答：** 相交题先说「长度差对齐」的常规解法，再给路径拼接的 O(1) 空间写法并解释「总步数相同」。回文题按「找中点 → 反转 → 比较 → 恢复」四步讲，主动提「恢复是为了不破坏入参」，这是加分点。

**易错点：**

- 路径拼接写成 `p = p.next || headB`，节点值可能为 `null` 无法区分，且空链表判断出错。
- 回文中点条件写成 `fast && fast.next`，`slow` 会偏后一个节点，偶数长度比较错位。
- 反转后忘记恢复，第二次调用 `isPalindrome` 结果错误。
- 比较时只比较到 `p1` 结束，奇数长度会把中间节点和自己比较（结果仍正确，但逻辑不严谨）。

## 6. LRU 与 LFU（算法视角）

**题目：** 设计缓存结构，支持 `get(key)` 与 `put(key, value)`，都要求 O(1)。① LRU：容量满时淘汰最久未使用的键。② LFU：容量满时淘汰使用频率最低的键，频率相同淘汰最久未使用的。

**示例：**

```js
const lru = new LRUCache(2);
lru.put(1, 1); lru.put(2, 2); lru.get(1); lru.put(3, 3); // 淘汰 2
```

**思路：**

- LRU 朴素：数组 + 时间戳，淘汰时扫描最小值，O(n)；最优是哈希 + 双向链表，头最近使用、尾最久未使用。JS 可直接用 `Map`：迭代顺序等于插入顺序，`delete` 后重新 `set` 会把键移到末尾，`keys().next().value` 即淘汰对象；`get` 也算使用，必须刷新。
- LFU 朴素：每个键存 `freq`，淘汰时扫描最小频率，O(n)。
- LFU 最优：`key -> {value, freq}` + `freq -> 有序键集合` + `minFreq`；同频率内用保持插入顺序的 Map，队首即同频最久未使用；频率提升时旧桶删除，若旧桶空了且它就是 `minFreq` 则加 1，再把键插到新桶尾部。

**代码：**

```js
class LRUCache {
    constructor(capacity) {
        this.cap = capacity;
        this.map = new Map();          // key -> value，迭代顺序即使用顺序
    }
    get(key) {
        if (!this.map.has(key)) return -1;
        const value = this.map.get(key);
        this.map.delete(key);          // 删除后重新插入 = 移到最近使用
        this.map.set(key, value);
        return value;
    }
    put(key, value) {
        if (this.cap <= 0) return;
        if (this.map.has(key)) {
            this.map.delete(key);
        } else if (this.map.size >= this.cap) {
            this.map.delete(this.map.keys().next().value);   // 淘汰最久未使用
        }
        this.map.set(key, value);
    }
}
class LFUCache {
    constructor(capacity) {
        this.cap = capacity;
        this.minFreq = 0;
        this.data = new Map();         // key -> { value, freq }
        this.buckets = new Map();      // freq -> Map<key, true>，按访问顺序排列
    }
    touch(key) {
        const node = this.data.get(key);
        const oldFreq = node.freq;
        const bucket = this.buckets.get(oldFreq);
        bucket.delete(key);
        if (bucket.size === 0) this.buckets.delete(oldFreq);
        if (bucket.size === 0 && this.minFreq === oldFreq) this.minFreq = oldFreq + 1;
        node.freq = oldFreq + 1;
        if (!this.buckets.has(node.freq)) this.buckets.set(node.freq, new Map());
        this.buckets.get(node.freq).set(key, true);
    }
    get(key) {
        if (!this.data.has(key)) return -1;
        this.touch(key);
        return this.data.get(key).value;
    }
    put(key, value) {
        if (this.cap <= 0) return;
        if (this.data.has(key)) {
            this.data.get(key).value = value;
            this.touch(key);
            return;
        }
        if (this.data.size >= this.cap) {
            const bucket = this.buckets.get(this.minFreq);
            const victim = bucket.keys().next().value;   // 同频最久未使用
            bucket.delete(victim);
            if (bucket.size === 0) this.buckets.delete(this.minFreq);
            this.data.delete(victim);
        }
        this.data.set(key, { value, freq: 1 });
        if (!this.buckets.has(1)) this.buckets.set(1, new Map());
        this.buckets.get(1).set(key, true);
        this.minFreq = 1;
    }
}
const lru = new LRUCache(2);
lru.put(1, 1); lru.put(2, 2); lru.get(1); lru.put(3, 3);      // 淘汰 2
console.log(lru.get(1), lru.get(2), lru.get(3));              // 1 -1 3
const lfu = new LFUCache(2);
lfu.put(1, 1); lfu.put(2, 2); lfu.get(1); lfu.put(3, 3);      // 淘汰 2
console.log(lfu.get(1), lfu.get(2), lfu.get(3));              // 1 -1 3
```

**复杂度：** 两种缓存的 `get` / `put` 均摊 O(1)，空间 O(capacity)。

**边界与坑：**

- `put` 已存在的键要更新值并刷新使用顺序（LRU）或频率（LFU），不能只覆盖值。
- LFU 的 `minFreq` 在旧桶还有元素时不能加 1，否则会指向空桶导致后续淘汰崩溃。

**面试怎么答：** LRU 先讲「哈希 + 双向链表」的标准答案，再说 JS 里可以用 `Map` 的插入顺序省掉链表（并说明这只是语言特性，Java 需要 `LinkedHashMap` 或手写链表）。LFU 讲「频率桶 + minFreq + 桶内 LRU」，重点解释频率提升时 minFreq 的更新条件。

**易错点：**

- LRU 的 `get` 没有刷新顺序，导致「读过的键反而先被淘汰」。
- 用 `Map` 时先 `set` 再 `delete`，顺序没有变化，刷新失效。
- LFU 更新已有键时没有调用 `touch`，频率不增加。

## 7. 复制带随机指针的链表

**题目：** 每个节点含 `next` 与 `random`（可指向任意节点或 `null`），深拷贝整条链表，返回新头节点。

**示例：**

```js
const head = buildRandomList([[7, null], [13, 0], [11, 4], [10, 2], [1, 0]]);
const copy = copyRandomList(head);
copy.val;            // 7
copy.next.random.val; // 7（与原链一致，但指向新节点）
```

**思路：**

- 暴力：先复制 `next` 链，再对每个节点的 `random` 从头遍历找到对应位置，O(n²)。
- 哈希表两趟（推荐）：第一趟建「原节点 → 新节点」映射并复制值；第二趟用映射设置 `next` 与 `random`。
  - 为什么必须两趟：设置 `random` 时目标节点可能还没创建，先建全量映射就能 O(1) 查。
  - 为什么复杂度是 O(n)：每个节点常数次哈希操作，空间 O(n)。
- O(1) 空间（进阶）：把新节点插到原节点之后（`A → A' → B → B'`），利用 `A'.random = A.random.next` 设置随机指针，最后拆分成两条链。
  - 为什么可行：新节点紧跟在原节点后，`random` 的「副本」就是原 `random` 的 `next`。
  - 代价：会临时修改原链表，结束后必须完整还原。

**代码：**

```js
class RandomNode {
    constructor(val, next = null, random = null) {
        this.val = val;
        this.next = next;
        this.random = random;
    }
}

function buildRandomList(items) {
    const nodes = items.map(([v]) => new RandomNode(v));
    items.forEach(([, r], i) => {
        if (i + 1 < nodes.length) nodes[i].next = nodes[i + 1];
        if (r !== null) nodes[i].random = nodes[r];
    });
    return nodes.length > 0 ? nodes[0] : null;
}

function copyRandomList(head) {
    if (head === null) return null;
    const map = new Map();          // 原节点 -> 新节点
    let cur = head;
    while (cur) {
        map.set(cur, new RandomNode(cur.val));
        cur = cur.next;
    }
    cur = head;
    while (cur) {
        const copy = map.get(cur);
        copy.next = cur.next ? map.get(cur.next) : null;
        copy.random = cur.random ? map.get(cur.random) : null;
        cur = cur.next;
    }
    return map.get(head);
}

// 验证
const origin = buildRandomList([[7, null], [13, 0], [11, 4], [10, 2], [1, 0]]);
const copy = copyRandomList(origin);
console.log(copy.val, copy.next.val);              // 7 13
console.log(copy.next.random.val);                 // 7
console.log(copy.next.random === copy);            // true，指向副本而非原节点
console.log(copyRandomList(null));                 // null
```

**复杂度：** 哈希表法时间 O(n)、空间 O(n)；插入拆分法时间 O(n)、空间 O(1)（不计返回值）。

**边界与坑：**

- 空链表返回 `null`；单节点且 `random` 指向自己时要正确映射。
- `random` 为 `null` 时必须显式赋 `null`，不能用 `map.get(null)`（得到 `undefined`）。
- 不能用「节点值」作为 Map 的键：值可能重复，必须用节点对象引用。
- O(1) 空间法拆分时，原节点的 `next` 要跳过副本指回原链的下一个，副本的 `next` 指向下一个副本。
- 深拷贝要求新链中所有 `random` 指向新节点，测试时可断言 `copy.next.random === copy`。

**面试怎么答：** 先给哈希表两趟解法，讲清「第一趟只建映射，第二趟才连边」的原因。然后主动提 O(1) 空间的「插入 - 赋值 - 拆分」三步法，说明它会临时改原链、必须还原，体现对边界和工程约束的考虑。

**易错点：**

- 只复制 `next` 链，`random` 直接赋原节点引用（变成浅拷贝）。
- 第二趟里 `copy.random = cur.random`，忘记映射到副本。
- 用 `map.get(cur.next)` 时没判空，`null` 被当成键查到 `undefined`。
- O(1) 空间法忘了还原原链，调用方后续遍历会串链。

## 8. 单调栈：每日温度与柱状图最大矩形

**题目：** ① 每日温度：对每天求「再过几天会出现更高温度」，没有则为 0。② 柱状图最大矩形：求直方图中能勾勒出的最大矩形面积。

**示例：**

```js
dailyTemperatures([73, 74, 75, 71, 69, 72, 76, 73]); // [1, 1, 4, 2, 1, 1, 0, 0]
largestRectangleArea([2, 1, 5, 6, 2, 3]);            // 10
```

**思路：**

- 每日温度暴力：每天向右扫，O(n²)；最坏是递减序列。
- 最优（单调递减栈）：栈存「还没有找到更高温度的下标」，温度从栈底到栈顶递减。
  - 为什么正确：当前温度比栈顶高时，栈顶那天的答案就是 `i - 栈顶下标`；弹出后继续比较，一次遍历解决所有「等待中」的天。
  - 为什么是 O(n)：每个下标入栈一次、出栈一次，均摊 O(1)。
  - 为什么栈里存下标：既要算天数差，也要取温度值。
- 最大矩形暴力：枚举每个柱子向左右扩展到第一个更矮的柱子，O(n²)。
- 最优（单调递增栈）：维护高度递增的下标栈。遇到更矮的柱子时弹栈，弹栈那一刻就确定了该柱子能扩展的左右边界。
  - 为什么宽度是 `i - 栈顶 - 1`：左边界是弹出后新的栈顶（第一个更矮的柱子），右边界是当前 `i`。
  - 为什么加两端哨兵 `0`：左哨兵保证栈不会空，右哨兵保证遍历结束时栈内元素全部弹出，省去收尾循环。

**代码：**

```js
function dailyTemperatures(temperatures) {
    const res = new Array(temperatures.length).fill(0);
    const stack = [];        // 下标，对应温度单调递减
    for (let i = 0; i < temperatures.length; i++) {
        while (stack.length > 0 && temperatures[stack[stack.length - 1]] < temperatures[i]) {
            const j = stack.pop();
            res[j] = i - j;
        }
        stack.push(i);
    }
    return res;
}

function largestRectangleArea(heights) {
    const h = [0, ...heights, 0];   // 两端哨兵
    const stack = [];
    let best = 0;
    for (let i = 0; i < h.length; i++) {
        while (stack.length > 0 && h[stack[stack.length - 1]] > h[i]) {
            const height = h[stack.pop()];
            const width = i - stack[stack.length - 1] - 1;
            best = Math.max(best, height * width);
        }
        stack.push(i);
    }
    return best;
}

// 验证
console.log(dailyTemperatures([73, 74, 75, 71, 69, 72, 76, 73]));
// [1, 1, 4, 2, 1, 1, 0, 0]
console.log(largestRectangleArea([2, 1, 5, 6, 2, 3]));   // 10
console.log(largestRectangleArea([2, 4]));               // 4
console.log(largestRectangleArea([]));                   // 0
```

**复杂度：** 两题时间均为 O(n)（每个下标至多入栈出栈一次），空间 O(n)（栈最多 n 个元素）。

**边界与坑：**

- 温度数组为空：返回 `[]`；单天返回 `[0]`。
- 温度相等时**不**弹栈（条件是 `<`），因为「更高」不包括相等；矩形题条件用 `>`，等高的柱子保留在栈里，宽度计算仍正确。
- 矩形题 `heights` 为空时 `[0, ...[], 0]` 得到 `[0, 0]`，循环计算出 0。
- 哨兵不能用 `-1`：高度必须比所有柱子小且非负，`0` 最合适（题面高度非负）。
- 宽度计算依赖 `stack[stack.length - 1]` 在弹出之后取，顺序写反会得到错误边界。

**面试怎么答：** 两题共用一个模板：「栈里存下标，维持单调性，弹出时结算答案」。每日温度强调「弹出即找到右边第一个更大值」；矩形题强调「弹出时左右边界都确定了，所以能算出以该柱子为高的最大矩形」。最后补一句「单调栈常用于『下一个更大/更小元素』和『以某元素为最值的区间』两类题」。

**易错点：**

- 每日温度写成 `<=`，遇到相同温度就弹栈，答案偏小。
- 矩形题忘记加哨兵，收尾时栈里还有元素没结算。
- 宽度写成 `i - stack[stack.length - 1]`，少了 `- 1`。
- 弹出后取 `stack[-1]` 未判空（无哨兵时左边界会丢失）。

## 9. 有效括号与表达式求值

**题目：** ① 判断只含 `()[]{}` 的字符串是否合法（左括号必须以正确顺序闭合）。② 实现加减乘除与括号的四则运算求值（除法向零取整）。

**示例：**

```js
isValid('()[]{}');                    // true
isValid('([)]');                      // false
calculate('1 + (2 - 3) * 4');         // -3
calculate('(1+(4+5+2)-3)+(6+8)');     // 23
```

**思路：**

- 括号匹配暴力：反复删除相邻的 `()` / `[]` / `{}`，O(n²)；最优是左括号入栈，右括号比对栈顶，结束后栈必须为空。
  - 为什么用栈：括号匹配是「最近未闭合优先」，正好后进先出；最后判空是为了发现 `'('` 这种多余左括号。
- 表达式求值朴素：转后缀表达式（调度场算法）再求值，需要两个栈和优先级表。
- 递归下降（推荐）：`expr → term (('+'|'-') term)*`、`term → factor (('*'|'/') factor)*`、`factor → 数字 | '(' expr ')' | '-' factor`。
  - 为什么能处理优先级与括号：乘除在 `term` 层先算完，加减在 `expr` 层后算；`factor` 遇到 `(` 递归调用 `expr`，返回时括号内部已算完；一元负号也在 `factor` 里递归处理。

**代码：**

```js
function isValid(s) {
    const pairs = { ')': '(', ']': '[', '}': '{' };
    const stack = [];
    for (const ch of s) {
        if (ch === '(' || ch === '[' || ch === '{') {
            stack.push(ch);
        } else if (stack.pop() !== pairs[ch]) {
            return false;              // 栈空或类型不匹配
        }
    }
    return stack.length === 0;
}

function calculate(s) {
    const str = s.replace(/\s+/g, '');
    let i = 0;

    const expr = () => {
        let val = term();
        while (i < str.length && (str[i] === '+' || str[i] === '-')) {
            const op = str[i++];
            const rhs = term();
            val = op === '+' ? val + rhs : val - rhs;
        }
        return val;
    };

    const term = () => {
        let val = factor();
        while (i < str.length && (str[i] === '*' || str[i] === '/')) {
            const op = str[i++];
            const rhs = factor();
            if (op === '*') val *= rhs;
            else val = Math.trunc(val / rhs);   // 向零取整
        }
        return val;
    };

    const factor = () => {
        if (str[i] === '-') { i++; return -factor(); }
        if (str[i] === '(') {
            i++;
            const v = expr();
            i++;                       // 跳过 ')'
            return v;
        }
        let num = 0;
        while (i < str.length && str[i] >= '0' && str[i] <= '9') num = num * 10 + Number(str[i++]);
        return num;
    };

    return expr();
}

// 验证
console.log(isValid('()[]{}'));                    // true
console.log(isValid('([)]'));                      // false
console.log(isValid('('));                         // false
console.log(calculate('1 + (2 - 3) * 4'));         // -3
console.log(calculate('(1+(4+5+2)-3)+(6+8)'));     // 23
console.log(calculate('-2*3+10/2'));               // -1
```

**复杂度：** 括号匹配 O(n)/O(n)；表达式求值 O(n)/O(深度)（递归栈深度等于括号嵌套层数）。

**边界与坑：**

- 空字符串：`isValid('')` 返回 `true`（空串视为合法），需与面试官确认约定。
- 右括号多余（`')('`）：第一次 `pop()` 得到 `undefined`，与期望值不等，返回 `false`。
- 表达式中的空格先整体去掉，否则数字解析会被空格打断。
- 除法必须 `Math.trunc`；`/` 得到小数，`Math.floor` 对负数是向下取整，与「向零取整」不符。

**面试怎么答：** 括号题一句话「左括号入栈，右括号比对栈顶，最后判空」。表达式题先说明「转后缀 + 栈」和「递归下降」两种路线，推荐后者并画文法：`expr / term / factor` 三层结构，强调「优先级由调用层次决定，括号由递归决定」。

**易错点：**

- `isValid` 只统计左右括号数量，`'([)]'` 会误判为合法。
- 忘记最后判空，`'('` 返回 `true`。
- 递归下降里 `factor` 解析完括号后忘记 `i++`，后面的字符被重复解析。

## 10. 用栈实现队列与用队列实现栈

**题目：** ① 仅用两个栈实现队列的 `push / pop / peek / empty`。② 仅用一个队列实现栈的 `push / pop / top / empty`。

**示例：**

```js
const q = new MyQueue();
q.push(1); q.push(2);
q.peek();   // 1
q.pop();    // 1
q.empty();  // false
```

**思路：**

- 队列用两个栈：`inStack` 入队、`outStack` 出队；只在 `outStack` 为空时一次性倒入，否则会打乱已倒序好的顺序。
  - 摊还 O(1)：每个元素最多被倒入一次、弹出一次；`peek` 也必须先 `transfer`，因为队头可能还压在 `inStack` 底部。
- 栈用一个队列：`push` 时把新元素放到队尾，再把前面 `n - 1` 个依次出队重入，新元素转到队头，`pop` 取队头即后进先出。
  - 代价：`push` O(n)、`pop` / `top` O(1)；也可反过来把开销放到出栈侧，用两个队列实现。

**代码：**

```js
class MyQueue {
    constructor() {
        this.inStack = [];
        this.outStack = [];
    }
    push(x) {
        this.inStack.push(x);
    }
    transfer() {
        if (this.outStack.length === 0) {
            while (this.inStack.length > 0) {
                this.outStack.push(this.inStack.pop());   // 逆序后队头在栈顶
            }
        }
    }
    pop() {
        this.transfer();
        return this.outStack.pop();
    }
    peek() {
        this.transfer();
        return this.outStack[this.outStack.length - 1];
    }
    empty() {
        return this.inStack.length === 0 && this.outStack.length === 0;
    }
}

class MyStack {
    constructor() {
        this.q = [];
    }
    push(x) {
        this.q.push(x);
        for (let i = 0; i < this.q.length - 1; i++) {
            this.q.push(this.q.shift());   // 把新元素转到队头
        }
    }
    pop() {
        return this.q.shift();
    }
    top() {
        return this.q[0];
    }
    empty() {
        return this.q.length === 0;
    }
}

// 验证
const q = new MyQueue();
q.push(1); q.push(2); q.push(3);
console.log(q.peek(), q.pop(), q.pop(), q.empty());   // 1 1 2 false
const st = new MyStack();
st.push(1); st.push(2); st.push(3);
console.log(st.top(), st.pop(), st.top());             // 3 3 2
```

**复杂度：** 队列摊还 O(1)/O(n)（两个栈的容量）；栈 `push` O(n)、`pop`/`top` O(1)，空间 O(n)。

**边界与坑：**

- `MyQueue.peek` 不能用 `pop` 再 `push` 回去（会把元素顺序弄乱），而是取 `outStack` 末尾。
- `empty` 必须同时检查两个栈；只查 `inStack` 会在元素已倒入 `outStack` 时误判为空。
- `MyStack.push` 的循环次数是 `q.length - 1`，写成长度会多旋转一次，把新元素又转回队尾。
- JS 的 `Array.prototype.shift` 是 O(n)，严格说 `MyStack` 的 `pop` 不是 O(1)；可改用 `Map` + 头尾指针实现真正 O(1) 队列。

**面试怎么答：** 队列题画「两个栈背靠背」的图，讲「倒入一次、摊还 O(1)」。栈题讲「push 时旋转队列，让新元素到队头」，并主动提「也可以把开销放到 pop 侧」的对称方案，展示对摊还分析的理解。

**易错点：**

- 每次 `push` 都把 `inStack` 全倒入 `outStack`，顺序被打乱。
- `peek` 实现成 `pop` 后忘记写回，队头元素丢失。
- `empty` 只判断一个栈。

## 11. 滑动窗口与双端队列

**题目：** ① 用双端队列维护滑动窗口的最大值与最小值。② 给定数组与 `limit`，求最长的连续子数组，使子数组内最大值与最小值之差不超过 `limit`。

**示例：**

```js
longestSubarray([8, 2, 4, 7], 4);          // 2（[2,4]）
longestSubarray([10, 1, 2, 4, 7, 2], 5);   // 4（[2,4,7,2]，差为 5）
longestSubarray([4, 2, 2, 2, 4, 4, 2, 2], 0); // 3
```

**思路：**

- 暴力：枚举所有子数组，每次扫一遍求最大最小，O(n³)；预处理稀疏表可降到 O(n²)。
- 双端队列维护最值：队首始终是当前窗口的最值，队尾维护单调性。新元素入队前弹掉「比它小（求最大值时）」的队尾元素，因为它们又老又小，不可能再成为最值。
  - 为什么每个元素只进出一次：摊还 O(1)，整个窗口滑动是 O(n)。
  - 为什么队列存下标：需要判断队首是否已滑出窗口左边界。
- 最长子数组（双单调队列）：同时维护最大值队列与最小值队列，右指针扩张；当 `max - min > limit` 时，左指针右移直到重新满足条件。
  - 为什么可以用滑动窗口：差值约束对「扩大窗口」单调不满足（窗口越大差越大），一旦违规，左指针必须前进，满足「左边界单调」的前提。
  - 为什么是两个队列：需要同时 O(1) 拿到窗口最大值与最小值。
  - 注意：左指针移动时要同步弹出队首已过期的下标，两个队列都要处理。

**代码：**

```js
function longestSubarray(nums, limit) {
    const maxDq = [];   // 下标，对应值单调递减
    const minDq = [];   // 下标，对应值单调递增
    let left = 0;
    let best = 0;
    for (let right = 0; right < nums.length; right++) {
        while (maxDq.length > 0 && nums[maxDq[maxDq.length - 1]] <= nums[right]) {
            maxDq.pop();
        }
        maxDq.push(right);
        while (minDq.length > 0 && nums[minDq[minDq.length - 1]] >= nums[right]) {
            minDq.pop();
        }
        minDq.push(right);
        while (nums[maxDq[0]] - nums[minDq[0]] > limit) {
            if (maxDq[0] === left) maxDq.shift();   // 队首过期
            if (minDq[0] === left) minDq.shift();
            left++;
        }
        best = Math.max(best, right - left + 1);
    }
    return best;
}

function maxInWindows(nums, k) {
    const res = [];
    const dq = [];      // 下标，值递减
    for (let i = 0; i < nums.length; i++) {
        while (dq.length > 0 && nums[dq[dq.length - 1]] <= nums[i]) dq.pop();
        dq.push(i);
        if (dq[0] <= i - k) dq.shift();
        if (i >= k - 1) res.push(nums[dq[0]]);
    }
    return res;
}

// 验证
console.log(longestSubarray([8, 2, 4, 7], 4));                 // 2
console.log(longestSubarray([10, 1, 2, 4, 7, 2], 5));          // 4
console.log(longestSubarray([4, 2, 2, 2, 4, 4, 2, 2], 0));     // 3
console.log(maxInWindows([1, 3, -1, -3, 5, 3, 6, 7], 3));      // [3,3,5,5,6,7]
```

**复杂度：** 两题均为 O(n) 时间（每个下标至多进出队各一次），O(k) / O(n) 空间。

**边界与坑：**

- `k` 大于数组长度：`maxInWindows` 返回空数组；`k = 1` 时返回原数组。
- `limit` 为 0：窗口内所有元素必须相等，示例 `[4,2,2,2,4,4,2,2]` 得到 3。
- 左指针移动时只弹最大值队列、忘了最小值队列，后续差值判断会用到过期下标。
- 队首过期判断用 `dq[0] < left`（严格小于）还是 `<= i - k`：窗口是 `[i - k + 1, i]`，`dq[0] <= i - k` 才是过期。
- JS 数组 `shift()` 是 O(n)，理论上会退化；面试可说明「用链表或头指针实现双端队列才是严格 O(1)」，但不影响本题思路正确性。

**面试怎么答：** 先讲「双端队列存下标，维护单调性，队首即最值」这个模板，再讲最长子数组如何把「最大值 - 最小值」变成两个队列的队首之差。最后主动指出 JS `shift` 的实现代价，说明在 C++/Java 里用 `deque` 才是严格 O(1)，这能体现工程意识。

**易错点：**

- 单调队列用 `<` 而不是 `<=`，遇到相等值时旧下标残留，窗口收缩时误判。
- 先判断窗口长度再弹队首，导致过期下标参与了最值计算。
- 最长子数组题把「差值超限」写成 `>= limit`，边界用例（差恰好等于 limit）被误判。
- 用普通数组 + `Math.max(...window)` 代替队列，复杂度退化到 O(nk)。

## 12. 设计题：最小栈与随机集合

**题目：** ① 最小栈：支持 `push / pop / top / getMin`，全部 O(1)。② 随机集合：支持 `insert / remove / getRandom`，平均 O(1)，且集合内元素不重复。

**示例：**

```js
const s = new MinStack();
s.push(-2); s.push(0); s.push(-3); s.getMin();   // -3
s.pop(); s.top(); s.getMin();                    // -3 0 -2
const set = new RandomizedSet();
set.insert(1); set.remove(2); set.insert(2);     // true false true
set.getRandom();                                 // 1 或 2
```

**思路：**

- 最小栈朴素：每次 `getMin` 遍历栈，O(n)。
- 最小栈最优：辅助栈 `mins` 与主栈同步增长，栈顶是当前最小值；弹出时直接 `pop` 就回到上一个最小值，三个操作都是尾部操作，O(1)，代价是额外 O(n)。
- 随机集合朴素：数组存元素 `remove` 要 O(n)；`Set` 增删 O(1) 但 `getRandom` 需转数组。
- 随机集合最优：数组 + 哈希表（值 → 下标）。
  - 删除时把待删元素与末尾交换再 `pop` 才是 O(1)；交换后先更新末尾元素下标，最后删目标键。

**代码：**

```js
class MinStack {
    constructor() {
        this.stack = [];
        this.mins = [];      // mins[i] = stack[0..i] 的最小值
    }
    push(x) {
        this.stack.push(x);
        const curMin = this.mins.length > 0 ? this.mins[this.mins.length - 1] : Infinity;
        this.mins.push(Math.min(x, curMin));
    }
    pop() {
        this.mins.pop();
        return this.stack.pop();
    }
    top() {
        return this.stack[this.stack.length - 1];
    }
    getMin() {
        return this.mins[this.mins.length - 1];
    }
}

class RandomizedSet {
    constructor() {
        this.arr = [];
        this.index = new Map();   // 值 -> 数组下标
    }
    insert(val) {
        if (this.index.has(val)) return false;
        this.index.set(val, this.arr.length);
        this.arr.push(val);
        return true;
    }
    remove(val) {
        if (!this.index.has(val)) return false;
        const i = this.index.get(val);
        const last = this.arr[this.arr.length - 1];
        this.arr[i] = last;              // 末尾元素填到待删位置
        this.index.set(last, i);
        this.arr.pop();
        this.index.delete(val);          // 最后再删，避免 val 就是 last 时误删
        return true;
    }
    getRandom() {
        return this.arr[Math.floor(Math.random() * this.arr.length)];
    }
}

// 验证
const s = new MinStack();
s.push(-2); s.push(0); s.push(-3);
console.log(s.getMin(), s.pop(), s.top(), s.getMin());   // -3 -3 0 -2
const set = new RandomizedSet();
console.log(set.insert(1), set.remove(2), set.insert(2)); // true false true
console.log(set.getRandom());                             // 1 或 2
console.log(set.remove(1), set.getRandom());              // true 2
```

**复杂度：** 最小栈三个操作 O(1)、空间 O(n)；随机集合平均 O(1)、空间 O(n)。

**边界与坑：**

- 空栈调用 `pop` / `top` / `getMin`：题目保证非空，工程实现应抛错。
- `push` 时 `mins` 的初值用 `Infinity`，避免空数组取 `undefined` 参与 `Math.min` 得到 `NaN`。
- 随机集合 `remove` 的顺序：先覆盖、再更新末尾下标、再 `pop`、最后删键；顺序错会丢元素或留下脏下标。
- `remove` 删除的元素正好是末尾元素时，`arr[i] = last` 是自赋值，`pop` 后仍正确，但索引更新不能省。

**面试怎么答：** 最小栈讲「辅助栈同步记录前缀最小值」，并对比「只存更小值」的写法为什么弹出时更麻烦。随机集合讲「数组 + 哈希 + 与末尾交换」，重点强调「删除 O(1) 的关键是把洞填上并更新索引」，这是本题唯一的难点。

**易错点：**

- 最小栈只用一个变量记录最小值，弹出后无法恢复上一个最小值。
- `mins.push(Math.min(x, this.mins[this.mins.length - 1]))` 在空栈时得到 `NaN`。
- 随机集合删除时先 `arr.pop()` 再取末尾元素，取到的是被删元素本身。
- 与末尾交换后忘记 `index.set(last, i)`，之后按值删除会删错位置。
