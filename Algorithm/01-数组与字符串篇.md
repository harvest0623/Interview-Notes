## 1. 两数之和与三数之和

**题目：** 两数之和：给定整数数组 `nums` 和整数 `target`，返回和为目标值的两个元素下标（每组输入只有一个答案，同一元素不可重复使用）。三数之和：返回所有和为 0 且不重复的三元组。

**示例：**

```js
twoSum([2, 7, 11, 15], 9);          // [0, 1]，2 + 7 = 9
threeSum([-1, 0, 1, 2, -1, -4]);    // [[-1, -1, 2], [-1, 0, 1]]
```

**思路：**

- 暴力：枚举 `i < j` 的所有组合逐个判断，时间 O(n²)、空间 O(1)，n 到 10^5 就超时。
- 两数之和最优：哈希表存「值 → 下标」。遍历到 `x` 时先查 `target - x` 是否已经出现过，再登记 `x`。
  - 为什么快：把「找另一个数」从线性扫描变成 O(1) 查表，一趟遍历即可；先查后存保证不会把当前元素自己匹配掉。
- 三数之和最优：排序 + 固定一个数 + 双指针。
  - 为什么排序：排序后数组有序，两数之和可以靠「和偏小就左指针右移、和偏大就右指针左移」的单调性收敛，把内层 O(n²) 降到 O(n)，总复杂度 O(n²)。
  - 为什么能去重：相同值在排序后相邻，遇到重复值直接跳过即可，不需要 `Set` 存整个三元组。

**代码：**

```js
function twoSum(nums, target) {
    const index = new Map();
    for (let i = 0; i < nums.length; i++) {
        const need = target - nums[i];
        if (index.has(need)) {
            return [index.get(need), i];
        }
        index.set(nums[i], i);
    }
    return [];
}

function threeSum(nums) {
    const res = [];
    const a = nums.slice().sort((x, y) => x - y);
    for (let i = 0; i < a.length - 2; i++) {
        if (a[i] > 0) break;                        // 最小值都大于 0，三数之和不可能为 0
        if (i > 0 && a[i] === a[i - 1]) continue;   // 跳过重复的第一个数
        let l = i + 1;
        let r = a.length - 1;
        while (l < r) {
            const sum = a[i] + a[l] + a[r];
            if (sum < 0) {
                l++;
            } else if (sum > 0) {
                r--;
            } else {
                res.push([a[i], a[l], a[r]]);
                while (l < r && a[l] === a[l + 1]) l++;   // 跳过重复的左值
                while (l < r && a[r] === a[r - 1]) r--;   // 跳过重复的右值
                l++;
                r--;
            }
        }
    }
    return res;
}

// 验证
console.log(twoSum([2, 7, 11, 15], 9));        // [0, 1]
console.log(threeSum([-1, 0, 1, 2, -1, -4]));  // [[-1, -1, 2], [-1, 0, 1]]
```

**复杂度：**

| 题 | 时间 | 空间 |
| --- | --- | --- |
| 两数之和（哈希） | O(n) | O(n) |
| 两数之和（排序 + 双指针，返回数值） | O(n log n) | O(1) |
| 三数之和 | O(n²) | O(1)（不计结果与排序栈） |

**边界与坑：**

- 数组长度不足 3 时三数之和直接返回空数组，循环条件 `i < a.length - 2` 天然覆盖。
- 存在多个相同值时，`Map` 中保存的应是**最后一次**出现的下标（覆盖写）还是第一次都行，本题只要求一组解；但若要「值相同取任意」，覆盖写不影响正确性。
- 三数之和的三个去重点缺一不可：外层 `i` 去重、内层左右指针去重；只写外层会在 `[-2,0,0,2,2]` 上产出重复三元组。
- 不能用 `a[i] > 0` 换成 `a[i] >= 0`，否则会漏掉 `[0,0,0]`。
- JS 的 `sort` 默认按字符串比较，必须显式传 `(x, y) => x - y`，否则 `[-1, -4, 2, 10]` 会排成 `[-1, -4, 10, 2]` 之类。

**面试怎么答：** 先给两数之和的哈希解法并强调「先查后存」，再说三数之和是「排序 + 双指针 + 三层去重」，最后补一句复杂度 O(n²) 和「如果要求返回原下标就不能排序，只能回到哈希或 O(n²) 枚举」。被追问 k 数之和时答「递归固定一个数，降到 k-1 数之和，剪枝与去重逻辑复用」。

**易错点：**

- 三数之和忘记 `slice()` 直接原地排序，改动了入参。
- 内层去重写成 `if (a[l] === a[l + 1]) l++` 而少了 `while`，连续三个相同值仍会重复。
- 两数之和先 `set` 后 `has`，遇到 `[3, 3]`、`target = 6` 时会返回 `[0, 0]`。

## 2. 滑动窗口最大值与最长无重复子串

**题目：** ① 给定数组 `nums` 和窗口大小 `k`，返回每个长度为 `k` 的窗口中的最大值。② 给定字符串 `s`，返回不含重复字符的最长子串长度。

**示例：**

```js
maxSlidingWindow([1, 3, -1, -3, 5, 3, 6, 7], 3); // [3, 3, 5, 5, 6, 7]
lengthOfLongestSubstring('abcabcbb');            // 3（"abc"）
lengthOfLongestSubstring('pwwkew');              // 3（"wke"）
```

**思路：**

- 滑动窗口最大值暴力：每个窗口扫一遍取最大，O(nk)，最坏 O(n²)。
- 最优：单调递减双端队列存**下标**。新元素入队前，把队尾所有「值不大于它」的下标弹出——它们比新元素早入队又更小，永远不可能再成为最大值，可直接淘汰。
  - 为什么是 O(n)：每个下标最多入队一次、出队一次，均摊 O(1)。
  - 为什么存下标而不是值：需要判断队首是否已经滑出窗口（`dq[0] <= i - k`）。
- 最长无重复子串暴力：以每个位置为起点向右扩，用 `Set` 判重，O(n²)。
- 最优：滑动窗口 + 记录「字符最后出现的下标」。右指针扩张时，若该字符上次出现在窗口内，左指针直接跳到 `last + 1`（不是 `left + 1`，一步到位）。
  - 为什么可以跳：窗口内一旦出现重复，左边界必须越过那个旧位置，否则任何包含这两次的窗口都非法。

**代码：**

```js
function maxSlidingWindow(nums, k) {
    const res = [];
    const dq = [];   // 存下标，对应值从队首到队尾单调递减
    for (let i = 0; i < nums.length; i++) {
        while (dq.length > 0 && nums[dq[dq.length - 1]] <= nums[i]) {
            dq.pop();   // 队尾比当前值小，永远不会再当最大值
        }
        dq.push(i);
        if (dq[0] <= i - k) {
            dq.shift();     // 队首滑出窗口
        }
        if (i >= k - 1) {
            res.push(nums[dq[0]]);
        }
    }
    return res;
}

function lengthOfLongestSubstring(s) {
    const last = new Map();   // 字符 -> 最后一次出现的下标
    let left = 0;
    let best = 0;
    for (let right = 0; right < s.length; right++) {
        const ch = s[right];
        if (last.has(ch) && last.get(ch) >= left) {
            left = last.get(ch) + 1;   // 左边界一步跳到重复字符之后
        }
        last.set(ch, right);
        best = Math.max(best, right - left + 1);
    }
    return best;
}

// 验证
console.log(maxSlidingWindow([1, 3, -1, -3, 5, 3, 6, 7], 3)); // [3, 3, 5, 5, 6, 7]
console.log(lengthOfLongestSubstring('abcabcbb'));            // 3
console.log(lengthOfLongestSubstring('pwwkew'));              // 3
```

**复杂度：**

| 题 | 时间 | 空间 |
| --- | --- | --- |
| 滑动窗口最大值（单调队列） | O(n)，均摊 | O(k) |
| 最长无重复子串（滑动窗口） | O(n) | O(字符集大小)，最坏 O(n) |

**边界与坑：**

- `k = 1` 时每个元素单独成窗；`k > n` 时应返回空数组，所以 `i >= k - 1` 这个判断不能省。
- 单调队列比较用 `<=` 还是 `<`：用 `<=` 会把相等值的旧下标弹掉，队列里保留最新的相等值，窗口收缩时它更晚滑出，结果仍正确；用 `<` 则需要额外的相等值清理逻辑，容易漏。
- 最长无重复的 `last.get(ch) >= left` 判断是关键：字符上次出现在窗口**左侧之外**时不能跳，否则左边界会倒退。
- 空字符串返回 0，循环自然覆盖。
- 窗口收缩要用 `while` 而不是 `if`（本题用「跳左边界」的写法天然规避了这一点，但通用模板必须 `while`）。

**面试怎么答：** 先说「滑动窗口 + 单调双端队列」，讲清楚「为什么弹出队尾：又小又早的元素不可能再成为最大值」，再讲「为什么存下标：为了判断过期」。第二题讲「左指针一步跳到重复位置之后」，并给出 `>= left` 这个判断的意义。最后补一句：如果要求窗口内最大值和最小值，维护两个单调队列即可。

**易错点：**

- 用 `Math.max(...window)` 每个窗口重算，复杂度退化为 O(nk)。
- 单调队列只弹一个元素而不用 `while`，队尾仍可能残留更小值。
- 最长无重复写成 `left = right`，会漏掉「当前字符上次出现在 left 之前」的正常扩张。
- JS 字符串按 UTF-16 码元取下标，处理 emoji 时会拆成代理对；面试提到这一点即可，不必实现。

## 3. 双指针：盛水容器与接雨水

**题目：** ① 盛最多水的容器：给定高度数组 `height`，选两条垂线，与 x 轴围成容器，求最大蓄水量。② 接雨水：每个宽度为 1 的柱子上能接多少雨水。

**示例：**

```js
maxArea([1, 8, 6, 2, 5, 4, 8, 3, 7]); // 49
trap([0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]); // 6
```

**思路：**

- 盛水容器暴力：枚举所有左右边界 `(i, j)`，面积 `min(h[i], h[j]) * (j - i)`，O(n²)。
- 最优：左右指针从两端向中间收。面积由「较短边」决定，因此**移动较短的一侧**才可能让面积上限变大；移动较高的一侧，宽度必然减小且高度受限于原短板，面积只会更小。
  - 为什么是 O(n)：每步淘汰一个边界，最多 2n 步。
- 接雨水暴力：对每个柱子向左右各扫一遍取最大高度，`min(leftMax, rightMax) - h[i]` 累加，O(n²)、空间 O(1)；预处理前后缀最大值可做到 O(n)/O(n)。
- 最优：双指针 + 两个变量 `leftMax`、`rightMax`，空间 O(1)。
  - 为什么能只用两个变量：当 `h[l] < h[r]` 时，左柱的存水量由 `leftMax` 决定——右侧至少有一根 `h[r] > h[l]` 的柱子兜底，右侧真实最大高度不会低于当前 `h[l]`，因此不必知道右侧完整信息。

**代码：**

```js
function maxArea(height) {
    let l = 0;
    let r = height.length - 1;
    let best = 0;
    while (l < r) {
        const h = Math.min(height[l], height[r]);
        best = Math.max(best, h * (r - l));
        if (height[l] < height[r]) {
            l++;   // 移动短板，才可能抬高容器高度
        } else {
            r--;
        }
    }
    return best;
}

function trap(height) {
    let l = 0;
    let r = height.length - 1;
    let leftMax = 0;
    let rightMax = 0;
    let water = 0;
    while (l < r) {
        if (height[l] < height[r]) {
            leftMax = Math.max(leftMax, height[l]);
            water += leftMax - height[l];   // 左侧已有挡板，右侧一定不低于当前高度
            l++;
        } else {
            rightMax = Math.max(rightMax, height[r]);
            water += rightMax - height[r];
            r--;
        }
    }
    return water;
}

// 验证
console.log(maxArea([1, 8, 6, 2, 5, 4, 8, 3, 7]));          // 49
console.log(trap([0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]));   // 6
console.log(trap([4, 2, 0, 3, 2, 5]));                      // 9
```

**复杂度：**

| 题 | 时间 | 空间 |
| --- | --- | --- |
| 盛水容器（双指针） | O(n) | O(1) |
| 接雨水（双指针） | O(n) | O(1) |
| 接雨水（前后缀最大值） | O(n) | O(n) |

**边界与坑：**

- 柱子数小于 2 时容器面积为 0，接雨水为 0，循环自然不执行。
- 盛水容器的宽度是 `r - l`，不是 `r - l + 1`（面积是「线」之间，不包含边界本身）。
- 接雨水里 `leftMax - height[l]` 可能为 0（当前柱是最高点），不能写 `Math.max(0, ...)` 以外的负数累加——实际上 `leftMax` 已先取 max，差值必为非负。
- 高度含 0 时接雨水为 0，逻辑正常；含负数属于非法输入，题面保证非负。
- 别把「移动短板」写成「移动长板」，这是两题共同的核心不变量。

**面试怎么答：** 盛水容器先讲暴力 O(n²)，再讲「面积由短板决定，所以移动短板」这一句就够。接雨水建议先给「每个柱子存水量 = min(左最大, 右最大) - 自身」这个定义，再讲双指针如何省掉一侧信息，最后提 O(n)/O(n) 的前后缀数组解法作为对照。被追问单调栈解法时说明「按行/按列求水的等价思路」。

**易错点：**

- 盛水容器先算面积再决定移动，顺序不能反（否则可能用错误边界算面积）。
- 接雨水写成 `leftMax = Math.max(leftMax, height[l]); water += leftMax - height[l];` 后忘记 `l++`，死循环。
- 认为接雨水双指针「先处理高的一侧」也行——处理顺序必须与「较矮的一侧」一致，否则 `leftMax/rightMax` 的含义被破坏。

## 4. 原地数组操作：移动零、删除重复项

**题目：** ① 移动零：把所有 0 移到末尾，保持非零元素相对顺序，要求原地。② 删除有序数组中的重复项：原地去重，返回新长度，`nums` 前 k 个元素为去重结果。③（进阶）每个元素最多保留两次。

**示例：**

```js
moveZeroes([0, 1, 0, 3, 12]);   // [1, 3, 12, 0, 0]
removeDuplicates([0, 0, 1, 1, 1, 2, 2, 3, 3, 4]); // 5，前 5 项为 [0, 1, 2, 3, 4]
```

**思路：**

- 移动零暴力：开一个新数组，先放非零再补零，O(n)/O(n)；或每遇到 0 就把后面整体左移，O(n²)。
- 最优：快慢指针。`slow` 指向「下一个非零元素该放的位置」，`fast` 扫描；遇到非零就与 `slow` 交换并 `slow++`。
  - 为什么是 O(n)：每个元素只被访问一次；交换而不是覆盖，天然把 0 换到后面，无需第二遍补零。
  - 为什么保持顺序：`slow` 单调递增，非零元素按 `fast` 扫描顺序落位。
- 删除重复项：同样快慢指针，但 `slow` 指向「最后一个已确认的唯一元素」。`fast` 找到与 `nums[slow]` 不同的值，就写到 `slow + 1` 并 `slow++`。
  - 为什么不需要交换：重复值本来就要丢弃，直接覆盖即可；返回值是 `slow + 1`。
- 进阶「最多保留两次」：把「与 `nums[slow]` 比较」换成「与 `nums[slow - 1]` 比较」，`slow` 指向最后一个已保留元素，窗口宽度 2。

**代码：**

```js
function moveZeroes(nums) {
    let slow = 0;
    for (let fast = 0; fast < nums.length; fast++) {
        if (nums[fast] !== 0) {
            const tmp = nums[slow];
            nums[slow] = nums[fast];
            nums[fast] = tmp;
            slow++;
        }
    }
    return nums;
}

function removeDuplicates(nums) {
    if (nums.length === 0) return 0;
    let slow = 0;
    for (let fast = 1; fast < nums.length; fast++) {
        if (nums[fast] !== nums[slow]) {
            slow++;
            nums[slow] = nums[fast];
        }
    }
    return slow + 1;
}

function removeDuplicatesAtMostTwice(nums) {
    if (nums.length <= 2) return nums.length;
    let slow = 1;   // slow 指向最后一个已保留元素
    for (let fast = 2; fast < nums.length; fast++) {
        if (nums[fast] !== nums[slow - 1]) {
            slow++;
            nums[slow] = nums[fast];
        }
    }
    return slow + 1;
}

// 验证
console.log(moveZeroes([0, 1, 0, 3, 12]));                       // [1, 3, 12, 0, 0]
console.log(removeDuplicates([0, 0, 1, 1, 1, 2, 2, 3, 3, 4]));   // 5
console.log(removeDuplicatesAtMostTwice([1, 1, 1, 2, 2, 3]));    // 5
```

**复杂度：** 时间 O(n)，空间 O(1)（只用了常数个指针与临时变量）。

**边界与坑：**

- 空数组：`moveZeroes` 返回 `[]`；`removeDuplicates` 要先判空，否则 `nums[slow]` 越界读取为 `undefined`，逻辑仍能跑但语义不清。
- 全为 0：`slow` 一直是 0，不交换，结果正确。
- 删除重复项返回值是 `slow + 1`（长度），不是 `slow`（下标），这是最高频的 off-by-one。
- 「最多保留两次」的初值：`slow = 1, fast = 2`，因为前两个元素必然可以保留；若写成 `slow = 0` 会破坏比较基准。
- 交换写法依赖解构或临时变量；JS 解构交换在超大数组上也不慢，但面试写临时变量更稳妥、可读。

**面试怎么答：** 统一说「快慢指针：slow 是写指针（已处理区尾部），fast 是读指针（未处理区头部）」，然后按题意给出「交换」还是「覆盖」的差别：移动零要保留 0，所以交换；删除重复项要丢弃元素，所以覆盖。最后主动提复杂度 O(n)/O(1) 和「返回长度而非数组」的 API 约定。

**易错点：**

- 移动零用覆盖写法（`nums[slow] = nums[fast]`）后忘记把尾部清零。
- 删除重复项 `fast` 从 0 开始，导致第一个元素和自己比较，多一次无意义循环。
- 把 `removeDuplicates` 的返回值当成新数组直接 `console.log(nums.slice(0, k))` 之外还去读 `nums.length`，误以为原数组被截断。
- 在「最多两次」题里用 `nums[fast] !== nums[slow]` 比较，结果变成完全去重。

## 5. 前缀和与差分数组

**题目：** ① 给定整数数组（可含负数）和目标值 `k`，求和为 `k` 的连续子数组个数。② 设计结构支持「区间 `[l, r]` 全部加 `val`」并随时还原数组。

**示例：**

```js
subarraySum([1, 1, 1], 2);      // 2
subarraySum([1, -1, 0], 0);     // 3
// 差分：[1, 2, 3, 4]，对 [1, 2] 加 2 -> [1, 4, 5, 4]
```

**思路：**

- 暴力：枚举左右端点累加求和，O(n²)（用前缀和可降到 O(n²) 时间 / O(n) 空间）。n = 2×10^4 时 O(n²) 已经偏慢。
- 最优（计数型）：前缀和 + 哈希表。设 `prefix[j]` 为前 j 个元素之和，则子数组 `(i, j]` 的和为 `prefix[j] - prefix[i] = k`，即「历史前缀中等于 `prefix[j] - k` 的个数」。
  - 为什么必须用哈希而不是滑动窗口：数组含负数，窗口和不再随右指针单调，收缩条件失效，只能靠「查历史前缀」。
  - 为什么 `count.set(0, 1)` 不能省：它代表空前缀，使得「从下标 0 开始的子数组」能被统计到。
- 差分（区间修改型）：`diff[i] = a[i] - a[i-1]`。区间 `[l, r]` 加 `val` 只会改变两个边界：`diff[l] += val`、`diff[r+1] -= val`；还原时对 `diff` 求前缀和。
  - 为什么快：把「O(length) 的区间更新」降为 O(1)，适合「多次更新、最后一次性查询」。若要求随时查询，就需要线段树 / 树状数组。

**代码：**

```js
function subarraySum(nums, k) {
    const count = new Map();
    count.set(0, 1);              // 空前缀，处理从下标 0 开始的子数组
    let prefix = 0;
    let ans = 0;
    for (const x of nums) {
        prefix += x;
        ans += count.get(prefix - k) || 0;
        count.set(prefix, (count.get(prefix) || 0) + 1);
    }
    return ans;
}

class DiffArray {
    constructor(nums) {
        this.n = nums.length;
        this.diff = new Array(this.n + 1).fill(0);
        if (this.n > 0) {
            this.diff[0] = nums[0];
        }
        for (let i = 1; i < this.n; i++) {
            this.diff[i] = nums[i] - nums[i - 1];
        }
    }

    add(l, r, val) {              // 闭区间 [l, r] 全部加 val
        this.diff[l] += val;
        this.diff[r + 1] -= val;  // r + 1 位置多开的一格，越界也安全
    }

    toArray() {                   // 前缀和还原
        const res = new Array(this.n);
        let cur = 0;
        for (let i = 0; i < this.n; i++) {
            cur += this.diff[i];
            res[i] = cur;
        }
        return res;
    }
}

// 验证
console.log(subarraySum([1, 1, 1], 2));                 // 2
console.log(subarraySum([1, -1, 0], 0));                // 3
const d = new DiffArray([1, 2, 3, 4]);
d.add(1, 2, 2);
console.log(d.toArray());                               // [1, 4, 5, 4]
```

**复杂度：**

| 操作 | 时间 | 空间 |
| --- | --- | --- |
| 子数组和为 k | O(n) | O(n)（哈希表最多 n+1 个键） |
| 差分单次区间加 | O(1) | O(n) |
| 差分整体还原 | O(n) | O(n) |

**边界与坑：**

- `k = 0` 且数组含 0：`[0]` 应返回 1；`count` 的初始 `{0: 1}` 保证正确。
- 前缀和可能超出 32 位整数范围，JS 用 `Number`（2^53 内安全），Java 需要 `long`。
- 差分数组长度开到 `n + 1`，否则 `add(n - 1, n - 1, val)` 时 `diff[n]` 越界；JS 数组越界写会静默扩长，但显式开格更严谨。
- 差分只适合「先批量修改、后统一查询」；要边改边查就用线段树 / 树状数组。

**面试怎么答：** 先讲「前缀和把区间和降为 O(1)」这个基本盘，再讲「计数型问题把前缀和塞进哈希表，一次遍历统计 `prefix - k`」，并主动指出「含负数时不能滑窗」这个考点。差分则强调「区间修改 → 两个端点」「多次修改一次查询」的适用场景；若被追问二维场景，答「用容斥 `A+B+C-D` 递推，单次查询 O(1)」。

**易错点：**

- 哈希表先更新答案再存当前前缀（顺序反了会把空子数组算进去）。
- 差分还原时从 `diff[1]` 开始累加，漏掉首元素。
- 二维前缀和查询写成 `pre[r2][c2] - pre[r1][c2] - pre[r2][c1] + pre[r1][c1]`，边界整体少 1。
- 认为「前缀和 + 哈希」也能处理「最长子数组」——可以，但存的是**最早**下标而不是计数。

## 6. 二分查找及其变体

**题目：** ① 在有序数组中查找目标值下标。② 找第一个 `>= target` 的位置（lower_bound）与第一个 `> target` 的位置（upper_bound）。③ 搜索旋转排序数组。④ 二分答案：Koko 吃香蕉的最小速度。

**示例：**

```js
lowerBound([1, 2, 2, 2, 5], 2);          // 1
upperBound([1, 2, 2, 2, 5], 2);          // 4
searchRotated([4, 5, 6, 7, 0, 1, 2], 0); // 4
minEatingSpeed([3, 6, 7, 11], 8);        // 4
```

**思路：**

- 暴力：线性扫描 O(n)，对旋转数组同样适用，但没利用有序性。
- 标准二分：闭区间写法 `[lo, hi]`，循环条件 `lo <= hi`，排除 mid 后 `mid ± 1`；`mid = lo + (hi - lo) / 2` 可避免 `lo + hi` 溢出。
- 边界二分（lower_bound / upper_bound）：左闭右开 `[lo, hi)`，循环条件 `lo < hi`，**不提前返回**，一直收缩到区间为空，返回值天然落在 `[0, n]`。
  - 为什么用这套模板找边界：`nums[mid] < target` 与 `>=` 的分界就是答案，不需要特判「找不到」。
- 旋转数组：旋转后数组由两段升序组成，每次 `mid` 必有一侧有序。判断 `nums[lo] <= nums[mid]` 说明左半段有序，再看 target 是否落在该有序区间内决定收缩方向。
- 二分答案：答案具有单调性（速度越大耗时越短），把「最小可行解」转成「在 `[下界, 上界]` 上找第一个满足条件的值」。

**代码：**

```js
function lowerBound(nums, target) {
    let lo = 0;
    let hi = nums.length;            // 搜索区间 [lo, hi)
    while (lo < hi) {
        const mid = lo + Math.floor((hi - lo) / 2);
        if (nums[mid] < target) lo = mid + 1;
        else hi = mid;
    }
    return lo;                        // 第一个 >= target 的下标，可能等于 n
}

function upperBound(nums, target) {
    let lo = 0;
    let hi = nums.length;
    while (lo < hi) {
        const mid = lo + Math.floor((hi - lo) / 2);
        if (nums[mid] <= target) lo = mid + 1;
        else hi = mid;
    }
    return lo;                        // 第一个 > target 的下标
}

function searchRotated(nums, target) {
    let lo = 0;
    let hi = nums.length - 1;
    while (lo <= hi) {
        const mid = lo + Math.floor((hi - lo) / 2);
        if (nums[mid] === target) return mid;
        if (nums[lo] <= nums[mid]) {              // 左半段有序
            if (nums[lo] <= target && target < nums[mid]) hi = mid - 1;
            else lo = mid + 1;
        } else {                                   // 右半段有序
            if (nums[mid] < target && target <= nums[hi]) lo = mid + 1;
            else hi = mid - 1;
        }
    }
    return -1;
}

function minEatingSpeed(piles, h) {
    let lo = 1;
    let hi = Math.max(...piles);      // 答案一定在 [1, 最大堆]
    const cost = (k) => piles.reduce((sum, p) => sum + Math.ceil(p / k), 0);
    while (lo < hi) {
        const mid = lo + Math.floor((hi - lo) / 2);
        if (cost(mid) <= h) hi = mid;  // mid 可行，尝试更小
        else lo = mid + 1;
    }
    return lo;
}

// 验证
console.log(lowerBound([1, 2, 2, 2, 5], 2));           // 1
console.log(upperBound([1, 2, 2, 2, 5], 2));           // 4
console.log(searchRotated([4, 5, 6, 7, 0, 1, 2], 0));  // 4
console.log(searchRotated([4, 5, 6, 7, 0, 1, 2], 3));  // -1
console.log(minEatingSpeed([3, 6, 7, 11], 8));         // 4
```

**复杂度：**

| 题 | 时间 | 空间 |
| --- | --- | --- |
| 标准二分 / lower_bound / upper_bound | O(log n) | O(1) |
| 旋转数组搜索 | O(log n) | O(1) |
| 二分答案（吃香蕉） | O(n log max(piles)) | O(1) |

**边界与坑：**

- 空数组：`lowerBound([], x)` 返回 0，调用方需判断「下标是否等于长度」来表示不存在。
- 有重复元素时标准二分返回的是「任意一个」目标下标，需要第一个/最后一个就必须用 lower_bound。
- 旋转数组中 `nums[lo] <= nums[mid]` 的等号不能丢，否则 `lo === mid`（区间只剩两个元素）时会被判成右半段有序。
- 二分答案的 `lo` 初始值不能是 0（速度不能为 0，会除零），取 1；`hi` 取最大堆保证可行。

**面试怎么答：** 先声明「我固定用一套模板：左闭右开找下界，闭区间找精确值」，然后给出 lower_bound 的三行核心 `if nums[mid] < target: lo = mid + 1 else hi = mid`。旋转数组讲「必有一侧有序」，二分答案讲「单调性 + 可行域收缩」并说明判定函数是 O(n)，所以总复杂度 O(n log C)。

**易错点：**

- `while (lo <= hi)` 配 `hi = mid`，区间不收敛导致死循环。
- 计算 `mid` 用 `(lo + hi) / 2`，JS 得到小数，下标访问出错（必须 `Math.floor`）。
- lower_bound 与 upper_bound 只差一个 `<` 和 `<=`，背反了会得到「最后一个小于等于」之类的错误语义。
- 旋转数组里用 `nums[lo] <= target <= nums[mid]` 的链式比较——JS 不支持，必须写成两个条件。

## 7. 字符串匹配与 KMP

**题目：** 在文本串 `s` 中查找模式串 `p`，返回第一次出现的下标（不存在返回 -1）；进阶：返回所有出现位置。

**示例：**

```js
kmpSearch('abababca', 'abca');   // 4
kmpSearchAll('aaaaa', 'aa');     // [0, 1, 2, 3]
```

**思路：**

- 暴力：每个起点逐字符比较，最坏 O(nm)（例如 `s = 'aaaaab'`、`p = 'aaab'` 每次都几乎比完）。
- 最优 KMP：预处理模式串的 `lps`（longest proper prefix which is also suffix，也叫 next 数组），匹配失败时模式串指针 `j` 回退到 `lps[j-1]` 而不是回到 0，文本指针 `i` 永不回退。
  - 为什么是 O(n + m)：`i` 单调递增，`j` 每次回退都至少减少 1，而 `j` 增加的总次数不超过 `i` 的增加次数，均摊 O(1)。
  - 为什么 `lps` 有效：它给出了「已匹配前缀中，最长的既是前缀又是后缀的长度」，回退到该长度可保证不遗漏任何可能的匹配起点。
  - `lps` 自身的构造：本质是模式串和自己做匹配，`len` 记录当前公共前后缀长度，失配时 `len = lps[len-1]` 递归回退。

**代码：**

```js
function buildLPS(p) {
    const lps = new Array(p.length).fill(0);
    let len = 0;
    let i = 1;
    while (i < p.length) {
        if (p[i] === p[len]) {
            lps[i++] = ++len;
        } else if (len > 0) {
            len = lps[len - 1];          // 回退到更短的前后缀继续尝试
        } else {
            lps[i++] = 0;
        }
    }
    return lps;
}

function kmpSearch(s, p) {
    if (p.length === 0) return 0;
    const lps = buildLPS(p);
    let i = 0;
    let j = 0;
    while (i < s.length) {
        if (s[i] === p[j]) {
            i++;
            j++;
            if (j === p.length) return i - j;
        } else if (j > 0) {
            j = lps[j - 1];          // 文本指针不回退
        } else {
            i++;
        }
    }
    return -1;
}

function kmpSearchAll(s, p) {
    const res = [];
    if (p.length === 0) return res;
    const lps = buildLPS(p);
    let i = 0;
    let j = 0;
    while (i < s.length) {
        if (s[i] === p[j]) {
            i++;
            j++;
            if (j === p.length) {
                res.push(i - j);
                j = lps[j - 1];      // 继续找重叠匹配
            }
        } else if (j > 0) {
            j = lps[j - 1];
        } else {
            i++;
        }
    }
    return res;
}

// 验证
console.log(buildLPS('ababaca'));       // [0, 0, 1, 2, 3, 0, 1]
console.log(kmpSearch('abababca', 'abca'));   // 4
console.log(kmpSearchAll('aaaaa', 'aa'));     // [0, 1, 2, 3]
```

**复杂度：** 时间 O(n + m)，空间 O(m)（`lps` 数组）。暴力为 O(nm)、空间 O(1)。

**边界与坑：**

- 空模式串：约定返回 0（与多数 `indexOf` 一致），否则 `p[0]` 为 `undefined` 会一路错下去。
- 模式串比文本长：循环自然结束返回 -1。
- `lps` 构造中 `i` 从 1 开始，`lps[0]` 恒为 0；写成从 0 开始会得到错误数组。
- 全部匹配后要继续找重叠结果，必须 `j = lps[j - 1]`，不能直接 `j = 0`（会漏掉 `aaaaa` 中重叠的 `aa`）。
- 用 `s[i] === p[j]` 时注意 `j` 不会越界：匹配成功分支里 `j` 达到 `p.length` 就立即处理并回退。

**面试怎么答：** 先写暴力并说明最坏 O(nm)，再讲 KMP 的核心一句话「利用已匹配部分的 border 信息，让文本指针不回退」。能手推 `ababaca` 的 `lps`（`[0,0,1,2,3,0,1]`）比背代码更有说服力。最后提一句工程里 `indexOf` 多用 Boyer-Moore / 双路匹配，KMP 更适合面试与流式匹配。

**易错点：**

- 把 `lps` 理解成「最长回文前缀」，它要求**既是前缀又是后缀**且是真前缀。
- 失配时写 `j = lps[j]`（越界或语义错），应为 `lps[j - 1]`。
- `buildLPS` 里失配且 `len === 0` 时忘记 `i++`，死循环。
- 找到一次匹配后直接 `break`，导致 `kmpSearchAll` 只返回第一个位置。

## 8. 最长回文子串

**题目：** 给定字符串 `s`，返回其中最长的回文子串（若存在多个，返回任意一个）。

**示例：**

```js
longestPalindrome('babad');   // "bab"（"aba" 也合法）
longestPalindrome('cbbd');    // "bb"
longestPalindrome('a');       // "a"
```

**思路：**

- 暴力：枚举所有子串（O(n²) 个）再判断是否回文（O(n)），总 O(n³)，只能处理 n ≤ 100。
- 区间 DP：`dp[i][j]` 表示 `s[i..j]` 是否回文，转移 `dp[i][j] = s[i] === s[j] && (j - i < 2 || dp[i+1][j-1])`，O(n²) 时间、O(n²) 空间。
- 中心扩展（推荐）：回文串关于中心对称，中心有 `2n - 1` 个（n 个字符中心 + n-1 个间隙中心）。从每个中心向两侧扩，直到字符不同。
  - 为什么是 O(n²)：每个中心最多扩 O(n)，共 O(n) 个中心；但常数小、空间 O(1)，实际最快。
  - 为什么奇数与偶数要分开：`aba` 中心是一个字符，`abba` 中心是间隙，统一写法是 `expand(i, i)` 与 `expand(i, i+1)` 取较长。
- Manacher：在字符间插入 `#` 把奇偶统一，利用回文半径的对称性把复杂度降到 O(n)，实现复杂，面试写出中心扩展即可，能说出 Manacher 的思路是加分项。

**代码：**

```js
function longestPalindrome(s) {
    if (s.length < 2) return s;
    let start = 0;
    let maxLen = 1;

    const expand = (l, r) => {
        while (l >= 0 && r < s.length && s[l] === s[r]) {
            l--;
            r++;
        }
        return r - l - 1;        // 回文长度
    };

    for (let i = 0; i < s.length; i++) {
        const len1 = expand(i, i);       // 奇数长度，中心是字符
        const len2 = expand(i, i + 1);   // 偶数长度，中心是间隙
        const len = Math.max(len1, len2);
        if (len > maxLen) {
            maxLen = len;
            start = i - Math.floor((len - 1) / 2);
        }
    }
    return s.slice(start, start + maxLen);
}

// 验证
console.log(longestPalindrome('babad'));   // "bab"
console.log(longestPalindrome('cbbd'));    // "bb"
console.log(longestPalindrome('a'));       // "a"
console.log(longestPalindrome('abacdfgdcaba')); // "aba"
```

**复杂度：**

| 解法 | 时间 | 空间 |
| --- | --- | --- |
| 暴力 | O(n³) | O(1) |
| 区间 DP | O(n²) | O(n²) |
| 中心扩展 | O(n²) | O(1) |
| Manacher | O(n) | O(n) |

**边界与坑：**

- 空串返回空串，长度 1 直接返回自身，避免 `expand` 里越界。
- 起始下标推导：`start = i - (len - 1) / 2`，偶数长度时 `(len - 1)` 为奇数，必须 `Math.floor`，JS 的 `/` 不取整会得到小数下标。
- `expand` 返回 `r - l - 1`：循环结束时 `l` 和 `r` 已经各多走一步，长度是 `(r - 1) - (l + 1) + 1 = r - l - 1`，这里最容易算错。
- 多个等长答案时题目通常接受任意一个，但面试要说明你的策略是「保留最先出现的」。
- 全相同字符（`'aaaa'`）时中心扩展退化为 O(n²)，但结果正确；Manacher 才能线性。

**面试怎么答：** 直接说「中心扩展，O(n²)/O(1)，比 DP 省空间且常数小」，然后讲清「2n-1 个中心」和「奇数/偶数两种扩展」。被追问优化时给出 Manacher 的两个要点：插入分隔符统一奇偶、利用对称半径跳过重复扩展。被问 DP 时补转移方程与遍历顺序（按长度递增）。

**易错点：**

- 只做奇数中心扩展，`'cbbd'` 会返回 `'b'` 而不是 `'bb'`。
- `start` 用 `i - len / 2`，偶数长度时偏左一格。
- `expand` 里先判断字符相等再移动指针，顺序写反导致长度算错。
- 返回 `s.substring(start, maxLen)`（第二个参数当成长度），实际应为 `start + maxLen`。

## 9. 区间合并与会议室问题

**题目：** ① 合并所有重叠区间（`[1,3]` 与 `[2,6]` 合并为 `[1,6]`）。② 判断一个人能否参加所有会议（区间是否两两不重叠）。③ 求所需的最少会议室数量。

**示例：**

```js
mergeIntervals([[1, 3], [2, 6], [8, 10], [15, 18]]); // [[1, 6], [8, 10], [15, 18]]
canAttendMeetings([[0, 30], [5, 10], [15, 20]]);     // false
minMeetingRooms([[0, 30], [5, 10], [15, 20]]);       // 2
```

**思路：**

- 暴力合并：两两检查是否重叠并合并，直到没有可合并的区间，最坏 O(n²) 且实现容易出错。
- 最优合并：按**起点**排序，然后一次线性扫描。
  - 为什么排序就够：排序后若两个区间可能重叠，它们的起点顺序已确定，任何区间只可能与「结果集中的最后一个区间」重叠或完全在其右侧，不存在跨区间重叠的遗漏。
  - 合并规则：当前起点 `<=` 上一终点就合并，终点取两者最大值（因为可能是包含关系，例如 `[1,10]` 与 `[2,3]`）。
- 会议室 I：同样按起点排序，只需比较相邻两场：`start[i] < end[i-1]` 即冲突。为什么只看相邻：排序后若与更早的会议冲突，必然先与相邻的冲突。
- 会议室 II：两种等价做法。
  - 双指针：把开始时间、结束时间分别排序。遍历开始时间，若 `start >= ends[j]`（最早结束的会议已经腾出房间）则复用，`j++`；否则房间数 +1。
  - 扫描线：开始 +1、结束 -1，按时间排序后求前缀和的最大值。**同一时刻要先处理结束事件**（端点相接不算重叠），否则 `[[1,2],[2,3]]` 会被算成需要 2 间。
  - 为什么不需要堆：只问「数量」，本质是求最大重叠层数；若要求输出具体分配方案，才需要小顶堆存每间房的结束时间。

**代码：**

```js
function mergeIntervals(intervals) {
    if (intervals.length === 0) return [];
    const a = intervals.slice().sort((x, y) => x[0] - y[0]);
    const res = [a[0].slice()];
    for (let i = 1; i < a.length; i++) {
        const last = res[res.length - 1];
        if (a[i][0] <= last[1]) last[1] = Math.max(last[1], a[i][1]);   // 处理包含关系
        else res.push(a[i].slice());
    }
    return res;
}

function canAttendMeetings(intervals) {
    const a = intervals.slice().sort((x, y) => x[0] - y[0]);
    for (let i = 1; i < a.length; i++) {
        if (a[i][0] < a[i - 1][1]) return false;
    }
    return true;
}

function minMeetingRooms(intervals) {
    const starts = intervals.map((x) => x[0]).sort((x, y) => x - y);
    const ends = intervals.map((x) => x[1]).sort((x, y) => x - y);
    let rooms = 0;
    let j = 0;                    // 指向最早可以复用的结束时间
    for (let i = 0; i < starts.length; i++) {
        if (starts[i] >= ends[j]) j++;          // 复用一个已有房间
        else rooms++;                           // 所有房间都在使用中，新开一间
    }
    return rooms;
}

function minMeetingRoomsSweep(intervals) {
    const events = [];
    for (const [s, e] of intervals) events.push([s, 1], [e, -1]);
    // 同一时刻结束事件（-1）排在开始事件（+1）之前
    events.sort((x, y) => (x[0] === y[0] ? x[1] - y[1] : x[0] - y[0]));
    let cur = 0;
    let best = 0;
    for (const [, delta] of events) {
        cur += delta;
        best = Math.max(best, cur);
    }
    return best;
}

// 验证
console.log(mergeIntervals([[1, 3], [2, 6], [8, 10], [15, 18]])); // [[1, 6], [8, 10], [15, 18]]
console.log(mergeIntervals([[1, 4], [4, 5]]));                    // [[1, 5]]
console.log(canAttendMeetings([[0, 30], [5, 10], [15, 20]]));      // false
console.log(minMeetingRooms([[0, 30], [5, 10], [15, 20]]));        // 2
console.log(minMeetingRoomsSweep([[1, 2], [2, 3]]));               // 1
```

**复杂度：**

| 题 | 时间 | 空间 |
| --- | --- | --- |
| 合并区间 | O(n log n) | O(n)（结果数组与排序副本） |
| 会议室 I | O(n log n) | O(n) |
| 会议室 II（双指针） | O(n log n) | O(n) |
| 会议室 II（扫描线） | O(n log n) | O(n) |

**边界与坑：**

- 空数组：合并返回 `[]`，会议室返回 0 / `true`。
- `[1,4]` 与 `[4,5]`：题目定义「端点相接算重叠」时可合并为 `[1,5]`；会议室场景端点相接不算冲突。**同一套 `<=` / `<` 不同题含义相反，必须先跟面试官确认**。
- 合并时直接 `res.push(a[i])` 会共享原数组引用，后续 `last[1] = ...` 可能改到入参，需要 `slice()` 拷贝。
- 扫描线排序比较器必须处理「同一时刻」，否则端点相接的用例会多算一间。

**面试怎么答：** 先讲「按起点排序 + 一次扫描」是区间题的通用套路，再说合并的两种关系（相交、包含）。会议室 II 主动给出双指针 + 扫描线两种写法，并强调「求最大重叠层数」这个本质。被追问「输出具体房间分配」时再说小顶堆：按开始时间入堆，堆顶结束时间早于当前开始就弹出复用。

**易错点：**

- 排序按终点而不是起点，导致 `[1,10]` 与 `[2,3]` 无法正确合并。
- 合并用 `last[1] = a[i][1]` 而不是 `Math.max`，遇到包含关系会把区间改短。
- 会议室 I 只检查 `a[i][0] < a[i-1][0]`（永远为假），写成了起点比较而不是「起点 vs 上一终点」。
- 双指针里把 `rooms` 与 `j` 混用，最后返回 `j`，结果变成「复用了多少间」而非「需要多少间」。

## 10. 螺旋矩阵与旋转图像

**题目：** ① 按顺时针螺旋顺序返回矩阵所有元素。② 生成 `n × n` 的螺旋矩阵（1 到 n²）。③ 原地将 `n × n` 矩阵顺时针旋转 90°。

**示例：**

```js
spiralOrder([[1, 2, 3], [4, 5, 6], [7, 8, 9]]); // [1, 2, 3, 6, 9, 8, 7, 4, 5]
generateMatrix(3); // [[1, 2, 3], [8, 9, 4], [7, 6, 5]]
rotate([[1, 2, 3], [4, 5, 6], [7, 8, 9]]);     // [[7, 4, 1], [8, 5, 2], [9, 6, 3]]
```

**思路：**

- 暴力：用方向数组 + `visited` 标记，走到边界或已访问就右转，O(mn) 时间、O(mn) 额外空间。好写，但空间不优且转向判断琐碎。
- 最优（螺旋遍历）：维护四个边界 `top / bottom / left / right`，每走完一条边就收缩一格。
  - 为什么 O(mn)：每个元素恰好访问一次；非方阵时最后一圈可能只剩一行或一列，必须加 `top <= bottom` / `left <= right` 判断，否则会重复输出。
- 旋转图像：顺时针 90° = 先沿主对角线转置，再把每一行反转；转置只交换 `(i, j)` 与 `(j, i)`，行反转用双指针交换，额外空间 O(1)。
  - 逆时针 90° = 转置后反转行的顺序；旋转 180° = 行反转 + 每行反转。

**代码：**

```js
function spiralOrder(matrix) {
    const res = [];
    if (matrix.length === 0 || matrix[0].length === 0) return res;
    let top = 0;
    let bottom = matrix.length - 1;
    let left = 0;
    let right = matrix[0].length - 1;
    while (top <= bottom && left <= right) {
        for (let j = left; j <= right; j++) res.push(matrix[top][j]);
        top++;
        for (let i = top; i <= bottom; i++) res.push(matrix[i][right]);
        right--;
        if (top <= bottom) {                       // 只剩一行时避免重复
            for (let j = right; j >= left; j--) res.push(matrix[bottom][j]);
            bottom--;
        }
        if (left <= right) {                       // 只剩一列时避免重复
            for (let i = bottom; i >= top; i--) res.push(matrix[i][left]);
            left++;
        }
    }
    return res;
}

function generateMatrix(n) {
    const m = Array.from({ length: n }, () => new Array(n).fill(0));
    let top = 0;
    let bottom = n - 1;
    let left = 0;
    let right = n - 1;
    let num = 1;
    while (num <= n * n) {
        for (let j = left; j <= right; j++) m[top][j] = num++;
        top++;
        for (let i = top; i <= bottom; i++) m[i][right] = num++;
        right--;
        for (let j = right; j >= left; j--) m[bottom][j] = num++;
        bottom--;
        for (let i = bottom; i >= top; i--) m[i][left] = num++;
        left++;
    }
    return m;
}

function rotate(matrix) {
    const n = matrix.length;
    for (let i = 0; i < n; i++) {
        for (let j = i + 1; j < n; j++) {          // 只遍历上三角
            [matrix[i][j], matrix[j][i]] = [matrix[j][i], matrix[i][j]];
        }
    }
    for (const row of matrix) {
        row.reverse();
    }
    return matrix;
}

// 验证
console.log(spiralOrder([[1, 2, 3], [4, 5, 6], [7, 8, 9]]));  // [1,2,3,6,9,8,7,4,5]
console.log(generateMatrix(3));                              // [[1,2,3],[8,9,4],[7,6,5]]
console.log(rotate([[1, 2, 3], [4, 5, 6], [7, 8, 9]]));       // [[7,4,1],[8,5,2],[9,6,3]]
```

**复杂度：**

| 题 | 时间 | 空间 |
| --- | --- | --- |
| 螺旋遍历 | O(mn) | O(1)（不计结果） |
| 生成螺旋矩阵 | O(n²) | O(n²)（结果本身） |
| 旋转图像 | O(n²) | O(1) |

**边界与坑：**

- 空矩阵 `[]` 或 `[[]]`：`matrix[0].length` 会抛错或得到 0，必须先判断。
- 旋转矩阵只适用于方阵；非方阵需要新开矩阵，不能原地。
- `rotate` 的转置循环 `j` 从 `i + 1` 开始；从 0 开始会把矩阵转置两次，等于没转。

**面试怎么答：** 先画图说明四条边与四个边界变量，强调「收缩边界」而不是「记录访问」。旋转图像用「转置 + 反转」两步讲，并顺便给出逆时针版本作为扩展。如果面试官问「不用额外空间怎么遍历」，答案就是这四边界法。

**易错点：**

- `bottom--` 与 `left++` 放在 `if` 外面，单行/单列用例重复输出。
- 螺旋写法里 `right--` 之后还用旧的 `right` 去遍历下边，导致多输出一列。
- 旋转用 `matrix = matrix.map(...)` 重新赋值，外部持有的原数组并没变（非原地）。

## 11. 排序算法对比（快排 / 归并 / 堆排）

**题目：** 手写快速排序、归并排序、堆排序，并从时间复杂度、空间、稳定性、适用场景四方面对比；说明 `Array.prototype.sort` 的底层实现。

**示例：**

```js
quickSort([3, 1, 4, 1, 5, 9, 2, 6]);   // [1, 1, 2, 3, 4, 5, 6, 9]
mergeSort([3, 1, 4, 1, 5, 9, 2, 6]);   // [1, 1, 2, 3, 4, 5, 6, 9]
heapSort([3, 1, 4, 1, 5, 9, 2, 6]);    // [1, 1, 2, 3, 4, 5, 6, 9]
```

**思路：**

- 快速排序：选基准（pivot），把小于基准的放左边、大于的放右边，再递归两侧。
  - 平均 O(n log n)、最坏 O(n²)：已排序数组配固定首/尾基准时每次只排除一个元素；随机化基准或「三数取中」可让期望稳定在 O(n log n)，大量重复元素用三路划分。为什么实际最快：原地、常数小、顺序访问对 CPU 缓存友好。
- 归并排序：二分到单元素，再两两合并有序段。
  - 为什么稳定且无最坏退化：划分点永远在中间；合并时相等元素优先取左段（`left[i] <= right[j]`）。代价是 O(n) 辅助数组，但对链表可 O(1) 合并，是链表排序首选。
- 堆排序：先建大顶堆，再反复「堆顶与末尾交换 + 堆大小减一 + 下沉」。
  - 建堆 O(n)、排序 O(n log n)：大部分结点靠近叶子，下沉高度小；之后 n 次取最大值，每次 O(log n)。为什么不常用：不稳定、跳跃访问缓存不友好，但空间 O(1) 且有最坏 O(n log n) 保证。

**代码：**

```js
function quickSort(nums, lo = 0, hi = nums.length - 1) {
    if (lo >= hi) return nums;
    const p = partition(nums, lo, hi);
    quickSort(nums, lo, p - 1);
    quickSort(nums, p + 1, hi);
    return nums;
}

function partition(nums, lo, hi) {
    const idx = lo + Math.floor(Math.random() * (hi - lo + 1));
    [nums[idx], nums[hi]] = [nums[hi], nums[idx]];   // 随机基准换到末尾
    const pivot = nums[hi];
    let i = lo;                                        // i 指向小于区的下一个位置
    for (let j = lo; j < hi; j++) {
        if (nums[j] < pivot) { [nums[i], nums[j]] = [nums[j], nums[i]]; i++; }   // Lomuto 划分
    }
    [nums[i], nums[hi]] = [nums[hi], nums[i]];
    return i;
}

function mergeSort(nums) {
    if (nums.length <= 1) return nums;
    const mid = Math.floor(nums.length / 2);
    const left = mergeSort(nums.slice(0, mid));
    const right = mergeSort(nums.slice(mid));
    const res = [];
    let i = 0;
    let j = 0;
    while (i < left.length && j < right.length) {
        res.push(left[i] <= right[j] ? left[i++] : right[j++]);   // 等号保证稳定
    }
    while (i < left.length) res.push(left[i++]);
    while (j < right.length) res.push(right[j++]);
    return res;
}

function heapSort(nums) {
    const n = nums.length;
    const down = (i, size) => {
        while (true) {
            let max = i;
            const l = 2 * i + 1;
            const r = l + 1;
            if (l < size && nums[l] > nums[max]) max = l;
            if (r < size && nums[r] > nums[max]) max = r;
            if (max === i) break;
            [nums[max], nums[i]] = [nums[i], nums[max]];
            i = max;
        }
    };
    for (let i = Math.floor(n / 2) - 1; i >= 0; i--) down(i, n);   // 建堆 O(n)
    for (let end = n - 1; end > 0; end--) {
        [nums[0], nums[end]] = [nums[end], nums[0]];
        down(0, end);
    }
    return nums;
}

// 三种算法输出一致
console.log(quickSort([3, 1, 4, 1, 5, 9, 2, 6]));
```

**复杂度对比：**

| 算法 | 平均 | 最坏 | 最好 | 额外空间 | 稳定 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| 快速排序 | O(n log n) | O(n²) | O(n log n) | O(log n) 递归栈 | 否 | 原地、常数最小 |
| 归并排序 | O(n log n) | O(n log n) | O(n log n) | O(n) | 是 | 链表排序可 O(1) |
| 堆排序 | O(n log n) | O(n log n) | O(n log n) | O(1) | 否 | 最坏有保证 |

**边界与坑：**

- 基准取首/尾且不做随机化：遇到已排序数组退化为 O(n²)，n = 10^5 时直接超时。
- `partition` 的 `i` 必须从 `lo` 开始（Lomuto 划分），写成 `i = lo + 1` 会把最小元素漏在错误位置。
- 归并的 `<=` 是稳定性的唯一保障；改成 `<` 后相等元素顺序反转。
- 快排递归深度最坏 O(n)，JS 可能栈溢出；堆排序建堆从 `n/2 - 1` 开始，写成 `n/2` 会漏掉一棵子树。

**面试怎么答：** 先给对比表，再各用一句话点出核心：快排「划分 + 随机基准」、归并「分治 + 合并」、堆排「建堆 + 反复取顶」。被问「为什么快排比堆排快」时答「顺序访问的缓存局部性 + 常数小」，被问「为什么归并适合链表」时答「链表合并只需改指针，不需要额外数组」；补充一句 V8 的 `Array.prototype.sort` 是 TimSort（稳定、最坏 O(n log n)、小数组退化为插入排序）。

**易错点：**

- 把快排的「不稳定」说成稳定（划分时会交换远距离元素）。
- 认为堆排序的最好情况是 O(n)——建堆 O(n) 只是其中一步，整体仍是 O(n log n)。

## 12. TopK 与第 K 大元素

**题目：** 求数组中第 K 大的元素，或返回前 K 大的元素（K 远小于 n，数据可能流式到达）。

**示例：**

```js
findKthLargest([3, 2, 1, 5, 6, 4], 2);    // 5
topKLargest([3, 2, 1, 5, 6, 4], 2);       // [6, 5]
```

**思路：**

- 全排序：`sort` 后取第 `n - k` 个，O(n log n)。最简单，K 接近 n 时也最合适。
- 小顶堆（推荐流式）：维护大小为 K 的小顶堆，堆顶是「当前 K 大中的最小值」即淘汰线；每个元素最多一次 O(log k) 的替换，空间 O(k)，适合海量数据与流式输入。
- 快速选择（quickselect）：复用快排的 `partition`，只处理包含目标下标的那一侧。
  - 为什么平均 O(n)：每次划分期望排除一半元素，总代价 n + n/2 + n/4 + … 收敛到 2n；最坏 O(n²)，随机化基准后概率极低，也可用「中位数的中位数」做到最坏 O(n)。
  - 为什么比堆快：原地、常数小，但会修改数组且最坏无保证。
- 计数 / 桶排序：数值范围有限（如年龄、分数）时 O(n + range)；工程选择上，一次性离线用 quickselect，流式或内存受限用小顶堆。

**代码：**

```js
function findKthLargest(nums, k) {
    const a = nums.slice();
    const target = a.length - k;         // 升序下的目标下标
    let lo = 0;
    let hi = a.length - 1;
    while (lo <= hi) {
        const p = partition(a, lo, hi);
        if (p === target) return a[p];
        if (p < target) lo = p + 1;          // 只处理右半段
        else hi = p - 1;
    }
    return -1;
}

function partition(a, lo, hi) {
    const idx = lo + Math.floor(Math.random() * (hi - lo + 1));
    [a[idx], a[hi]] = [a[hi], a[idx]];
    const pivot = a[hi];
    let i = lo;
    for (let j = lo; j < hi; j++) {
        if (a[j] < pivot) {
            [a[i], a[j]] = [a[j], a[i]];
            i++;
        }
    }
    [a[i], a[hi]] = [a[hi], a[i]];
    return i;
}

function topKLargest(nums, k) {
    const heap = [];                       // 小顶堆，堆顶是当前 K 大的最小值
    for (const x of nums) {
        heap.push(x);
        let i = heap.length - 1;
        while (i > 0) {                    // 上浮
            const p = (i - 1) >> 1;
            if (heap[p] <= heap[i]) break;
            [heap[p], heap[i]] = [heap[i], heap[p]];
            i = p;
        }
        if (heap.length > k) {
            heap[0] = heap.pop();          // 末尾元素覆盖堆顶，淘汰最小值
            let j = 0;
            while (true) {                 // 下沉
                let m = j;
                const l = 2 * j + 1;
                const r = l + 1;
                if (l < heap.length && heap[l] < heap[m]) m = l;
                if (r < heap.length && heap[r] < heap[m]) m = r;
                if (m === j) break;
                [heap[m], heap[j]] = [heap[j], heap[m]];
                j = m;
            }
        }
    }
    return heap.slice().sort((x, y) => y - x);
}

// 验证
console.log(findKthLargest([3, 2, 1, 5, 6, 4], 2));              // 5
console.log(topKLargest([3, 2, 1, 5, 6, 4], 2));                // [6, 5]
```

**复杂度：**

| 方案 | 时间 | 空间 | 适用 |
| --- | --- | --- | --- |
| 全排序 | O(n log n) | O(1) / O(n) | K 接近 n，代码最短 |
| 小顶堆 | O(n log k) | O(k) | 流式、海量数据 |
| 快速选择 | 平均 O(n)、最坏 O(n²) | O(1) | 一次性、可改数组 |

**边界与坑：**

- `target = n - k` 是「第 K 大」在升序数组中的下标；写成 `k - 1` 求的是第 K 小。
- quickselect 的 `while (lo <= hi)` 配 `hi = p - 1`，区间必然收缩；但 `p` 命中后要立即返回，否则会继续循环。
- 大量重复元素时 Lomuto 划分退化（等于 pivot 的元素全堆在一侧），可用三路划分或随机化缓解，但最坏仍 O(n²)。
- 返回「前 K 大」时堆内顺序不是有序的，需要额外排序，这一步是 O(k log k)。

**面试怎么答：** 先给三条路线并说明取舍：`sort` 最省事、堆适合流式、quickselect 平均最优。重点讲「为什么用小顶堆而不是大顶堆」——小顶堆的堆顶是淘汰线。再补一句「如果 K = n/2 且要求最坏 O(n)，用中位数的中位数」，展示知识深度。

**易错点：**

- 堆方案用大顶堆，最后还得把堆里 K 个元素排序才知道第 K 大，逻辑变复杂。
- `findKthLargest` 直接在原数组上划分，调用方后续还要用原数组时数据已被打乱。
