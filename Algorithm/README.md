# 算法与数据结构面试题

> 本目录收录算法与数据结构方向的高频面试题及参考答案，共 5 册 60 题。内容按题型拆分，代码以 JavaScript 为主，重点题补充 Python 或伪代码，默认以「面试手写 + 复杂度分析」为标准，而不是工程源码级别。

> 本专题与「[手写题进阶](../手写题进阶/README.md)」的区别：这里练的是**算法思维与复杂度**——如何从题目特征识别题型、选择数据结构、推导时间与空间上界、处理边界；手写题进阶练的是**工程手写**——`EventEmitter`、`compose`、`memoize`、`Promise` 等 API 的完整实现，关注 API 设计、异常隔离、内存泄漏与框架集成。两者有重叠（如 LRU），但本专题讲淘汰策略与 O(1) 的实现原理，手写题进阶讲完整类结构、`Map` 细节与可测试性。

## 核心速查表

**常见数据结构操作复杂度**

| 数据结构 | 访问 | 查找 | 插入 | 删除 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 数组 | O(1) | O(n) | O(n) | O(n) | 尾部 `push`/`pop` 均摊 O(1)，中间插入要搬移 |
| 链表 | O(n) | O(n) | O(1) | O(1) | 前提是已持有前驱或节点引用 |
| 栈 / 队列 | O(1) 取顶 | O(n) | O(1) | O(1) | JS 数组 `shift` 是 O(n)，队列要用头指针 |
| 哈希表 | 平均 O(1) | 平均 O(1) | 平均 O(1) | 平均 O(1) | 最坏 O(n)，扩容有均摊成本 |
| 二叉搜索树 | O(log n) | O(log n) | O(log n) | O(log n) | 仅平衡时成立，退化成链是 O(n) |
| 堆 | O(1) 取顶 | O(n) | O(log n) | O(log n) | 建堆 O(n)，取 TopK 用大小为 K 的堆 |
| 跳表 / 有序集合 | O(log n) | O(log n) | O(log n) | O(log n) | Redis ZSET 的底层结构 |
| Trie | O(L) | O(L) | O(L) | O(L) | L 为字符串长度，适合前缀查询 |
| 并查集 | — | 近似 O(1) | 近似 O(1) | — | 路径压缩 + 按秩合并，空间 O(n) |

**刷题模板（二分 / 滑动窗口 / DFS / DP）**

```js
// 1. 二分：左闭右开，返回第一个 >= target 的下标
function lowerBound(nums, target) {
    let left = 0;
    let right = nums.length;
    while (left < right) {
        const mid = (left + right) >> 1;
        if (nums[mid] < target) left = mid + 1;
        else right = mid;
    }
    return left;
}

// 2. 滑动窗口：最长无重复子串
function longestUnique(s) {
    const last = new Map();
    let left = 0;
    let best = 0;
    for (let right = 0; right < s.length; right++) {
        if (last.has(s[right]) && last.get(s[right]) >= left) {
            left = last.get(s[right]) + 1;
        }
        last.set(s[right], right);
        best = Math.max(best, right - left + 1);
    }
    return best;
}

// 3. DFS：图遍历，递归前先标记 visited
function dfs(node, visited) {
    if (!node || visited.has(node)) return;
    visited.add(node);
    for (const next of node.neighbors || []) {
        dfs(next, visited);
    }
}

// 4. DP：01 背包，一维滚动数组，容量倒序
function knapsack(weights, values, capacity) {
    const dp = new Array(capacity + 1).fill(0);
    for (let i = 0; i < weights.length; i++) {
        for (let c = capacity; c >= weights[i]; c--) {
            dp[c] = Math.max(dp[c], dp[c - weights[i]] + values[i]);
        }
    }
    return dp[capacity];
}
```

> 模板只能解决「结构相似」的题，真正要练的是：先判断题型，再决定用哪个模板，最后用边界用例验证。DFS 深度可能超过调用栈上限时，改写成显式栈的迭代版本。

## 易错点清单

```
1. 二分边界混乱：左闭右开与闭区间混用，mid 不前进导致死循环
2. 滑动窗口收缩条件写反，或移动 left 时忘记同步更新计数
3. 递归 DFS 忘记标记 visited，有环图会无限递归直至栈溢出
4. DP 数组长度多开或少开一位，dp[0] / dp[1] 的初始化与题意不符
5. 01 背包内层容量正序遍历，退化成完全背包，物品被重复使用
6. 链表操作不先保存 next，断链后找不到后继节点
7. 快慢指针起点或步长不一致，环形入口与中点计算错误
8. sort 不传比较器时按字符串字典序排序，[10, 2, 1] 会排成 [1, 10, 2]
9. 在滑动窗口或队列里频繁 shift / splice，单次 O(n) 导致整体 O(n^2)
10. 位运算会把操作数截断为 32 位有符号整数，超过 2^31 要用 BigInt
11. Math.random 区间公式漏掉 +1，最大值永远取不到；安全场景不能用它
12. 用普通对象存动态 key，__proto__ / constructor 会命中原型链，应使用 Map
13. 只分析时间忽略空间，递归栈深度与哈希表容量都要计入
14. 拓扑排序不检测环，最终输出节点数小于总数时应判定无解
15. 并查集只实现 find 不做路径压缩，反复查询会退化到 O(n)
16. 设计题只关注功能，不说明容量上限、并发更新与持久化，追问时容易失分
```
