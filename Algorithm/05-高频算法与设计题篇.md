## 1. 大数据量去重与 BitMap

**题目：** 给定 40 亿个无符号 32 位整数（值域 0 ~ 2^32 - 1），在 1 GB 内存内完成去重、判断某个数是否存在，并尽可能按升序输出。

**思路与方案对比：**

| 方案 | 时间 | 空间 | 主要问题 |
| --- | --- | --- | --- |
| `HashSet` 全量存储 | O(n) | 每元素几十字节，40 亿个远超 1 GB | 内存爆炸 |
| 外部排序后去重 | O(n log n) | 磁盘为主 | 受磁盘带宽限制，实现复杂 |
| 分片哈希到小文件 | O(n) | 单文件可内存处理 | 需要多轮磁盘读写 |
| BitMap 位图 | O(n) | 值域 bit 数，2^32 bit = 512 MB | 只适合整数，且值域不能过大 |
| 布隆过滤器 | O(k) | 位图的 1/3 ~ 1/2 | 有假阳性，不能精确去重 |

**关键计算：** 2^32 个状态，每个状态 1 bit，共 2^32 bit = 2^29 字节 = 512 MB，装进 1 GB 内存可行。若值域只有 1 亿，则约 12.5 MB。若值域更大（如 64 位整数），位图不可行，应改用分片或布隆过滤器。

**代码：** 用 `Uint32Array` 按 32 位一个字存放，`value >>> 5` 求字下标，`value & 31` 求位下标。

```js
class BitMap {
    constructor(maxValue) {
        this.size = maxValue + 1;
        this.words = new Uint32Array(Math.ceil(this.size / 32));
    }

    add(value) {
        if (!this.#inRange(value)) return false;
        const index = value >>> 5;
        const offset = value & 31;
        this.words[index] |= 1 << offset;
        return true;
    }

    has(value) {
        if (!this.#inRange(value)) return false;
        const index = value >>> 5;
        const offset = value & 31;
        return (this.words[index] & (1 << offset)) !== 0;
    }

    remove(value) {
        if (!this.#inRange(value)) return false;
        const index = value >>> 5;
        const offset = value & 31;
        this.words[index] &= ~(1 << offset);
        return true;
    }

    #inRange(value) {
        return Number.isInteger(value) && value >= 0 && value < this.size;
    }

    *values() {
        for (let i = 0; i < this.words.length; i++) {
            let word = this.words[i];
            while (word !== 0) {
                const low = word & -word;
                const bit = 31 - Math.clz32(low);
                yield i * 32 + bit;
                word ^= low;
            }
        }
    }
}

function dedupeByBitMap(numbers, maxValue) {
    const map = new BitMap(maxValue);
    for (const value of numbers) map.add(value);
    return [...map.values()];
}

console.log(dedupeByBitMap([5, 1, 9, 5, 7, 1, 3], 9));
// [1, 3, 5, 7, 9]，天然升序
```

**复杂度：**

- 建图与查询：时间 O(1) 每次操作，整体 O(n)；空间 O(U / 8) 字节，U 为值域大小。
- 遍历输出按字、按低位到高位扫描，天然升序，时间 O(U / 32 + 输出个数)。
- 40 亿个数、值域 2^32 时，位图约 512 MB，仍满足 1 GB 限制。

**边界与坑：**

- 泛化到 64 位值域需要 2^64 bit（约 2 EB），必须分片、外部排序或改用布隆过滤器。
- 负数、浮点数不能直接做下标，需要先映射：负数加偏移、浮点转定点或先哈希。
- JS 位运算按 32 位有符号整数处理，`1 << 31` 是负数，但用 `Uint32Array` 存字、用 `!== 0` 判断位是安全的。
- 值域上限包含端点时长度要 `maxValue + 1`，否则最大值越界。
- 位图无法直接表达「出现过几次」，需要计数就用 `Uint8Array` / `Uint16Array` 计数数组，空间放大 8~16 倍。

**面试怎么答：** 先反问值域和内存上限，再算「值域 bit 数 / 8」判断位图是否放得下；放得下就写位图并强调 `value >>> 5` 与 `value & 31`；放不下就给出分片哈希或布隆过滤器的降级方案，并说明精确性与空间的取舍。

**易错点：**

- 用 `Math.floor(value / 32)` 而不是 `value >>> 5`，虽然结果一致，但位运算更直观，且要说明 32 位限制。
- 用普通数组存 bit，每个元素一个 JS Number，空间反而比原数据还大。
- 忘记 `maxValue + 1`，导致边界值静默丢失。
- 以为位图能处理任意整数，忽略值域爆炸。
- `values()` 里用 `word & -word` 求 lowbit 后忘记清位，造成死循环。

## 2. 布隆过滤器的实现

**题目：** 实现布隆过滤器，支持 `add` 与 `has`；给定预期元素数 n 和可接受误判率 p，自动计算位数组长度 m 与哈希函数个数 k；说明为什么标准布隆过滤器不能删除元素。

**思路与方案对比：**

| 方案 | 查询 | 空间 | 特点 |
| --- | --- | --- | --- |
| 哈希表 | O(1) 精确 | 存完整 key | 内存大 |
| 排序数组 + 二分 | O(log n) 精确 | 存完整 key | 不支持高频插入 |
| 位图 | O(1) 精确 | 值域决定 | 值域受限，字符串不可用 |
| 布隆过滤器 | O(k) | 约每元素 1~2 字节 | 省内存，有假阳性，无假阴性 |
| 计数布隆过滤器 | O(k) | 约 4 倍标准版 | 支持删除，计数器溢出仍有风险 |
| Cuckoo Filter | O(1) 均摊 | 与布隆接近 | 支持删除，误判率可控 |

**参数公式：**

- 位数组长度：`m = -n * ln(p) / (ln2)^2`
- 哈希个数：`k = (m / n) * ln2 ≈ 0.693 * m / n`
- 实际误判率：`p ≈ (1 - e^(-kn/m))^k`

**代码：** 用双重哈希 `h1 + i * h2` 生成 k 个位置，避免写 k 个独立哈希函数。

```js
class BloomFilter {
    constructor(expected, falsePositiveRate = 0.01) {
        this.n = expected;
        this.p = falsePositiveRate;
        this.m = Math.ceil(-(expected * Math.log(falsePositiveRate)) / (Math.LN2 ** 2));
        this.k = Math.max(1, Math.round((this.m / expected) * Math.LN2));
        this.bits = new Uint32Array(Math.ceil(this.m / 32));
    }

    #hash(text, seed) {
        let h = seed >>> 0;
        for (let i = 0; i < text.length; i++) {
            h ^= text.charCodeAt(i);
            h = Math.imul(h, 16777619) >>> 0;
        }
        h ^= h >>> 13;
        h = Math.imul(h, 0x5bd1e995) >>> 0;
        return (h ^ (h >>> 15)) >>> 0;
    }

    #positions(key) {
        const text = String(key);
        const h1 = this.#hash(text, 0x811c9dc5);
        const h2 = this.#hash(text, 0x9e3779b9) | 1; // 保证为奇数，避免步长为 0
        const positions = new Array(this.k);
        for (let i = 0; i < this.k; i++) {
            positions[i] = ((h1 + i * h2) >>> 0) % this.m;
        }
        return positions;
    }

    add(key) {
        for (const pos of this.#positions(key)) {
            const index = pos >>> 5;
            const offset = pos & 31;
            this.bits[index] |= 1 << offset;
        }
    }

    has(key) {
        for (const pos of this.#positions(key)) {
            const index = pos >>> 5;
            const offset = pos & 31;
            if ((this.bits[index] & (1 << offset)) === 0) return false;
        }
        return true;
    }
}

const filter = new BloomFilter(1000, 0.01);
for (let i = 0; i < 1000; i++) filter.add(`user-${i}`);

let falsePositive = 0;
for (let i = 0; i < 10000; i++) {
    if (filter.has(`nobody-${i}`)) falsePositive++;
}
console.log(`m=${filter.m}, k=${filter.k}, 误判=${falsePositive}/10000`);
// 误判率应接近设计值 1%
```

**复杂度：**

- `add` / `has`：O(k)，k 通常 3~10，可视为 O(1)。
- 空间：O(m) bit，与元素长度无关，这是相对哈希表的核心优势。
- 误判率随插入量增长：超过设计容量 n 后误判率迅速上升。

**边界与坑：**

- 标准布隆不能删除：一个 bit 可能被多个元素共享，清位会制造假阴性。需要删除就用计数布隆或 Cuckoo Filter。
- 容量必须预估准确，n 估小会导致误判率远超设计值；可考虑可扩容布隆（分层多个过滤器）。
- 哈希函数必须均匀且相互独立，双重哈希要求 h2 与 m 互质，否则位置覆盖不全。
- 布隆过滤器只能回答「可能存在 / 一定不存在」，不能返回元素本身。
- 位翻转（持久化损坏）同样会产生假阴性，不能当作绝对可靠的存储。

**面试怎么答：** 先写公式解释 m 与 k 的推导，再写双重哈希实现，最后主动说「布隆只挡不存在，缓存穿透场景放在 DB 前」「删除要用计数布隆或 Cuckoo」。这三句基本覆盖追问。

**易错点：**

- 用 `String(key)` 后忘记处理哈希碰撞，误以为布隆可以精确判断。
- `k` 取固定值 3，而不是按 m/n 计算。
- 位数组用普通数组或 `Array` 存，内存远大于预期。
- 把 `has` 返回 true 当成「一定存在」。
- 忘记说明位数组大小是 bit，计算内存时少乘 / 8 或多乘。

## 3. 位运算技巧

**题目：** 总结面试高频位运算：判断 2 的幂、统计 1 的个数、取最低位 1、找出只出现一次的数、不用加减乘除做加法、枚举子集；并说明 JS 位运算的 32 位陷阱。

**思路与方案对比：**

| 需求 | 位运算写法 | 等价朴素写法 | 复杂度 |
| --- | --- | --- | --- |
| 判断奇偶 | `n & 1` | `n % 2` | O(1) |
| 乘 2 / 除 2 | `n << 1` / `n >> 1` | `n * 2` / `Math.floor(n / 2)` | O(1) |
| 判断 2 的幂 | `n & (n - 1)` | 反复除 2 | O(1) vs O(log n) |
| 最低位 1 | `n & -n` | 循环取模 | O(1) |
| 1 的个数 | `n &= n - 1` | 逐位检查 | O(popcount) |
| 只出现一次 | 全部异或 | 哈希计数 | O(1) 空间 |
| 枚举子集 | 二进制掩码 | 递归回溯 | O(2^n) |

**代码：**

```js
function countBits(n) {
    let count = 0;
    while (n !== 0) {
        n &= n - 1; // 每次消掉最低位的 1
        count++;
    }
    return count;
}

function isPowerOfTwo(n) {
    return n > 0 && (n & (n - 1)) === 0;
}

function lowestBit(n) {
    return n & -n;
}

function singleNumber(nums) {
    return nums.reduce((acc, value) => acc ^ value, 0);
}

function addWithoutPlus(a, b) {
    while (b !== 0) {
        const carry = (a & b) << 1; // 进位
        a = a ^ b;                  // 无进位和
        b = carry;
    }
    return a;
}

function subsets(nums) {
    const result = [];
    const total = 1 << nums.length;
    for (let mask = 0; mask < total; mask++) {
        const subset = [];
        for (let i = 0; i < nums.length; i++) {
            if (mask & (1 << i)) subset.push(nums[i]);
        }
        result.push(subset);
    }
    return result;
}

function swap(a, b) {
    a ^= b;
    b ^= a;
    a ^= b;
    return [a, b];
}

console.log(countBits(0b1011011));       // 5
console.log(isPowerOfTwo(1024));         // true
console.log(lowestBit(12));              // 4
console.log(singleNumber([4, 1, 2, 1, 2])); // 4
console.log(addWithoutPlus(13, 9));      // 22
console.log(swap(3, 8));                 // [8, 3]
```

**复杂度：**

- `countBits` / `addWithoutPlus`：O(1) 次迭代上界为位数（32 位），可视为 O(1)。
- `singleNumber`：O(n) 时间、O(1) 空间。
- `subsets`：O(n * 2^n) 时间、O(n * 2^n) 输出空间。

**边界与坑：**

- JS 的 `&`、`|`、`^`、`<<`、`>>` 都会先把操作数转成 32 位有符号整数，超过 2^31 - 1 的值会失真；处理大整数要用 `BigInt` 或 `Math`。
- `1 << 31` 是 `-2147483648`，需要无符号结果时用 `>>> 0`。
- `>>` 是算术右移，负数会保留符号；`>>>` 是无符号右移。对负数做 `n >> 1` 与 `n / 2` 的结果不同。
- 判断 2 的幂必须限定 `n > 0`，否则 0 会被误判。
- 异或找单数的前提是「其余元素都出现偶数次」，出现三次就不适用（需要按位取模）。
- `addWithoutPlus` 对负数在 JS 中虽然多数情况能算出结果，但超过 32 位仍会溢出，面试中应说明前提。

**面试怎么答：** 不要逐个背技巧，先讲三个母题：`n & (n - 1)` 消 1、`n & -n` 取 lowbit、异或消对。其余技巧都是这三个的变形；最后补一句 JS 位运算只有 32 位，BigInt 场景要单独处理。

**易错点：**

- 用 `n & (n - 1)` 统计 1 的个数时写成 `n & (n + 1)`。
- 判断 2 的幂漏掉 `n > 0`。
- 把 `n >>> 1` 与 `Math.floor(n / 2)` 混用，负数结果不一致。
- 子集枚举里 `1 << n` 在 n ≥ 31 时溢出。
- 交换两个数时其中一个为 0 或两数相同，异或交换会得到 0（面试中建议直接用临时变量）。

## 4. 随机数与蓄水池抽样

**题目：** 数据流长度 N 未知且只能遍历一次，如何等概率抽取 k 个样本？给出算法、正确性证明，并说明 `Math.random()` 的常见误用。

**思路与方案对比：**

| 方案 | 时间 | 空间 | 问题 |
| --- | --- | --- | --- |
| 全部读入后洗牌取前 k | O(N) | O(N) | 流式场景不可行 |
| 随机排序键取前 k | O(N log N) | O(N) | 排序开销大 |
| 蓄水池抽样 | O(N) | O(k) | 单遍、等概率，推荐 |
| 加权蓄水池（A-Res） | O(N) | O(k) | 元素带权重时使用 |

**代码：**

```js
function reservoirSample(iterable, k) {
    if (k <= 0) return [];
    const reservoir = [];
    let seen = 0;
    for (const item of iterable) {
        seen++;
        if (seen <= k) {
            reservoir.push(item);
            continue;
        }
        // 第 seen 个元素以 k / seen 的概率留下
        const j = Math.floor(Math.random() * seen);
        if (j < k) reservoir[j] = item;
    }
    return reservoir;
}

// 加权版本：A-Res，按 key = random^(1/w) 保留 key 最大的 k 个
function weightedReservoirSample(items, weights, k) {
    const heap = [];
    for (let i = 0; i < items.length; i++) {
        const key = Math.random() ** (1 / weights[i]);
        if (heap.length < k) {
            heap.push({ key, item: items[i] });
            heap.sort((a, b) => a.key - b.key);
        } else if (key > heap[0].key) {
            heap[0] = { key, item: items[i] };
            heap.sort((a, b) => a.key - b.key);
        }
    }
    return heap.map((entry) => entry.item);
}

// 闭区间随机整数：注意是 max - min + 1
function randomInt(min, max) {
    return Math.floor(Math.random() * (max - min + 1)) + min;
}

// 验证：每个元素被抽中的概率应接近 k / N
const N = 100;
const K = 10;
const hit = new Array(N).fill(0);
for (let round = 0; round < 20000; round++) {
    const picked = reservoirSample(Array.from({ length: N }, (_, i) => i), K);
    for (const value of picked) hit[value]++;
}
console.log('最小/最大命中率', Math.min(...hit) / 20000, Math.max(...hit) / 20000);
// 均应在 0.1 附近
```

**正确性证明（核心一句话）：** 第 i 个元素进入蓄水池的概率是 k/i；对之后每个 j > i，它被替换的概率是 1/j，连乘 `k/i * ∏(1 - 1/j) = k/N`。因此每个元素最终留下的概率相同。

**复杂度：**

- 时间 O(N)，每个元素一次随机数与常数次比较。
- 空间 O(k)，只保存候选样本。
- 加权版本若用堆维护 Top K，时间 O(N log k)；上面的 `sort` 写法是 O(N * k log k)，仅用于演示。

**边界与坑：**

- k 大于流长度时返回全部元素，不要报错。
- k = 0 直接返回空数组，`Math.random() * 0` 会得到 NaN 下标。
- `Math.random()` 返回 [0, 1)，永远不会等于 1；区间公式必须是 `max - min + 1`，否则最大值永远取不到。
- `Math.random()` 不是密码学安全随机源，验证码、令牌要用 `crypto.randomInt` / `crypto.randomUUID`。
- 大范围整数直接乘会有精度问题，超过 2^53 要用 BigInt 或重新设计。
- 加权为 0 时 `1/0` 得到 Infinity，`random ** Infinity` 为 0，语义上等价于永不选中，但要显式过滤。
- 流不可重放，抽样必须在一次遍历内完成；分布式场景需要在各分片先抽样再合并，并保留每个元素被抽中的概率。

**面试怎么答：** 先写「前 k 个直接进池，之后第 i 个以 k/i 概率替换池中随机一个」，再补证明和 k > N、k = 0 的边界；最后提 `Math.random` 的区间偏差与非密码学安全。

**易错点：**

- 替换概率写成 `k / (seen + 1)` 或 `1 / seen`，分布不正确。
- 用 `Math.round(Math.random() * max)`，两端概率只有中间的一半。
- 忘记 `seen` 计数器，用 `reservoir.length` 当总数，池满后概率就固定成 k/k。
- 认为「随机数够随机就一定均匀」，忽略取整偏差。
- 加权抽样直接用权重做前缀和后随机，虽然正确但每次 O(n)，不是流式算法。

## 5. 洗牌算法与加权随机

**题目：** 实现数组随机打乱，保证每种排列等概率；再实现按权重随机选择（如广告投放、抽奖），说明常见错误写法。

**思路与方案对比：**

| 方案 | 时间 | 正确性 | 备注 |
| --- | --- | --- | --- |
| `sort(() => Math.random() - 0.5)` | O(n log n) | 分布有偏 | 比较器不满足传递性，禁止使用 |
| 每次随机 `splice` 取出 | O(n^2) | 正确 | 实现简单，数据量大时慢 |
| Fisher-Yates 原地洗牌 | O(n) | 每种排列 1/n! | 标准答案 |
| 只洗前 k 个（部分洗牌） | O(k) | 前 k 个等概率 | 抽样场景更快 |
| 前缀和 + 二分 | O(log n) 每次 | 正确 | 预处理 O(n) |
| Alias Method 别名法 | O(1) 每次 | 正确 | 预处理 O(n)，实现较复杂 |

**代码：**

```js
function shuffle(array) {
    for (let i = array.length - 1; i > 0; i--) {
        const j = Math.floor(Math.random() * (i + 1));
        [array[i], array[j]] = [array[j], array[i]];
    }
    return array;
}

// 只保证前 k 个是等概率样本，其余顺序不保证
function partialShuffle(array, k) {
    const n = array.length;
    const limit = Math.min(k, n);
    for (let i = 0; i < limit; i++) {
        const j = i + Math.floor(Math.random() * (n - i));
        [array[i], array[j]] = [array[j], array[i]];
    }
    return array.slice(0, limit);
}

class WeightedRandom {
    constructor(weights) {
        this.prefix = new Float64Array(weights.length);
        let sum = 0;
        for (let i = 0; i < weights.length; i++) {
            if (weights[i] < 0) throw new RangeError('权重不能为负');
            sum += weights[i];
            this.prefix[i] = sum;
        }
        if (sum <= 0) throw new RangeError('权重总和必须大于 0');
        this.total = sum;
    }

    pick() {
        const target = Math.random() * this.total;
        let low = 0;
        let high = this.prefix.length - 1;
        while (low < high) {
            const mid = (low + high) >> 1;
            if (this.prefix[mid] < target) low = mid + 1;
            else high = mid;
        }
        return low;
    }
}

// 洗牌分布验证：3 个元素共 6 种排列，次数应接近
const counts = new Map();
for (let round = 0; round < 60000; round++) {
    const key = shuffle([0, 1, 2]).join('');
    counts.set(key, (counts.get(key) || 0) + 1);
}
console.log('排列分布', [...counts.entries()]);

const lottery = new WeightedRandom([1, 2, 7]);
const picks = [0, 0, 0];
for (let round = 0; round < 100000; round++) picks[lottery.pick()]++;
console.log('权重 1:2:7 =>', picks.map((n) => (n / 100000).toFixed(3)));
```

**复杂度：**

- 完整洗牌：时间 O(n)，空间 O(1)（原地）。
- 部分洗牌：时间 O(k)。
- 权重选择：预处理 O(n)，每次查询 O(log n)；Alias Method 预处理 O(n)、查询 O(1)。

**边界与坑：**

- `sort(() => Math.random() - 0.5)` 在 V8 中对短数组使用插入排序、长数组使用归并/Timsort，随机比较器不满足一致性，结果分布明显有偏，且不同引擎结果不同。
- Fisher-Yates 必须从后往前、`j` 落在 `[0, i]`；写成 `[0, n-1]` 会破坏等概率性。
- 权重为 0 的元素永远不应被选中，前缀和相等时二分要选到正确区间。
- 浮点权重累加可能有误差，权重是整数时应尽量用整数运算或按比例放大。
- Alias Method 在权重动态变化时需要重建表，不适合频繁更新的场景。
- 部分洗牌后数组已被修改，如果调用方还需要原数组，要先拷贝。

**面试怎么答：** 先写 Fisher-Yates，说明「第 i 位与 [0, i] 中随机一个交换，保证每个元素落到每个位置的概率都是 1/n」；再对比错误写法；加权随机先讲前缀和 + 二分，追问极致性能时提 Alias Method。

**易错点：**

- 用 `sort` 随机比较器，误以为「随机排序就是洗牌」。
- 洗牌循环写成 `j = Math.floor(Math.random() * n)`，可能与已处理位置重复交换，分布有偏。
- 加权随机每次从权重数组里做线性扫描，O(n) 查询。
- 归一化权重时除以总和却忘记处理总和为 0。
- 抽奖场景用 `Math.random()` 做安全相关决策，可被预测。

## 6. 设计短链与类 Twitter 系统

**题目：** 设计一个短链服务（长链接转短码、短码跳转），并设计类 Twitter 的发推与首页时间线；说明写扩散与读扩散的取舍。

**思路与方案对比（短链发号）：**

| 方案 | 冲突 | 安全性 | 说明 |
| --- | --- | --- | --- |
| 随机 6 位 Base62 | 可能冲突，需查重 | 不可枚举 | 62^6 ≈ 568 亿，量不大时够用 |
| 自增 ID + Base62 | 无冲突 | 可被顺序遍历 | 需要加盐、异或或 Feistel 混淆 |
| 号段模式（批量取 ID） | 无冲突 | 取决于混淆 | 减少数据库压力，常用 |

**Twitter 时间线：**

| 模式 | 写 | 读 | 适用 |
| --- | --- | --- | --- |
| 写扩散（推模式） | 发推时写入所有粉丝的 inbox | 直接读自己的 inbox，快 | 粉丝少的普通用户 |
| 读扩散（拉模式） | 只写自己的 outbox | 读时合并所有关注者的 outbox | 大 V、关注数多 |
| 混合 | 普通用户写扩散，大 V 走拉模式 | 读时合并 inbox 与大 V outbox | 工业界常用 |

**代码：** Base62 编解码 + 短链服务 + 多路时间线归并。

```js
const BASE62 = '0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ';

function encodeBase62(id) {
    let n = BigInt(id);
    if (n === 0n) return BASE62[0];
    let code = '';
    while (n > 0n) {
        code = BASE62[Number(n % 62n)] + code;
        n /= 62n;
    }
    return code;
}

function decodeBase62(code) {
    let n = 0n;
    for (const ch of code) {
        const digit = BASE62.indexOf(ch);
        if (digit === -1) throw new Error(`非法字符: ${ch}`);
        n = n * 62n + BigInt(digit);
    }
    return n;
}

class ShortLinkService {
    constructor() { this.links = new Map(); this.seq = 1000n; }

    create(longUrl) {
        const code = encodeBase62(++this.seq);
        this.links.set(code, { longUrl, createdAt: Date.now() });
        return code;
    }

    resolve(code) {
        const record = this.links.get(code);
        return record ? record.longUrl : null;
    }
}

function mergeTimelines(timelines, limit = 10) {
    const result = [];
    const pointers = new Array(timelines.length).fill(0);
    while (result.length < limit) {
        let best = -1;
        for (let i = 0; i < timelines.length; i++) {
            if (pointers[i] < timelines[i].length &&
                (best === -1 || timelines[i][pointers[i]].ts > timelines[best][pointers[best]].ts)) {
                best = i;
            }
        }
        if (best === -1) break;
        result.push(timelines[best][pointers[best]]);
        pointers[best]++;
    }
    return result;
}

const service = new ShortLinkService();
const code = service.create('https://example.com/a/very/long/path?q=1');
console.log(code, decodeBase62(code) === 1001n, service.resolve(code));
```

**复杂度：**

- Base62 编码/解码：O(log_62 id)，7 位短码可表示约 3.5 万亿个 ID。
- 短链创建/解析：哈希表 O(1)，实际含一次数据库/缓存访问。
- 多路归并：朴素扫描 O(limit * k)，用小顶堆可做到 O(N log k)（N 为输出条数）；若先收集全部再排序是 O(total log total)。

**边界与坑：**

- 自增 ID 直接暴露会被遍历爬取，需要加盐、异或或 Feistel 网络混淆，并配合限流。
- 短链要校验协议，只允许 http/https，防止 `javascript:` 等开放重定向与 XSS。
- 301 会被浏览器长期缓存，目标 URL 变更后用户仍跳旧地址；统计场景用 302。
- 大 V 粉丝数百万，写扩散会造成写放大与长尾延迟；inbox 通常只保留最近 N 条并做裁剪。
- 时间线分页用游标（最后一条的 ID/时间）而不是 offset，否则新推文插入会导致重复或漏读。

**面试怎么答：** 短链按「发号器 → Base62 → 存储 → 302 跳转 → 缓存/限流」五步讲；Twitter 按「发推写入 outbox → 粉丝分发 inbox → 读时归并」讲，主动指出大 V 的写扩散问题与混合方案，最后补分页游标和缓存。

**易错点：**

- 随机生成短码却不做唯一性校验。
- 认为短链只能用 301，忽略统计与可变更需求。
- 时间线用 `offset` 分页，数据插入后错位。
- 忽略删除推文、取关后的时间线清理。
- 写扩散时同步扇出，发推接口被粉丝数量拖垮。

## 7. 设计排行榜

**题目：** 设计实时排行榜：支持更新玩家分数、查询某玩家名次、获取 Top K；分数范围 0~100，玩家千万级；进一步支持日榜/周榜。

**思路与方案对比：**

| 方案 | 更新 | 查名次 | Top K | 适用 |
| --- | --- | --- | --- | --- |
| 数组全量排序 | O(1) 写入 | O(n log n) | O(n log n) | 数据量小、离线 |
| 哈希 + 查询时排序 | O(1) | O(n log n) | O(n log n) | 查询频率低 |
| 分数桶 + 桶内集合 | O(1) | O(分数范围) | O(分数范围 + K) | 分数范围小（本题） |
| 跳表 / Redis ZSET | O(log n) | O(log n) | O(log n + K) | 通用，生产首选 |
| 小顶堆维护 Top K | O(log K) | 不支持 | O(K) | 只关心 Top K |
| 分片 + 各片 Top K 归并 | O(log n) | O(log n) | O(k * 分片数) | 超大规模 |

**代码：** 分数范围小时用「桶 + 每个桶一个 Set」，更新 O(1)，名次靠累加更高分桶的人数。

```js
class Leaderboard {
    constructor(maxScore = 100) {
        this.maxScore = maxScore;
        this.buckets = Array.from({ length: maxScore + 1 }, () => new Set());
        this.scores = new Map();
    }

    update(player, score) {
        if (!Number.isInteger(score) || score < 0 || score > this.maxScore) {
            throw new RangeError(`score 必须是 0~${this.maxScore} 的整数`);
        }
        const old = this.scores.get(player);
        if (old !== undefined) this.buckets[old].delete(player);
        this.scores.set(player, score);
        this.buckets[score].add(player);
    }

    remove(player) {
        const score = this.scores.get(player);
        if (score === undefined) return false;
        this.buckets[score].delete(player);
        this.scores.delete(player);
        return true;
    }

    rank(player) {
        const score = this.scores.get(player);
        if (score === undefined) return -1;
        let higher = 0;
        for (let s = score + 1; s <= this.maxScore; s++) {
            higher += this.buckets[s].size;
        }
        return higher + 1; // 同分并列，采用竞争排名
    }

    topK(k) {
        const result = [];
        let higher = 0;
        for (let s = this.maxScore; s >= 0 && result.length < k; s--) {
            for (const player of this.buckets[s]) {
                if (result.length >= k) break;
                result.push({ player, score: s, rank: higher + 1 });
            }
            higher += this.buckets[s].size;
        }
        return result;
    }
}

const board = new Leaderboard(100);
board.update('A', 90);
board.update('B', 95);
board.update('C', 90);
console.log(board.rank('C')); // 2，A 与 C 同为 90 分并列第 2
console.log(board.topK(2));
```

**复杂度：**

- 更新/删除：O(1)。
- 查名次：O(maxScore)，本题 101 次累加，常数级。
- Top K：O(maxScore + K)。
- 若分数范围大（如 0~10^9），把桶换成跳表或 Redis ZSET，更新与查名次均 O(log n)。

**边界与坑：**

- 同分排名规则要先确认：竞争排名（1,1,3）、密集排名（1,1,2）还是按更新时间破平。
- 玩家分数下降时，必须先从未旧桶删除，再插入新桶，否则一人出现在多个桶里。
- 桶内用 Set 保证更新幂等；用数组会导致删除 O(n)。
- 日榜/周榜按时间分 key，例如 `rank:2026-11-03`、`rank:2026-W45`，设置 TTL 自动过期，跨周期用并集或定时快照。
- 千万玩家、分数范围大时，`rank` 的 O(maxScore) 不可接受，应换跳表；Redis ZSET 的 `ZREVRANK` 是 O(log n)。
- Top K 的 K 很大时，逐个从高分桶取仍是 O(K)，但输出本身就有 O(K) 成本。
- 并发更新要用原子操作或单线程 Redis，避免读改写竞态。

**面试怎么答：** 先根据分数范围选结构：范围小用桶，范围大用跳表/ZSET；再说明同分规则；最后补周期榜的 key 设计与 TTL。若面试官追问 Redis，直接说 `ZINCRBY` 更新、`ZREVRANK` 查名次、`ZREVRANGE` 取 Top K。

**易错点：**

- 更新分数时只加新桶不删旧桶。
- 用 `Array.prototype.indexOf` 在桶内删人，复杂度退化。
- 名次从 0 开始返回，和产品定义的「第几名」差 1。
- 忘记处理不存在的玩家，返回 undefined 而不是约定的 -1/null。
- 周期榜不做 TTL，历史 key 无限增长。
- 认为 Redis ZSET 的 `ZREVRANGE` 是 O(K)，实际是 O(log n + K)。

## 8. 设计限流器

**题目：** 设计限流器，支持「每秒最多 N 次」与「每分钟最多 N 次」，允许一定突发，超限返回 429；说明单机与分布式实现的差异。

**思路与方案对比：**

| 算法 | 突发 | 精度 | 空间 | 特点 |
| --- | --- | --- | --- | --- |
| 固定窗口计数 | 窗口边界可能 2N | 低 | O(1) | 最简单，临界突刺 |
| 滑动窗口日志 | 精确 | 高 | O(limit) | 每次请求存时间戳 |
| 令牌桶 | 允许，容量可配 | 高 | O(1) | 长期平均速率 = 令牌生成速率 |
| 漏桶 | 不允许，恒定流出 | 高 | O(1)（队列） | 保护下游，削峰 |

**代码：** 固定窗口、滑动窗口日志、令牌桶三个版本，时间参数可注入便于测试。

```js
class FixedWindowLimiter {
    constructor(limit, windowMs) {
        this.limit = limit;
        this.windowMs = windowMs;
        this.windowStart = -1;
        this.count = 0;
    }

    allow(now = Date.now()) {
        const start = Math.floor(now / this.windowMs) * this.windowMs;
        if (start !== this.windowStart) {
            this.windowStart = start;
            this.count = 0;
        }
        if (this.count >= this.limit) return false;
        this.count++;
        return true;
    }
}

class SlidingWindowLogLimiter {
    constructor(limit, windowMs) {
        this.limit = limit;
        this.windowMs = windowMs;
        this.log = [];
        this.head = 0;
    }

    allow(now = Date.now()) {
        const expiredBefore = now - this.windowMs;
        while (this.head < this.log.length && this.log[this.head] <= expiredBefore) {
            this.head++;
        }
        if (this.head > 1024) {
            this.log = this.log.slice(this.head);
            this.head = 0;
        }
        if (this.log.length - this.head >= this.limit) return false;
        this.log.push(now);
        return true;
    }
}

class TokenBucketLimiter {
    constructor(capacity, refillPerSecond) {
        this.capacity = capacity;
        this.refillPerSecond = refillPerSecond;
        this.tokens = capacity;
        this.last = Date.now();
    }

    allow(cost = 1, now = Date.now()) {
        const elapsed = Math.max(0, now - this.last) / 1000;
        this.tokens = Math.min(this.capacity, this.tokens + elapsed * this.refillPerSecond);
        this.last = now;
        if (this.tokens < cost) return false;
        this.tokens -= cost;
        return true;
    }
}

const base = 1_000_000;
const fixed = new FixedWindowLimiter(3, 1000);
console.log([0, 100, 200, 300, 1000].map((t) => fixed.allow(base + t))); // true true true false true

const bucket = new TokenBucketLimiter(2, 1);
console.log([0, 0, 500, 1000].map((t) => bucket.allow(1, base + t)));    // true true false true
```

**复杂度：**

- 固定窗口 / 令牌桶：时间 O(1)，空间 O(1)。
- 滑动日志：均摊 O(1)（每个时间戳最多出队一次），空间 O(limit)。
- 分布式：Redis + Lua 保证原子性，单次 O(1) 网络往返；滑动日志可用 ZSET，空间 O(limit)。

**边界与坑：**

- 固定窗口在窗口切换处可能放过 2N 个请求（最后 1 ms 打满 N 个，下一窗口开头再打满 N 个）；滑动日志则在 limit 很大时内存高。
- 多实例限流必须用共享存储或集中式网关；`INCR + EXPIRE` 不是原子操作，要用 Lua 或 `SET NX EX`。
- 时钟回拨会让令牌桶的 `elapsed` 为负，代码里用 `Math.max(0, ...)` 兜底；容量决定突发上限，速率决定长期平均。
- 返回 429 时应带 `Retry-After`，并区分「限流」与「熔断」。
- 限流维度：IP、用户、接口、租户；代理场景要取可信的 `X-Forwarded-For`，防止伪造绕过。

**面试怎么答：** 先问「要限平均速率还是限瞬时并发，是否允许突发」；允许突发选令牌桶，要求恒定速率选漏桶，追求简单选固定窗口但要指出临界问题；分布式补 Redis Lua 原子性与多维度 key。

**易错点：**

- 令牌桶每次请求都重置 `last`，但补充计算错误，导致速率漂移。
- 滑动日志清理时用 `>=` / `<` 搞反，边界请求被多算或漏算。
- 分布式用本地 Map 计数，集群扩容后总流量翻倍。
- 把限流和并发控制混为一谈，限流管 QPS，并发管同时处理数。

## 9. 设计缓存（LRU / LFU / 多级）

**题目：** 实现 O(1) 的 LRU 与 LFU 缓存；并设计「本地缓存 + Redis + DB」的多级缓存，说明一致性与穿透、击穿、雪崩的处理。

**思路与方案对比：**

| 策略 | 淘汰依据 | 适用 |
| --- | --- | --- |
| LRU | 最久未使用 | 时间局部性强，实现简单 |
| LFU | 使用频率最低 | 热点稳定，抗偶发访问 |
| 多级缓存 | 逐级回源 | L1 进程内 + L2 分布式，高并发读 |

**代码：** LRU 利用 `Map` 的插入顺序；LFU 用「频率 → 有序 Map」，桶空时维护 `minFreq`。

```js
class LRUCache {
    constructor(capacity) { this.capacity = capacity; this.map = new Map(); }

    get(key) {
        if (!this.map.has(key)) return -1;
        const value = this.map.get(key);
        this.map.delete(key);
        this.map.set(key, value); // 移到末尾表示最近使用
        return value;
    }

    put(key, value) {
        if (this.capacity <= 0) return;
        this.map.delete(key);
        this.map.set(key, value);
        if (this.map.size > this.capacity) this.map.delete(this.map.keys().next().value);
    }
}

class LFUCache {
    constructor(capacity) {
        this.capacity = capacity;
        this.entries = new Map();     // key -> { value, freq }
        this.buckets = new Map();     // freq -> Map(key, true)，同频内按插入顺序淘汰
        this.minFreq = 0;
    }

    get(key) {
        const entry = this.entries.get(key);
        if (!entry) return -1;
        this.#touch(key, entry);
        return entry.value;
    }

    put(key, value) {
        if (this.capacity <= 0) return;
        const entry = this.entries.get(key);
        if (entry) {
            entry.value = value;
            this.#touch(key, entry);
            return;
        }
        if (this.entries.size === this.capacity) {
            const bucket = this.buckets.get(this.minFreq);
            const evictKey = bucket.keys().next().value;
            bucket.delete(evictKey);
            this.entries.delete(evictKey);
            if (bucket.size === 0) this.buckets.delete(this.minFreq);
        }
        this.entries.set(key, { value, freq: 1 });
        if (!this.buckets.has(1)) this.buckets.set(1, new Map());
        this.buckets.get(1).set(key, true);
        this.minFreq = 1;
    }

    #touch(key, entry) {
        const old = this.buckets.get(entry.freq);
        old.delete(key);
        if (old.size === 0) {
            this.buckets.delete(entry.freq);
            if (this.minFreq === entry.freq) this.minFreq++;
        }
        entry.freq++;
        if (!this.buckets.has(entry.freq)) this.buckets.set(entry.freq, new Map());
        this.buckets.get(entry.freq).set(key, true);
    }
}
```

**复杂度：**

- LRU / LFU：`get` 与 `put` 均 O(1)，空间 O(capacity)，多级缓存未命中时逐级回源。

**多级缓存要点：**

- 读路径：L1（进程内）→ L2（Redis）→ DB，回填时逐级写入。
- 一致性：Cache-Aside，先更新 DB 再删除缓存；强一致可订阅 binlog，或延迟双删。
- 穿透用布隆过滤器 / 空值缓存；击穿用互斥锁或单飞；雪崩用随机 TTL + 熔断降级。

**边界与坑：**

- LRU 的 `get` 也算使用，必须调整顺序；`capacity = 0` 要单独处理。
- LFU 同频淘汰依赖桶内 LRU，频次只增不减，长期运行要做衰减。
- 双写不一致：先改缓存后改 DB、并发写、删除失败都会脏读，需重试与最终一致。

**面试怎么答：** 先手写 LRU，再写 LFU 的「频率桶 + minFreq」；多级缓存按读路径讲，主动补穿透/击穿/雪崩三个词和对应手段，最后说一致性选择最终一致。

**易错点：**

- LRU 用数组 + `indexOf`，`get` 变成 O(n)。
- LFU 只维护全局计数、不维护 `minFreq`，淘汰要扫描全部 key。
- LFU 频率增加后忘记把 key 从旧桶删除。

## 10. 设计调度器（任务调度与时间轮）

**题目：** 实现延时任务调度器：支持 `schedule(delay, task)`、取消、到点执行；对比最小堆与时间轮，并说明分布式定时任务的实现。

**思路与方案对比：**

| 方案 | 插入 | 取到期任务 | 取消 | 说明 |
| --- | --- | --- | --- | --- |
| 每秒全量扫描 | O(1) | O(n) | O(1) | 任务少时可用，任务多时 CPU 空转 |
| 最小堆 + 定时器 | O(log n) | O(log n) | O(n) 懒删除 | 单机通用，JDK `ScheduledThreadPoolExecutor` |
| 时间轮 | O(1) | O(1) 均摊 | O(1)（链表节点） | 任务多、延时固定粒度，Netty/Kafka |
| 多级时间轮 | O(1) | O(1) | O(1) | 解决长延时，层级溢出 |
| Redis ZSET | O(log n) | O(log n) | O(1) | 分布式，轮询到期 |
| 延时队列 / 定时消息 | O(log n) | O(log n) | 视实现 | RocketMQ、RabbitMQ 延迟插件 |

**代码：** 单机时间轮，按 tick 推进，槽位内保存绝对到期 tick；超过一圈的任务会在后续圈次被再次检查。

```js
class TimeWheel {
    constructor(tickMs = 10, wheelSize = 60) {
        this.tickMs = tickMs;
        this.wheelSize = wheelSize;
        this.slots = Array.from({ length: wheelSize }, () => []);
        this.tick = 0;
    }

    schedule(delayMs, task) {
        const delayTicks = Math.max(1, Math.ceil(delayMs / this.tickMs));
        const due = this.tick + delayTicks;
        this.slots[due % this.wheelSize].push({ due, task });
        return due;
    }

    advance(ticks = 1) {
        const fired = [];
        for (let i = 0; i < ticks; i++) {
            this.tick++;
            const index = this.tick % this.wheelSize;
            const slot = this.slots[index];
            const keep = [];
            for (const item of slot) {
                if (item.due <= this.tick) fired.push(item.task);
                else keep.push(item); // 还没到期的长延时任务留在槽里
            }
            this.slots[index] = keep;
        }
        for (const task of fired) task();
        return fired.length;
    }
}

const wheel = new TimeWheel(10, 8);
const order = [];
wheel.schedule(30, () => order.push('a'));
wheel.schedule(10, () => order.push('b'));
wheel.schedule(80, () => order.push('c'));
console.log(wheel.advance(8)); // 3
console.log(order);            // ['b', 'a', 'c']
```

**复杂度：**

- 时间轮：插入 O(1)，推进一个 tick O(1) 均摊（处理该槽位任务），空间 O(槽位数 + 任务数)。
- 最小堆：插入/取最小 O(log n)，取消可懒删除。
- 时间轮单圈最大延时为 `wheelSize * tickMs`，超出会多转几圈；生产上用多级轮（秒/分/时）避免长任务反复扫描。
- Redis ZSET：`ZADD` 与 `ZRANGEBYSCORE` 均 O(log n)，需轮询或配合到期通知。

**边界与坑：**

- 任务执行时间过长会阻塞 tick 推进，耗时任务应丢到线程池/异步执行。
- 时间轮基于相对 tick，系统时钟回拨不影响逻辑 tick，但用 `Date.now()` 计算绝对时间会受影响。
- 任务需要持久化（重启不丢），单机内存轮不满足，需 DB/Redis + 恢复扫描。
- 多实例部署要避免重复执行，用分布式锁或任务分片；锁要考虑超时与续期。
- 同一时刻大量任务到期会造成尖刺，可加随机抖动或分批执行。
- 取消任务要真正从槽位移除（或用取消标记懒删除），否则会泄漏内存。
- 长延时（如 7 天）用单级小轮会转很多圈，应使用多级时间轮或直接落 DB。
- `setTimeout` 不保证精确时间，只保证不早于；调度器要接受延迟并做补偿。

**面试怎么答：** 先问任务量、延时范围、是否持久化、单机还是分布式；单机大量短延时任务选时间轮并说明 O(1)，通用场景选最小堆；分布式选 Redis ZSET 或延时队列，并补重复执行、持久化、时钟与尖刺问题。

**易错点：**

- 时间轮的槽位下标用 `due` 而不是 `due % wheelSize`，数组越界。
- 只按槽位触发而不判断绝对到期时间，长延时任务提前执行。
- 任务执行放在 tick 循环里同步跑，拖慢整个轮子。
- 认为 `setTimeout(fn, 100)` 一定在 100 ms 执行。
- 分布式任务不做幂等，重试导致重复扣款/发券。
- 忘记给时间轮任务留取消入口，线上无法止损。

## 11. 面试手写题的算法化思路

**题目：** 面对「实现一个 XXX」或业务场景题，如何从需求快速推导到合适的数据结构与算法，而不是一上来就写代码？

**思路与方案对比（五步法）：**

1. **明确操作与规模**：有哪些操作（插入、查询、删除、取最值、按区间）？n 和 q 多大？值域多大？是否在线？
2. **先写暴力解**：说清时间/空间复杂度，拿到正确性基线，也向面试官暴露你的思考过程。
3. **定位瓶颈**：重复查找 → 哈希 / 二分；动态最值 → 堆 / 单调栈 / 单调队列；区间求和 → 前缀和 / 差分 / 树状数组 / 线段树；先后关系 → 栈 / 队列；连通关系 → 并查集 / 图；状态转移 → DP / 位掩码。
4. **验证结构**：用边界样例（空、单元素、重复、极值）走一遍，确认操作复杂度满足要求。
5. **再优化**：先保证正确，再替换结构；每一步都说明 trade-off，而不是直接抛最终答案。

**题型到结构的映射：**

| 题型特征 | 首选结构 | 典型题 |
| --- | --- | --- |
| 判断存在 / 计数 | 哈希表、位图 | 两数之和、去重 |
| 动态取最大/最小 | 堆、有序集合 | Top K、中位数 |
| 下一个更大/更小 | 单调栈 | 每日温度、柱状图最大矩形 |
| 连续子数组/窗口 | 滑动窗口、前缀和 | 最长无重复子串、和为 K 的子数组 |
| 区间合并/覆盖 | 排序 + 扫描线 | 合并区间、会议室 |
| 先后依赖 | 拓扑排序 | 课程表、构建顺序 |
| 连通性 | 并查集、DFS/BFS | 岛屿数量、朋友圈 |
| 最优子结构 | DP | 背包、编辑距离 |
| 设计 O(1) 操作 | 哈希 + 双向链表 | LRU、LFU、O(1) 插入删除随机取 |

**代码：** 用两个例子演示「暴力 → 最优」的推导：两数之和从双重循环到哈希，滑动窗口最大值从每次扫描到单调队列。

```js
// 暴力 O(n^2) → 哈希 O(n)
function twoSum(nums, target) {
    const seen = new Map();
    for (let i = 0; i < nums.length; i++) {
        const need = target - nums[i];
        if (seen.has(need)) return [seen.get(need), i];
        seen.set(nums[i], i);
    }
    return [];
}

// 暴力 O(n*k) → 单调队列 O(n)
function maxSlidingWindow(nums, k) {
    const deque = []; // 存下标，对应值单调递减
    const result = [];
    for (let i = 0; i < nums.length; i++) {
        while (deque.length && nums[deque[deque.length - 1]] <= nums[i]) {
            deque.pop();
        }
        deque.push(i);
        if (deque[0] <= i - k) deque.shift();
        if (i >= k - 1) result.push(nums[deque[0]]);
    }
    return result;
}

console.log(twoSum([2, 7, 11, 15], 9));        // [0, 1]
console.log(maxSlidingWindow([1, 3, -1, -3, 5, 3, 6, 7], 3));
// [3, 3, 5, 5, 6, 7]
```

**复杂度：**

- 两数之和：O(n) 时间、O(n) 空间，用空间换时间。
- 滑动窗口最大值：O(n) 时间（每个下标最多入队、出队一次），O(k) 空间。
- 方法论本身不改变复杂度，但能避免选错结构导致「写出来却超时」。

**边界与坑：**

- 不要为了炫技直接上线段树/平衡树，先确认约束；面试官更看重推导过程。
- 哈希解法要说明「重复元素」「返回下标还是返回值」「无解返回什么」。
- 单调队列的 `shift` 在 JS 数组上是 O(n)，严格 O(n) 要用头指针或链表；面试中可说明这一点。
- 滑动窗口要明确窗口何时扩张、何时收缩，以及 `k` 大于数组长度的情况。
- 设计题先问「操作频率分布」，读多写少和写多读少的结构选择完全不同。
- 写完代码先跑边界用例，再讲复杂度，顺序不要反。

**面试怎么答：** 用「约束 → 暴力 → 瓶颈 → 结构 → 边界」五步口述，让面试官看到你的推导；每换一次结构都报一次复杂度，最后主动补边界测试和可优化点。

**易错点：**

- 没问清输入规模就写 O(n^2) 解法。
- 把「哈希表万能」挂在嘴边，遇到有序性、区间查询就失效。
- 单调栈/队列里存值而不是下标，无法处理过期和重复值。
- 滑动窗口的收缩条件写错，导致窗口内不满足性质。
- 设计题只写代码不讲容量、并发、持久化。
- 过早优化，正确性还没验证就开始换数据结构。

## 12. 复杂度分析与常见陷阱

**题目：** 如何系统分析一段代码的时间与空间复杂度？JS 中哪些看似 O(1) 的操作实际上是 O(n)？递归复杂度如何快速估算？

**思路与方案对比（分析方法）：**

1. **数循环**：单层 O(n)，两层独立 O(n^2)，两层相关看内层上界；循环变量每次乘 2 是 O(log n)。
2. **递归**：画递归树，节点数 × 单节点代价；或用主定理。
3. **摊还**：单次可能 O(n)，但一串操作总代价有上界（如动态数组扩容、单调栈）。
4. **空间**：临时数组、哈希表、递归调用栈都要算；尾递归优化在 JS 中并不可靠。
5. **区分最坏/平均/均摊**：哈希表平均 O(1)、最坏 O(n)；快排平均 O(n log n)、最坏 O(n^2)。

**主定理速记：**

| 递推式 | 复杂度 | 典型 |
| --- | --- | --- |
| T(n) = 2T(n/2) + O(n) | O(n log n) | 归并排序 |
| T(n) = 2T(n/2) + O(1) | O(n) | 二叉树遍历 |
| T(n) = T(n-1) + O(1) | O(n) | 单递归链表 |
| T(n) = T(n-1) + O(n) | O(n^2) | 快排最坏 |
| T(n) = 2T(n-1) + O(1) | O(2^n) | 子集枚举 |
| T(n) = T(n/2) + O(1) | O(log n) | 二分查找 |

**JS 中容易误判的操作：**

| 操作 | 实际复杂度 | 说明 |
| --- | --- | --- |
| `arr.push` / `pop` | 均摊 O(1) | 扩容时整体搬移 |
| `arr.shift` / `unshift` | O(n) | 需要移动所有元素 |
| `arr.splice(i, 1)` | O(n) | 中间删除要搬移 |
| `arr.includes` / `indexOf` | O(n) | 线性查找 |
| `arr.sort` | O(n log n) | 比较器必须是全序 |
| `str += 'x'` | 引擎优化，理论 O(n) | 不要依赖，大量拼接用数组 join |
| `Map` / `Set` 增删查 | 平均 O(1) | 最坏 O(n) |
| 对象属性访问 | 平均 O(1) | 避免频繁增删导致退化为字典模式 |
| `JSON.parse` / `stringify` | O(数据大小) | 不是免费操作 |
| 递归深度过大 | 栈溢出 | 约一万层就可能抛错 |

**代码：** 用「计数」代替掐表，观察 n 翻倍时操作数的增长倍率。

```js
function measure(label, fn, sizes) {
    const rows = [];
    for (const n of sizes) {
        let steps = 0;
        fn(n, () => steps++);
        rows.push({ n, steps });
    }
    console.log(label, rows);
}

function linear(n, tick) {
    let sum = 0;
    for (let i = 0; i < n; i++) tick();
    return sum;
}

function quadratic(n, tick) {
    let sum = 0;
    for (let i = 0; i < n; i++) {
        for (let j = 0; j < n; j++) tick();
    }
    return sum;
}

function logarithmic(n, tick) {
    let count = 0;
    while (n > 1) {
        n = Math.floor(n / 2);
        tick();
    }
    return count;
}

measure('O(n)', linear, [1000, 2000, 4000]);
// n 翻倍，steps 翻倍
measure('O(n^2)', quadratic, [100, 200, 400]);
// n 翻倍，steps 约 4 倍
measure('O(log n)', logarithmic, [1024, 2048, 4096]);
// n 翻倍，steps 只加 1
```

**复杂度：**

- `linear`：O(n)；`quadratic`：O(n^2)；`logarithmic`：O(log n)。
- 实际工程中常数因子同样重要：同样是 O(n)，一次哈希查找可能比一次内存拷贝慢一个数量级。
- 空间复杂度要包含输入之外的辅助空间；递归栈深度 d 至少要 O(d)。

**边界与坑：**

- 只数最内层循环而忽略外层上界，容易把 O(n log n) 误判成 O(n)。
- 递归里既有循环又有递归时，不能简单相乘，要画递归树。
- 摊还 O(1) 不等于每次 O(1)：动态数组某次 push 可能 O(n)。
- 哈希表在极端碰撞下退化到 O(n)，安全场景要考虑哈希碰撞攻击。
- JS 数字是双精度浮点，超过 2^53 的整数运算不精确；大数用 BigInt。
- `sort` 不传比较器时按字符串字典序排序，`[10, 2, 1]` 会排成 `[1, 10, 2]`。
- 微基准测试受 JIT 预热、GC 影响很大，面试中优先讲复杂度而不是报毫秒数。

**面试怎么答：** 先给代码标出每层的执行次数，写出求和式，再给结论；递归题画树或用主定理；最后补一句「这是最坏/平均复杂度，空间含递归栈」——完整性往往比算得快更加分。

**易错点：**

- 把 `arr.shift()` 当成 O(1)，在滑动窗口里循环 shift 导致整体 O(n^2)。
- 认为哈希表永远 O(1)，忽略最坏情况与扩容成本。
- 递归只算时间不算栈空间。
- 把 O(n log n) 说成 O(n)，因为「只多了一层 log」。
- 忽略常数因子，用复杂度解释所有性能差异。
- 对 `sort` 的默认行为不了解，数字数组排序出错。
