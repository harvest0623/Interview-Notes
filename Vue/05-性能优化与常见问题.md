## 1. Vue 性能优化手段总览

**优化维度：**

| 维度 | 手段 |
| --- | --- |
| **减少渲染量** | `v-if`/`v-show` 合理选择、虚拟列表、分页、`v-once`、`v-memo`、组件拆分 |
| **减少计算量** | `computed` 缓存、避免模板中写复杂表达式、`shallowRef`/`markRaw` |
| **减少加载量** | 路由懒加载、异步组件、按需引入、图片/字体优化、Tree-shaking |
| **减少更新范围** | 状态就近、拆分子组件、避免不必要的响应式（浅层 API） |
| **提升响应速度** | 骨架屏、`Suspense`、预加载、防抖节流 |
| **服务端** | SSR/SSG、CDN、缓存、gzip/brotli |

**Vue 3 自带的优化（无需手动做）：**

- **编译期**：静态提升、PatchFlag、Block Tree、事件缓存。
- **运行时**：Proxy 懒代理、更优的 Diff（最长递增子序列）、更好的 Tree-shaking。

**总原则：先测量，后优化；优先解决瓶颈，避免过度优化。**

## 3. 长列表优化（虚拟列表）

**问题：** 渲染上万条 DOM 会造成创建慢、内存占用高、滚动卡顿。

**原理：** 只渲染**可视区域 + 缓冲**的项，用占位高度撑起滚动条，滚动时根据 `scrollTop` 计算渲染区间。

```vue
<script setup>
import { ref, computed } from 'vue';

const props = defineProps({
  list: { type: Array, required: true },
  itemHeight: { type: Number, default: 50 },
  height: { type: Number, default: 500 },
});

const scrollTop = ref(0);

const startIndex = computed(() => Math.floor(scrollTop.value / props.itemHeight));
const visibleCount = computed(() => Math.ceil(props.height / props.itemHeight));
const endIndex = computed(() => startIndex.value + visibleCount.value);
const visibleList = computed(() => props.list.slice(startIndex.value, endIndex.value + 1));
const offsetY = computed(() => startIndex.value * props.itemHeight);

const onScroll = (e) => { scrollTop.value = e.currentTarget.scrollTop; };
</script>

<template>
  <div class="viewport" :style="{ height: height + 'px', overflowY: 'auto' }" @scroll="onScroll">
    <!-- 撑起总高度 -->
    <div :style="{ height: list.length * itemHeight + 'px', position: 'relative' }">
      <!-- 偏移到正确位置 -->
      <div :style="{ transform: `translateY(${offsetY}px)` }">
        <div v-for="(item, i) in visibleList" :key="startIndex + i" :style="{ height: itemHeight + 'px' }">
          <slot :item="item" :index="startIndex + i" />
        </div>
      </div>
    </div>
  </div>
</template>
```

**要点与进阶：**

- **动态高度**：需测量每项高度并缓存，或用 `ResizeObserver` + 位置缓存，实现更复杂。
- **常见库**：`vue-virtual-scroller`、`@tanstack/vue-virtual`、`vue-virtual-scroll-list`。
- **滚动优化**：用 `requestAnimationFrame` 节流滚动更新；`@scroll.passive` 提升滚动性能。
- **注意**：不要用 `v-if` 频繁增删项，用 `translateY` 而非改 `top`，避免布局重排。
- **适用场景**：聊天记录、大表格、长列表、日志。

## 4. 异步组件与懒加载

**`defineAsyncComponent`：** 按需加载组件（不随首屏一起打包）。

```vue
<script setup>
import { defineAsyncComponent } from 'vue';

// 基础用法
const AsyncComp = defineAsyncComponent(() => import('./HeavyComp.vue'));

// 完整配置：加载态、错误态、超时
const AsyncComp2 = defineAsyncComponent({
  loader: () => import('./HeavyComp.vue'),
  loadingComponent: Loading,      // 加载中显示
  errorComponent: ErrorComp,      // 加载失败显示
  delay: 200,                     // 延迟显示 loading（避免闪烁）
  timeout: 3000,                  // 超时
});
</script>

<template>
  <AsyncComp />
</template>
```

**配合 `<Suspense>` 使用：**

```vue
<template>
  <Suspense>
    <template #default><AsyncComp /></template>
    <template #fallback><Loading /></template>
  </Suspense>
</template>
```

**适用场景：**

- 体积大的组件（富文本编辑器、图表、地图、视频播放器）。
- 弹窗/抽屉等**交互后才出现**的组件。
- 低频使用的功能模块。

**要点：**

- 异步组件本质是**动态 `import()`**，打包工具会拆成独立 chunk，**用到时才下载**。
- 配合**预加载**可在交互前提前请求：

```js
const loader = () => import('./HeavyComp.vue');
// 悬停时预取
onMouseEnter={() => loader()}
```

- `delay` 可避免快速加载时 loading 一闪而过。

## 5. v-once、v-memo 与函数式组件

**① `v-once`：只渲染一次，后续更新跳过该子树。**

```vue
<!-- 静态内容，永不变化 -->
<header v-once>
  <h1>{{ title }}</h1>
  <p>版本 1.0.0</p>
</header>
```

> 适用：内容确定不会变化的静态区块（页头、页脚、说明文字）。

**② `v-memo`（Vue 3.2+）：依赖不变则跳过该子树更新。**

```vue
<div v-memo="[item.id === selected]">
  <ExpensiveChild :item="item" :selected="selected" />
</div>

<!-- 只对特定依赖做记忆 -->
<li v-for="item in list" :key="item.id" v-memo="[item.id === selected]">
  {{ item.name }}
</li>
```

> 适用：`v-for` 大列表中，只有少数项会变化时；`v-memo="[]"` 等价于 `v-once`。

**③ 函数式组件：无状态、无实例，渲染开销更小。**

```vue
<script>
import { h } from 'vue';

// 函数式组件：只接收 props，无生命周期、无响应式状态
const MyButton = (props, { slots, emit }) => {
  return h('button', { class: 'btn', onClick: () => emit('click') }, slots.default?.());
};
MyButton.props = ['type'];
export default MyButton;
</script>
```

> 适用：纯展示型组件（图标、标签、简单按钮）。Vue 3 中普通组件的性能已足够好，函数式组件收益有限，**不建议滥用**。

**要点：**

- `v-once` 会**永久冻结**该部分，若内容后续需要变化则不能用。
- `v-memo` 是**条件性跳过**，比 `v-once` 更灵活。
- 优先通过**组件拆分 + `computed` 缓存**解决问题，而不是把所有模板塞进 `v-memo`。

## 6. keep-alive 的优化实践

```vue
<template>
  <keep-alive :include="cachedViews" :max="10">
    <router-view v-slot="{ Component }">
      <component :is="Component" :key="$route.fullPath" />
    </router-view>
  </keep-alive>
</template>

<script setup>
import { ref } from 'vue';
const cachedViews = ref(['Home', 'UserList']);   // 按组件 name 匹配
</script>
```

**优化要点：**

| 要点 | 说明 |
| --- | --- |
| **精确 `include`** | 只缓存必要页面，避免内存无限增长 |
| **设置 `max`** | 用 LRU 限制缓存数量，防止内存泄漏 |
| **配合路由 `meta`** | `meta: { keepAlive: true }` 动态生成 `include` |
| **`onActivated` 刷新数据** | 缓存组件不会重新 `mounted`，需在 `onActivated` 中拉取最新数据 |
| **`key` 的选择** | 用 `$route.fullPath` 可让不同参数的路由**各自缓存**；不设 key 则复用同一实例 |
| **清理大对象** | `onDeactivated` 中释放不需要的重量级数据 |

```vue
<!-- 路由 meta 控制缓存 -->
<script setup>
import { computed } from 'vue';
import { useRoute } from 'vue-router';

const route = useRoute();
const cachedViews = computed(() =>
  route.matched.filter((r) => r.meta?.keepAlive).map((r) => r.name)
);
</script>
```

**要点：**

- 组件必须**有 `name`**（`<script setup>` 中可用 `defineOptions({ name: 'Xxx' })`）才能被 `include` 匹配。
- 缓存会让**内存持续占用**，长时间不用的页面应通过 `max` 或手动移除。
- 表单页缓存可保留用户输入，但要注意数据「过期」问题。

## 7. v-if / v-show 与渲染性能

| | `v-if` | `v-show` |
| --- | --- | --- |
| 初始开销 | 假值时**更低**（不渲染） | 始终渲染 |
| 切换开销 | 高（销毁/创建） | 低（改 `display`） |
| 内存占用 | 假值时几乎为 0 | 始终占用 DOM |
| 适用 | 切换不频繁、初始多为假 | 频繁切换 |

**性能建议：**

```vue
<!-- 频繁切换（Tab、折叠面板）→ v-show -->
<el-tab-pane v-show="active === 'a'">...</el-tab-pane>

<!-- 很少显示（弹窗、错误提示）→ v-if（惰性、省内存） -->
<Modal v-if="showModal" />

<!-- 权限控制 → v-if（不渲染 DOM，更安全） -->
<AdminPanel v-if="isAdmin" />
```

**注意：**

- `v-if` 切换会触发**子组件完整生命周期**（创建/销毁），若组件很重则切换成本高 → 用 `v-show` 或 `keep-alive`。
- `v-show` 不支持 `<template>`，也不能与 `v-else` 搭配。
- 初始为假且**大多数时候都不显示**的内容，用 `v-if` 更省内存。

## 8. 响应式性能陷阱（shallowRef / markRaw）

**陷阱一：深层响应式代理大对象**

```js
// 大列表 / 大对象，深层代理开销明显
const bigList = ref(hugeArray);

// 优化：只关心整体替换时用 shallowRef
const bigList2 = shallowRef(hugeArray);
bigList2.value = newArray;    // 触发更新
```

**陷阱二：第三方实例被代理**

```js
// 错误：ECharts 实例被 Proxy 包裹，内部 this 指向错乱
const chart = ref(echarts.init(el));

// 正确：markRaw 跳过代理
const chart = markRaw(echarts.init(el));
```

**陷阱三：动态组件对象被代理**

```vue
<script setup>
import { shallowRef, markRaw } from 'vue';
import TabA from './TabA.vue';

// 错误：组件对象被深度代理，可能有性能与行为问题
const comp = ref(TabA);

// 正确
const comp2 = shallowRef(TabA);
const comp3 = markRaw(TabA);
</script>
```

**陷阱四：`computed` / `watch` 侦听过大范围**

```js
// 差：deep 遍历整个大对象
watch(bigObj, cb, { deep: true });

// 好：精确侦听某个字段
watch(() => bigObj.user.name, cb);
```

**陷阱五：模板中写复杂表达式**

```vue
<!-- 差：每次渲染都重新计算 -->
<div>{{ list.filter(i => i.active).map(i => i.name).join(',') }}</div>

<!-- 好：用 computed 缓存 -->
<div>{{ activeNames }}</div>
```

**要点：**

- 不需要深层响应式的数据一律用 **`shallowRef`/`shallowReactive`**。
- 第三方实例、DOM、组件对象用 **`markRaw`**。
- 模板中的派生逻辑放 **`computed`**，避免在模板里做大计算。

## 9. 事件、侦听器与定时器的清理

**必须清理的资源：**

| 资源 | 清理时机 |
| --- | --- |
| `setInterval` / `setTimeout` | `onBeforeUnmount` |
| `window` / `document` 事件监听 | `onBeforeUnmount` |
| 自定义事件总线订阅 | `onBeforeUnmount` |
| WebSocket / EventSource | `onBeforeUnmount` |
| `ResizeObserver` / `IntersectionObserver` | `onBeforeUnmount` |
| `watch` / `watchEffect` | 组件卸载自动停止（异步创建的需手动 `stop()`） |

```vue
<script setup>
import { onMounted, onBeforeUnmount, watch } from 'vue';

let timer = null;
let controller = null;

const onResize = () => console.log('resize');

onMounted(() => {
  timer = setInterval(() => {}, 1000);
  window.addEventListener('resize', onResize);
  controller = new AbortController();
  fetch('/api', { signal: controller.signal });
});

onBeforeUnmount(() => {
  clearInterval(timer);
  window.removeEventListener('resize', onResize);
  controller?.abort();          // 取消未完成的请求
});

// 异步创建的侦听器需手动停止
let stop = null;
setTimeout(() => {
  stop = watch(source, cb);
}, 1000);
onBeforeUnmount(() => stop?.());
</script>
```

**要点：**

- `watch`/`watchEffect` 在**同步** `setup` 中创建时会自动随组件停止；**异步**创建（`setTimeout`、`await` 后）的需手动 `stop()`。
- 未清理会导致 **内存泄漏** 与「组件已卸载却仍在更新状态」的告警。
- 用 **`AbortController`** 是取消请求的现代方案。

## 10. SSR 水合（hydration）常见问题

**什么是水合：** 服务端返回静态 HTML 后，客户端 Vue 接管并**绑定事件、建立响应式**，使页面可交互。

**常见问题：**

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| **Hydration mismatch** | 服务端与客户端首屏结构不一致 | 随机数/时间戳/浏览器 API 放 `onMounted` |
| **`window is not defined`** | 服务端没有浏览器 API | 判断环境或用 `onMounted` |
| **状态污染** | 服务端模块级单例被多请求共享 | 每次请求创建新 app 实例 |
| **内存泄漏** | 服务端跨请求残留状态 | 避免模块级可变状态 |
| **事件不生效** | 水合未完成 / 结构不匹配 | 检查 HTML 结构一致性 |

```vue
<script setup>
import { ref, onMounted } from 'vue';

// ❌ 服务端执行会报错（window 不存在）
// const width = ref(window.innerWidth);

// ✅ 只在其客户端执行
const width = ref(0);
onMounted(() => { width.value = window.innerWidth; });

// ✅ 或判断环境
if (import.meta.env.SSR) { /* 服务端逻辑 */ }
</script>
```

```vue
<template>
  <!-- ❌ 服务端与客户端时间不同 → mismatch -->
  <!-- <p>{{ new Date().toLocaleString() }}</p> -->

  <!-- ✅ 客户端挂载后再显示 -->
  <p>{{ time }}</p>
</template>
```

**要点：**

- 服务端只执行 `setup` 与**不依赖 DOM 的部分**，`onMounted` 等只在客户端执行。
- 所有「服务端无法确定」的值（时间、随机、本地存储、屏幕尺寸）都要延后到客户端。
- `useSSRContext`（Nuxt）/ `createSSRApp` 每次请求创建独立实例。
- 开发环境的水合警告要**认真对待**，它是 hydration 错误的直接信号。

## 12. 常见问题排查汇总

**① 数据变了但视图不更新**

- 原因（Vue 2）：直接改数组索引/length、给对象新增属性 → 用 `$set` / `splice`。
- 原因（Vue 3）：解构 `reactive` 丢失响应式 → 用 `toRefs`；对象被 `markRaw`。
- 原因：修改的不是响应式数据（漏了 `.value`）。

**② `ref` 拿不到 DOM / 为 `null`**

- `onMounted` 之前访问、`v-if` 为假、变量名与模板 `ref` 不一致。
- 子组件未 `defineExpose`。

**③ `v-for` 与 `v-if` 一起用报错**

- Vue 3 中 `v-if` 优先级更高，访问不到 `v-for` 变量。
- 解决：`<template v-for>` 包裹，或先 `computed` 过滤。

**④ 修改 props 报错 / 数据被污染**

- props 只读；对象类型 props 被修改会污染父数据。
- 解决：`emit` 让父更新；需要本地副本用 `computed` 或拷贝。

**⑤ 组件缓存后数据不刷新**

- `keep-alive` 缓存的组件不会重新 `mounted`。
- 解决：在 `onActivated` 中重新拉取数据。

**⑥ Watch 不触发**

- 侦听的是「值」而非「响应式源」（如 `watch(obj.a)` 传了值）；应用 getter：`watch(() => obj.a, cb)`。
- `ref` 对象未加 `deep: true`。

**⑦ 内存泄漏 / 组件卸载后仍 setState**

- 未清理定时器、事件监听、订阅、websocket。
- 解决：`onBeforeUnmount` 中统一清理。

**⑧ 路由跳转后页面白屏 / 404（刷新）**

- History 模式未配置服务端 fallback。
- 解决：Nginx `try_files ... /index.html`。

**⑨ 动态路由不生效**

- `addRoute` 后未重新导航。
- 解决：`next({ ...to, replace: true })`；登出时移除动态路由。

**⑩ 打包体积过大**

- 未按需引入组件库、未做路由懒加载、引入了完整 lodash。
- 解决：按需导入、`manualChunks` 分包、`import { fn } from 'lodash-es'`。

**⑪ 首屏白屏时间长**

- 包体过大、未拆分、无骨架屏。
- 解决：代码分割、预加载、SSR/SSG、骨架屏、CDN。

**⑫ `Cannot read property of undefined`（模板中）**

- 异步数据未返回时访问了深层属性。
- 解决：可选链 `obj?.a?.b`、`v-if` 守卫、给初始值。

**排查思路：**

```
1. 看控制台报错与 Vue 警告（Vue 的警告信息通常直接指出问题）
2. 用 DevTools 检查数据流与组件状态
3. 判断属于「响应式问题 / 生命周期问题 / 渲染问题 / 构建问题」
4. 最小化复现，逐步定位
5. 修复后回归验证
```
