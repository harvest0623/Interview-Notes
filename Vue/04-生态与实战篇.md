## 1. Vue Router 的原理

**核心：** 监听 URL 变化，在不刷新页面的前提下**匹配并渲染对应组件**。

**两种实现：**

| | Hash 模式 | History 模式 |
| --- | --- | --- |
| URL | `example.com/#/user` | `example.com/user` |
| 监听 | `hashchange` | `popstate` |
| 切换 | `location.hash = '#/user'` | `history.pushState` |
| 服务端 | 无需配置 | 需 fallback 到 `index.html` |
| SEO | 较差 | 较好 |

```js
// 简化实现
class MyRouter {
  constructor(options) {
    this.routes = options.routes;
    this.current = ref('/');
    // 监听 URL 变化
    window.addEventListener('popstate', () => this.onPopState());
    window.addEventListener('hashchange', () => this.onPopState()); // hash 模式
  }

  push(path) {
    history.pushState({}, '', path);   // 注意：不会触发 popstate
    this.current.value = path;         // 手动通知更新
  }

  onPopState() {
    this.current.value = location.pathname;
  }
}
```

**要点：**

- `history.pushState` **不触发 `popstate`**，所以路由库在 `push` 后要**手动更新响应式变量**；浏览器前进/后退才会触发 `popstate`。
- 路由匹配本质是「**路径 → 组件**」的映射，支持动态参数、嵌套路由、通配符。
- `<router-view>` 是动态组件 `<component :is>` 的封装；`<router-link>` 是 `<a>` 的封装（阻止默认跳转）。

## 2. 路由模式的配置与区别

```js
import { createRouter, createWebHistory, createWebHashHistory } from 'vue-router';

const router = createRouter({
  history: createWebHistory(),        // History 模式
  // history: createWebHashHistory(), // Hash 模式
  // history: createMemoryHistory(),  // SSR / 测试
  routes: [
    { path: '/', component: Home },
    { path: '/user/:id', component: UserDetail, props: true },
    { path: '/:pathMatch(.*)*', component: NotFound },
  ],
});
```

| 模式 | 创建方式 | 特点 |
| --- | --- | --- |
| Hash | `createWebHashHistory()` | 无需服务端配置，URL 带 `#` |
| History | `createWebHistory()` | URL 干净，需服务端 fallback |
| Memory | `createMemoryHistory()` | 不依赖浏览器，用于 SSR/测试 |

**History 模式的服务端配置（Nginx）：**

```nginx
location / {
  try_files $uri $uri/ /index.html;   # 找不到文件就返回 index.html
}
```

**要点：**

- History 模式刷新非根路径会请求该路径，服务端必须 fallback，否则 404。
- 子路径部署需设置 `base`：`createWebHistory('/admin/')`。
- `props: true` 可把路由参数作为 props 传给组件，解耦 `useRoute`。

## 3. 路由守卫有哪些？执行顺序如何？

**三类守卫：全局、路由独享、组件内。**

```js
// ① 全局前置守卫（最常用：登录校验）
router.beforeEach((to, from, next) => {
  const token = localStorage.getItem('token');
  if (to.meta.requiresAuth && !token) {
    next({ path: '/login', query: { redirect: to.fullPath } });
  } else {
    next();
  }
});

// ② 全局解析守卫（在 beforeRouteEnter 之后调用）
router.beforeResolve(async (to) => {
  // 适合：等待异步数据/组件加载完成再放行
});

// ③ 全局后置钩子（无法改变导航）
router.afterEach((to, from) => {
  document.title = to.meta.title || 'App';
  // 关闭进度条、上报埋点
});
```

```js
// ④ 路由独享守卫
{ path: '/admin', component: Admin, beforeEnter: (to, from) => {} }

// ⑤ 组件内守卫（组合式 API）
import { onBeforeRouteLeave, onBeforeRouteUpdate } from 'vue-router';
onBeforeRouteLeave((to, from) => {
  if (hasUnsavedChanges()) return window.confirm('确定离开吗？');
});
onBeforeRouteUpdate((to, from) => {});
```

**完整执行顺序：**

```
1. 触发导航
2. 失活组件的 beforeRouteLeave
3. 全局 beforeEach
4. 重用的组件 beforeRouteUpdate
5. 路由独享 beforeEnter
6. 解析异步路由组件
7. 被激活组件的 beforeRouteEnter（此时拿不到 this，需通过 next 回调）
8. 全局 beforeResolve
9. 导航被确认
10. 全局 afterEach
11. DOM 更新
12. beforeRouteEnter 的 next 回调
```

**要点：**

- `next()` 必须被调用（Vue Router 4 中也可用 `return false` / `return '/path'` 替代）。
- `next(false)` 中断导航，`next('/login')` 重定向。
- `beforeRouteEnter` 中**没有 `this`**（组件尚未创建）。
- 异步守卫中注意 `next` 只调用一次。

## 4. 动态路由与权限控制

**思路：** 用户登录后获取**角色/权限**，据此**动态添加路由**。

```js
// ① 定义「静态路由」（无需权限）与「动态路由」（按角色）
const constantRoutes = [
  { path: '/login', component: Login },
];

const asyncRoutes = [
  { path: '/admin', component: Admin, meta: { roles: ['admin'] } },
  { path: '/user', component: User, meta: { roles: ['user', 'admin'] } },
];

// ② 登录后用 addRoute 动态注册
function filterRoutes(routes, roles) {
  return routes.filter((route) => {
    if (!route.meta?.roles) return true;
    return route.meta.roles.some((role) => roles.includes(role));
  });
}

router.beforeEach(async (to, from, next) => {
  const token = getToken();
  if (!token) {
    return to.path === '/login' ? next() : next('/login');
  }
  if (to.path === '/login') return next('/');
  if (!hasAddedRoutes()) {
    const roles = await fetchUserRoles();
    filterRoutes(asyncRoutes, roles).forEach((r) => router.addRoute(r));
    return next({ ...to, replace: true });   // 重新导航，确保新路由生效
  }
  next();
});
```

**要点与坑：**

- `addRoute` 后需 `next({ ...to, replace: true })` **重新触发导航**，否则新路由不会匹配。
- **登出时必须移除动态路由**（`router.removeRoute` 或记录并重置），否则残留权限。
- 通配符 `/:pathMatch(.*)*` 的 404 路由要在**动态路由添加后**再注册，否则会抢先匹配。
- 前端权限只是**体验层**，**服务端必须再次鉴权**（接口层面）。
- 权限粒度：路由级 → 菜单级 → 按钮级（`v-permission` 指令或 `Can` 组件）。

## 5. 路由懒加载与代码分割

**目的：** 按路由拆分 chunk，减小首屏包体。

```js
// ① 使用动态 import（最常用）
const routes = [
  { path: '/home', component: () => import('../views/Home.vue') },
  {
    path: '/about',
    component: () => import(/* webpackChunkName: "about" */ '../views/About.vue'),
  },
];

// ② 分组（同一 chunk）
const User = () => import(/* webpackChunkName: "user-group" */ '../views/User.vue');
const UserDetail = () => import(/* webpackChunkName: "user-group" */ '../views/UserDetail.vue');
```

**配合 `<Suspense>` 提供加载态：**

```vue
<template>
  <router-view v-slot="{ Component }">
    <Suspense>
      <component :is="Component" />
      <template #fallback><Loading /></template>
    </Suspense>
  </router-view>
</template>
```

**要点：**

- 动态 `import()` 返回 Promise，打包工具据此**自动分包**。
- 合理的分组策略：**按业务模块**分组，避免碎片化（请求过多）或过度合并（单包过大）。
- 可与**预加载**结合，鼠标悬停时提前加载目标路由。
- 配合路由进度条（`nprogress`）提升体验：

```js
router.beforeEach(() => NProgress.start());
router.afterEach(() => NProgress.done());
```

## 6. Pinia 与 Vuex 的对比

| | Pinia | Vuex |
| --- | --- | --- |
| 版本 | Vue 3 官方推荐 | Vuex 4（Vue 3）、Vuex 3（Vue 2） |
| 语法 | **组合式 API 风格**（`defineStore`+`setup`） | 选项式（`state`/`mutations`/`actions`） |
| 是否需 mutations | **不需要**（直接改 state 或 action 修改） | **必须**通过 mutation 改 state |
| 模块化 | 每个 store 独立，天然模块化 | 需 `modules` + `namespaced` |
| TypeScript | **原生完整支持** | 支持较弱（类型推导繁琐） |
| 是否需嵌套/Provider | 不需要（`useStore()` 直接用） | 需 `app.use(store)` 注入 |
| 体积 | 更小（约 1KB） | 更大 |
| DevTools 支持 | 支持（含时间旅行） | 支持 |
| 异步 | 直接在 action 里写 | action 中写 |
| 学习成本 | 低 | 中 |

```js
// Pinia：极简
export const useCounter = defineStore('counter', {
  state: () => ({ count: 0 }),
  actions: { inc() { this.count++; } },
});

// Vuex：需要 mutation + action
export default {
  state: { count: 0 },
  mutations: { INCREMENT(state) { state.count++; } },
  actions: { inc({ commit }) { commit('INCREMENT'); } },
};
```

**要点：** Vue 3 新项目**首选 Pinia**；Vuex 主要用于存量项目与 Vue 2。

## 7. Pinia 的核心概念与用法

**核心概念：`state`、`getters`、`actions`。**

```js
// stores/counter.js —— 选项式写法
import { defineStore } from 'pinia';

export const useCounterStore = defineStore('counter', {
  state: () => ({
    count: 0,
    user: null,
  }),
  getters: {
    double: (state) => state.count * 2,
    // 使用其他 getter（需用 this，且不能用箭头函数）
    quadruple(): number { return this.double * 2; },
  },
  actions: {
    increment() { this.count++; },                    // 直接改 state
    async fetchUser(id) {
      this.user = await api.getUser(id);              // 支持异步
    },
  },
});
```

```js
// stores/counter.js —— 组合式（setup）写法
import { ref, computed } from 'vue';
import { defineStore } from 'pinia';

export const useCounterStore = defineStore('counter', () => {
  const count = ref(0);
  const double = computed(() => count.value * 2);
  function increment() { count.value++; }
  return { count, double, increment };
});
```

```vue
<script setup>
import { storeToRefs } from 'pinia';
import { useCounterStore } from '@/stores/counter';

const counter = useCounterStore();

// 直接访问（不响应式）
console.log(counter.count);
counter.increment();

// 解构保持响应式
const { count, double } = storeToRefs(counter);  // state/getters
// actions 可直接解构（本身是函数）
const { increment } = counter;
</script>
```

**要点：**

- **`storeToRefs`** 才能让解构的 state/getter 保持响应式；action 不需要。
- **不用 `this` 时用组合式写法**更清晰；`getter` 内部用 `this` 必须写普通函数（不能箭头函数）。
- Pinia 中可直接修改 state（无需 mutation），也可用 `$patch` 批量修改：

```js
counter.$patch({ count: 10 });
counter.$patch((state) => { state.count++; });
```

- 重置：`counter.$reset()`；订阅：`counter.$subscribe()`。
- 每个 store 通过 `defineStore(id, ...)` **唯一 id** 标识。

## 8. Vuex 的核心概念与数据流

**核心概念：**

| 概念 | 说明 |
| --- | --- |
| `state` | 唯一数据源 |
| `getters` | 派生状态（类似 computed） |
| `mutations` | **唯一**修改 state 的方式，**必须同步** |
| `actions` | 提交 mutation，可包含异步逻辑 |
| `modules` | 模块拆分，配合 `namespaced` |

**单向数据流：**

```
组件 dispatch(action) → action 提交 commit(mutation) → mutation 修改 state → state 变化 → 组件重新渲染
```

```js
const store = createStore({
  state: { count: 0 },
  getters: { double: (state) => state.count * 2 },
  mutations: {
    INCREMENT(state) { state.count++; },     // 同步
  },
  actions: {
    async incrementAsync({ commit }) {       // 异步
      await delay(1000);
      commit('INCREMENT');
    },
  },
  modules: {
    user: {
      namespaced: true,                      // 开启命名空间
      state: () => ({ name: '' }),
      mutations: { SET_NAME(state, name) { state.name = name; } },
    },
  },
});

// 组件中
store.commit('INCREMENT');
store.dispatch('incrementAsync');
store.getters.double;
store.state.user.name;                       // 模块状态
```

**为什么 mutation 必须同步？**

- 为了 DevTools 能**追踪每次状态变化**（时间旅行）。异步操作放在 action 中，异步完成后再 `commit`，保证 mutation 记录的是确定的状态变更。

**要点：**

- Vuex 4 支持组合式 API：`useStore()` + `storeToRefs()`。
- 模块默认**不开启命名空间**，需显式 `namespaced: true`。

## 9. 状态持久化

**问题：** 刷新页面后 Pinia/Vuex 内存中的状态会丢失。

**方案一：`pinia-plugin-persistedstate`（推荐）**

```js
// main.js
import { createPinia } from 'pinia';
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate';

const pinia = createPinia();
pinia.use(piniaPluginPersistedstate);
app.use(pinia);
```

```js
// store 中开启
export const useUserStore = defineStore('user', {
  state: () => ({ token: '', profile: null }),
  persist: {
    key: 'user',
    storage: localStorage,        // 默认 localStorage，可改 sessionStorage
    paths: ['token'],             // 只持久化部分字段（3.x 为 paths / 旧版 pick）
  },
});
```

**方案二：手写订阅**

```js
export const useUserStore = defineStore('user', {
  state: () => ({ token: localStorage.getItem('token') || '' }),
  actions: {
    setToken(token) {
      this.token = token;
      localStorage.setItem('token', token);
    },
  },
});

// 或统一订阅
store.$subscribe((mutation, state) => {
  localStorage.setItem('store', JSON.stringify(state));
});
```

**存储选型：**

| 存储 | 容量 | 生命周期 | 适用 |
| --- | --- | --- | --- |
| `localStorage` | ~5MB | 永久（除非清除） | 登录态、用户偏好 |
| `sessionStorage` | ~5MB | 会话（关标签页失效） | 临时表单数据 |
| `cookie` | ~4KB | 可设置过期 | 需随请求发送的 token（注意 HttpOnly） |
| `IndexedDB` | 大 | 永久 | 大量结构化数据 |

**要点：**

- 只持久化**必要字段**（如 token），避免把敏感信息与临时状态写入。
- **敏感数据（token）**优先存 `HttpOnly` Cookie，防止 XSS 窃取。
- 需处理**存储数据版本变更**与**反序列化失败**的容错。

## 10. Axios 封装与拦截器

```js
// utils/request.js
import axios from 'axios';
import { useUserStore } from '@/stores/user';
import { ElMessage } from 'element-plus';
import router from '@/router';

const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10000,
});

// 请求拦截器
service.interceptors.request.use(
  (config) => {
    const userStore = useUserStore();
    if (userStore.token) {
      config.headers.Authorization = `Bearer ${userStore.token}`;
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// 响应拦截器
service.interceptors.response.use(
  (response) => {
    const { code, data, message } = response.data;
    if (code === 0 || code === 200) return data;   // 直接返回业务数据
    if (code === 401) {                            // 未登录/过期
      const userStore = useUserStore();
      userStore.logout();
      router.push('/login');
    }
    ElMessage.error(message || '请求失败');
    return Promise.reject(new Error(message));
  },
  (error) => {
    // 网络错误 / 超时 / HTTP 状态码错误
    let msg = '网络异常，请稍后重试';
    if (error.code === 'ECONNABORTED') msg = '请求超时';
    else if (error.response?.status === 404) msg = '资源不存在';
    else if (error.response?.status === 500) msg = '服务器错误';
    ElMessage.error(msg);
    return Promise.reject(error);
  }
);

export default service;
```

**其他常见处理：**

```js
// 取消重复请求
const pending = new Map();
// 请求拦截中：相同请求取消旧的
// 响应拦截中：完成后移除记录

// 重试
service.interceptors.response.use(null, async (error) => {
  const config = error.config;
  if (!config.__retryCount) config.__retryCount = 0;
  if (config.__retryCount < 3 && error.code === 'ECONNABORTED') {
    config.__retryCount++;
    return service(config);
  }
  return Promise.reject(error);
});
```

**要点：**

- 统一处理 **token 注入、错误提示、401 跳转、超时、重试**。
- 拦截器中**直接返回 `data`** 可减少调用方的 `res.data.data` 层级。
- 注意 **Pinia store 在拦截器中的使用时机**（需在 `app.use(pinia)` 之后调用 `useUserStore`）。
- 并发请求用 `Promise.all`，需要独立错误处理用 `Promise.allSettled`。

## 11. Vue 中的样式方案

| 方案 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **全局样式** | `<style>` | 简单 | 污染全局 |
| **`scoped`** | `<style scoped>`，编译加属性选择器 | 组件级隔离、内置 | 深度选择器麻烦 |
| **CSS Modules** | `<style module>` | 类名哈希隔离 | 动态类名不便 |
| **CSS 预处理器** | `<style lang="scss">` | 变量、嵌套、mixin | 需构建支持 |
| **Tailwind** | 原子化类名 | 快速、产物小 | 类名冗长 |
| **CSS-in-JS** | 较少用 | 动态 | 运行时开销 |

**`scoped` 的原理：**

```vue
<style scoped>
.title { color: red; }
</style>
```

编译后：

```html
<div class="title" data-v-7ba5bd90>...</div>
```

```css
.title[data-v-7ba5bd90] { color: red; }
```

- 给元素加上**唯一属性**（`data-v-hash`），样式选择器也带上该属性 → 实现「**局部作用域**」。

**深度选择器（`scoped` 中修改子组件样式）：**

```vue
<style scoped>
/* Vue 3 推荐 :deep() */
:deep(.el-input__inner) { border-color: red; }

/* 还有 :slotted() 和 :global() */
:slotted(.child) { color: blue; }
:global(.global-class) { color: green; }
</style>
```

**要点：**

- `scoped` 是**属性选择器隔离**，不是 Shadow DOM；子组件**根元素**会同时受父子样式影响。
- `:deep()` 会穿透到子组件（Vue 2 中写 `::v-deep` / `/deep/`）。
- 需要动态类名（如按 props 计算）时，CSS Modules 需配合 `:class="$style.x"`。
- 全局主题变量推荐 **CSS 变量**（`:root { --primary: ... }`），便于运行时切换主题。

## 12. Vue 中的 SSR 与 Nuxt

**SSR（服务端渲染）**：在服务端把 Vue 组件渲染为 HTML 字符串返回，首屏更快、利于 SEO。

**流程：**

```
请求 → 服务端执行组件 → 生成 HTML → 返回给浏览器 → 下载 JS → 激活（hydration）→ 可交互
```

**Vue 提供的能力：**

```js
// 服务端
import { createSSRApp } from 'vue';
import { renderToString } from 'vue/server-renderer';

const app = createSSRApp(App);
const html = await renderToString(app);

// 客户端激活
createSSRApp(App).mount('#app');
```

**Vue 3 SSR 的注意点：**

- **生命周期**：服务端只执行 `setup` 与 `beforeCreate`/`created` 类的逻辑，`onMounted` 不会在服务端执行。
- **不能访问浏览器 API**：`window`、`document`、`localStorage` 只能在 `onMounted` 或 `import.meta.env.SSR` 判断中使用。
- **避免状态污染**：服务端是**共享进程**，不能用模块级单例存储请求相关状态（需用 `createSSRApp` 每次创建新实例）。
- **`Suspense`** 与 `async setup` 用于服务端数据预取。
- **hydration mismatch**：服务端与客户端首屏结构必须一致，随机数/时间戳需放到 `onMounted`。

```vue
<script setup>
import { ref, onMounted } from 'vue';
const isClient = ref(false);
onMounted(() => { isClient.value = true; });   // 仅客户端
</script>
```

**Nuxt 3：**

- 基于 Vue 3 的全栈框架，约定式路由（`pages/` 目录即路由）。
- 支持 **SSR / SSG / ISR / SPA** 多种渲染模式。
- `useAsyncData` / `useFetch` 做服务端数据预取与同步。
- 自动导入（组件、组合式函数、API）。
- 内置 `server/api` 编写后端接口，`middleware` 做路由中间件。

```vue
<script setup>
// Nuxt：服务端预取数据，自动同步到客户端
const { data } = await useFetch('/api/user');
</script>
```

**要点：** 需要 SEO / 首屏优化的项目用 Nuxt；纯后台系统用 SPA 即可。

## 13. 环境变量与构建配置

**Vite 环境变量（`.env` 文件）：**

```bash
# .env               所有环境
# .env.development   开发环境
# .env.production    生产环境
VITE_API_BASE_URL=https://api.example.com
VITE_APP_TITLE=My App
```

```js
// 只有 VITE_ 前缀的变量才会暴露给客户端代码
console.log(import.meta.env.VITE_API_BASE_URL);
console.log(import.meta.env.MODE);        // 'development' | 'production'
console.log(import.meta.env.DEV);         // 是否开发环境
console.log(import.meta.env.PROD);        // 是否生产环境
```

**vite.config.js 常用配置：**

```js
import { defineConfig, loadEnv } from 'vite';
import vue from '@vitejs/plugin-vue';
import path from 'node:path';

export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd());

  return {
    plugins: [vue()],
    resolve: {
      alias: { '@': path.resolve(__dirname, 'src') },   // 需与 tsconfig paths 同步
    },
    server: {
      port: 5173,
      open: true,
      proxy: {                                           // 开发环境代理
        '/api': {
          target: env.VITE_API_BASE_URL,
          changeOrigin: true,
          rewrite: (p) => p.replace(/^\/api/, ''),
        },
      },
    },
    build: {
      outDir: 'dist',
      sourcemap: false,
      chunkSizeWarningLimit: 1000,
      rollupOptions: {
        output: {
          manualChunks: {                                // 手动分包
            vue: ['vue', 'vue-router', 'pinia'],
            vendor: ['axios', 'lodash-es'],
          },
        },
      },
    },
  };
});
```

**要点：**

- **只有 `VITE_` 前缀**的变量会注入客户端，敏感信息（密钥）不应放前端环境变量。
- 别名 `@` 需同时在 Vite 与 `tsconfig.json` 的 `paths` 中配置。
- `manualChunks` 把第三方库拆出，利用浏览器缓存（库不变则缓存命中）。
- 生产环境关闭 `sourcemap` 或用 `hidden` 模式并上传到监控平台。

## 14. 组件库的二次封装

**目的：** 统一风格、收敛配置、减少重复代码、便于后续替换底层库。

**示例：封装一个带默认配置的 `Table` 组件**

```vue
<!-- components/MyTable.vue -->
<script setup lang="ts">
import { ElTable, ElTableColumn } from 'element-plus';

interface Column {
  prop: string;
  label: string;
  width?: number | string;
  formatter?: (row: any) => string;
}

const props = withDefaults(defineProps<{
  data: any[];
  columns: Column[];
  loading?: boolean;
  border?: boolean;
}>(), {
  loading: false,
  border: true,
});

const emit = defineEmits<{ 'row-click': [row: any] }>();
</script>

<template>
  <ElTable
    v-loading="props.loading"
    :data="props.data"
    :border="props.border"
    @row-click="(row) => emit('row-click', row)"
  >
    <ElTableColumn
      v-for="col in props.columns"
      :key="col.prop"
      :prop="col.prop"
      :label="col.label"
      :width="col.width"
      :formatter="col.formatter"
    />
  </ElTable>
</template>
```

**封装原则：**

| 原则 | 说明 |
| --- | --- |
| **透传属性与事件** | 用 `v-bind="$attrs"` 让父组件能传任意原生属性 |
| **透传插槽** | `<template v-for="(_, name) in $slots" #[name]="slotProps">` |
| **Props 类型完整** | 用 TS 定义 Props，编辑器有提示 |
| **默认值合理** | 用 `withDefaults` 提供常用默认值 |
| **可控扩展** | 保留底层组件的能力，不要过度限制 |
| **`inheritAttrs`** | 需要自定义 attribute 透传位置时设为 `false` |

```vue
<script setup>
defineOptions({ inheritAttrs: false });
</script>

<template>
  <div class="wrapper">
    <ElInput v-bind="{ ...$attrs, ...props }" />
  </div>
</template>
```

**要点：**

- 二次封装的核心价值是**统一规范**与**降低替换成本**，不是「包一层就完事」。
- 要保留**透传能力**（`$attrs`、`$slots`），否则扩展性差。
- 组件库按需引入（`unplugin-vue-components`）可显著减小打包体积。
- 语义化命名 + 完整 TS 类型，是团队复用的前提。
