## 1. Vue 的响应式原理

**一句话：** 通过**数据劫持**（拦截读写）+ **依赖收集** + **派发更新**，实现「数据变化 → 自动更新视图」。

**Vue 2：`Object.defineProperty` + 观察者模式**

```
1. 遍历 data，用 Object.defineProperty 把每个属性转为 getter/setter
2. getter：收集当前正在求值的 Watcher（依赖收集，Dep.depend）
3. setter：通知该属性的所有 Watcher 更新（派发更新，Dep.notify）
4. Watcher 更新 → 触发组件重新渲染 → 生成新虚拟 DOM → patch 到真实 DOM
```

**Vue 3：`Proxy` + `effect` 副作用系统**

```
1. reactive() 用 Proxy 代理对象，拦截 get / set / deleteProperty / has 等
2. get 时用 track() 收集当前 activeEffect 到 targetMap（WeakMap 结构）
3. set 时用 trigger() 找出依赖该 key 的 effect 并执行
4. effect 重新执行 → 组件渲染函数重跑 → patch 更新 DOM
```

**核心三段式：**

```
数据劫持（拦截读写）→ 依赖收集（谁用了我）→ 触发更新（我变了通知谁）
```

**要点：**

- 响应式本质是「**知道谁依赖了我，我变化时通知它们**」。
- Vue 3 的 `track`/`trigger` 使用三层结构存储：`WeakMap<target, Map<key, Set<effect>>>`。
- 用 `WeakMap` 避免内存泄漏（对象被回收后依赖记录也释放）。

## 2. Vue 2 用 Object.defineProperty 的缺陷

| 缺陷 | 说明 |
| --- | --- |
| **无法检测新增/删除属性** | `defineProperty` 在初始化时逐个定义，后续 `obj.newKey = 1` 无响应 → 需 `Vue.set` / `$set` |
| **无法检测数组索引与长度** | `arr[0] = x`、`arr.length = 0` 不触发更新 → 需用 `splice` 或重写方法 |
| **必须深度遍历** | 初始化时要递归遍历所有属性（`observe`），**性能开销大**，大对象/深层对象初始化慢 |
| **无法代理 Map/Set** | 只能对普通对象的属性生效 |
| **不支持懒代理** | 不管是否用到，都要提前递归转换 |

```js
// Vue 2 的痛点
data() {
  return { obj: { a: 1 } };
}
this.obj.b = 2;        // 不响应
this.$set(this.obj, 'b', 2);  // 需要这样

this.list[0] = 'x';    // 不响应
this.list.splice(0, 1, 'x');  // 需要这样
```

**要点：** 归根结底是 `defineProperty` **只能劫持已存在的属性**，且**不支持索引/length**，必须提前递归。

## 3. Vue 3 为什么改用 Proxy？

| 对比 | `Object.defineProperty`（Vue 2） | `Proxy`（Vue 3） |
| --- | --- | --- |
| 劫持范围 | 对象**属性** | **整个对象** |
| 新增/删除属性 | 不支持 | **支持** |
| 数组索引/length | 不支持 | **支持** |
| Map / Set | 不支持 | **支持** |
| 初始化性能 | 需递归遍历所有属性 | **懒代理**（访问到才代理） |
| 语法 | `defineProperty(obj, key, desc)` | `new Proxy(target, handler)` |
| 兼容性 | 好（支持 IE） | 不支持 IE（无 polyfill） |

```js
const proxy = new Proxy(target, {
  get(target, key, receiver) {
    track(target, key);                    // 依赖收集
    return Reflect.get(target, key, receiver);
  },
  set(target, key, value, receiver) {
    const result = Reflect.set(target, key, value, receiver);
    trigger(target, key);                  // 派发更新
    return result;
  },
  deleteProperty(target, key) {
    const result = Reflect.deleteProperty(target, key);
    trigger(target, key);
    return result;
  },
});
```

**Proxy 的优势：**

- **懒代理**：只有访问到深层属性时才递归代理，初始化更快、内存更省。
- **支持全部操作**：增删属性、数组索引、`in`、`delete` 都能拦截。
- 拦截能力更完整（13 种 trap），`Reflect` 保证默认行为。

**唯一缺点：** 不支持 IE11（Vue 3 选择放弃 IE 兼容以换取更强能力）。

## 4. 依赖收集与派发更新的完整流程

**Vue 3 的核心数据结构与流程：**

```js
// 三层结构存储依赖
targetMap: WeakMap{
  target: Map{
    key: Set<ReactiveEffect>
  }
}
```

**① 依赖收集（track）：**

```js
let activeEffect = null;

function track(target, key) {
  if (!activeEffect) return;
  let depsMap = targetMap.get(target);
  if (!depsMap) targetMap.set(target, (depsMap = new Map()));
  let deps = depsMap.get(key);
  if (!deps) depsMap.set(key, (deps = new Set()));
  deps.add(activeEffect);            // 记录「哪个 effect 依赖了这个 key」
}
```

**② 派发更新（trigger）：**

```js
function trigger(target, key) {
  const depsMap = targetMap.get(target);
  if (!depsMap) return;
  const effects = depsMap.get(key);
  effects && effects.forEach((effect) => effect());   // 重新执行依赖的 effect
}
```

**③ effect 包装（把渲染函数变成响应式副作用）：**

```js
function effect(fn) {
  const effectFn = () => {
    activeEffect = effectFn;   // 标记当前正在执行的 effect
    fn();                      // 执行渲染，期间触发 get → track
    activeEffect = null;
  };
  effectFn();
  return effectFn;
}
```

**整体流程：**

```
组件渲染 → 执行 render（被 effect 包裹）→ 访问响应式数据 → Proxy.get → track 收集
数据修改 → Proxy.set → trigger 找到依赖的 effect → 调度更新 → 重新渲染 → patch
```

**要点：**

- `activeEffect` 用于**标记当前正在求值的副作用**，从而知道「谁依赖了我」。
- 依赖是**按 target + key 精确记录**的，只有真正相关的 effect 才会被触发。

## 5. Vue 3 的响应式为什么要 .value？

**因为 `ref` 处理的是「基本类型」。** JS 中基本类型是**按值传递**的，无法用 `Proxy` 直接代理一个 `number`/`string`——`Proxy` 只能代理对象。

**解决方案：** 把值**包在一个对象**里，通过代理该对象的 `value` 属性实现响应式。

```js
function ref(value) {
  return reactive({ value });   // 本质是 { value: xxx } 的响应式对象
}

const count = ref(0);
count.value++;         // 实际是访问/修改包裹对象的 value 属性
```

**为什么模板里不用 `.value`？** 因为模板编译时会**自动解包（unwrap）**：

```vue
<script setup>
const count = ref(0);
</script>
<template>
  <!-- 模板中自动解包，等价于 count.value -->
  <p>{{ count }}</p>
</template>
```

**自动解包的规则：**

- **模板中**：顶层 `ref` 自动解包，无需 `.value`。
- **`reactive` 对象中**：作为属性时自动解包。

```js
const count = ref(0);
const state = reactive({ count });
state.count;   // 自动解包，不用 .value
```

- **在 JS 中**（`setup`、函数、`computed`/`watch` 回调）：**必须写 `.value`**。

**要点：**

- `reactive` 只能代理**对象/数组/Map/Set**，基本类型必须用 `ref`。
- `ref` 也能包对象（内部用 `reactive` 处理），`ref(obj).value` 是深层响应式。
- 解构 `reactive` 会丢失响应式 → 用 `toRefs`。

## 6. Vue 2 是如何处理数组响应式的？

`Object.defineProperty` **无法拦截数组的索引赋值与 `length` 变化**，因此 Vue 2 采用了**「重写数组原型方法 + 递归 observe」**的方案：

**① 用「拦截器」覆盖 7 个会改变数组的方法：**

```
push / pop / shift / unshift / splice / sort / reverse
```

```js
const arrayProto = Array.prototype;
const arrayMethods = Object.create(arrayProto);

['push', 'pop', 'shift', 'unshift', 'splice', 'sort', 'reverse'].forEach((method) => {
  const original = arrayProto[method];
  // 定义在 arrayMethods 上，不改原生 Array.prototype
  Object.defineProperty(arrayMethods, method, {
    value: function mutator(...args) {
      const result = original.apply(this, args);
      const ob = this.__ob__;
      let inserted;
      switch (method) {
        case 'push':
        case 'unshift':
          inserted = args;      // 新增元素也要 ob serve
          break;
        case 'splice':
          inserted = args.slice(2);
          break;
      }
      if (inserted) ob.observeArray(inserted);   // 对新元素做响应式
      ob.dep.notify();                            // 通知更新
      return result;
    },
    enumerable: false,
    writable: true,
    configurable: true,
  });
});

// 把数组实例的原型指向 arrayMethods
if (Array.isArray(value)) {
  value.__proto__ = arrayMethods;   // 支持 __proto__ 时
}
```

**② 用 `Vue.set` / `$set` 处理索引赋值：**

```js
Vue.set(arr, 0, 'new');   // 手动触发 notify
this.$set(this.obj, 'newKey', 1);
```

**要点：**

- 之所以能拦截，是因为**修改了数组实例的原型链**，而非直接改 `Array.prototype`（避免污染全局）。
- 索引赋值 `arr[0] = x` 与 `arr.length = 0` **依然不响应**，只能用 `splice` 或 `$set`。
- Vue 3 用 `Proxy` 后，以上问题**全部消失**，`arr[0] = x` 也能响应。

## 7. 异步更新队列与批量更新

**问题：** 同一轮同步代码中多次修改数据，若每次都触发渲染，会造成大量重复计算与 DOM 操作。

**Vue 的方案：异步更新队列（微任务批量）**

- 数据变化后不立即更新 DOM，而是把**对应的 Watcher/effect 推入队列**。
- 用 `nextTick` 把「刷新队列」放入**微任务**，等同步代码执行完统一刷新。
- 刷新时对队列**去重**（同一个 Watcher 只执行一次），并按 id **排序**（保证父子组件更新顺序）。

```js
// 三次修改，只会渲染一次
this.count++;
this.count++;
this.count++;
// 最终 DOM 只更新一次
```

**Vue 3 的调度器（scheduler）：**

```js
const queue = [];
let isFlushPending = false;

function queueJob(job) {
  if (!queue.includes(job)) queue.push(job);   // 去重
  if (!isFlushPending) {
    isFlushPending = true;
    Promise.resolve().then(flushJobs);          // 微任务刷新
  }
}

function flushJobs() {
  queue.sort((a, b) => a.id - b.id);            // 按 id 排序（父先于子）
  for (const job of queue) job();
  queue.length = 0;
  isFlushPending = false;
}
```

**要点：**

- 批量更新的意义：**减少重复渲染、保证更新顺序一致**。
- 因为异步，所以「改数据后立刻读 DOM」会拿到旧值 → 需要 `nextTick`。
- 组件更新顺序按**父 → 子**（id 递增），避免子先更新导致的重复渲染。

## 8. nextTick 的实现原理

`nextTick` 把回调推迟到**当前微任务队列末尾**执行，从而保证「**DOM 更新已经完成**」。

**实现思路（简化）：**

```js
const callbacks = [];
let pending = false;

function flushCallbacks() {
  pending = false;
  const copies = callbacks.slice(0);
  callbacks.length = 0;
  copies.forEach((cb) => cb());
}

let timerFunc;

// 优先微任务：Promise → MutationObserver → setImmediate → setTimeout（降级）
if (typeof Promise !== 'undefined') {
  const p = Promise.resolve();
  timerFunc = () => p.then(flushCallbacks);
} else if (typeof MutationObserver !== 'undefined') {
  let counter = 1;
  const observer = new MutationObserver(flushCallbacks);
  const textNode = document.createTextNode(String(counter));
  observer.observe(textNode, { characterData: true });
  timerFunc = () => { counter = (counter + 1) % 2; textNode.data = String(counter); };
} else {
  timerFunc = () => setTimeout(flushCallbacks, 0);
}

export function nextTick(cb) {
  callbacks.push(cb);
  if (!pending) {
    pending = true;
    timerFunc();          // 只调度一次，多个回调合并到同一批
  }
  // 支持 Promise 用法
  return Promise.resolve();
}
```

**为什么用微任务？**

- 微任务在**当前宏任务结束后、下一个宏任务前**执行，早于渲染，能「尽快」且「在 DOM 更新后」拿到结果。
- 相比 `setTimeout`，微任务延迟更低、不产生额外宏任务。

**要点：**

- 多次调用 `nextTick` 的回调会在**同一批**（同一个微任务）中执行。
- 数据变更触发的**渲染任务**也是一个微任务，`nextTick` 的回调会在其**之后**执行，因此能读到更新后的 DOM。
- Vue 3 的 `nextTick` 直接基于 `Promise.then`。

## 9. 虚拟 DOM 与 Diff 算法

**虚拟 DOM（VNode）**：用 JS 对象描述真实 DOM 结构。

```js
// VNode 结构（简化）
{
  type: 'div',
  props: { class: 'box' },
  children: [ /* 子 VNode */ ],
  key: undefined,
  el: null,          // 对应的真实 DOM
}
```

**为什么需要虚拟 DOM？**

- **跨平台**：同一套 VNode 可渲染到浏览器、Native、小程序。
- **批量与最小化**：先在内存计算差异，再一次性 patch 到真实 DOM。
- **配合编译优化**：可以在编译期标记动态部分，减少运行时比较。

**Diff 的核心目标：** 找出新旧 VNode 的最小差异，尽量**复用**真实 DOM。

**同层比较（不跨层级）：**

- 只比较**同一层级**的节点，不做跨层移动（跨层移动会被拆成「删除 + 创建」）。
- 类型不同 → **销毁旧节点、创建新节点**（不尝试复用）。
- 类型相同 → 复用 DOM，只更新变化的属性与 children。

**更新子节点（Diff 策略）：**

- 旧节点是**数组**、新节点是**数组** → 走 **Diff 算法**（核心）。
- 旧是数组、新是文本 / 旧是文本、新是数组 → 分别做「删除旧 + 插入新」。
- 旧是空、新是数组 → 直接创建；旧是数组、新是空 → 直接删除。

**列表 Diff 的关键是 `key`：** 有 key 才能识别「同一个节点在新旧列表中的位置」，从而正确复用与移动。

## 10. Vue 2 双端 Diff 与 Vue 3 的优化

**Vue 2：双端比较（双指针）**

- 同时从**新旧列表的两端**向中间比较，共 4 种匹配：
  - 旧头 vs 新头、旧尾 vs 新尾、旧头 vs 新尾、旧尾 vs 新头。
- 4 种都不匹配时，用 `key` 在旧列表中查找可复用节点，然后**移动**。
- **缺点**：移动逻辑较繁琐，某些场景移动次数偏多。

**Vue 3：基于「最长递增子序列（LIS）」**

- 先**前序遍历**处理头部相同节点，再**后序遍历**处理尾部相同节点，缩小比对范围。
- 中间乱序部分：建立「新 key → 旧 index」映射，然后求**最长递增子序列**。
- **递增子序列中的节点不需要移动**，只移动其余节点 → **移动次数最少**。

```
Vue 2：4 指针比对 + 查找移动
Vue 3：前序/后序预处理 + 最长递增子序列，最小化 DOM 移动
```

```js
// 求最长递增子序列（Vue 3 的 getSequence 核心思路）
function getSequence(arr) {
  const result = [0];
  const p = arr.slice();
  for (let i = 1; i < arr.length; i++) {
    const arrI = arr[i];
    if (arrI === -1) continue;
    const last = result[result.length - 1];
    if (arr[last] < arrI) {
      p[i] = last;
      result.push(i);
      continue;
    }
    // 二分查找替换位置
    let left = 0, right = result.length - 1;
    while (left < right) {
      const mid = (left + right) >> 1;
      if (arr[result[mid]] < arrI) left = mid + 1;
      else right = mid;
    }
    if (arrI < arr[result[left]]) {
      if (left > 0) p[i] = result[left - 1];
      result[left] = i;
    }
  }
  // 回溯得出最终序列
  let len = result.length, last = result[len - 1];
  while (len-- > 0) { result[len] = last; last = p[last]; }
  return result;
}
```

**要点：**

- Vue 3 相对 Vue 2 的核心优势：**DOM 移动次数更少**（LIS 保证最多只移动必要节点）。
- 前提仍需**稳定的 `key`**，否则退化为低效比较。

## 11. 编译优化：静态提升、PatchFlag、Block Tree

Vue 3 在**编译期**做了一系列优化，减少运行时的比较成本。

**① 静态提升（Static Hoisting）**

静态节点被提升到 `render` 函数**外部**，只创建一次，不再重复创建 VNode。

```js
// 未优化：每次渲染都创建
function render() {
  return createVNode('div', null, [createVNode('span', null, 'static')]);
}

// 优化后：静态 VNode 提升到外部
const _hoisted_1 = createVNode('span', null, 'static');
function render() {
  return createVNode('div', null, [_hoisted_1]);
}
```

**② PatchFlag（补丁标志）**

编译期**标记**每个动态节点的变化类型（文本、class、props、style 等），Diff 时**只比较标记的部分**，跳过静态属性。

```js
// 编译产物带 patchFlag
createElementVNode('div', { class: _ctx.cls }, null, 8 /* PROPS */, ['class']);
```

**③ Block Tree（块树）**

- 把模板切分为「**块**」，块内只收集**动态节点**（放到 `dynamicChildren` 数组）。
- Diff 时**直接遍历动态节点数组**，完全跳过静态节点。
- `<template>` 的整体结构被「拍平」，形成树状的 Block，进一步减少遍历量。

**④ 其他优化：**

- **静态属性提升**、**缓存事件处理函数**、**`v-once`**、**`v-memo`**。
- 对 `v-if` / `v-for` 的**动态子块**单独处理。

**要点：**

- Vue 2 的 Diff 需要**全量遍历**子节点；Vue 3 通过编译信息**跳过静态部分**，只比较动态部分。
- 这也是 Vue 3 更新性能提升的关键原因之一：**编译时把「哪里会变」提前告诉运行时**。

## 12. 为什么 v-for 与 v-if 不建议同用？

**Vue 2：`v-for` 优先级更高**

```vue
<!-- v-for 先执行，v-if 每个循环都判断一次 → 浪费性能 -->
<li v-for="item in list" v-if="item.active" :key="item.id"></li>
```

- 即使列表大部分项都会被过滤掉，也要遍历整个列表。

**Vue 3：`v-if` 优先级更高**

```vue
<!-- v-if 先执行，此时 item 还未定义 → 报错 -->
<li v-for="item in list" v-if="item.active" :key="item.id"></li>
```

- 会抛出「无法访问 `item`」的错误，因为 `v-if` 在 `v-for` 之前求值。

**正确写法：**

```vue
<!-- 方案一：外层用 template 包裹 v-for -->
<template v-for="item in list" :key="item.id">
  <li v-if="item.active">{{ item.name }}</li>
</template>

<!-- 方案二：先过滤（推荐，computed 有缓存） -->
<script setup>
const activeList = computed(() => list.value.filter((i) => i.active));
</script>
<template>
  <li v-for="item in activeList" :key="item.id">{{ item.name }}</li>
</template>

<!-- 方案三：用外层容器承载 v-if -->
<ul v-if="list.length">
  <li v-for="item in list" :key="item.id">{{ item.name }}</li>
</ul>
```

**要点：** 推荐**方案二**，用 `computed` 先过滤，逻辑清晰且避免重复判断。

## 13. 响应式数据的更新注意事项

**Vue 3 常见坑：**

**① 解构 `reactive` 丢失响应式**

```js
const state = reactive({ count: 0 });
const { count } = state;        // count 是普通值，失去响应式
const { count: c } = toRefs(state); // 正确：保持响应式
```

**② 替换整个 `reactive` 对象会断开引用**

```js
let state = reactive({ a: 1 });
state = reactive({ a: 2 });     // 外部引用丢失
// 正确：用 ref 或逐属性修改
const state = ref({ a: 1 });
state.value = { a: 2 };         // ref 可以整体替换
```

**③ 用 `ref` 包裹对象时要注意 `.value`**

```js
const obj = ref({ a: 1 });
obj.value.a = 2;      // 正确（ref 内部是 reactive）
```

**④ 数组/Map/Set 的替换**

```js
const list = ref([1, 2]);
list.value.push(3);          // 响应式
list.value = [4, 5];         // 响应式（替换）
list.value[0] = 9;           // 响应式（Proxy 支持）
```

**Vue 2 特有坑（Vue 3 已修复）：**

```js
this.obj.newKey = 1;      // 不响应 → this.$set(this.obj, 'newKey', 1)
this.list[0] = 'x';       // 不响应 → this.$set / splice
this.list.length = 0;     // 不响应 → this.list.splice(0)
```

**要点：**

- 尽量**不整体替换 `reactive` 对象**，用 `ref` 或改属性。
- 需要跨模块传递时用 `ref`（支持整体替换 + 自动解包）。
- 明确数据是「深层响应式」还是「浅层响应式」（`shallowRef`/`shallowReactive`）。

## 14. watch 的 deep 与 immediate 原理

**`immediate`**：创建侦听器时**立即执行一次**回调。

```js
watch(source, callback, { immediate: true });
```

**`deep`**：深度侦听对象的**嵌套属性**变化。

```js
watch(obj, callback, { deep: true });
```

**原理：**

- **`immediate`**：在 `watch` 内部创建 effect 后，**手动调用一次** `job`（回调），并把 `oldValue` 设为 `undefined`。

```js
function watch(source, cb, options = {}) {
  let getter;
  if (isReactive(source)) {
    getter = () => traverse(source);     // 递归访问所有属性以收集依赖
    options.deep = true;                 // reactive 默认 deep
  } else {
    getter = source;
  }

  let oldValue, newValue;
  const job = () => {
    newValue = effectFn();
    cb(newValue, oldValue, onCleanup);
    oldValue = newValue;
  };

  const effectFn = effect(getter, {
    lazy: true,
    scheduler: job,                       // 依赖变化时执行 job
  });

  if (options.immediate) job();           // 立即执行一次
  oldValue = effectFn();
}
```

- **`deep`**：通过对 `source` 做**递归遍历（`traverse`）**，让 getter 访问到所有嵌套属性，从而把这些属性的依赖都收集进来。

```js
function traverse(value, seen = new Set()) {
  if (typeof value !== 'object' || value === null || seen.has(value)) return value;
  seen.add(value);
  for (const key in value) traverse(value[key], seen);  // 递归访问，触发 track
  return value;
}
```

**要点：**

- `watch` 侦听 `reactive` 对象时**默认就是 deep**（因为访问对象会触发深层依赖）；侦听 `ref` 包裹的对象则需显式 `deep: true`。
- `deep: true` 有**性能开销**（遍历整个对象），大对象应避免或改用侦听具体字段：`() => obj.a.b.c`。
- `watch` 回调支持 `onCleanup` 做清理（如取消上一次请求）：

```js
watch(id, async (newId, oldId, onCleanup) => {
  const ctrl = new AbortController();
  onCleanup(() => ctrl.abort());
  const data = await fetch(`/api/${newId}`, { signal: ctrl.signal });
});
```
