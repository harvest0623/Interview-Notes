## 学习路径建议

```
交互与组件场景篇（高频、可现场手写：虚拟列表 / 拖拽 / 大表格）
   ↓
数据与通信场景篇（项目经验密度最高：上传下载 / 实时通信 / 登录鉴权）
   ↓
业务与工程场景篇（体现架构感：主题 / i18n / 多页签 / 低代码 / PWA）
```

> 面试策略：**虚拟列表、分片上传、权限体系是硬门槛**（答不出细节说明没真正落地过）；**断点续传、WebSocket 可靠性、埋点是分水岭**（能讲清失败路径才算做过）；**低代码与 PWA 是加分项**（能说清适用边界比会背 API 更加分）。
>
> 场景题的答题骨架统一为：**先定约束（数据量、设备、网络、兼容）→ 给方案与选型对比 → 讲核心实现 → 讲边界与降级 → 说取舍理由**。只贴代码不谈取舍，是这类题最常见的失分点。

## 核心速查表

**大文件上传全流程**

```
选择文件 → 计算 hash（抽样 + Worker） → 调 init 接口
   ├─ 命中秒传（服务端已有该 hash） → 直接返回 fileUrl，结束
   └─ 未命中 → 服务端返回 uploadedChunks（已传分片序号）
        → 并发池（3~6 路）逐片 PUT（带 index + hash）
        → 失败分片重试（指数退避，最多 3 次）
        → 全部完成 → 调 merge 接口（服务端校验 MD5/ETag）→ 返回 fileUrl
进度 = 已成功分片字节数 / 文件总字节数（按字节，不按片数）
```

**权限模型三层**

```
菜单层：登录 → 拉取 userInfo.permissions → 过滤静态路由表 → addRoute
按钮层：v-permission / usePermission，只控制「可不可见」，不当作安全边界
接口层：后端鉴权为唯一可信来源；前端只在 401/403 时做提示与降级
数据层：部门/本人/全部，由后端在查询条件中注入，前端只传业务参数
```

**埋点字段最小集**

```
event     事件名（click_ / expose_ / pv_ 前缀区分类型）
ts        客户端时间戳（毫秒）
page      路由 path 或页面 ID
uid       登录用户 ID（未登录用设备 ID）
device    平台 / 浏览器 / 分辨率 / 网络类型
trace_id  一次会话的链路 ID（用于串联 PV 与点击）
extra     业务参数（商品 ID、坑位号等），避免塞大对象
```

**虚拟列表核心公式**

```
固定高度：
  start = floor(scrollTop / itemHeight) - overscan
  end   = start + ceil(viewportHeight / itemHeight) + 2 * overscan
  offsetY = start * itemHeight        // 用 transform 而非 top，避免重排

不定高度：
  offsets[i] = offsets[i-1] + heights[i-1]   // 前缀和
  用二分查找 scrollTop 落在哪个区间 → 得到 start
  测量到真实高度后写回 heights[i]，并补偿 scrollTop（锚点防跳动）
```

**易错点清单**

```
1. 虚拟列表只做「渲染裁剪」不做「布局裁剪」，容器总高度必须撑出来，否则滚动条会抖
2. IntersectionObserver 的 root 不设置时以视口为准，滚动容器内部滚动不会触发
3. HTML5 拖拽必须在 dragover 里 preventDefault，否则永远不触发 drop
4. Pointer Events 方案忘记 touch-action: none，移动端会变成页面滚动而不是拖拽
5. contenteditable 不等于富文本编辑器，中文输入法必须处理 compositionstart/end
6. canvas 压缩图片前不处理 EXIF 方向，手机竖拍照片会变横
7. 分片上传的进度按字节算，按片数算在最后一片偏小的时候会跳变
8. hash 计算放主线程会卡住 UI，大文件必须用 Worker + 增量计算
9. WebSocket 心跳不是协议层 ping，浏览器端只能发应用层消息并等 pong
10. 双 Token 刷新要做「单飞」，否则并发 401 会连续刷新导致 refresh token 失效
11. 前端权限只负责体验，任何「隐藏了按钮就等于安全」的说法都是错的
12. sendBeacon 有 64KB 限制且只能 POST，大批量数据要分批或改用 fetch keepalive
13. sourcemap 不能随产物公开发布，要 hidden-source-map 后单独上传到监控平台
14. 主题切换的首屏闪烁只能靠「HTML 解析前执行的内联脚本」解决，React 挂载后设置必然晚一帧
15. keep-alive 缓存的 key 用 fullPath 还是 path，直接决定「同一路由不同参数」是否复用
```
