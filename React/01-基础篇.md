## 1. React 是什么？有哪些特点？

**React** 是由 Facebook 开源的用于构建用户界面的 **JavaScript 库**（注意是「库」而非完整框架，路由/状态管理需借助生态）。核心思想是**组件化**与**声明式**。

**核心特点：**

| 特点 | 说明 |
| --- | --- |
| **声明式** | 只描述 UI 应该是什么样，由 React 负责 DOM 操作 |
| **组件化** | 把 UI 拆成独立可复用的组件，便于维护 |
| **单向数据流** | 数据从父到子流动，props 只读，可预测性强 |
| **虚拟 DOM** | 用 JS 对象描述 UI，通过 Diff 计算最小更新量，减少真实 DOM 操作 |
| **JSX** | 在 JS 中书写类 HTML 的语法糖 |
| **Hooks** | 让函数组件拥有状态与副作用能力 |
| **跨平台** | 同一套思想可扩展到 React Native（移动端）、SSR 等 |

```jsx
// 声明式：只关心「要渲染成什么」
function Welcome({ name }) {
  return <h1>Hello, {name}</h1>;
}
```

**与 Vue 的简要对比：** React 更贴近 JS（JSX + 函数式），自由度更高、生态更大；Vue 提供更多官方约定（模板、指令、SFC），上手更平缓。

## 2. JSX 是什么？为什么使用 JSX？

**JSX（JavaScript XML）** 是 JS 的**语法扩展**，允许在 JS 中书写类 HTML 结构，最终会被 **Babel / SWC 编译**为 `React.createElement` 调用（React 17+ 使用新的 `jsx` 运行时，无需显式导入 React）。

```jsx
// 编写
const el = <h1 className="title">Hello</h1>;

// 编译后（经典运行时）
const el = React.createElement('h1', { className: 'title' }, 'Hello');

// 编译后（自动运行时，React 17+）
import { jsx as _jsx } from 'react/jsx-runtime';
const el = _jsx('h1', { className: 'title', children: 'Hello' });
```

**为什么用 JSX？**

- **直观**：UI 结构与逻辑就近书写，所见即所得。
- **能力完整**：可用 JS 表达式（`{}`）做条件、循环、计算。
- **编译期检查**：拼写错误、属性错误能被工具发现。
- **组件化友好**：函数调用与标签语法统一。

**语法要点：**

```jsx
const name = 'Tom';
const element = (
  <div className="box">
    {/* 注释这样写 */}
    <h1>Hello, {name}</h1>
    <img src={logo} alt="logo" />
    <input disabled={true} />
  </div>
);
```

**与 HTML 的差异：**

| HTML | JSX |
| --- | --- |
| `class` | `className` |
| `for` | `htmlFor` |
| 内联样式为字符串 | 对象：`style={{ color: 'red' }}` |
| 事件小写 `onclick` | 驼峰 `onClick` |
| 自闭合可选 | 必须闭合 `<img />` |
| 必须有单一根元素 | Fragment `<>...</>` 可多根 |

**注意：** JSX 中 `{}` 内只能是**表达式**，不能写 `if`/`for` 语句。

## 3. React 元素与组件的区别？

**React 元素（Element）**：一个**描述 UI 的普通 JS 对象**，是不可变的、最小的渲染单位。

```jsx
const element = <h1>Hello</h1>;
// 本质：{ type: 'h1', props: { children: 'Hello' } }
```

**组件（Component）**：一个**返回 React 元素的函数（或类）**，是可复用的 UI 单元。

```jsx
function Welcome() {          // 组件
  return <h1>Hello</h1>;      // 返回元素
}
```

| | React 元素 | 组件 |
| --- | --- | --- |
| 本质 | 普通对象（UI 描述） | 函数 / 类 |
| 可变性 | 不可变 | 可维护自身状态 |
| 关系 | 组件的返回值 | 元素的「生产者」 |
| 使用 | `ReactDOM.render(element)` | `<Welcome />` |

> 类比：**组件是函数，元素是函数的返回值**；元素只是「快照」，真正渲染由 React 处理。

## 4. 函数组件与类组件的区别？

| | 函数组件 | 类组件 |
| --- | --- | --- |
| 定义 | 普通函数，返回 JSX | `class extends React.Component` |
| 状态 | `useState` 等 Hooks | `this.state` / `this.setState` |
| 生命周期 | `useEffect` 模拟 | 生命周期方法 |
| `this` | 无 | 需处理 `this` 绑定 |
| 代码量 | 更少、更简洁 | 更冗长 |
| 逻辑复用 | 自定义 Hook（组合优于继承） | HOC / render props |
| 性能 | 略优（无实例开销） | 略差 |
| 错误边界 | 不能（需类组件） | 可以 |
| 现状 | **官方推荐** | 兼容维护 |

```jsx
// 函数组件
function Counter() {
  const [count, setCount] = useState(0);
  useEffect(() => {
    document.title = `count: ${count}`;
  }, [count]);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

// 类组件
class CounterClass extends React.Component {
  state = { count: 0 };
  componentDidMount() {
    document.title = `count: ${this.state.count}`;
  }
  componentDidUpdate() {
    document.title = `count: ${this.state.count}`;
  }
  render() {
    return (
      <button onClick={() => this.setState({ count: this.state.count + 1 })}>
        {this.state.count}
      </button>
    );
  }
}
```

**要点：** 函数组件无法完全替代类组件的地方是**错误边界**（需 `componentDidCatch` / `getDerivedStateFromError`），其余场景官方推荐函数组件 + Hooks。

## 5. props 与 state 的区别？

| | props | state |
| --- | --- | --- |
| 来源 | 父组件传入 | 组件内部自行维护 |
| 可变性 | **只读**，不可直接修改 | 可通过 `setState` / `useState` 修改 |
| 作用 | 组件间通信、配置 | 组件内部状态 |
| 触发重渲染 | 变化时（父重渲染） | 变化时 |
| 类比 | 函数的参数 | 函数内部变量 |

```jsx
function User({ name }) {       // props：外部传入
  const [age, setAge] = useState(18);  // state：内部维护
  return <p>{name} - {age}</p>;
}
```

**要点：**

- **props 只读**：子组件不能修改父传入的 props，需要变更时通过父组件传下的回调。
- state 应保持**最小必要**，能由 props 或已有 state 推导出的数据不要放进 state。
- 两者变化都会触发重渲染，但要注意**不可变更新**（不要直接改对象/数组）。

```jsx
// 错误：直接修改
state.obj.x = 1;

// 正确：创建新对象
setObj({ ...obj, x: 1 });
```

## 6. setState 是同步还是异步？

**结论：`setState` 本身是同步的，但「更新与渲染」在 React 的批量更新机制下被合并，导致「看起来是异步的」。**

- 在 **React 事件处理 / 生命周期（React 18 前）** 中：多次 `setState` 会被**合并（batch）** 为一次更新，读取 `this.state` 拿到的是旧值。
- 在 `setTimeout`、原生事件回调等（React 18 前的「非受控环境」）中：**不批量**，会同步更新。
- **React 18 起**：所有场景（含 `setTimeout`、Promise、原生事件）都**自动批量更新**（Automatic Batching）。

```jsx
// React 事件中：
handleClick() {
  this.setState({ count: this.state.count + 1 });
  this.setState({ count: this.state.count + 1 });
  console.log(this.state.count); // 旧值，且最终只 +1（被合并）
}
```

**对象式 vs 函数式更新：**

```jsx
// 对象式：依赖旧值，多次调用会被合并覆盖
setCount(count + 1);
setCount(count + 1); // 结果仍是 count + 1

// 函数式：基于上一次结果，安全
setCount((c) => c + 1);
setCount((c) => c + 1); // 正确 +2
```

**为什么设计成批量更新？**

- 避免每个 `setState` 都触发一次渲染，减少无效渲染，提升性能。
- 保证数据一致性（同一次事件中的多次更新一起生效）。

**想要同步拿到更新后的值：**

- 使用 `setState` 的第二个参数回调：`this.setState(updater, () => {...})`。
- 函数组件中在 `useEffect` 里读取最新值。

## 7. 组件通信有哪些方式？

| 场景 | 方式 |
| --- | --- |
| 父 → 子 | **props** 传递数据 |
| 子 → 父 | 父传**回调函数**，子调用 |
| 兄弟组件 | 状态**提升到共同父组件** |
| 跨层级 / 全局 | **Context**、`useContext` |
| 任意组件 | **状态管理库**（Redux、Zustand、MobX） |
| 父操作子实例 | `ref` + `useImperativeHandle` |
| 复杂的表单 | 受控 + 状态提升，或表单库 |

```jsx
// 父 → 子
<Child title="hello" />

// 子 → 父
function Child({ onAdd }) {
  return <button onClick={() => onAdd(1)}>+1</button>;
}

// 跨层级：Context
const ThemeContext = React.createContext('light');
const theme = useContext(ThemeContext);
```

**选择建议：**

- 层级浅、范围小 → props + 回调。
- 主题、语言、登录态等全局低频数据 → Context。
- 复杂、高频、需调试追踪 → 状态管理库（必要时再引入，避免过度设计）。

## 8. 受控组件与非受控组件

**受控组件**：表单值由 **React state 驱动**，`value` + `onChange` 同步，React 是「唯一数据源」。

```jsx
function Controlled() {
  const [value, setValue] = useState('');
  return (
    <input value={value} onChange={(e) => setValue(e.target.value)} />
  );
}
```

**非受控组件**：表单值由 **DOM 自己维护**，通过 `ref` 在需要时读取。

```jsx
function Uncontrolled() {
  const inputRef = useRef(null);
  const handleSubmit = () => console.log(inputRef.current.value);
  return (
    <>
      <input ref={inputRef} defaultValue="hello" />
      <button onClick={handleSubmit}>提交</button>
    </>
  );
}
```

| | 受控组件 | 非受控组件 |
| --- | --- | --- |
| 数据源 | React state | DOM |
| 取值 | 直接从 state | `ref.current.value` |
| 实时校验/联动 | 容易 | 较难 |
| 性能 | 每次输入都 setState | 无额外渲染 |
| 初始值 | `value` | `defaultValue` |
| 适用 | 需要即时校验、动态联动 | 简单表单、文件上传、集成第三方 DOM 库 |

**要点：** 一个组件若同时传了 `value` 却没传 `onChange`，会变成**只读**；用 `defaultValue` 才是非受控。文件 `<input type="file" />` 只能是**非受控**（出于安全，值不可设置）。

## 9. React 事件机制（合成事件）

**合成事件（SyntheticEvent）**：React 对原生事件做了一层**跨浏览器封装**，统一 API，并通过**事件委托**统一挂载到根容器上处理。

**关键点：**

1. **事件委托**：React 17 之前把事件绑在 `document` 上；**React 17 起绑在根容器（`root`）**，便于多版本共存与微前端。
2. **合成事件对象**：`e` 是 `SyntheticEvent` 实例，提供 `preventDefault`、`stopPropagation` 等统一方法。
3. **事件池（React 16 及以前）**：事件对象会被复用，异步访问属性可能为 `null`；**React 17 已移除事件池**，可安全异步访问。
4. **避免合成事件被复用**，React 17 前需调用 `e.persist()`。

```jsx
function Button() {
  const handleClick = (e) => {
    e.preventDefault();       // 阻止默认行为
    e.stopPropagation();      // 阻止冒泡
    console.log(e.nativeEvent); // 访问原生事件对象
  };
  return <button onClick={handleClick}>点我</button>;
}
```

**为什么用合成事件？**

- **性能**：事件统一委托到根节点，减少监听器数量。
- **一致性**：屏蔽浏览器差异，行为统一。
- **可控**：便于 React 统一管理事件与更新优先级。

**注意：** 合成事件与原生的 `stopPropagation` 行为在混合使用时需谨慎；原生事件绑定应使用 `useEffect` + `addEventListener`。

## 10. 条件渲染的方式

```jsx
// ① if / else：适合分支较多的场景
function Greeting({ isLogin }) {
  if (isLogin) return <h1>欢迎回来</h1>;
  return <h1>请登录</h1>;
}

// ② 三元运算符：适合二选一
{isLogin ? <LogoutBtn /> : <LoginBtn />}

// ③ 逻辑与 &&：适合「满足才显示」
{list.length > 0 && <List data={list} />}

// ④ 三元取 null：控制显示隐藏
{visible ? <Modal /> : null}

// ⑤ 变量提取：逻辑复杂时更清晰
let content;
if (isLoading) content = <Spinner />;
else content = <List />;
```

**易错点（`&&` 陷阱）：**

```jsx
// count 为 0 时，会渲染出 0 本身！
{count && <div>{count}</div>}

// 修复：显式判断
{count > 0 && <div>{count}</div>}
{!!count && <div>{count}</div>}
```

> 原则：优先保证可读性，复杂条件抽成变量或提前 `return`。

## 11. 列表渲染与 key 的作用

用 `map` 渲染列表时必须给每项加 `key`。

```jsx
const list = [{ id: 1, name: 'a' }, { id: 2, name: 'b' }];

<ul>
  {list.map((item) => (
    <li key={item.id}>{item.name}</li>
  ))}
</ul>
```

**key 的作用：** 帮助 React 在 Diff 时**识别哪些元素发生了变化、被添加或删除**，从而**复用**已有 DOM、减少不必要的重建。

**为什么不要用数组索引作为 key？**

```jsx
// 反例：用 index 作 key
{list.map((item, index) => <Item key={index} />)}
```

- 列表**顺序变化**（插入/删除/排序）时，索引对应的元素会「错位」，导致 React 复用错误的 DOM。
- 对于**带内部状态或非受控输入**的项，会出现输入框内容错乱、状态残留等问题。

**key 的要点：**

- key 只需在**兄弟节点间唯一**，不必全局唯一；用稳定唯一 ID 最佳。
- key 变化会让 React **卸载旧组件、挂载新组件**（可用于重置组件状态）。
- **不要**在 `map` 渲染时用随机数（`Math.random()`）作 key，否则每次渲染都重建。

## 12. 生命周期有哪些？各阶段做什么？

**三个阶段：挂载（Mount）、更新（Update）、卸载（Unmount）**。

| 阶段 | 类组件方法 | 说明 | 函数组件对应 |
| --- | --- | --- | --- |
| 挂载 | `constructor` | 初始化 state、绑定 this | `useState` 初始化 |
| 挂载 | `static getDerivedStateFromProps` | 由 props 派生 state（少用） | 渲染期计算 |
| 挂载 | `render` | 返回 UI（纯函数） | 组件函数体 |
| 挂载 | `componentDidMount` | 请求、订阅、DOM 操作 | `useEffect(fn, [])` |
| 更新 | `shouldComponentUpdate` | 是否重渲染（性能优化） | `memo` |
| 更新 | `getSnapshotBeforeUpdate` | 更新前读取 DOM（如滚动位置） | `useLayoutEffect` |
| 更新 | `componentDidUpdate` | 更新后副作用 | `useEffect(fn, [dep])` |
| 卸载 | `componentWillUnmount` | 清理定时器、取消订阅 | `useEffect` 返回的清理函数 |
| 错误 | `componentDidCatch` / `getDerivedStateFromError` | 捕获子组件错误 | 无法替代（需类组件） |

**已废弃的生命周期（UNSAFE_）：**

- `componentWillMount`、`componentWillReceiveProps`、`componentWillUpdate`
- 原因：在异步渲染（Fiber/并发）下可能被**多次调用**，产生副作用不可控。

```jsx
class Demo extends React.Component {
  componentDidMount() {
    this.timer = setInterval(() => {}, 1000);
  }
  componentWillUnmount() {
    clearInterval(this.timer);   // 必须清理，否则内存泄漏
  }
  render() {
    return <div />;
  }
}
```

**常用口诀：**

- **挂载时请求数据/订阅** → `componentDidMount` / `useEffect([])`。
- **依赖变化时执行副作用** → `componentDidUpdate` / `useEffect([dep])`。
- **卸载时清理** → `componentWillUnmount` / `useEffect` 清理函数。

## 13. React 中的 refs 有哪些用法？

**ref** 用于访问 DOM 节点或组件实例，以及保存**不触发渲染的可变值**。

**① 访问 DOM：**

```jsx
function Input() {
  const ref = useRef(null);
  const focus = () => ref.current.focus();
  return <input ref={ref} />;
}
```

**② 保存可变值（不触发渲染）：**

```jsx
const timerRef = useRef(null);
useEffect(() => {
  timerRef.current = setInterval(() => {}, 1000);
  return () => clearInterval(timerRef.current);
}, []);
```

**③ 转发 ref 给子组件（`forwardRef`）：**

```jsx
const Input = React.forwardRef((props, ref) => <input ref={ref} {...props} />);
```

**④ 暴露指定方法（`useImperativeHandle`）：**

```jsx
const Input = forwardRef((props, ref) => {
  const inputRef = useRef(null);
  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current.focus(),
  }));
  return <input ref={inputRef} />;
});
```

**⑤ 回调 ref：**

```jsx
const setRef = (node) => { /* node 为挂载后的 DOM，卸载时收到 null */ };
<div ref={setRef} />;
```

**要点：**

- `useRef` 的 `.current` 修改**不会触发重渲染**（区别于 state）。
- ref 在**提交（commit）阶段**被赋值，`render` 期间 `ref.current` 尚不可靠。
- 不要滥用 ref 直接操作 DOM，优先用声明式方式。

## 14. 高阶组件 HOC

**高阶组件（Higher-Order Component）**：接收一个组件，返回一个**新组件**的函数，用于**逻辑复用**。

```jsx
function withLoading(WrappedComponent) {
  return function WithLoading({ isLoading, ...rest }) {
    if (isLoading) return <Spinner />;
    return <WrappedComponent {...rest} />;
  };
}

const ListWithLoading = withLoading(List);
```

**要点：**

- HOC 是**纯函数**，不修改原组件，而是返回增强后的新组件。
- **不要**在 `render` 中创建 HOC（每次渲染都会产生新组件类型，导致子树整体重挂载）：

  ```jsx
  // 错误
  render() {
    const Enhanced = withLoading(List);  // 每次渲染都新建
    return <Enhanced />;
  }
  ```

- **必须透传 props**：`<Wrapped {...this.props} />`。
- **ref 不会自动透传**，需要 `forwardRef`。
- 使用 `displayName` 便于调试：`WithLoading.displayName = 'WithLoading(List)'`。
- 避免多层嵌套（wrapper hell），Hooks 时代优先用**自定义 Hook**替代 HOC 做逻辑复用。

**典型用途：** 权限校验、日志埋点、加载态、错误处理、Context 注入。

## 15. render props 与组合模式

**Render Props**：通过名为 `render`（或 `children`）的 props 传入一个**返回 React 元素的函数**，把渲染逻辑交给调用方。

```jsx
function MouseTracker({ render }) {
  const [pos, setPos] = useState({ x: 0, y: 0 });
  return (
    <div onMouseMove={(e) => setPos({ x: e.clientX, y: e.clientY })}>
      {render(pos)}
    </div>
  );
}

// 使用
<MouseTracker render={({ x, y }) => <p>{x}, {y}</p>} />;
```

**children as function（等价写法）：**

```jsx
<MouseTracker>
  {({ x, y }) => <p>{x}, {y}</p>}
</MouseTracker>
```

**组合模式（Composition）**：用 `children` 与具名 props 组装 UI，是 React 推荐的复用方式。

```jsx
function Card({ header, children, footer }) {
  return (
    <div className="card">
      <div className="header">{header}</div>
      <div className="body">{children}</div>
      <div className="footer">{footer}</div>
    </div>
  );
}
```

**对比：**

| 方式 | 特点 | 现状 |
| --- | --- | --- |
| HOC | 包裹组件增强，易产生嵌套地狱 | 仍然可用 |
| Render Props | 渲染逻辑交给调用方，灵活 | 部分被 Hooks 取代 |
| **组合（children）** | 最直观、无额外抽象 | **官方推荐** |
| 自定义 Hook | 复用**逻辑**而非 UI | **现在首选** |

> 原则：**组合优于继承**。复用「行为」用自定义 Hook，复用「结构」用 `children` / 组合。

## 16. 错误边界 Error Boundary

**错误边界**：一个**类组件**，能捕获**其子树**在渲染、生命周期、构造函数中抛出的错误，并渲染降级 UI，避免整个应用白屏。

```jsx
class ErrorBoundary extends React.Component {
  state = { hasError: false };

  static getDerivedStateFromError(error) {
    return { hasError: true };  // 渲染降级 UI
  }

  componentDidCatch(error, info) {
    // 上报错误日志
    console.error(error, info.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return <h1>出错了，请稍后重试</h1>;
    }
    return this.props.children;
  }
}

// 使用
<ErrorBoundary>
  <MyWidget />
</ErrorBoundary>
```

**能捕获：** 渲染阶段、生命周期、子组件构造函数中的错误。

**不能捕获：**

- **事件处理函数**中的错误（用 `try/catch`）。
- **异步代码**（`setTimeout`、Promise）中的错误。
- **服务端渲染**的错误。
- **错误边界自身**抛出的错误。

**要点：**

- 必须用**类组件**实现（函数组件暂不支持，可借助 `react-error-boundary` 库）。
- 应在**多处、细粒度**地包裹，而非只包在根节点。
- 事件与异步错误需自行 `try/catch` 并交给错误边界处理（如把错误存入 state 触发降级）。

```jsx
function MyButton() {
  const [error, setError] = useState(null);
  const onClick = () => {
    try { risky(); } catch (e) { setError(e); }  // 转为渲染期错误
  };
  if (error) throw error;  // 交给上层 ErrorBoundary
  return <button onClick={onClick}>点我</button>;
}
```
