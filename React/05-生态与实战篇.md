## 1. React 路由原理（History 与 Hash）

**核心原理：** 前端路由通过监听 **URL 变化**，在不刷新页面的前提下切换组件。

**两种模式：**

| | Hash 模式 | History 模式 |
| --- | --- | --- |
| URL 形式 | `example.com/#/user` | `example.com/user` |
| 监听事件 | `hashchange` | `popstate` |
| 改变方式 | `location.hash = '#/user'` | `history.pushState` / `replaceState` |
| 服务端配置 | 无需 | **需配置 fallback 到 index.html** |
| 兼容性 | 好 | 现代浏览器均可 |

```js
// Hash：通过 hash 变化触发
window.addEventListener('hashchange', () => render(location.hash));

// History：pushState 不触发 popstate，需手动通知
window.history.pushState({}, '', '/user');
window.addEventListener('popstate', () => render(location.pathname));
```

**要点：**

- `history.pushState` **不会触发 `popstate`**，只改变 URL；前进/后退才触发 `popstate`。因此路由库在 `push` 后需**手动触发一次渲染**。
- History 模式刷新页面时浏览器会请求该路径，需服务端把 `/*` 都返回 `index.html`（Nginx `try_files`）。
- 路由匹配本质是**把 path 解析为组件**，并支持**动态参数、嵌套路由、懒加载**。

## 2. React Router 常用 API 与用法

**v6 主要 API：**

```jsx
import {
  BrowserRouter, Routes, Route, Link, NavLink,
  useNavigate, useParams, useSearchParams, useLocation, Outlet,
} from 'react-router-dom';

<BrowserRouter>
  <Routes>
    <Route path="/" element={<Layout />}>
      <Route index element={<Home />} />
      <Route path="users/:id" element={<UserDetail />} />
      <Route path="*" element={<NotFound />} />
    </Route>
  </Routes>
</BrowserRouter>;

// 布局 + 嵌套路由
function Layout() {
  return (
    <>
      <nav><NavLink to="/">首页</NavLink></nav>
      <Outlet />   {/* 子路由渲染位置 */}
    </>
  );
}
```

**常用 Hook：**

```jsx
const navigate = useNavigate();
const { id } = useParams();                 // 动态参数
const [searchParams] = useSearchParams();   // query 参数
const location = useLocation();             // 当前路径信息

navigate('/user/1');                        // 跳转
navigate(-1);                               // 后退
navigate('/user', { replace: true });       // 替换历史
searchParams.get('page');                   // ?page=2
```

**v6 相比 v5 的变化：**

- `<Switch>` → `<Routes>`；`component`/`render` → `element`。
- 路由匹配改为**精确匹配优先 + 最佳匹配**，不再需要 `exact`。
- 嵌套路由用 `<Outlet>`，配置更直观。
- 新增 `useNavigate` 取代 `useHistory`。
- 数据路由（v6.4+）：`loader`、`action`、`createBrowserRouter`。

```jsx
// v6.4 数据路由
const router = createBrowserRouter([
  { path: '/', element: <Home />, loader: () => fetchData() },
]);
```

## 3. 状态管理方案对比

| 方案 | 特点 | 适用 |
| --- | --- | --- |
| **Context + useReducer** | React 内置，无依赖 | 低频全局数据（主题、语言、登录态） |
| **Redux / RTK** | 单向数据流、可预测、中间件、DevTools | 大型复杂应用、需要严格规范与调试 |
| **Zustand** | 极简、Hook 式、无 Provider、细粒度订阅 | 中小型项目、追求开发效率 |
| **MobX** | 响应式、面向对象、自动追踪依赖 | 复杂模型、习惯 OOP |
| **Jotai / Recoil** | 原子化（atom），细粒度 | 组件间细粒度共享状态 |
| **Valtio** | Proxy 代理式，可变写法 | 喜欢直观可变写法 |

**选择建议：**

```
低频全局数据     → Context
中小项目/快速开发 → Zustand
大型/团队规范     → Redux Toolkit
细粒度组件状态    → Jotai / Recoil
```

**要不要用状态管理库？** 优先考虑：

1. 能否用**状态提升**或 **Context** 解决？
2. 是否是**服务端数据**（应交给 React Query / SWR 做缓存与同步）？
3. 只有**真正需要跨组件共享的客户端状态**才引入状态库，避免过度设计。

## 4. Redux 的核心概念与数据流

**三大原则：**

1. **单一数据源**：整个应用状态存在一个 `store` 中。
2. **状态只读**：只能通过 `dispatch(action)` 修改。
3. **纯函数修改**：`reducer` 是纯函数，返回新的 state。

**核心概念：**

| 概念 | 说明 |
| --- | --- |
| `store` | 保存全局状态的对象 |
| `action` | 描述「发生了什么」的普通对象，含 `type` |
| `reducer` | `(state, action) => newState` 的纯函数 |
| `dispatch` | 派发 action 的唯一方式 |
| `middleware` | 拦截 dispatch，处理异步/日志（thunk、saga） |
| `selector` | 从 state 提取数据的函数 |

**单向数据流：**

```
UI 事件 → dispatch(action) → middleware → reducer(纯函数) → 新 store → 订阅者更新 → UI 重渲染
```

```js
// 简化实现
function createStore(reducer) {
  let state;
  const listeners = [];
  const getState = () => state;
  const dispatch = (action) => {
    state = reducer(state, action);
    listeners.forEach((l) => l());
  };
  const subscribe = (l) => { listeners.push(l); return () => { /* 取消订阅 */ }; };
  dispatch({ type: '@@INIT' });
  return { getState, dispatch, subscribe };
}
```

**要点：** Redux 的价值在于**可预测性 + 可调试性（时间旅行）+ 中间件生态**，代价是**样板代码多**（RTK 已大幅简化）。

## 5. Redux Toolkit 与异步方案

**Redux Toolkit（RTK）** 是官方推荐的 Redux 写法，简化样板代码。

```js
import { createSlice, configureStore } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: (state) => { state.value += 1; },       // 内部用 Immer，可直接「改」
    decrement: (state) => { state.value -= 1; },
    addBy: (state, action) => { state.value += action.payload; },
  },
});

export const { increment, decrement, addBy } = counterSlice.actions;

const store = configureStore({ reducer: { counter: counterSlice.reducer } });
```

**异步方案对比：**

| 方案 | 说明 | 特点 |
| --- | --- | --- |
| `redux-thunk` | action 返回函数，函数内做异步 | 简单、RTK 内置 |
| `redux-saga` | 用 Generator 管理副作用 | 强大、可测试、学习成本高 |
| `redux-observable` | 基于 RxJS | 适合复杂流 |
| **RTK Query** | 内置数据请求与缓存方案 | 自动缓存/失效/轮询，替代手写异步 |

**RTK Query 示例：**

```js
const api = createApi({
  baseQuery: fetchBaseQuery({ baseUrl: '/api' }),
  endpoints: (build) => ({
    getUser: build.query({ query: (id) => `/user/${id}` }),
    addUser: build.mutation({ query: (body) => ({ url: '/user', method: 'POST', body }) }),
  }),
});

const { data, isLoading } = useGetUserQuery(1);
```

**要点：**

- RTK 内部用 **Immer**，允许「直接修改」写法，实际仍生成不可变新状态。
- **服务端数据**推荐 RTK Query / React Query，**客户端状态**用 slice，二者分工明确。

## 6. Zustand 为什么流行？

**Zustand** 是轻量的状态管理库，基于「**外部 store + `useSyncExternalStore`**」实现。

```jsx
import { create } from 'zustand';

const useStore = create((set) => ({
  count: 0,
  inc: () => set((s) => ({ count: s.count + 1 })),
  reset: () => set({ count: 0 }),
}));

function Counter() {
  const count = useStore((s) => s.count);   // 选择器：只订阅需要的部分
  const inc = useStore((s) => s.inc);
  return <button onClick={inc}>{count}</button>;
}
```

**优点：**

- **极简 API**：无需 Provider、无需 action/reducer 样板。
- **细粒度订阅**：用 selector 只订阅关心的字段，避免无关重渲染。
- **无包裹地狱**：可在任意位置直接 `useStore`。
- **体积小**、性能好。
- 支持 `middleware`（persist、immer、devtools）。

```jsx
// 持久化 + 不可变写法
const useStore = create(
  persist(
    immer((set) => ({ count: 0, inc: () => set((s) => { s.count += 1; }) })),
    { name: 'counter' }
  )
);
```

**要点：**

- 用 selector 时注意**返回新对象会每次都变化**（需 `useShallow` 或返回基本类型）。
- 与 Redux 的差异：Zustand 更轻、学习成本低；Redux 规范更强、生态与调试工具更完整。

## 7. React 中的样式方案

| 方案 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **全局 CSS** | 传统 `import './x.css'` | 简单 | 命名冲突、无作用域 |
| **CSS Modules** | `.module.css`，编译生成哈希类名 | 局部作用域、无运行时开销 | 动态样式不便 |
| **CSS-in-JS** | styled-components、emotion | 动态、可传 props、与组件同源 | 运行时开销、包体大 |
| **Utility-first** | Tailwind CSS | 快速、无命名、产物小 | 类名冗长、可读性争议 |
| **原子化 CSS-in-JS** | vanilla-extract | 零运行时、类型安全 | 学习成本 |
| **Shadow DOM / scoped** | 较少用 | 强隔离 | 生态支持一般 |

```jsx
// CSS Modules
import styles from './Button.module.css';
<button className={styles.primary} />;

// styled-components
const Button = styled.button`
  color: ${(p) => (p.primary ? 'white' : 'black')};
  background: ${(p) => (p.primary ? 'blue' : 'gray')};
`;

// Tailwind
<button className="px-4 py-2 bg-blue-500 text-white rounded" />;
```

**趋势：** 从**运行时 CSS-in-JS**（styled-components）转向**零运行时方案**（Tailwind、vanilla-extract、CSS Modules）以改善首屏与 React 18 并发兼容性（`useInsertionEffect` 就是为此引入的）。

## 8. CSR、SSR、SSG、ISR 的区别与选型

| 模式 | 何时渲染 | 首屏 | SEO | 适用 |
| --- | --- | --- | --- | --- |
| **CSR** | 浏览器运行时 | 慢（白屏） | 差 | 后台系统、交互密集应用 |
| **SSR** | 每次请求在服务端 | 快 | 好 | 电商、内容站、需 SEO 且动态 |
| **SSG** | 构建时预生成 | 最快 | 好 | 博客、文档、营销页 |
| **ISR** | 静态 + 定期/按需再生成 | 快 | 好 | 大量内容、更新不频繁 |

**Next.js 对应：**

```jsx
// SSG
export async function getStaticProps() { /* 构建时执行 */ }

// ISR
export async function getStaticProps() {
  return { props: {}, revalidate: 60 };   // 60 秒后重新生成
}

// SSR
export async function getServerSideProps() { /* 每次请求执行 */ }
```

**关键概念：**

- **水合（Hydration）**：服务端 HTML 到达后，客户端 JS 接管、绑定事件，页面变为可交互。
- **hydration mismatch**：服务端与客户端首屏不一致会报错（时间、随机数、浏览器 API 等）。
- **流式 SSR**：HTML 分块传输，先展示可交互部分（React 18 `renderToPipeableStream`）。
- **RSC（React Server Components）**：组件在服务端渲染，不发送其 JS 到客户端，减少包体（Next.js App Router）。

**选型建议：** 需 SEO 且内容动态 → SSR；内容静态 → SSG/ISR；后台/内部系统 → CSR 足够。

## 9. React 表单处理方案

**① 受控组件**（简单表单）：

```jsx
const [form, setForm] = useState({ name: '', age: '' });
const onChange = (e) => setForm({ ...form, [e.target.name]: e.target.value });
```

**② 非受控 + ref**（简单、少校验）：

```jsx
const formRef = useRef();
const onSubmit = () => console.log(formRef.current.name.value);
```

**③ 表单库 `react-hook-form`**（推荐大表单）：

```jsx
import { useForm } from 'react-hook-form';

function MyForm() {
  const { register, handleSubmit, formState: { errors } } = useForm();
  const onSubmit = (data) => console.log(data);

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('name', { required: '请输入姓名' })} />
      {errors.name && <p>{errors.name.message}</p>}
      <input type="submit" />
    </form>
  );
}
```

**对比：**

| | 受控 | 非受控 | react-hook-form |
| --- | --- | --- | --- |
| 重渲染 | 每次输入都渲染 | 无 | **极少**（订阅式） |
| 校验 | 手写 | 手写 | 内置 + 集成 zod/yup |
| 大表单性能 | 差 | 好 | 好 |
| 复杂度 | 低 | 低 | 中 |

**要点：**

- 大表单优先**非受控 + 订阅式**（react-hook-form），避免每个输入触发整表重渲染。
- 校验可用 `zod` + `@hookform/resolvers` 做类型安全的 schema 校验。
- 客户端校验只为体验，**服务端必须再校验**。

## 10. 手写自定义 Hook：useDebounce 与 useRequest

**`useDebounce`：**

```jsx
function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);   // 值或 delay 变化时重置
  }, [value, delay]);

  return debounced;
}

// 使用
const [query, setQuery] = useState('');
const debouncedQuery = useDebounce(query, 500);
useEffect(() => { if (debouncedQuery) search(debouncedQuery); }, [debouncedQuery]);
```

**`useRequest`（含竞态与清理）：**

```jsx
function useRequest(fn, deps = []) {
  const [state, setState] = useState({ data: null, loading: true, error: null });

  useEffect(() => {
    let cancelled = false;                 // 防止竞态：旧请求覆盖新结果
    setState((s) => ({ ...s, loading: true }));

    fn()
      .then((data) => { if (!cancelled) setState({ data, loading: false, error: null }); })
      .catch((error) => { if (!cancelled) setState({ data: null, loading: false, error }); });

    return () => { cancelled = true; };    // 依赖变化或卸载时取消
  }, deps);

  return state;
}
```

**要点：**

- **竞态问题**：快速切换参数时，旧请求可能后返回并覆盖新结果 → 用 `cancelled` 标记或 `AbortController`。
- **卸载后 setState** 会告警 → 用 `cancelled` 或 `isMounted` 判断。
- 生产环境推荐 `react-query` / `swr`，内置缓存、重试、聚焦刷新、竞态处理。

## 11. Portal 与 Modal 实现

**Portal** 把子节点渲染到**父组件 DOM 层级之外**的节点（如 `document.body`），常用于 Modal、Tooltip、Dropdown（避免 `overflow: hidden`、`z-index` 层叠问题）。

```jsx
import { createPortal } from 'react-dom';

function Modal({ open, onClose, children }) {
  useEffect(() => {
    const onKey = (e) => e.key === 'Escape' && onClose();
    document.addEventListener('keydown', onKey);
    document.body.style.overflow = open ? 'hidden' : '';  // 锁定滚动
    return () => {
      document.removeEventListener('keydown', onKey);
      document.body.style.overflow = '';
    };
  }, [open, onClose]);

  if (!open) return null;

  return createPortal(
    <div className="overlay" onClick={onClose}>
      <div className="modal" onClick={(e) => e.stopPropagation()}>
        {children}
      </div>
    </div>,
    document.body
  );
}
```

**要点与坑：**

- **React 事件冒泡仍按 React 树传播**（Portal 不改变 React 树结构），但**原生 DOM 事件**按真实 DOM 层级传播。
- 需处理**滚动锁定、焦点管理（focus trap）、ESC 关闭、点击遮罩关闭**、无障碍（`role="dialog"`、`aria-modal`）。
- 可封装为 `usePortal` 自定义 Hook，动态创建/销毁挂载节点。

```jsx
function usePortal(id = 'portal-root') {
  const el = useRef(document.getElementById(id) || document.createElement('div'));
  useEffect(() => {
    el.current.id = id;
    document.body.appendChild(el.current);
    return () => { document.body.removeChild(el.current); };
  }, [id]);
  return el.current;
}
```

## 12. 场景设计：组件库与主题系统

**设计要求：**

1. **API 一致**：统一 `size`、`variant`、`disabled` 等命名。
2. **可组合**：用 `children` 与组合式 API，而非大量布尔 props。
3. **可扩展样式**：`className` + `style` 透传，支持自定义。
4. **主题系统**：CSS 变量或 Context 提供主题，支持暗色模式与定制。
5. **类型完善**：导出 Props 类型，用泛型支持不同类型。
6. **无障碍**：语义化标签、键盘可达、ARIA 属性。

**主题实现（CSS 变量 + Context）：**

```jsx
const ThemeContext = createContext('light');

function ThemeProvider({ theme, children }) {
  useEffect(() => {
    document.documentElement.dataset.theme = theme;  // 配合 CSS 变量
  }, [theme]);
  return <ThemeContext.Provider value={theme}>{children}</ThemeContext.Provider>;
}
```

```css
:root { --primary: #1677ff; --bg: #fff; --text: #333; }
[data-theme='dark'] { --primary: #4096ff; --bg: #141414; --text: #eee; }
```

**Props 透传与前向：**

```tsx
type ButtonProps = React.ButtonHTMLAttributes<HTMLButtonElement> & {
  variant?: 'primary' | 'ghost';
};
const Button = React.forwardRef<HTMLButtonElement, ButtonProps>(
  ({ variant = 'primary', className, ...rest }, ref) => (
    <button ref={ref} className={`btn btn-${variant} ${className ?? ''}`} {...rest} />
  )
);
```

**要点：** 组件库的核心是**稳定的 API 契约**与**可定制性**，需权衡「灵活性」与「约束性」。

## 13. 场景设计：权限控制与路由守卫

**① 组件级权限（HOC / Hook）：**

```jsx
function usePermission(required) {
  const { permissions } = useUser();
  return permissions.includes(required);
}

function AuthButton({ permission, children }) {
  const allowed = usePermission(permission);
  return allowed ? children : null;
}
```

**② 路由守卫（包裹路由）：**

```jsx
function RequireAuth({ children }) {
  const { user, loading } = useUser();
  const location = useLocation();

  if (loading) return <Spinner />;
  if (!user) return <Navigate to="/login" state={{ from: location }} replace />;
  return children;
}

<Route path="/admin" element={<RequireAuth><Admin /></RequireAuth>} />
```

**③ 基于角色的路由（动态生成）：**

```jsx
const routes = [
  { path: '/dashboard', element: <Dashboard />, roles: ['user', 'admin'] },
  { path: '/admin', element: <Admin />, roles: ['admin'] },
];

const allowed = routes.filter((r) => r.roles.some((role) => user.roles.includes(role)));
```

**④ 按钮/菜单级控制：**

```jsx
<Can permission="user:delete">
  <Button>删除</Button>
</Can>
```

**要点：**

- **前端权限只是体验优化**，真正的权限校验必须在**服务端**做（接口鉴权）。
- 权限粒度：路由级、菜单级、按钮级、字段级（按需选择）。
- 登录态恢复（刷新保持）配合 token + 请求拦截器（`axios` interceptor）。

## 14. 常见实战问题排查

**① 列表渲染错乱 / 输入框内容串位**

- 原因：用**数组索引**作 `key`，列表顺序变化时 DOM 复用错位。
- 解决：用**稳定唯一 ID** 作 key。

**② 请求竞态（race condition）**

- 现象：快速切换筛选条件，旧请求后返回覆盖了新数据。
- 解决：`cancelled` 标记、`AbortController`、或用 React Query/SWR。

```jsx
useEffect(() => {
  const ctrl = new AbortController();
  fetch(url, { signal: ctrl.signal }).then(/* ... */).catch(() => {});
  return () => ctrl.abort();
}, [url]);
```

**③ 内存泄漏**

- 打字：组件卸载后 `setState`、未清理的定时器/订阅/事件监听。
- 解决：`useEffect` 清理函数、`AbortController`、移除监听。

**④ 无限重渲染（Maximum update depth exceeded）**

- 原因：在 `render` 中调用 `setState`、effect 依赖不稳定导致循环、`setState` 传了新对象每次引用变化。
- 解决：检查 effect 依赖、用函数式更新、稳定依赖引用。

**⑤ 状态更新不生效**

- 原因：直接修改 state（`state.x = 1`）、依赖闭包旧值。
- 解决：用不可变更新、函数式更新。

**⑥ `useEffect` 执行两次（开发环境）**

- 原因：StrictMode 刻意双调用，用于暴露副作用问题。
- 解决：正确实现清理函数或让副作用幂等；不要「修复」成只执行一次。

**⑦ 样式不生效 / 被覆盖**

- 原因：CSS Modules 类名哈希、样式优先级、Portal 渲染到 body 外。
- 解决：确认类名拼接、提高具体度、用 `:where()` 或 `styled-components`。

**⑧ Context 导致大面积重渲染**

- 原因：Provider 的 `value` 每次渲染都是新对象。
- 解决：`useMemo` 稳定 value、拆分 Context、改用细粒度状态库。

**⑨ 组件不更新（props 变化但界面不变）**

- 原因：`React.memo` 浅比较判定「相等」、直接修改了传入的对象。
- 解决：确保不可变更新，或自定义比较函数。

**⑩ `key` 导致状态重置**

- 现象：给组件一个变化的 `key` 会强制重建（有时是**故意**用来重置状态）。
- 解决：明确 `key` 的用途，避免误用。

**排查思路：** 先看控制台报错 → 用 DevTools Profiler 看渲染 → 定位是「渲染问题 / 数据问题 / 副作用问题」→ 最小化复现 → 针对性修复。
