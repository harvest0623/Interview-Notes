## 1. memo、useMemo、useCallback 的区别

| | `React.memo` | `useMemo` | `useCallback` |
| --- | --- | --- | --- |
| 类型 | **高阶组件** | Hook | Hook |
| 作用对象 | **组件** | 计算结果（值） | 函数 |
| 作用 | 浅比较 props，相同则跳过重渲染 | 缓存计算值 | 缓存函数引用 |
| 使用位置 | 包裹组件 | 组件内部 | 组件内部 |

```jsx
// React.memo：props 不变则跳过渲染
const Child = React.memo(function Child({ value }) {
  return <div>{value}</div>;
});

// useMemo：缓存昂贵计算
const total = useMemo(() => items.reduce((s, i) => s + i.price, 0), [items]);

// useCallback：缓存函数引用，配合 memo 使用
const handleClick = useCallback(() => setCount((c) => c + 1), []);
```

**三者协作：** 父组件把**对象/函数**作为 props 传给 `memo` 子组件时，必须用 `useMemo`/`useCallback` 稳定引用，否则每次渲染都是新引用，`memo` 失效。

```jsx
const Child = React.memo(({ onSave, config }) => { /* ... */ });

function Parent() {
  const onSave = useCallback(() => {}, []);          // 稳定引用
  const config = useMemo(() => ({ a: 1 }), []);      // 稳定引用
  return <Child onSave={onSave} config={config} />;
}
```

**要点：**

- 三者都是**优化手段**，不是必需品；先测量瓶颈再优化。
- `memo` 的比较有成本，浅比较大对象可能得不偿失。
- `memo` 只做**浅比较**，深层对象变化检测不到。

## 2. React.memo 与 PureComponent

| | `React.memo` | `PureComponent` |
| --- | --- | --- |
| 适用 | **函数组件** | 类组件 |
| 比较方式 | 浅比较 props | 浅比较 props 与 state |
| 是否可自定义 | 可传第二个参数比较函数 | 只能重写 `shouldComponentUpdate` |

```jsx
// PureComponent：自动浅比较 props/state
class List extends React.PureComponent {
  render() { return <div>{this.props.items.length}</div>; }
}

// memo：函数组件版本
const List2 = React.memo(function List({ items }) {
  return <div>{items.length}</div>;
});

// 自定义比较（返回 true 表示「相等，跳过渲染」）
const List3 = React.memo(function List({ items }) {
  return <div>{items.length}</div>;
}, (prevProps, nextProps) => prevProps.items.length === nextProps.items.length);
```

**关键坑：浅比较对引用类型无效**

```jsx
// 每次渲染都传新对象/数组 → 浅比较判定为「不等」→ memo 失效
<List items={[1, 2, 3]} />            // 每次都是新数组
<List onClick={() => {}} />            // 每次都是新函数
<List items={items} onClick={handle} /> // 正确：用稳定引用
```

**要点：**

- 没有 props 的组件用 `memo` 收益最大（可完全阻断重渲染）。
- `memo` 不会阻止**自身 state 变化**引起的渲染。
- 传对象/函数作为 props 时，配合 `useMemo`/`useCallback` 或在父层稳定引用。

## 3. 如何避免不必要的重渲染？

**① 用 `React.memo` 阻断父组件带来的无意义重渲染**

```jsx
const Item = React.memo(function Item({ data }) { /* ... */ });
```

**② 稳定引用：`useMemo` / `useCallback`**

```jsx
const onSelect = useCallback((id) => setSelected(id), []);
const options = useMemo(() => list.filter(Boolean), [list]);
```

**③ 状态就近原则**：把 state 放在**真正需要它的最近公共父组件**，避免提升过高导致大面积重渲染。

**④ `children` 透传（组件作为 props 不变）**

```jsx
// ExpensiveTree 的 element 引用未变，重渲染被阻断
<Layout>
  <ExpensiveTree />
</Layout>

function Layout({ children }) {
  const [count, setCount] = useState(0);
  return (
    <div onClick={() => setCount(count + 1)}>
      {count}
      {children}   {/* 不会因 count 变化而重渲染 */}
    </div>
  );
}
```

**⑤ 拆分与状态下沉**：把频繁变化的状态隔离到小子组件。

**⑥ Context 优化**：拆分为多个 Context、用 `useMemo` 稳定 `value`。

**⑦ 避免在 render 中做重计算**：用 `useMemo` 缓存。

**⑧ 使用 `useTransition`/`useDeferredValue`**：把非紧急更新降级，保持输入流畅。

**⑨ 正确使用 `key`**：不要用随机数作 key，避免整列表重建。

> 原则：**先定位瓶颈**（Profiler），再针对性优化；不要盲目到处加 `memo`/`useMemo`。

## 4. 代码分割与懒加载

**目的：** 减小首屏包体，按需加载，加速首屏。

**① `React.lazy` + `Suspense`：**

```jsx
const Detail = React.lazy(() => import('./Detail'));

function App() {
  return (
    <Suspense fallback={<Spinner />}>
      <Detail />
    </Suspense>
  );
}
```

**② 路由级分割：**

```jsx
const Home = lazy(() => import('./pages/Home'));
const About = lazy(() => import('./pages/About'));

<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/about" element={<About />} />
</Routes>
```

**③ 动态导入（按需触发）：**

```jsx
const onOpen = async () => {
  const { Modal } = await import('./Modal');
  setComp(() => Modal);
};
```

**④ 预加载（提前加载可能用到的模块）：**

```jsx
// 鼠标悬停时预取
<Link onMouseEnter={() => import('./Detail')}>详情</Link>
```

**⑤ 命名导出与分割：**

```jsx
// 只加载需要的部分（配合 webpack magic comment）
const Chart = lazy(() => import(/* webpackChunkName: "chart" */ './Chart'));
```

**要点：**

- 分割粒度：**路由级**最常用；组件级（大依赖如富文本编辑器、图表库）收益明显。
- 配合 `Suspense` 提供加载态；`lazy` 组件必须**默认导出**。
- 过度分割会增加请求数，需权衡。

## 5. 长列表优化（虚拟列表）

**问题：** 渲染上万条 DOM 会导致创建慢、内存高、滚动卡顿。

**虚拟列表（Virtual List）原理：** 只渲染**可视区域 + 少量缓冲**的项，用「占位高度」撑起滚动条，滚动时根据 `scrollTop` 计算需要渲染的区间。

```jsx
function VirtualList({ items, itemHeight = 40, height = 400 }) {
  const [scrollTop, setScrollTop] = useState(0);

  const start = Math.floor(scrollTop / itemHeight);
  const visibleCount = Math.ceil(height / itemHeight);
  const end = start + visibleCount;
  const visibleItems = items.slice(start, end + 1);

  return (
    <div
      style={{ height, overflowY: 'auto' }}
      onScroll={(e) => setScrollTop(e.currentTarget.scrollTop)}
    >
      {/* 撑起总高度 */}
      <div style={{ height: items.length * itemHeight, position: 'relative' }}>
        {/* 可视项通过 translateY 偏移到正确位置 */}
        <div style={{ transform: `translateY(${start * itemHeight}px)` }}>
          {visibleItems.map((item, i) => (
            <div key={start + i} style={{ height: itemHeight }}>
              {item.text}
            </div>
          ))}
        </div>
      </div>
    </div>
  );
}
```

**要点与进阶：**

- **动态高度**：需测量每项高度并缓存，实现更复杂（`react-window` 的 `VariableSizeList`）。
- **常用库**：`react-window`（轻量）、`react-virtualized`（功能全）、`@tanstack/react-virtual`。
- **滚动节流**：用 `requestAnimationFrame` 或 `useDeferredValue` 优化滚动更新频率。
- **避免布局抖动**：用绝对定位 / `translateY` 而非改 `top`。

## 6. 大列表与表单的性能优化

**列表：**

- 虚拟列表（见上题）。
- 稳定 `key`，避免用索引。
- 行组件用 `memo` + 稳定 props。
- 分页 / 无限滚动（配合 `IntersectionObserver`）。

```jsx
const observer = new IntersectionObserver(([entry]) => {
  if (entry.isIntersecting) loadMore();
});
observer.observe(sentinelRef.current);
```

**表单：**

- 大表单避免**每个字段都受控**导致整表重渲染：用**非受控**或**局部状态**。
- 用 `react-hook-form` 这类**非受控 + 订阅式**库，减少重渲染。
- 拆分字段组件，让变化只影响自身。
- 防抖校验，避免每次输入都跑重逻辑。

```jsx
// 防抖校验
const [value, setValue] = useState('');
const debounced = useDebounce(value, 300);
useEffect(() => { validate(debounced); }, [debounced]);
```

**要点：** 核心思路都是**缩小重渲染范围** + **减少高频操作**。

## 7. 图片与资源优化

- **懒加载**：`loading="lazy"` 或 `IntersectionObserver`，首屏外图片延迟加载。
- **响应式图片**：`srcset` + `sizes`，或 `<picture>` 按屏幕选图。
- **现代格式**：WebP / AVIF 替代 PNG/JPG。
- **尺寸适配**：按显示尺寸提供图片，避免大图缩显。
- **占位与骨架屏**：`aspect-ratio` 预留空间，防止布局偏移（CLS）。
- **CDN + 缓存**：静态资源走 CDN，配置长缓存 + 文件名 hash。

```jsx
<img src="a.webp" loading="lazy" width="400" height="300" alt="示例"
     srcSet="a-400.webp 400w, a-800.webp 800w"
     sizes="(max-width: 600px) 400px, 800px" />
```

**其他资源：**

- 字体：`font-display: swap`、子集化。
- 第三方脚本：`defer` / `async`、按需加载。
- 图标：用 SVG Sprite 或 icon font，避免大量小图片。

## 8. React 性能分析工具（Profiler）

**① React DevTools Profiler**：录制渲染，查看每次提交耗时、哪些组件渲染、渲染原因（why did this render）。

- **Flame Chart**：火焰图，看各组件渲染耗时。
- **Ranked Chart**：按耗时排序，快速定位「重灾区」。
- **Highlight updates**：高亮重渲染的组件。

**② `<Profiler>` 组件**：编程式采集渲染耗时。

```jsx
<Profiler id="App" onRender={(id, phase, actualDuration, baseDuration) => {
  console.log({ id, phase, actualDuration, baseDuration });
}}>
  <App />
</Profiler>
```

- `actualDuration`：本次实际渲染耗时。
- `baseDuration`：不优化情况下的估计耗时，二者差距反映优化效果。

**③ Chrome Performance 面板**：查看主线程任务、帧率、长任务（Long Task）。

**④ React 19 / DevTools 的「why did this render」**：直接显示重渲染原因。

**要点：** 优化流程 = **测量 → 定位瓶颈 → 针对性优化 → 复测**，避免凭感觉优化。

## 9. 并发特性优化（useTransition / useDeferredValue）

用于把**非紧急的高开销更新降级**，保证输入等紧急交互不卡顿。

```jsx
// useTransition：把「过滤大列表」标记为非紧急
const [isPending, startTransition] = useTransition();

const onChange = (e) => {
  setQuery(e.target.value);                    // 紧急：输入立即响应
  startTransition(() => setList(filter(e.target.value))); // 非紧急：可被打断
};
```

```jsx
// useDeferredValue：让大列表使用「滞后」的查询值
const deferredQuery = useDeferredValue(query);
return <ExpensiveList query={deferredQuery} />;
```

**适用场景：**

- 输入框实时过滤大列表。
- 搜索联想、图表随参数重绘。
- 任何「输入流畅性」与「结果实时性」冲突的场景。

**要点：**

- 只对**真正耗时**的更新使用；滥用会增加复杂度。
- `startTransition` 内的更新**不能**触发紧急更新（如受控输入的值）。
- 本质是**优先级调度**（基于 Lanes），不是加速计算本身。

## 10. 避免内联对象与函数的陷阱

**陷阱：** 每次渲染都会创建新的对象/函数，导致 `memo` 子组件浅比较失败而重渲染，或 effect 依赖频繁变化。

```jsx
// 反例：每次渲染都新建对象/函数
<Child config={{ a: 1 }} onClick={() => doSomething()} />
<Child style={{ color: 'red' }} />

// 优化一：稳定引用
const config = useMemo(() => ({ a: 1 }), []);
const onClick = useCallback(() => doSomething(), []);
<Child config={config} onClick={onClick} />
```

```jsx
// 优化二：把常量提到组件外（完全静态的值无需 useMemo）
const CONFIG = { a: 1 };
function Parent() {
  return <Child config={CONFIG} />;
}

// 优化三：style 对象外提
const style = { color: 'red' };
<div style={style} />
```

**注意区分：**

- **静态值** → 提到组件外（无需 `useMemo`）。
- **依赖 props/state 的值** → 用 `useMemo`/`useCallback`。
- **仅用于 DOM 属性（非 memo 子组件）** → 通常无需优化，React 内部 diff 会处理。

**要点：** 内联本身不是错，只有当它**破坏了 `memo` 或稳定依赖**时才需要优化。

## 11. 首屏优化（SSR、预渲染与水合）

**渲染模式：**

| 模式 | 说明 |
| --- | --- |
| **CSR**（客户端渲染） | 先下载 JS 再渲染，首屏白屏久 |
| **SSR**（服务端渲染） | 服务端返回 HTML，首屏快，需水合 |
| **SSG**（静态生成） | 构建时生成 HTML，最快，内容静态 |
| **ISR**（增量静态再生成） | 静态 + 定期/按需更新 |

**SSR 流程：**

```
服务端渲染 HTML → 浏览器展示首屏 → 下载 JS → 水合（hydration）绑定事件 → 成为可交互
```

**水合（Hydration）问题：**

- 服务端与客户端渲染结果**必须一致**，否则报 hydration mismatch（常见于 `Date.now()`、`Math.random()`、`localStorage`、`window` 判断）。
- React 18 支持**流式 SSR** 与**选择性水合**（`renderToPipeableStream` + `Suspense`），可优先水合可交互部分。

**优化手段：**

- 代码分割 + 路由懒加载，减小首屏包。
- 关键 CSS 内联、非关键资源延迟。
- 图片懒加载、`preload` 关键资源、`preconnect`。
- 骨架屏提升感知速度。
- 用 `react-dom/server` 的流式 API 加快 TTFB/FCP。
- 慎用会破坏水合的副作用（时间、随机、浏览器 API）→ 放到 `useEffect` 中。

```jsx
// 避免 hydration mismatch
const [now, setNow] = useState(null);
useEffect(() => setNow(Date.now()), []);   // 仅客户端执行
```

## 12. 性能优化清单与原则

**总原则：先测量，后优化；优化要可验证；不过度优化。**

**① 减少渲染**

- `React.memo`、`useMemo`、`useCallback`。
- 状态就近、状态下沉、`children` 透传。
- 稳定引用、避免内联对象/函数。

**② 减少计算**

- `useMemo` 缓存昂贵计算。
- 虚拟列表处理长列表。
- 防抖/节流高频操作。

**③ 减少体积 / 加快加载**

- 代码分割 + 懒加载。
- Tree-shaking、按需引入（`import { x } from 'lib'` 注意副作用）。
- 图片/字体优化、CDN。

**④ 提升响应性**

- `useTransition` / `useDeferredValue` 降级非紧急更新。
- 骨架屏、乐观更新提升感知性能。

**⑤ 架构层面**

- SSR/SSG 加快首屏。
- 合理拆分状态、选择合适的状态管理方案。

**高频「标准答案」结构：**

```
1. 渲染层：memo / useMemo / useCallback / 状态就近 / children 透传
2. 计算层：缓存、虚拟列表、防抖节流
3. 加载层：代码分割、懒加载、资源优化、SSR
4. 工具：Profiler 定位瓶颈，用数据驱动优化
```
