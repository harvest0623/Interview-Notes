# UDP 协议

UDP（User Datagram Protocol，用户数据报协议）是无连接的传输层协议，追求**简单、高效**，不保证可靠性。

---

## 特点

1. **无连接**：不需要握手，想发就发，不维护连接状态。
2. **不可靠传输**：不保证数据到达、不保证顺序，可能丢包、重复。
3. **无拥塞控制**：不会因为网络拥塞而降低发送速率，因此可能加剧拥塞。
4. **无流量控制**：不关心接收端缓冲是否来得及处理。
5. **面向报文**：保留消息边界，一次发送对应一次接收（不像 TCP 是字节流）。
6. **头部开销小**：仅 8 字节（TCP 至少 20 字节），传输效率高。
7. **支持一对多**：可广播、多播。

---

## 适用场景

| 场景 | 原因 |
| --- | --- |
| 视频会议、语音通话、直播 | 实时性优先，偶尔丢包可接受 |
| 在线游戏 | 延迟敏感，旧数据过期即无用 |
| DNS 查询 | 请求/响应小、一次一问一答，握手成本不划算 |
| 广播 / 多播 | TCP 只支持一对一 |

---

## TCP 与 UDP 对比

| 维度 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠（重传、确认、排序） | 不可靠 |
| 顺序 | 保证有序 | 不保证 |
| 速度 | 较慢（握手、拥塞控制） | 较快 |
| 头部开销 | 20 字节起 | 8 字节 |
| 流量/拥塞控制 | 有 | 无 |
| 传输方式 | 字节流 | 数据报 |
| 典型应用 | HTTP/HTTPS、文件传输、邮件 | 音视频、游戏、DNS、QUIC |

---

## 补充：QUIC 与 UDP

HTTP/3 基于 **QUIC 协议**，而 QUIC 构建在 **UDP** 之上：

- 取 TCP 之长：可靠传输、流量控制、TLS 加密、多路复用；
- 避开 TCP 之短：不再受 TCP 层**队头阻塞**影响，且握手更快（0/1 RTT）。

> 一句话总结：**TCP 求稳，UDP 求快；要可靠又要快，就在 UDP 上自己造一套（QUIC）。**
