# 请求重试

> **题目：实现一个 `retry` 函数，当请求失败时自动重试，最多重试 N 次；全部失败后抛出最终错误。**

考察点：`Promise` 的封装与递归、失败次数/剩余次数的语义、延迟重试与指数退避。

## 1. 思路

- `retry(fn, count)` 返回一个新的 Promise，对外统一暴露「最终成功/最终失败」的结果。
- 内部把一次执行封装成 `run`：调用 `fn()`，成功就 `resolve`，失败就 `count--` 并递归 `run`，直到次数用完再 `reject`。
- **递归调用 `run`** 是核心——每次失败都会重新发起一次请求，直到成功或次数耗尽。

```
retry(fn, 3)
   │
   ├─ 第 1 次失败 → count=2 → 重试
   ├─ 第 2 次失败 → count=1 → 重试
   ├─ 第 3 次失败 → count=0 → reject（彻底失败）
   └─ 任意一次成功 → resolve（结束）
```

---

## 2. 基础版实现

```js
function retry(fn, count) {
    return new Promise((resolve, reject) => {
        const run = () => {
            fn()
                .then((res) => {
                    console.log(`请求成功：${res}`);
                    resolve(res); // 成功：结束流程
                })
                .catch(() => {
                    count--; // 失败：消耗一次机会
                    if (count) {
                        console.log(`还剩 ${count} 次重试机会，准备重试...`);
                        run(); // 递归重试
                    } else {
                        reject('重试次数耗尽，请求彻底失败'); // 机会用完：彻底失败
                    }
                });
        };
        run(); // 首次执行
    });
}
```

## 3. 增强版：延迟 + 指数退避

真实场景中，失败后立即重试往往还会失败（服务端可能正在抖动）。因此通常会**等待一段时间再重试**，并让等待时间逐次翻倍（指数退避）：

```js
function retry(fn, count, delay = 1000) {
    return new Promise((resolve, reject) => {
        const run = () => {
            fn()
                .then(resolve)
                .catch((err) => {
                    count--;
                    if (count <= 0) {
                        return reject(`重试次数耗尽：${err}`);
                    }
                    console.log(`还剩 ${count} 次机会，${delay}ms 后重试...`);
                    setTimeout(() => {
                        delay *= 2; // 指数退避：1s → 2s → 4s ...
                        run();
                    }, delay);
              });
        };
        run();
    });
}
```

对应 [retry.js](retry.js)。

**其他常见增强方向**

- **总超时控制**：给整个重试流程设置一个最大总时长。
- **仅对特定错误重试**：如只对超时/5xx 重试，参数错误（4xx）不应重试。
- **随机抖动（jitter）**：在退避时间上加随机量，避免大量请求同时重试造成「惊群」。

---

## 4. 关键点说明

- **`count` 的语义要统一**：本实现中 `count = 3` 表示「最多额外重试 3 次」。`count--` 后判断 `if (count)` / `if (count <= 0)`，务必和文档/注释保持一致，否则容易出现「少重试一次」或「多重试一次」的 bug。
- **只在 `catch` 里递归**：成功分支必须 `resolve` 并终止，绝不能继续重试。
- **延迟重试用 `setTimeout` 而不是忙等**，避免占用主线程。

---

## 5. 易错点

- **忘记「首次执行」**：`run()` 一定要在 Promise 构造时先调用一次，否则永远不发起请求。
- **成功后又触发重试**：把 `resolve` 写在 `.then` 里后，要保证流程结束，不要在里面再调用 `run`。
- **无限重试**：必须有次数上限，否则接口长期不可用时会一直打请求。
- **同步异常没被捕获**：若 `fn()` 不是返回 Promise，或内部同步 `throw`，`catch` 无法捕获，需要 `Promise.resolve().then(fn)` 兜底。
- **重试与并发控制叠加**：重试会放大请求量，建议结合「控制并发」（同级目录）一起使用。
