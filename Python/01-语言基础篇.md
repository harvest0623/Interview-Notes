## 1. Python 的特点与解释执行过程

**Python 的核心特点：**

| 特点 | 说明 |
| --- | --- |
| 简洁易读 | 强制缩进、语法靠近自然语言，适合快速开发与维护 |
| 动态类型 | 变量不需要声明类型，运行时绑定；带来灵活性也带来运行时错误 |
| 解释执行 | 源码先编译为字节码，再由虚拟机逐条解释执行 |
| 跨平台 | 同一份源码在 Windows/Linux/macOS 上均可运行（C 扩展除外） |
| 多范式 | 支持面向对象、函数式、过程式；一切皆对象 |
| 生态丰富 | 标准库 + PyPI 覆盖 Web、数据、AI、自动化 |
| 性能一般 | 纯解释执行，计算密集场景远慢于 C/Go；靠 C 扩展、NumPy、PyPy 弥补 |
| GIL 限制 | CPython 同一进程内同一时刻只有一个线程执行字节码（**实现细节，非语言规范**） |

**解释执行过程（源码到运行）：**

```text
hello.py（源码）
   ↓ 1. 词法/语法分析，生成 AST
   ↓ 2. 编译为字节码（code object）
   ↓ 3. 写入 __pycache__/hello.cpython-311.pyc（带 magic number + 源码 mtime/size 校验）
   ↓ 4. CPython 的 PVM（ceval 求值循环）逐条取指令执行
   ↓ 5. 调用 C 层（builtins、扩展模块）完成实际计算
输出结果
```

**几个关键分点：**

1. **「解释型」并不准确**：Python 是「先编译成字节码，再解释执行」，字节码是平台无关的中间表示。
2. **`.pyc` 何时生成**：只有被 **`import` 的模块**才会写盘缓存；用 `python main.py` 直接运行的**主脚本不会生成 `.pyc`**。
3. **`.pyc` 的作用**：省去重复的编译步骤，加快**导入**速度（不是加快程序运行速度）。
4. **PVM 执行**：`ceval.c` 中的大 `switch`/计算跳转循环，按字节码指令操作栈帧（frame）上的值栈。
5. **CPython 与 PyPy**：PyPy 带 **JIT（即时编译）**，把热点字节码编译为机器码，纯 Python 计算密集场景常快数倍；但内存占用高、C 扩展兼容性(CPython API)较差。

**解释型 vs 编译型的对比：**

| 维度 | 编译型（C/Go/Rust） | 解释型（Python 字节码） |
| --- | --- | --- |
| 产物 | 机器码可执行文件 | 字节码 `.pyc`（依赖解释器运行） |
| 执行方式 | CPU 直接执行机器码 | PVM 逐条解释，间接执行 |
| 启动速度 | 快 | 慢（需初始化解释器） |
| 运行速度 | 快 | 慢（逐条分派开销） |
| 跨平台 | 需针对平台编译 | 同一 `.pyc` 跨平台 |
| 错误发现时机 | 多为编译期 | 多在运行期 |
| 优化手段 | 编译器优化 | JIT（PyPy）、C 扩展、自适应解释器（3.11+） |

```python
import dis

def add(a, b):
    return a + b

# 查看函数被编译成的字节码
dis.dis(add)
#  0 LOAD_FAST   0 (a)
#  2 LOAD_FAST   1 (b)
#  4 BINARY_OP   0 (+)
#  6 RETURN_VALUE

# 查看模块级编译结果与常量表
code = compile("x = 1 + 2", "<demo>", "exec")
print(code.co_code)          # 字节码指令序列
print(code.co_consts)        # ('x' 名对应的常量：3 ← 常量折叠已在编译期完成)
```

**易错点：**

- `.pyc` 校验的是**源码 mtime 与大小**，所以改完源码立刻运行一般能重新编译；但若大小与时间戳都未变（罕见），会用到过期缓存，需手动删除 `__pycache__`。
- 字节码是 CPython 的**内部实现**，不同版本指令集会变化（3.6 起用 16 位指令，3.11 引入自适应专门化），面试不要把它当稳定 ABI。
- GIL 是 CPython 的实现选择，Jython/IronPython 没有 GIL；Python 3.13 已提供实验性的 free-threading 构建。

## 2. 可变类型与不可变类型

**定义：**

- **不可变（immutable）**：对象一旦创建，其值不可改变。所谓「修改」实际是**创建新对象**，旧对象保持不变。
- **可变（mutable）**：对象创建后可以在**原地**增删改内容，`id()` 不变。

| 类型 | 类别 | 可哈希（能作 dict key / set 元素） | 典型「修改」行为 |
| --- | --- | --- | --- |
| `int` / `float` / `bool` | 不可变 | 是 | 生成新对象 |
| `str` | 不可变 | 是 | 生成新字符串 |
| `bytes` | 不可变 | 是 | 生成新 bytes |
| `tuple` | 不可变（**浅层**） | 元素都可哈希时才可 | 不能改元素，但内部可变元素可被改 |
| `frozenset` | 不可变 | 是 | 生成新集合 |
| `list` | 可变 | 否 | `append`/`pop`/下标赋值，原地改 |
| `dict` | 可变 | 否 | `d[k]=v`，原地改 |
| `set` | 可变 | 否 | `add`/`discard`，原地改 |
| `bytearray` | 可变 | 否 | 原地改字节 |
| 自定义对象 | 默认可变 | 默认可哈希（按 `id`） | 改属性 |

**三个必须讲清的点：**

**① 赋值（`=`）不是复制，只是绑定名字**

```python
a = [1, 2, 3]
b = a              # b 与 a 指向同一个列表对象
b.append(4)
print(a)           # [1, 2, 3, 4] ← a 也变了，因为它们是同一个对象
print(a is b)      # True

x = 10
y = x
y += 1             # 不可变：y 指向新对象 11，x 不受影响
print(x, y)        # 10 11
```

**② 传参是「传对象引用」（call by object reference / call by sharing）**

- 传进去的是**对象的引用副本**；函数内重新绑定参数名，不影响外部。
- 对**可变对象原地修改**，外部可见；对**不可变对象**只能重新绑定，外部不可见。

```python
def modify(lst, s):
    lst.append(99)     # 原地修改 → 影响外部
    s += "!"           # 字符串不可变，只是让局部名 s 指向新对象 → 不影响外部
    return s

nums = [1, 2]
text = "hi"
print(modify(nums, text), nums, text)   # hi! [1, 2, 99] hi
```

**③ 经典陷阱：可变默认参数只求值一次**

```python
def bad(item, box=[]):        # 默认值在「函数定义时」创建一次，被所有调用共享
    box.append(item)
    return box

print(bad(1))    # [1]
print(bad(2))    # [1, 2]  ← 本以为是 [2]，实际被上一次调用污染
print(bad.__defaults__)   # ([1, 2],)

# 正确写法：默认用 None，函数体内创建
def good(item, box=None):
    if box is None:
        box = []
    box.append(item)
    return box

print(good(1), good(2))   # [1] [2]
```

**`tuple` 的「伪不可变」：**

```python
t = (1, 2, [3, 4])
t[2].append(5)     # 合法：元组本身没变，但内部的 list 被改了
print(t)           # (1, 2, [3, 4, 5])
# t[2] = [9]       # TypeError: 'tuple' object does not support item assignment
```

**易错点：**

- 「Python 参数是值传递还是引用传递？」——标准答案：**传对象引用**，可变对象可被修改，不可变对象不会。
- `+=` 对 list 是 `__iadd__`（原地扩展，等价 `extend`）；对 tuple/str 是 `__add__`（生成新对象），故 `t += (1,)` 会换 id。
- 可变默认参数、类属性用可变对象、闭包共享变量，是三个最容易在生产环境埋雷的地方。
- 判断类型别用 `type(x) == int`，用 `isinstance(x, int)` 才能覆盖子类与 `bool`/`IntEnum` 场景。

## 3. is 与 == 的区别

| 运算符 | 比较内容 | 底层调用 | 用途 |
| --- | --- | --- | --- |
| `is` | **身份**（是否同一个对象，比较 `id()`） | 直接比较指针，不可重载 | 与 `None`/`True`/`False`/哨兵对象比较 |
| `==` | **值**（内容是否相等） | `__eq__()`，可被重载 | 业务上的相等判断 |

```python
a = [1, 2, 3]
b = [1, 2, 3]
c = a

print(a == b)     # True  ← 值相等
print(a is b)     # False ← 不同对象
print(a is c)     # True  ← 同一对象
print(id(a) == id(c))    # True

# 自定义 __eq__：== 可被改变，is 永远不变
class Point:
    def __init__(self, x): self.x = x
    def __eq__(self, other): return isinstance(other, Point) and self.x == other.x

print(Point(1) == Point(1))   # True（靠 __eq__）
print(Point(1) is Point(1))   # False（两个不同的对象）
```

**小整数池与字符串驻留（面试高频追问）：**

- CPython 在启动时预创建 `-5 ~ 256` 的整数对象，落在该区间的字面量**共用同一对象**，于是 `is` 意外为 `True`。
- 字符串存在**驻留（interning）**：符合标识符规则（字母/数字/下划线组成）的字面量、编译期的常量折叠结果会被驻留或合并。
- 这是**实现细节**，不属于语言保证，绝不能依赖。

```python
print(256 is 256)        # True（小整数池）
print(257 is 257)        # False（超出范围，两处字面量各自创建对象）
a, b = 257, 257          # 同一次编译常量折叠，可能共用
print(a is b)            # True（视实现与编译优化而定，别依赖）

s1 = "hello"
s2 = "hello"
print(s1 is s2)          # True（驻留）
s3 = "hello world!"      # 含空格，不满足标识符规则
s4 = "hello world!"
print(s3 is s4)          # False（不一定驻留）
```

**正确用法：**

```python
x = None
if x is None:            # 推荐：None 是单例，用 is 最快最稳
    ...
if x is not None:
    ...
```

**易错点：**

- 用 `==` 判断 `None` 在自定义了 `__eq__` 的类上可能出错（比如 NumPy 数组 `arr == None` 返回数组），**判空一律用 `is None`**。
- Python 3.8+ 对「`is` 与字面量比较」给出 `SyntaxWarning`（如 `x is 1000`），说明它几乎总是错的。
- `nan != nan` 为 True（IEEE 754 规则）；判断 NaN 应用 `math.isnan(x)` 或 `x != x`。
- 两个小整数池的 `is` 结果为 True 只是「恰好」，面试要明确说这是**实现细节不可依赖**。

## 4. 深拷贝与浅拷贝

| 方式 | 写法 | 外层容器 | 内层元素 | 循环引用 |
| --- | --- | --- | --- | --- |
| 赋值 | `b = a` | 不复制（同一对象） | 同一对象 | 无问题 |
| 浅拷贝 | `copy.copy(a)`、`a.copy()`、`a[:]`、`dict(a)` | **新建** | **仍是同一引用** | 会形成环 |
| 深拷贝 | `copy.deepcopy(a)` | **新建** | **递归新建** | 自动处理（`memo`） |

**浅拷贝的几种常见写法：**

```python
import copy

src = [1, [2, 3]]

s1 = copy.copy(src)     # 通用的浅拷贝
s2 = src.copy()         # list 自带的
s3 = src[:]             # 切片也是浅拷贝
s4 = list(src)          # 构造新列表
print(s1 is src)        # False（外层是新的）
print(s1[1] is src[1])  # True （内层仍共享）

s1[1].append(99)        # 改内层
print(src)              # [1, [2, 3, 99]] ← 原对象被影响！
```

**深拷贝会递归复制所有层级：**

```python
import copy

src = [1, [2, 3], {"k": [4]}]
deep = copy.deepcopy(src)
deep[1].append(99)
deep[2]["k"].append(5)
print(src)    # [1, [2, 3], {'k': [4]}] ← 完全不受影响
print(deep)   # [1, [2, 3, 99], {'k': [4, 5]}]
```

**`deepcopy` 如何避免无限递归：`memo` 字典**

```python
import copy

a = [1, 2]
a.append(a)                 # 自引用，形成环
b = copy.deepcopy(a)        # 不会爆栈
print(b[2] is b)            # True ← 环也被正确复制
print(b)                    # [1, 2, [...]]
```

`deepcopy` 内部维护 `memo`（id → 新对象）字典：复制过的对象直接复用，既提高性能又正确还原循环结构。

**不可变对象的特例：**

```python
import copy
t = (1, 2)
print(copy.copy(t) is t)        # True ← 元组不可变，浅拷贝直接返回原对象
print(copy.deepcopy((1, 2)) is (1, 2))  # True（元素都不可变时直接复用）

s = "abc"
print(copy.copy(s) is s)        # True
```

**易错点：**

- **切片、`list()`、`dict()`、`set.copy()` 全是浅拷贝**，面试常问「切片是深拷贝吗」——不是。
- `deepcopy` 会调用对象的 `__deepcopy__(memo)`；自定义类若引用了不可复制资源（文件、锁、socket），需自行实现，否则报 `TypeError: cannot pickle ...`。
- `deepcopy` 性能开销大，大对象频繁复制会成为热点；能用不可变结构（tuple/frozenset/字符串）就尽量避免深拷贝。
- 浅拷贝对「不可变内层元素」是安全的（如 `[[元组]]`），但对嵌套可变结构是隐患。

## 5. 列表、元组、字典、集合的区别

| 维度 | `list` | `tuple` | `dict` | `set` |
| --- | --- | --- | --- | --- |
| 有序性 | 有序（按插入位置） | 有序 | 3.7+ **按插入序**（语言保证） | 无序（按哈希序，不保证稳定） |
| 可变性 | 可变 | 不可变 | 可变 | 可变 |
| 元素可重复 | 是 | 是 | 键唯一 | 元素唯一 |
| 可哈希（作 dict key） | 否 | 元素可哈希时**是** | 否 | 否（`frozenset` 可以） |
| 索引访问 | `O(1)` | `O(1)` | 按键 `O(1)` | 不支持（无下标） |
| 成员判断 `in` | `O(n)` | `O(n)` | `O(1)` | `O(1)` |
| 尾部插入/删除 | `append/pop` 均摊 `O(1)` | — | `O(1)` 均摊 | `O(1)` 均摊 |
| 中部插入/删除 | `O(n)` | — | `O(n)`（rehash 时） | 均摊 `O(1)` |
| 典型用途 | 有序序列、栈/队列 | 固定记录、常量、dict key | 映射、计数、缓存 | 去重、集合运算 |
| 底层实现 | 动态数组（过度分配） | 定长数组 | 紧凑哈希表 | 哈希表（仅存键） |

```python
# 一句话选型：有序可重复 → list；固定不可改 → tuple；键值映射 → dict；去重/集合运算 → set

lst = [3, 1, 1, 2]
tup = (3, 1, 1, 2)
dct = {"a": 1, "b": 2}
st  = {3, 1, 2}

print(len(lst), len(tup), len(dct), len(st))   # 4 4 2 3（set 自动去重）

# 去重：set 是最快的方案（但会丢失顺序）
print(list(dict.fromkeys([3, 1, 1, 2])))       # [3, 1, 2] ← 保序去重
print(list(set([3, 1, 1, 2])))                 # [1, 2, 3] 或其它顺序

# 计数：dict.get 或 collections.Counter
from collections import Counter
print(Counter(["a", "b", "a"]))                # Counter({'a': 2, 'b': 1})

# 元组可作 key，列表不行
grid = {(0, 0): "起点", (1, 2): "终点"}
print(grid[(0, 0)])                            # 起点
# {[0, 0]: "起点"}                             # TypeError: unhashable type: 'list'
```

**易错点：**

- `in` 对 list 是线性查找，大列表里反复判断会退化成 `O(n²)`，应改用 set/dict。
- `set` 的遍历顺序由哈希决定，且与插入顺序无关；需要保序去重用 `dict.fromkeys()`。
- `tuple` 只有当**所有元素都可哈希**时才能作 dict key（`(1, [2])` 不行）。
- `dict` 在 3.7 之前不保证有序，「3.6 是实现细节上的有序，3.7 才写进语言规范」是标准表述。

## 6. 字典的底层实现与哈希冲突

**① 从「老字典」到「紧凑字典」（Python 3.6 起）**

早期 CPython 的 dict 是一个**稀疏的哈希表**（每个槽位存 key/value/hash 三元组），内存浪费严重。3.6 改为**紧凑字典（compact dict）**，把结构拆成两部分：

```text
PyDictObject
├── ma_used    : 元素个数
├── ma_keys ──→ PyDictKeysObject
│               ├── dk_indices[]  : 稀疏的索引数组（只存 8-bit 下标或 DKIX_* 标记）
│               └── dk_entries[]  : 紧凑的实体数组，按「插入顺序」排列
│                                  (hash, key, value) ...
└── ma_values （仅当所有键为字符串且 value 可共享时使用的分离表；否则为 NULL）
```

关键点：

1. **`dk_indices` 稀疏、`dk_entries` 紧凑**：以前三个数组都稀疏，现在只有索引数组稀疏且每格只占 1 字节 → 内存降约 20%~30%。
2. **`entries` 按插入顺序追加** → 遍历 dict 时天然就是插入序，这就是「3.6 起 dict 有序」的来源。
3. **3.7 起语言规范正式保证插入序**，从此可以作为依赖。

**② 查找过程**

```text
hash(key) → h
i = h & mask            （mask = len(dk_indices) - 1，等价于取低位）
loop:
    idx = dk_indices[i]
    if idx == DKIX_EMPTY  : 未找到，可插入
    if idx == DKIX_DUMMY  : 该槽被伪删除过，继续探测
    if entries[idx].hash == h and 键相等: 命中
    否则按探测序列找下一个候选槽（perturb 机制）
```

**③ 哈希冲突处理：开放寻址（Open Addressing）**

- 冲突时不挂链表，而是**按探测序列在表中继续找下一个空位**。
- CPython 使用 **perturb 伪随机探测**：`perturb >>= 5; i = (5*i + perturb + 1) & mask`，让探测序列更分散，减少聚集。
- 因此**负载因子必须保持较低**（`USABLE_FRACTION = 2/3`）：`dk_indices` 长度是「至少能容纳 `used * 3 / 2`」的 `2^n`。

**④ 删除是「伪删除」**

- 删除元素时只把对应 `dk_indices` 槽标记为 `DKIX_DUMMY`，`dk_entries` 里的记录**不立即压缩**。
- 所以**迭代过程中删除元素会抛 `RuntimeError: dictionary changed size during iteration`**（即使先转 list 也不行）。
- 反复增删同一批键会让表变「稀」，达到阈值后才 resize 重建。

**⑤ 扩容时机**

- 插入新键时若 `used * 3 >= 容量 * 2`（即负载因子超过 2/3）触发 **resize**，容量翻倍并**重新哈希全部元素**。
- 扩容瞬时开销 `O(n)`，但均摊为 `O(1)`。
- 大字典一次性释放时（dict_resize 到最小）会回收内存。

**⑥ 键必须可哈希**

- 调用 `__hash__()` 得到整数，且要求「`a == b` ⟹ `hash(a) == hash(b)`」。
- 自定义类若重写 `__eq__` 而未定义 `__hash__`，该类的 `__hash__` 会被置为 `None` → 不可哈希。

```python
import sys

d = {"a": 1, "b": 2}
print(sys.getsizeof(d))            # 小字典的对象大小（含 keys 结构）

# 插入顺序可依赖（3.7+）
d = {}
d["x"] = 1
d["y"] = 2
d.pop("x")
d["x"] = 3
print(list(d))                     # ['y', 'x'] ← 重新插入会排到末尾

# 迭代中改字典 → 报错
d = {"a": 1, "b": 2, "c": 3}
try:
    for k in d:
        del d[k]
except RuntimeError as e:
    print("RuntimeError:", e)      # dictionary changed size during iteration

# 正确做法：对 keys 的副本迭代
for k in list(d):
    del d[k]

# 自定义类：重写 __eq__ 必须一并定义 __hash__
class NoHash:
    def __eq__(self, other): return True
try:
    {NoHash(): 1}
except TypeError as e:
    print(e)                       # unhashable type: 'NoHash'
```

**易错点：**

- 「dict 无序」是**过时说法**：Python 3.7+ 字典**保证插入序**，答案要带上版本号。
- 用可变对象（list/dict/set）当 key 会直接抛 `unhashable type`；用**内容会变的自定义对象**当 key 更隐蔽——哈希变了就再也找不到。
- 自定义类同时重写 `__eq__` 和 `__hash__` 时，必须保证「相等则哈希相同」，否则字典/集合行为错乱。
- 删除元素不是立即腾出内存，所以「删了一堆键，内存没降」是正常现象（entries 仍占位）。

## 7. 字符串常用操作与不可变性

**不可变性的直接推论：**

- 任何「修改」都返回**新字符串**，原对象不变。
- 字符串可以被缓存/驻留，所以能安全地作 dict key。

**常用方法速查：**

| 需求 | 方法 | 说明 |
| --- | --- | --- |
| 分割 | `s.split(sep)` / `s.rsplit` / `s.splitlines()` | 不传 sep 时按空白切分并去空串 |
| 拼接 | `sep.join(iterable)` | 元素必须是 str，性能最好的拼接方式 |
| 去空白 | `s.strip()` / `lstrip()` / `rstrip(chars)` | 参数是**字符集合**，不是子串 |
| 查找 | `s.find(x)` / `s.index(x)` / `s.count(x)` | `find` 未找到返回 `-1`，`index` 抛 `ValueError` |
| 替换 | `s.replace(old, new, count)` | 返回新串 |
| 判断 | `startswith` / `endswith` / `isalpha` / `isdigit` | 可传 tuple 做多前缀判断 |
| 大小写 | `upper` / `lower` / `capitalize` / `title` | 返回新串 |
| 格式化 | `f"{x:.2f}"` / `s.format()` / `%` | f-string 最快、最易读 |
| 补齐 | `s.zfill(n)` / `ljust` / `rjust` / `center` | 常用于对齐输出 |

**为什么推荐 `join` 而不是 `+` 拼接：**

```text
+ 拼接：每一步都创建新字符串并整体复制 → 循环 n 次是 O(n²)
join ：先算总长度，一次性分配，再逐段拷贝 → O(n)
```

```python
import timeit

def by_plus():
    s = ""
    for i in range(2000):
        s += str(i)          # 不断创建新对象（CPython 有 in-place 优化，但仍不如 join）
    return s

def by_join():
    return "".join(str(i) for i in range(2000))

print(timeit.timeit(by_plus, number=200))   # 明显更慢
print(timeit.timeit(by_join, number=200))   # 更快
```

**f-string 与格式化：**

```python
name, score = "Ada", 92.5678
print(f"{name} 得分 {score:.2f}")       # Ada 得分 92.57
print(f"{score:>10.2f}|")               # 右对齐宽度 10：    92.57|
print(f"{1234567:,}")                   # 1,234,567
print(f"{0.25:.1%}")                    # 25.0%
print(f"{name!r}")                      # 'Ada'（repr）

# 3.8+ 调试写法
x = 42
print(f"{x=}")                          # x=42
```

**易错点：**

- `strip("abc")` 删除的是**首尾出现在集合 {a,b,c} 中的字符**，不是子串 `"abc"`，容易误解。
- `str` 与 `bytes` 不能直接拼接，需显式 `encode()/decode()`；`b"abc"[0]` 得到的是**整数**而非单字符。
- 用 `is` 比较字符串不可靠（只有驻留的才相同），业务比较一律用 `==`。
- `s[::-1]` 反转字符串虽好写，但对大字符串内存翻倍，纯逻辑题可用即可。

## 8. 列表推导式与生成器表达式

| 写法 | 语法 | 结果类型 | 求值时机 | 内存 |
| --- | --- | --- | --- | --- |
| 列表推导式 | `[x for x in it if c]` | `list` | **立即**全部求值 | `O(n)` |
| 集合推导式 | `{x for x in it}` | `set` | 立即 | `O(n)` |
| 字典推导式 | `{k: v for k, v in it}` | `dict` | 立即 | `O(n)` |
| 生成器表达式 | `(x for x in it)` | `generator` | **惰性**、逐个产出 | `O(1)` |

```python
nums = range(6)

print([x * x for x in nums])                 # [0, 1, 4, 9, 16, 25]
print([x for x in nums if x % 2 == 0])       # [0, 2, 4]
print({x % 3 for x in nums})                 # {0, 1, 2}
print({x: x * x for x in nums if x < 3})     # {0: 0, 1: 1, 2: 4}

gen = (x * x for x in nums)
print(gen)                                   # <generator object ...>
print(next(gen), next(gen))                  # 0 1 ← 惰性，用一次算一次
print(sum(x * x for x in range(10**6)))      # 生成器表达式省内存，无需建大列表

# 嵌套与多重条件
matrix = [[1, 2], [3, 4]]
print([n for row in matrix for n in row])    # [1, 2, 3, 4] ← 双层 for 从左到右展开
print([x for x in nums if x % 2 == 0 if x > 2])   # 多重 if 等于 and
```

**闭包延迟绑定坑（经典题）：**

```python
# 错误：lambda 捕获的是变量 i 本身，等到调用时 i 已是最终值
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])                  # [2, 2, 2]

# 正确一：用默认参数在定义时「快照」当前值
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])                  # [0, 1, 2]

# 正确二：functools.partial 绑定参数
from functools import partial
def show(i): return i
funcs = [partial(show, i) for i in range(3)]
print([f() for f in funcs])                  # [0, 1, 2]
```

**`any` / `all` 的短路特性：**

```python
print(any([False, True, 1 / 0 == 1]))   # 会在 True 处短路……但列表已求值，此处会报错
print(all(x > 0 for x in [1, 2, 3]))    # True
print(any(x < 0 for x in [1, -1, 0]))   # True
# 生成器表达式 + any/all 是「短路遍历」的推荐写法

def has_bad(data):
    return any(x > 100 for x in data)   # 一旦遇到大于 100 就停止遍历
```

**易错点：**

- 「元组推导式」不存在：`(x for x in it)` 得到的是**生成器**，想要元组要写 `tuple(x for x in it)`。
- Python 3 的推导式**不会泄漏循环变量**（Python 2 会），但 `for` 语句中的变量会留在当前作用域。
- 生成器表达式**只能消费一次**，遍历完即空；需要重复遍历就转成 list。
- 复杂推导式（三层以上嵌套）会严重损害可读性，面试建议拆成普通循环。

## 9. 函数参数：位置、默认、可变参数

| 参数类型 | 写法 | 传入方式 | 备注 |
| --- | --- | --- | --- |
| 位置参数 | `def f(a, b)` | 按顺序或按名 | 必传 |
| 默认参数 | `def f(a, b=2)` | 可省略 | **定义时求值一次**，后置 |
| 可变位置参数 | `def f(*args)` | 多余位置参数打包成 tuple | `args` 是元组 |
| 可变关键字参数 | `def f(**kwargs)` | 多余关键字参数打包成 dict | `kwargs` 是字典 |
| 仅位置参数 | `def f(a, /, b)` | 只能用位置传 | PEP 570（3.8+） |
| 仅关键字参数 | `def f(a, *, b)` | 只能用关键字传 | `*` 之后不可位置传 |

**参数顺序规则（必须牢记）：**

```text
位置参数 → 默认参数 → *args → 仅关键字参数 → **kwargs
```

```python
def func(pos, default=1, *args, keyword, **kwargs):
    print(pos, default, args, keyword, kwargs)

func(1, 2, 3, 4, keyword="k", extra="e")
# 1 2 (3, 4) k {'extra': 'e'}

func(1, keyword="k")            # 1 1 () k {}  ← 默认值与空可变参数

# 仅位置 / 仅关键字（3.8+）
def g(a, /, b, *, c):
    return a, b, c

print(g(1, 2, c=3))             # (1, 2, 3)
# g(a=1, b=2, c=3)              # TypeError: a 只能是位置参数
# g(1, 2, 3)                    # TypeError: c 只能是关键字参数

# 调用时用 * / ** 解包
args = (1, 2)
kwargs = {"keyword": "k"}
func(*args, **kwargs)           # 等价 func(1, 2, keyword="k")
```

**可变默认参数陷阱（本章最高频考点）：**

```python
# 反例：默认值 [] 在定义时创建一次，所有调用共享同一个列表
def append_bad(v, target=[]):
    target.append(v)
    return target

print(append_bad(1))            # [1]
print(append_bad(2))            # [1, 2] ← 不是 [2]

# 正例
def append_ok(v, target=None):
    if target is None:
        target = []
    target.append(v)
    return target

print(append_ok(1), append_ok(2))   # [1] [2]

# 同样的坑也存在于「默认值依赖外部可变状态」
import time
def log(msg, ts=time.time()):   # ts 被固定为定义时刻！想要实时时间不应作默认值
    return f"[{ts:.0f}] {msg}"
```

**易错点：**

- 默认参数在**函数定义时求值一次**，因此默认值不要写可变对象（list/dict/set）或实时变化的表达式（`time.time()`、`random.random()`）。
- `*args` 之后的参数**必须**用关键字传递（这也是函数签名里 `*` 的实际作用）。
- `**kwargs` 的键**必须是字符串**（不能是数字或其它对象）。
- 位置参数与关键字参数混用时，位置参数必须在前：`f(1, b=2)` 合法，`f(a=1, 2)` 是语法错误。

## 10. 作用域与 LEGB 规则

**LEGB：名字解析的四个层次，由内向外查找。**

| 层级 | 名称 | 范围 |
| --- | --- | --- |
| **L** | Local | 当前函数内部 |
| **E** | Enclosing | 外层嵌套函数（闭包） |
| **G** | Global | 当前模块（`.py` 文件）顶层 |
| **B** | Built-in | 内置命名空间（`len`、`print`、`__builtins__`） |

```python
x = "global"                     # G

def outer():
    x = "enclosing"              # E
    def inner():
        x = "local"              # L
        print(x)                 # local ← 就近找到即停
    inner()
    print(x)                     # enclosing

outer()
print(x)                         # global
print(len("abc"))                # 3 ← B（内置）

print(max([1, 2]))               # 若你在模块里定义 max = 10，这里就会变成 10（遮蔽内置）
```

**`global` 与 `nonlocal`：**

| 关键字 | 作用 | 使用位置 | 前提 |
| --- | --- | --- | --- |
| `global` | 声明名字属于**模块级**，赋值即修改全局 | 函数内 | 无 |
| `nonlocal` | 声明名字属于**最近的外层函数**（闭包） | 嵌套函数内 | 该名字必须已在外层存在 |

```python
count = 0

def bump():
    global count             # 没有这行，count += 1 会因「赋值即局部」而报 UnboundLocalError
    count += 1

bump(); bump()
print(count)                 # 2

def counter():
    n = 0
    def inc():
        nonlocal n           # 绑定到外层 counter 的 n
        n += 1
        return n
    return inc

c = counter()
print(c(), c(), c())         # 1 2 3
```

**最容易踩的 `UnboundLocalError`：**

```python
x = 10

def bad():
    print(x)      # 这里就开始报 UnboundLocalError
    x = 20        # 「有赋值 → x 是局部变量」，于是上面的 print 找不到局部 x

try:
    bad()
except UnboundLocalError as e:
    print("UnboundLocalError:", e)

# 关键结论：变量是否局部，由「编译期」是否出现赋值决定，而不是执行顺序
```

**易错点：**

- 函数内**只要出现过赋值**（含 `x = ...`、`for x in ...`、`with ... as x`、`except E as x`、解包），该名字在整个函数体里都是**局部变量**，读取未赋值的它就会 `UnboundLocalError`。
- 模块顶层不存在 `nonlocal` 可绑定的对象（报 `SyntaxError: no binding for nonlocal`）。
- `global` 声明的名字若不存在，会在全局命名空间**创建**它；而 `nonlocal` 必须已存在，否则是语法错误。
- 不要用 `locals()` 或 `globals()` 的返回值去「改」局部变量（`locals()` 返回快照，修改无效）。

## 11. 闭包与 nonlocal

**闭包的三个条件：**

1. 存在嵌套函数；
2. 内层函数引用了外层函数的**自由变量**；
3. 外层函数**返回内层函数**（或把它传出）。

此时外层函数的局部变量**不会随调用结束而销毁**，而是被保存在内层函数的 `__closure__` 中。

```python
def make_counter():
    n = 0
    def inc():
        nonlocal n
        n += 1
        return n
    return inc

c = make_counter()
print(c(), c())                       # 1 2

cell = c.__closure__[0]               # 闭包单元格（cell）
print(cell.cell_contents)             # 2 ← 可以直接读出被保存的变量
print(c.__closure__)                  # (<cell at 0x...: int object at 0x...>,)
```

**为什么需要闭包：外层函数已返回，变量却还活着**

```text
make_counter() 的栈帧已销毁，
但 inc 的 __closure__ 持有指向 n 的 cell，
cell 又让 n 保持被引用 → 直到 c 被回收，n 才释放。
```

**经典延迟绑定坑：**

```python
# 错误：所有闭包共享同一个 i
def make_funcs_bad():
    return [lambda: i for i in range(3)]

print([f() for f in make_funcs_bad()])       # [2, 2, 2]

# 正确一：默认参数在定义时绑定
def make_funcs_ok1():
    return [lambda i=i: i for i in range(3)]

# 正确二：额外套一层工厂函数
def make_funcs_ok2():
    def make(i):
        return lambda: i
    return [make(i) for i in range(3)]

print([f() for f in make_funcs_ok1()])       # [0, 1, 2]
print([f() for f in make_funcs_ok2()])       # [0, 1, 2]
```

**闭包的实际用途：**

- **装饰器**（下一题）：保存额外状态（如调用次数、缓存）。
- **函数工厂**：生成「参数已固定的专用函数」。
- **回调与延迟执行**：如事件处理、`functools.partial` 的替代。
- **替代全局变量**：把状态藏在闭包里，避免污染全局命名空间。

**易错点：**

- 闭包保存的是**变量本身（cell）**而不是值，所以循环里的延迟绑定问题非常常见；解决方式就是「默认参数快照」或「工厂函数」。
- `__closure__` 只包含**自由变量**（内层函数引用、又没在内层赋值的名字）；`nonlocal` 声明过的变量会进入 cell。
- 闭包会**延长变量生命周期**，如果保存的是大对象（如大 DataFrame），会造成隐性内存占用。
- 「Python 2 只能读不能写闭包变量」已过时——Python 3 用 `nonlocal` 即可写，面试要说明版本差异。

## 12. 装饰器

**本质：装饰器 = 高阶函数 + 闭包。** 它接受一个函数，返回一个「增强版」的新函数。

```text
@decorator
def f(): ...

等价于：
def f(): ...
f = decorator(f)
```

**① 最基础的形式**

```python
def log(func):
    def wrapper(*args, **kwargs):
        print(f"调用 {func.__name__}")
        result = func(*args, **kwargs)
        print(f"返回 {result}")
        return result
    return wrapper

@log
def add(a, b):
    return a + b

add(1, 2)
# 调用 add
# 返回 3
```

**② 必须加 `functools.wraps`**

```python
import functools

def log(func):
    @functools.wraps(func)          # 把 __name__/__doc__/__module__ 等元信息复制到 wrapper
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@log
def add(a, b):
    """两数相加。"""
    return a + b

print(add.__name__, add.__doc__)    # add 两数相加。
# 若不加 wraps：__name__ 会变成 wrapper，文档丢失，调试与依赖签名的框架（如 FastAPI）会出错
```

**③ 带参数的装饰器：三层嵌套**

```python
def repeat(times):                      # 第 1 层：接收装饰器参数
    def decorator(func):                # 第 2 层：接收被装饰函数
        @functools.wraps(func)
        def wrapper(*args, **kwargs):   # 第 3 层：接收调用参数
            result = None
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def greet(name):
    print(f"hi {name}")

greet("Ada")                            # 打印三次 hi Ada
```

**④ 类装饰器与类实现的装饰器**

```python
class Counter:
    def __init__(self, func):
        functools.wraps(func)(self)     # 保留元信息
        self.func = func
        self.count = 0
    def __call__(self, *args, **kwargs):
        self.count += 1
        return self.func(*args, **kwargs)

@Counter
def hello():
    return "hello"

hello(); hello()
print(hello.count)                      # 2 ← 类装饰器天然适合保存状态
```

**⑤ 常用内置装饰器**

| 装饰器 | 作用 | 要点 |
| --- | --- | --- |
| `@property` | 把方法变成属性访问 | 配套 `@x.setter` / `@x.deleter`；属性名不能再同名函数 |
| `@staticmethod` | 静态方法 | 不收 `self`/`cls`，仅作命名空间组织 |
| `@classmethod` | 类方法 | 首参为 `cls`，常用于替代构造函数、工厂方法 |
| `@functools.lru_cache` | 结果缓存 | 参数必须可哈希；`3.9+` 可用 `@cache`（无大小限制） |
| `@dataclass` | 自动生成 `__init__`/`__repr__`/`__eq__` | 常用于数据载体类 |

```python
import functools
from dataclasses import dataclass

class Circle:
    def __init__(self, r): self._r = r
    @property
    def area(self):                     # 访问时像属性，调用时执行函数
        return 3.14159 * self._r ** 2
    @area.setter
    def area(self, v):
        self._r = (v / 3.14159) ** 0.5

print(Circle(1).area)                   # 3.14159

@functools.lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(80))                          # 极快（记忆化）

@dataclass
class User:
    name: str
    age: int = 0

print(User("Ada"))                      # User(name='Ada', age=0)
```

**多个装饰器的执行顺序：**

```python
@a
@b
def f(): ...
# 等价 f = a(b(f))：装饰顺序「自下而上」，执行顺序「自上而下」（a 的外层先跑）
```

**易错点：**

- 装饰器代码在**模块导入时执行一次**（不是每次调用都执行），因此写在其内部的副作用（打印、注册、读配置）只发生一次。
- 忘记 `@functools.wraps` → 函数签名、`__name__`、文档全部丢失，`FastAPI`/`pytest` 这类依赖反射的框架会直接出错。
- 装饰器作用在**方法**上时，`wrapper(*args, **kwargs)` 要把 `self` 一起透传（别用固定位置的参数列表裁剪）。
- `lru_cache` 的参数与返回值需可哈希/可缓存；对实例方法直接使用会把 `self` 计入 key，导致对象无法回收（内存泄漏）。

## 13. 迭代器与生成器

**① 可迭代对象 vs 迭代器**

| 概念 | 协议 | 例子 |
| --- | --- | --- |
| 可迭代对象 Iterable | 实现 `__iter__()`（返回迭代器） | `list`、`tuple`、`dict`、`str`、`set`、文件对象 |
| 迭代器 Iterator | 同时实现 `__iter__()`（返回自身）与 `__next__()` | `iter(list)`、生成器、`enumerate` 对象 |

```text
for x in obj:           等价于：
_it = iter(obj)          # 调 obj.__iter__()
while True:
    try:
        x = next(_it)    # 调 _it.__next__()
    except StopIteration:
        break
```

**② `yield`：暂停与恢复**

```python
def gen():
    print("开始")
    x = yield 1          # 执行到 yield 暂停，返回值 1；恢复时把 send 的值赋给 x
    print("收到:", x)
    y = yield 2
    print("收到:", y)
    return "done"        # 结束值放进 StopIteration.value

g = gen()
print(next(g))           # 开始 / 1
print(g.send("A"))       # 收到: A / 2
try:
    g.send("B")          # 收到: B → 结束
except StopIteration as e:
    print("返回值:", e.value)   # 返回值: done
```

关键机制：

- 生成器函数**调用时不执行任何代码**，只返回一个生成器对象。
- `yield` 把**栈帧（frame）挂起**并保存局部变量与执行位置；`next` 时从挂起点**恢复**。
- 生成器本身是迭代器，实现了 `__iter__` 与 `__next__`。

**③ `send` / `throw` / `close`**

| 方法 | 作用 |
| --- | --- |
| `next(g)` / `g.send(None)` | 恢复执行到下一个 `yield` |
| `g.send(value)` | 恢复执行，并把 `value` 作为当前 `yield` 表达式的结果 |
| `g.throw(exc)` | 在挂起点抛出异常（生成器内部可 `try/except` 捕获） |
| `g.close()` | 在挂起点抛 `GeneratorExit`，触发 `finally`，之后不可再迭代 |

```python
def guarded():
    try:
        yield 1
    except ValueError as e:
        print("捕获:", e)
    finally:
        print("清理资源")           # close() 或抛异常退出时都会执行

g = guarded()
print(next(g))                      # 1
g.throw(ValueError("bad"))          # 捕获: bad / 清理资源

g2 = guarded()
next(g2)
g2.close()                          # 清理资源
```

**④ `yield from`：委托给另一个可迭代对象**

```python
def sub():
    yield 1
    yield 2
    return "sub-done"

def outer():
    result = yield from sub()       # 把迭代委托出去，并接收子生成器的返回值
    print("子生成器返回:", result)
    yield 3

print(list(outer()))                # 子生成器返回: sub-done（打印）/ [1, 2, 3]

from itertools import chain
print(list(chain([1, 2], [3, 4])))  # [1, 2, 3, 4] ← 惰性串联多个可迭代对象
```

**⑤ 惰性求值省内存**

```python
import sys

big_list = [i for i in range(10**6)]
big_gen = (i for i in range(10**6))

print(sys.getsizeof(big_list))    # 约 8 MB
print(sys.getsizeof(big_gen))     # 约 200 字节 ← 只保存当前状态

# 读取大文件的正确姿势：不一次性读入内存
def read_lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:            # 文件对象自身就是迭代器
            yield line.rstrip("\n")
```

**易错点：**

- **迭代器与生成器只能消费一次**，遍历完再遍历就是空；需要多次使用先 `list()` 物化。
- 生成器函数第一次 `send` 必须传 `None`（或先用 `next`），否则 `TypeError: can't send non-None value to a just-started generator`。
- 生成器被 GC 或 `close()` 时会在挂起点抛 `GeneratorExit`，`finally` 会执行；不要在 `finally` 里再 `yield`（报 `RuntimeError`）。
- 用 `return` 提前结束生成器时，值放在 `StopIteration.value`；`for` 循环会忽略它，需要显式捕获才能拿到。

## 14. 异常处理与自定义异常

**`try/except/else/finally` 的执行顺序：**

| 子句 | 执行时机 | 说明 |
| --- | --- | --- |
| `try` | 始终 | 放可能出错的代码 |
| `except` | 发生匹配异常时 | 可写多个，从上到下匹配 |
| `else` | **try 无异常时** | 放「只有在成功后才执行」的代码 |
| `finally` | **始终**（含 return / 异常传播） | 释放资源，不受 return 影响 |

```python
def parse(text):
    try:
        value = int(text)                 # 可能抛 ValueError
    except ValueError as e:
        print("解析失败:", e)
    else:
        print("解析成功:", value)          # 只有无异常才走这里
    finally:
        print("无论如何都会执行")          # 资源清理放这里

parse("12")
# 解析成功: 12
# 无论如何都会执行
parse("abc")
# 解析失败: invalid literal for int() with base 10: 'abc'
# 无论如何都会执行
```

**异常继承体系：**

```text
BaseException
├── SystemExit            （sys.exit 抛出，不应被 except Exception 捕获）
├── KeyboardInterrupt     （Ctrl+C）
├── GeneratorExit
└── Exception             ← 业务代码的基类
    ├── StopIteration
    ├── ArithmeticError → ZeroDivisionError / OverflowError
    ├── LookupError → IndexError / KeyError
    ├── OSError → FileNotFoundError / PermissionError / TimeoutError
    ├── ValueError → UnicodeError
    ├── TypeError
    ├── AttributeError
    ├── ImportError → ModuleNotFoundError
    ├── RuntimeError → RecursionError
    └── NameError → UnboundLocalError
```

**自定义异常与 `raise ... from ...`：**

```python
class AppError(Exception):
    """应用异常基类。"""

class ConfigError(AppError):
    def __init__(self, key, message="配置缺失"):
        super().__init__(f"{message}: {key}")   # 调用父类构造，保证 args 可用
        self.key = key

def load(config, key):
    if key not in config:
        raise ConfigError(key) from KeyError(key)   # 显式链接原因，保留原始 traceback
    return config[key]

try:
    load({}, "db_url")
except AppError as e:
    print(type(e).__name__, e, e.key)    # ConfigError 配置缺失: db_url db_url
    print(e.__cause__)                   # 'db_url' ← from 决定 __cause__
```

**`raise from` vs 隐式链：**

| 写法 | `__cause__` | 说明 |
| --- | --- | --- |
| `raise B from A` | A | 显式因果链，输出显示「The above exception was the direct cause」 |
| `raise B`（在 except 内） | 自动设为 A | 隐式链，「During handling of the above exception...」 |
| `raise B from None` | 置空 | 隐藏内部异常，只暴露 B（对外 API 常用） |

**EAFP vs LBYL：**

| 风格 | 含义 | 写法 | 适用 |
| --- | --- | --- | --- |
| **EAFP** | 先做，出错再处理（Python 推荐） | `try: d[k] except KeyError` | 出错概率低、竞态敏感（文件/字典） |
| **LBYL** | 先检查再做 | `if k in d: d[k]` | 检查本身开销小、逻辑清晰时 |

```python
d = {"a": 1}

# EAFP
try:
    v = d["b"]
except KeyError:
    v = 0
print(v)                       # 0

# LBYL
if "b" in d:
    v = d["b"]
else:
    v = 0

# 更简洁的等价写法
print(d.get("b", 0))           # 0
```

**易错点：**

- 「先检查再操作」在并发场景下有 **TOCTOU（检查与使用之间的时间窗）** 问题，应优先 EAFP（`d.get`、`os.makedirs(exist_ok=True)`、`LOCK_NB`）。
- **别裸 `except:`**：会连 `KeyboardInterrupt`、`SystemExit` 一起吞掉，导致程序无法 Ctrl+C 退出；至少写 `except Exception:`。
- `finally` 里若 `return`/`raise`，会**覆盖** try/except 中的返回值与异常，属于隐蔽 bug。
- Python 3 中 `except E as e` 的 `e` 在 except 块结束后会被**自动 `del`**，块外引用会 `NameError`。

## 15. 上下文管理器与 with

**协议：`__enter__` / `__exit__`**

```python
class Timer:
    def __enter__(self):
        import time
        self.start = time.perf_counter()
        return self                     # with ... as x 里的 x 就是它
    def __exit__(self, exc_type, exc, tb):
        import time
        self.cost = time.perf_counter() - self.start
        print(f"耗时 {self.cost:.4f}s")
        # 返回 True 会「抑制异常」，返回 None/False 会让异常继续抛出
        return False

with Timer() as t:
    sum(range(10**6))
print(t.cost > 0)                       # True
```

**`with` 的执行流程（含异常）：**

```text
1. mgr = Timer()            # 求值上下文表达式
2. value = mgr.__enter__()  # 进入
3. 执行 with 语句体
4. 无论正常结束还是抛异常，都调用 mgr.__exit__(exc_type, exc, tb)
5. 若 __exit__ 返回「真值」→ 异常被抑制；否则异常继续向外传播
```

```python
class Suppress:
    def __enter__(self): return self
    def __exit__(self, exc_type, exc, tb):
        return True                     # 吞掉所有异常

with Suppress():
    raise ValueError("会被忽略")
print("继续执行")                        # 继续执行
```

**用生成器写上下文管理器：`@contextlib.contextmanager`**

```python
import contextlib

@contextlib.contextmanager
def tag(name):
    print(f"<{name}>")                  # __enter__ 部分：yield 之前
    try:
        yield f"内容-{name}"            # with ... as x 拿到这个值
    finally:
        print(f"</{name}>")             # __exit__ 部分：yield 之后

with tag("b") as inner:
    print(inner)
# <b>
# 内容-b
# </b>
```

**`contextlib` 常用工具：**

| 工具 | 作用 |
| --- | --- |
| `suppress(*excs)` | 忽略指定异常，替代空的 `try/except` |
| `closing(obj)` | 退出时调用 `obj.close()` |
| `ExitStack()` | 动态管理多个上下文，常用于「不确定数量的资源」 |
| `nullcontext()` | 占位，便于可选地使用 with |

```python
import contextlib

with contextlib.suppress(FileNotFoundError):
    open("no_such_file.txt")

with contextlib.ExitStack() as stack:
    files = [stack.enter_context(open(p)) for p in ["a.txt", "b.txt"]]  # 逆序自动关闭
```

**标准库中的常见用例：**

```python
# 文件：退出时自动 close，即使中途抛异常
with open("data.txt", "w", encoding="utf-8") as f:
    f.write("hello")

# 锁：保证释放，避免死锁
import threading
lock = threading.Lock()
with lock:
    pass

# 事务（如 sqlite3）
import sqlite3
with sqlite3.connect(":memory:") as conn:   # 退出时 commit/rollback
    pass
```

**易错点：**

- `__exit__` 返回 `None`（默认）**不会**抑制异常，很多人以为写了 `__exit__` 就能吞异常。
- `@contextmanager` 装饰的函数里 **`yield` 只能出现一次**；若不 `try/finally` 包裹，`with` 体内抛异常时清理代码不会执行。
- `with` 不等于 `try/finally` 的全部能力：`with` 无法处理「多分支、部分资源可能未创建」的复杂场景，那时用 `ExitStack`。
- 自定义 `__exit__` 中若自身抛异常，会**替换掉**原来的异常，排查时要注意因果链。

## 16. 解包与星号表达式

**① 序列解包（unpacking）**

```python
a, b, c = [1, 2, 3]
x, y = y, x                     # 交换变量：右侧先构造元组，再解包
print(a, b, c, x, y)            # 1 2 3 2 1

# 星号收集剩余项（Python 3 特性）
first, *rest = [1, 2, 3, 4]
print(first, rest)              # 1 [2, 3, 4]

*init, last = (1, 2, 3, 4)
print(init, last)               # [1, 2, 3] 4

head, *middle, tail = "abcdef"
print(head, middle, tail)       # a ['b', 'c', 'd', 'e'] f

# 嵌套解包
(uid, (name, age)), role = (1, ("Ada", 30)), "admin"
print(uid, name, age, role)     # 1 Ada 30 admin
```

**② `*` 在「定义」与「调用」中的角色**

| 场景 | 写法 | 含义 |
| --- | --- | --- |
| 函数定义 | `def f(*args)` | 收集多余位置参数为 tuple |
| 函数定义 | `def f(**kwargs)` | 收集多余关键字参数为 dict |
| 函数定义 | `def f(a, *, b)` | `b` 之后仅关键字 |
| 函数调用 | `f(*iterable)` | 把可迭代对象拆成位置参数 |
| 函数调用 | `f(**mapping)` | 把映射拆成关键字参数 |
| 容器字面量 | `[*a, *b]`、`{**d1, **d2}`、`(*a, *b)` | 合并/展开（3.5+，dict 用 `**`） |

```python
def add(a, b, c):
    return a + b + c

nums = [1, 2, 3]
print(add(*nums))                       # 6
print(add(**{"a": 1, "b": 2, "c": 3}))  # 6

# 合并列表 / 元组 / 字典
print([*[1, 2], *[3, 4]])               # [1, 2, 3, 4]
print((*range(2), *range(2, 4)))        # (0, 1, 2, 3)
d1, d2 = {"a": 1}, {"b": 2, "a": 9}
print({**d1, **d2})                     # {'a': 9, 'b': 2} ← 后者覆盖前者
print(d1 | d2)                          # {'a': 9, 'b': 2} ← Python 3.9+ 的 | 合并
```

**③ 配合 `zip` / `enumerate` 的实战**

```python
pairs = [("a", 1), ("b", 2)]
for key, value in pairs:                # 逐项解包
    print(key, value)

matrix = [[1, 2], [3, 4]]
for (r1, r2) in matrix:
    print(r1 + r2)                      # 3 / 7

# 转置：zip(*matrix)
print([list(col) for col in zip(*matrix)])   # [[1, 3], [2, 4]]
```

**易错点：**

- 解包要求**左右数量匹配**，否则 `ValueError: not enough values to unpack` / `too many values to unpack`。
- **一个解包语句里只能有一个 `*` 目标**：`*a, *b = ...` 是 `SyntaxError`。
- `*rest` 收集到的**类型与源对象无关**，始终是 `list`（`*a, = (1, 2)` 得到的是列表）。
- `f(**d)` 的键必须是字符串、且不能与已传的位置参数重复，否则 `TypeError: got multiple values for argument`。
