## 1. 内存管理与垃圾回收机制

**CPython 的内存管理与垃圾回收由三套机制协作完成，面试要点是「为什么三套都要有」。**

1. **引用计数（Reference Counting）——主力，实时回收**
   - 每个对象头里的 `ob_refcnt` 记录「有多少个引用指向我」。
   - 引用通过赋值、传参、放入容器等方式 **+1**；变量 `del`、重新赋值、离开作用域、容器销毁时 **-1**。
   - 计数归零 **立即** 释放内存并调用 `__del__`（若无引用环，回收是确定的、实时的）。
   - 统计上，绝大多数对象在计数归零时就能被回收，所以它承担了 **90%+** 的回收工作。

2. **标记-清除（Mark and Sweep）——辅力，专门打破循环引用**
   - 引用计数有个致命缺陷：**对象之间互相引用时，计数永远不为 0**，谁也无法释放。
   - 因此引入了周期性运行的标记-清除：从根对象（全局变量、栈、寄存器）出发做可达性分析，**没被标记到的容器对象**（不可达环）统一回收。
   - 注意：只有 **能被 GC 追踪的容器类型**（`list`、`dict`、`set`、自定义对象…）参与，`int`、`str` 这类不含引用的对象不参与，效率因此可控。

3. **分代回收（Generational GC）——性能优化，让标记-清除别跑太勤**
   - 统计规律：**越年轻的对象越容易死，越老的对象越可能长期存活**。
   - 于是把对象分为 **0 / 1 / 2 三代**，新对象都在 0 代；0 代扫得最勤，某代扫描后还活着的对象被晋升到更高代，扫得越少。
   - 只有 0 代回收会频繁触发，全代（2 代）回收很少发生，从而把标记-清除的开销摊薄。

**三代回收阈值与 `gc` 模块接口：**

| 机制 | 触发方式 | 作用对象 | 是否处理循环引用 |
| --- | --- | --- | --- |
| 引用计数 | 计数归零时立即 | 所有对象 | **否** |
| 标记-清除 | 由分代阈值触发 | 可追踪容器对象 | **是** |
| 分代回收 | 0 代分配数超过阈值 | 同上 | 是（按代组织） |

| 接口 | 作用 |
| --- | --- |
| `gc.get_threshold()` | 返回 `(700, 10, 10)`，即 0/1/2 代阈值 |
| `gc.set_threshold(700, 10, 10)` | 调整分代回收触发频率 |
| `gc.collect(n)` | 手动回收第 n 代；`gc.collect()` 等价于全代回收，返回回收对象数 |
| `gc.get_count()` | 返回 `(0代计数, 1代计数, 2代计数)` |
| `gc.disable()` / `gc.enable()` | 关闭/开启自动回收（引用计数不受影响，仍在工作） |
| `gc.isenabled()` | 查询自动回收是否开启 |
| `gc.garbage` | 存放「无法回收的不可达对象」的列表（历史遗留，Py3.4 后基本为空） |
| `gc.get_referrers(obj)` / `gc.get_referents(obj)` | 查询谁引用了 obj / obj 引用了谁 |

**分代的晋升规则（默认阈值）：**

```text
0 代：分配数 - 释放数 达到 700  → 触发 0 代回收，活下来的对象晋升到 1 代
1 代：0 代回收满 10 次          → 触发 1 代回收，活下来的对象晋升到 2 代
2 代：1 代回收满 10 次          → 触发 2 代（全代）回收
```

```python
import gc
import sys

print(gc.get_threshold())        # (700, 10, 10)
print(gc.get_count())            # 当前各代计数，如 (12, 0, 0)
print(gc.isenabled())            # True
gc.set_threshold(1000, 15, 15)   # 调大阈值：回收更懒、吞吐更高

# 引用计数：getrefcount 返回「本对象引用数 + 1」
class Node:
    pass

n = Node()
print(sys.getrefcount(n))        # 2（n 本身 1 个 + 实参临时引用 1 个）
m = n
print(sys.getrefcount(n))        # 3（多了变量 m）
del m
print(sys.getrefcount(n))        # 2（回到初始状态）

# 手动触发回收
print(gc.collect(0))             # 只回收第 0 代，返回该代被释放的对象数
print(gc.collect())              # 全代回收（等价 gc.collect(2)）
```

**为什么光有引用计数还不够？**

```python
import gc

gc.disable()  # 关闭自动回收，排除干扰

class Node:
    def __init__(self, name):
        self.name = name

a, b = Node('a'), Node('b')
a.peer, b.peer = b, a        # 互相引用：两个对象的引用计数都恒为 1

del a, b                     # 变量没了，但对象互相引用，引用计数都不为 0
print(gc.get_count())        # 计数在涨，却永远不会自动释放
n = gc.collect()             # 标记-清除出手，找到不可达环
print('本次回收对象数：', n)

gc.enable()
```

**易错点：**

- `sys.getrefcount(obj)` **总比实际多 1**，因为把 `obj` 作为实参传入时，函数栈上会临时多一个引用。
- **暂停分代回收（`gc.disable()`）不会暂停引用计数**：无环对象照旧即时释放，只有循环引用才会泄漏成内存增长。
- 参与标记-清除的是**容器对象**，`int`/`str`/`float` 等不含引用的标量对象**不参与**，否则回收成本不可接受。

> 提示：频繁触发 GC 会拖慢程序，临时关闭自动回收（`gc.disable()`，配合定时 `gc.collect()`）是常见调优手段；但只要代码会产生大量循环引用，就需要评估泄漏风险。

## 2. 引用计数与循环引用

**引用计数（reference counting）是 CPython 的主力回收机制，`sys.getrefcount` 与「循环引用」是这一题的两大考点。**

**引用计数什么时候变化：**

| 场景 | 变化 |
| --- | --- |
| 变量赋值 `b = a` | 对象 +1 |
| 作为参数传入 / 放入容器（`lst.append(a)`） | +1 |
| 变量被重新赋值 `a = None` | 原对象 -1 |
| `del a` | -1 |
| 变量离开作用域 / 函数返回 | -1 |
| 容器本身被销毁 | 其内部元素引用全部 -1 |

```python
import sys

class Obj:
    pass

a = Obj()                      # 引用计数 = 1
print(sys.getrefcount(a))      # 2 → 实际 1，多出的是 getrefcount 的实参临时引用

b = a                          # 引用计数 = 2
lst = [a]                      # 引用计数 = 3
print(sys.getrefcount(a))      # 4（2 个变量 + 1 个容器 + 1 个实参）

del b
lst.clear()                    # 引用计数回到 1
print(sys.getrefcount(a))      # 2
del a                          # 计数归零 → 立即释放
```

**为什么 `getrefcount` 的结果要「减 1」：**

- 调用 `sys.getrefcount(a)` 时，解释器要把 `a` 压入调用栈作为实参，这一步就产生了一个新的强引用。
- 所以公式是：`实际引用数 = sys.getrefcount(obj) - 1`。
- 这个「多 1」是面试高频细节，不要答成「返回值就是引用数」。

**循环引用示例（引用计数永远不为 0）：**

```python
import gc
import weakref

gc.disable()  # 排除自动回收干扰，便于观察

class Node:
    def __init__(self, name):
        self.name = name
        self.peer = None

def make_cycle():
    a, b = Node('a'), Node('b')
    a.peer, b.peer = b, a     # 互相持有强引用 → 引用计数永远 >= 1
    return weakref.ref(a), weakref.ref(b)

ra, rb = make_cycle()
print('函数返回后 a 是否还存活：', ra() is not None)   # True（引用计数未归零）
gc.collect()                                           # 手动触发标记-清除
print('回收后 a 是否还存活：', ra() is not None)        # False
```

**三种解法（面试建议都说一遍）：**

**① 依赖 GC 的标记-清除**

- 最省事：什么都不用改，等分代回收自动处理。
- 缺点：回收时机不可控、内存占用有延迟峰值；大量短命环路会造成内存曲线呈锯齿状。

**② 用 `weakref` 把「环」拆成单向强引用**

```python
import weakref

class Parent:
    def __init__(self, name):
        self.name = name
        self.children = []

class Child:
    def __init__(self, parent):
        self.parent = weakref.ref(parent)   # 弱引用：不增加父对象计数

p = Parent('p')
c = Child(p)
p.children.append(c)                        # 父 → 子 强引用，子 → 父 弱引用，环被打断
print(c.parent().name)                      # 'p'
del p
print(c.parent())                           # None（父对象被正常释放）
```

**③ 手动断开 / 使用 `with` 或上下文清理**

```python
a.peer = None   # 显式断开一侧引用，计数立刻归零
b.peer = None
```

**`__del__` 对回收的影响：**

```python
import gc

class Bad:
    def __init__(self, name):
        self.name = name
    def __del__(self):
        print(f'销毁 {self.name}')

gc.disable()
x = Bad('x')
x.self_ref = x          # 形成自引用环
del x
print('手动回收前：无输出（对象仍在环里）')
gc.collect()            # Python 3.4+（PEP 442）后，环中的 __del__ 也能被调用，然后回收
```

| 版本 | 带 `__del__` 的循环引用行为 |
| --- | --- |
| Python ≤ 3.3 | 不能回收，对象被塞进 `gc.garbage`，`__del__` 不执行 → **永久泄漏** |
| Python 3.4+（PEP 442） | 可以回收，`__del__` 会被正常调用（顺序不保证），`gc.garbage` 基本不再使用 |

**易错点：**

- `gc.garbage` 是**历史产物**，Py3.4 之后通常为空；回答「`__del__` 会导致永久泄漏」时务必补充版本差异。
- `__del__` 的调用时机不确定（对象被回收时才调用），**不要**用它做资源释放——应该用 `with` / `try...finally` / `weakref.finalize`。
- 程序退出时 `__del__` 甚至可能不执行，因此「靠 `__del__` 关文件/断连接」是错误姿势。

> 提示：`weakref.finalize(obj, callback)` 比 `__del__` 更可靠，它注册的回调即使用户手动 `del` 或程序结束也能被调用。

## 3. 小整数池与字符串驻留

**这一题的本质是「CPython 为了性能做的缓存与复用」，它直接导致 `is` 的结果具有不确定性——所以比较值永远用 `==`。**

**三个层面的复用机制：**

1. **小整数池（small int cache）**：解释器启动时就预创建 `[-5, 256]` 的 `int` 对象，之后所有落在这个范围的整数都复用同一对象。
2. **字符串驻留（string interning）**：形如标识符的字符串（字母/数字/下划线组合）在编译期被放入驻留字典，相同字面量指向同一对象。
3. **编译期常量折叠（constant folding）**：`'a' + 'b'`、`2 * 3` 这类「纯字面量运算」在编译阶段就合并成单个常量，因此可以复用。

| 机制 | 适用范围 | 触发时机 |
| --- | --- | --- |
| 小整数池 | `-5 ~ 256` 的整数 | 解释器启动时预建 + 运算快路径 |
| 字符串驻留 | 类标识符字符串、`sys.intern()` 显式调用 | 编译期 / 显式 |
| 常量折叠 | 字面量之间的算术拼接 | 编译期 |
| 无复用 | 超出范围的数、运行时构造的字符串 | — |

```python
# 1) 小整数池：[-5, 256] 内复用同一对象
a, b = 256, 256
print(a is b)          # True

c, d = -5, -5
print(c is d)          # True

# 2) 超出范围：结果取决于「是否属于同一代码对象」
def f():
    x = 257
    y = 257
    return x is y
print(f())             # True → 同一代码对象里，相同的常量会被合并进 co_consts 复用

# 而在交互式/脚本中逐行执行时，两行是两个独立代码对象，通常得到 False
```

```python
# 3) 字符串驻留与常量折叠
s1 = 'hello_world'
s2 = 'hello_world'
print(s1 is s2)              # True（字面量驻留）

s3 = 'hello' + '_' + 'world' # 编译期折叠成 'hello_world'
print(s3 is s1)              # True（折叠后指向同一驻留对象）

s4 = ''.join(['hello_', 'world'])
print(s4 is s1, s4 == s1)    # False True（运行时构造 → 新对象，不驻留）

import sys
print(sys.intern(s4) is s1)  # True（显式驻留后指向同一对象）
```

```python
# 4) 运行期计算的结果通常不共享
def compute():
    return 256

print(compute() is 256)      # True（仍命中池中的 256）

x = 256 + 0                  # 快路径结果多来自池中对象
print(x is 256)              # True

y = 1000 + 0
print(y is 1000)             # 结果依赖实现，不要依赖
```

> 结论：`is` 判断的是「是否同一个对象」，只应用于 `None`、`True`、`False` 以及自己明确知道是单例的对象；比较数值/字符串请用 `==`。

**易错点：**

- 用 `is` 比较数值/字符串是**未定义行为**（implementation-defined），换解释器版本、换 REPL/脚本执行方式都可能翻车。
- `''.join(...)`、`f'{a}{b}'`、切片等运行时产生的字符串**不会**被自动驻留，`is` 必然为 `False`。
- 驻留会**长期占用内存**（驻留字典不释放），不要对「海量、一次性、超长的用户输入字符串」滥用 `sys.intern()`；它适合「少量、高频比较」的键。

## 4. GIL 全局解释器锁

**GIL（Global Interpreter Lock，全局解释器锁）是 CPython 的一把互斥锁：任意时刻只有一个线程能执行 Python 字节码。** 它是一道分水岭题。

**为什么存在（设计权衡，不是 bug）：**

1. **简化 CPython 的内存管理**：引用计数需要原子性，如果多线程真正并行修改 `ob_refcnt`，就得给每个对象加锁（细粒度锁），复杂且慢；GIL 用一把大锁换来了实现简单与单线程高性能。
2. **保证 C 扩展的线程安全**：大量 C 扩展、第三方库都假设「同一时刻只有一个线程在跑 Python 层代码」，去掉 GIL 会让整个生态的线程安全假设失效。
3. **历史包袱**：CPython 诞生于单核时代，GIL 让单线程性能最优，改造成本巨大。

**核心影响：**

| 维度 | 说明 |
| --- | --- |
| 并行能力 | 同一时刻**只有 1 个线程执行字节码**，多线程无法在纯 Python 层真正并行 |
| 线程切换 | 线程持有 GIL 执行一定时间（默认 5 ms，`sys.getswitchinterval()`）或被阻塞时释放 |
| IO 密集型 | **有效**：`time.sleep`、文件读写、网络 `socket` 等 IO 调用会**释放 GIL**，其他线程可趁隙执行 |
| CPU 密集型 | **无效甚至更慢**：多线程只是轮流占用 GIL，还多了切换开销 |
| 是否还需线程锁 | **需要**：GIL 只保证「单条字节码」的原子性，`i += 1` 是「读-改-写」多条字节码，仍会竞态 |

```python
import sys
import threading
import time

print(sys.getswitchinterval())   # 0.005 → 默认 5ms 就让出一次 GIL
# sys.setswitchinterval(0.001)   # 调小：切换更频繁，响应更好但吞吐下降

def cpu_task(n):
    total = 0
    for i in range(n):
        total += i
    return total

def io_task():
    time.sleep(0.3)              # sleep 期间会释放 GIL

# ---- CPU 密集型：多线程不提速 ----
n = 10_000_000
t0 = time.perf_counter()
cpu_task(n)
cpu_task(n)
print('单线程耗时：', round(time.perf_counter() - t0, 2))

t0 = time.perf_counter()
ts = [threading.Thread(target=cpu_task, args=(n,)) for _ in range(2)]
for t in ts: t.start()
for t in ts: t.join()
print('双线程耗时：', round(time.perf_counter() - t0, 2))   # 与单线程接近，甚至更慢
```

```python
# ---- IO 密集型：多线程有效 ----
t0 = time.perf_counter()
ts = [threading.Thread(target=io_task) for _ in range(4)]
for t in ts: t.start()
for t in ts: t.join()
print('4 线程 IO 耗时：', round(time.perf_counter() - t0, 2))  # 约 0.3s，而非 1.2s
```

**为什么有了 GIL 还需要自己加锁：**

```python
import threading

counter = 0

def add_many():
    global counter
    for _ in range(1_000_000):
        counter += 1   # 实际是 LOAD_GLOBAL / LOAD_CONST / BINARY_OP / STORE_GLOBAL 多条字节码

ts = [threading.Thread(target=add_many) for _ in range(4)]
for t in ts: t.start()
for t in ts: t.join()
print(counter)   # 大概率小于 4000000 → 线程切换发生在字节码之间，出现丢失更新
```

**如何绕过 GIL：**

| 方案 | 适用场景 | 说明 |
| --- | --- | --- |
| **多进程** `multiprocessing` | CPU 密集型 | 每个进程独立解释器与 GIL，可真正并行（代价：进程开销、数据需序列化） |
| **C 扩展释放 GIL** | 数值计算 | NumPy / Cython / `ctypes` 在计算时主动 `Py_BEGIN_ALLOW_THREADS` 释放 GIL |
| **`asyncio` 协程** | 高并发 IO | 单线程事件循环，本质是「自己调度 IO 等待」，不依赖多线程绕过 |
| **其他解释器** | 特定场景 | Jython、IronPython 无 GIL（生态弱）；PyPy 也有自己的 GIL |
| **free-threading** | 前沿 | Python 3.13 起提供**实验性**的无 GIL 构建（PEP 703），尚不适合生产；仅作了解 |

**易错点：**

- 「GIL 让多线程完全无用」是**错的**：IO 密集与调用释放 GIL 的 C 库时，多线程依然有效。
- 「GIL 是 Python 语言特性」是**错的**：它是 **CPython 实现**的细节，Jython/IronPython 没有。
- 「多线程 CPU 任务会有数据竞争所以结果错，说明加了 GIL 也没用」——顺序反了：**正因 GIL 只保护单条字节码，复合操作仍需自行加锁**。
- 别把 GIL 当成「线程安全护身符」：`counter += 1`、`list[i] += 1`、检查后修改等「非原子序列」都可能出错。

> 提示：Python 3.12 起 `sys.setswitchinterval` 的默认值与切换行为有微调，且 3.13 的 free-threading 需要单独编译，面试中提及「正在演进」即可，不必展开。

## 5. 魔术方法

**魔术方法（magic method / dunder method）是「双下划线包围」的特殊方法，它们让自定义对象能对接 Python 的语法与内置协议。** 面试常考分类记忆 + `__repr__`/`__str__` 区别 + `__eq__`/`__hash__` 联动。

**按用途分类速查：**

| 分类 | 方法 | 触发时机 |
| --- | --- | --- |
| 构造与销毁 | `__new__` / `__init__` / `__del__` | 创建、初始化、销毁 |
| 表示 | `__repr__` / `__str__` / `__format__` / `__bytes__` | `repr()`、`print()`/`str()`、`format()` |
| 比较 | `__eq__` / `__ne__` / `__lt__` / `__le__` / `__gt__` / `__ge__` | `==`、`<`…（也驱动排序） |
| 哈希 | `__hash__` | `hash(obj)`、作为 dict key / set 元素 |
| 容器 | `__len__` / `__getitem__` / `__setitem__` / `__delitem__` / `__contains__` / `__iter__` / `__next__` | `len`、`obj[k]`、`in`、`for` |
| 上下文 | `__enter__` / `__exit__` | `with ... as ...` |
| 调用 | `__call__` | `obj(...)` |
| 属性访问 | `__getattr__` / `__getattribute__` / `__setattr__` / `__delattr__` / `__dir__` | 属性读写、`dir()` |
| 算术 | `__add__` / `__sub__` / `__mul__` / `__radd__` / `__iadd__` … | `+`、`-`、`*`、`+=` |
| 转换 | `__int__` / `__float__` / `__bool__` / `__index__` | `int()`、`bool()`、切片索引 |
| 描述符 | `__get__` / `__set__` / `__delete__` | 作为类属性被访问（见第 9 题） |

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):                 # 面向开发者：调试、容器内显示
        return f'Vector({self.x!r}, {self.y!r})'

    def __str__(self):                  # 面向用户：print / str()
        return f'({self.x}, {self.y})'

    def __eq__(self, other):            # ==
        return isinstance(other, Vector) and (self.x, self.y) == (other.x, other.y)

    def __hash__(self):                 # 与 __eq__ 必须一致
        return hash((self.x, self.y))

    def __add__(self, other):           # +
        return Vector(self.x + other.x, self.y + other.y)

    def __len__(self):                  # len()
        return 2

    def __getitem__(self, i):           # v[0] / v[1]
        return (self.x, self.y)[i]

    def __call__(self):                 # v()    像函数一样可调用
        return self.x + self.y

v = Vector(1, 2)
print(v)                    # (1, 2)          → __str__
print(repr(v))              # Vector(1, 2)    → __repr__
print([v])                  # [Vector(1, 2)]  → 容器内用 __repr__
print(v == Vector(1, 2))    # True
print(v + Vector(3, 4))     # Vector(4, 6)
print(len(v), v[0], v())    # 2 1 3
print({v: '点'})            # 可作字典键
```

**`__repr__` 与 `__str__` 的区别（高频）：**

| | `__repr__` | `__str__` |
| --- | --- | --- |
| 面向对象 | 开发者（调试） | 最终用户（展示） |
| 调用入口 | `repr(obj)`、交互式回显、容器内显示 | `str(obj)`、`print(obj)`、`f'{obj}'` |
| 目标 | **尽量精确、无歧义**，理想情况可 `eval` 回去 | **可读友好** |
| 缺省行为 | 无则返回 `<类名 object at 0x…>` | 无则**回退到 `__repr__`** |

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __repr__(self):
        return f'Point({self.x}, {self.y})'
    # 不定义 __str__ → str() 会回退到 __repr__

p = Point(1, 2)
print(str(p))    # Point(1, 2)
print(p)         # Point(1, 2)
```

**比较 / 哈希的联动（必记）：**

```python
class OnlyEq:
    def __eq__(self, other):
        return True
    # 未定义 __hash__ → 类变为不可哈希

try:
    hash(OnlyEq())
except TypeError as e:
    print(e)   # unhashable type: 'OnlyEq'
```

- 只要定义了 `__eq__` 而不定义 `__hash__`，Python 会把 `__hash__` 隐式设为 `None` → 对象**不可哈希**。
- 要恢复哈希，必须显式定义 `__hash__`，且保证 **`a == b` ⇒ `hash(a) == hash(b)`**（相等对象哈希必须相同），否则 `dict`/`set` 会错乱。

**上下文管理与「旧式迭代协议」：**

```python
import time

class Timer:
    def __enter__(self):
        self.t0 = time.perf_counter()
        return self                     # as 后拿到的是 __enter__ 的返回值

    def __exit__(self, exc_type, exc_value, tb):
        print('耗时', round(time.perf_counter() - self.t0, 4))
        return False                    # False → 不吞异常，向外传播

with Timer() as t:
    sum(range(1_000_000))
```

```python
class MyList:
    def __init__(self, data):
        self.data = list(data)
    def __len__(self):
        return len(self.data)
    def __getitem__(self, i):
        return self.data[i]             # 只实现 __getitem__ 也能支持 for 循环

for item in MyList([1, 2, 3]):          # 解释器不断 __getitem__(0,1,2…), 直到 IndexError
    print(item)
```

**易错点：**

- `__repr__` 返回的**必须是字符串**，返回非字符串会抛 `TypeError`；且其中不要调用 `self.__repr__()` 造成递归。
- `__exit__` 返回 `True` 会**吞掉异常**，返回 `None`/`False` 则异常继续向外抛——写错会导致「异常凭空消失」。
- 同时定义 `__eq__` 与 `__hash__` 时，若 `__hash__` 基于**可变字段**，对象放进 `set`/`dict` 后字段一变就再也找不到。
- `__getattr__`（找不到才调用）与 `__getattribute__`（每次访问都调用）极易混淆，后者写不好会**无限递归**。

## 6. 类属性与实例属性

**属性查找顺序是这一题的核心：`实例 __dict__` → 类的 MRO 链 → 找不到才报错（或触发 `__getattr__`）。**

**两者对比：**

| 维度 | 类属性 | 实例属性 |
| --- | --- | --- |
| 定义位置 | `class` 体内部、方法之外 | 通常在 `__init__` 中用 `self.x = ...` |
| 存储位置 | 类对象的 `__dict__`（`映射代理`） | 实例的 `__dict__` |
| 共享性 | **所有实例共享同一份** | 每个实例各有一份 |
| 读优先级 | 低于实例属性（实例同名属性会「遮蔽」类属性） | **最高** |
| 写影响 | 改类属性会影响所有未覆盖它的实例 | 只影响该实例 |

```python
class A:
    x = 1                 # 类属性

a = A()
b = A()

print(a.x, b.x, A.x)      # 1 1 1 → 实例 __dict__ 里没有 x，去类里找

a.x = 10                  # 关键：这次赋值创建的是「实例属性」，不是改类属性
print(a.x, b.x, A.x)      # 10 1 1 → a 的实例 __dict__ 里有了 x

A.x = 99                  # 直接改类属性
print(a.x, b.x, A.x)      # 10 99 99 → a 被自己的实例属性遮蔽，b 跟着类走

a.__dict__                # {'x': 10}
A.__dict__['x']           # 99
```

**可变类属性的共享陷阱（高频坑）：**

```python
class B:
    items = []            # 可变对象放在类属性上 → 所有实例共享

b1, b2 = B(), B()
b1.items.append(1)        # 注意：没有赋值，只是原地修改 → 改的是「类的列表」
print(b1.items, b2.items) # [1] [1] ← 两个实例看到同一份数据

# 正确写法：可变状态放到 __init__ 里，让它成为实例属性
class C:
    def __init__(self):
        self.items = []   # 每个实例独立的列表
```

**查找顺序与遮蔽（含继承）：**

```text
obj.attr 查找顺序：
1) 数据描述符（定义 __set__ 的，如 property） —— 优先级最高（见第 9 题）
2) 实例的 __dict__
3) 类及其 MRO 上的类属性
4) 非数据描述符（如普通方法函数）
5) 都没有 → 触发 __getattr__ → 仍无则 AttributeError
```

```python
class Base:
    tag = 'base'
    def hi(self):
        return 'hi'

class Sub(Base):
    tag = 'sub'

s = Sub()
print(s.tag)              # sub   → MRO 上先找到 Sub.tag
print(Sub.__mro__)        # (Sub, Base, object)
print(s.hi())             # hi    → 方法存在于类上，实例调用时绑定 self
```

**易错点：**

- `b1.items.append(...)` 是**原地修改类属性**（不触发实例属性创建），所以影响所有实例；只有 `self.items = ...` 才会创建实例属性。
- 「读」走的是「实例 → 类」，「写」`self.x = v` **永远创建/更新实例属性**，想改类属性必须显式写 `类名.x = v` 或 `type(self).x = v`。
- 用 `__slots__` 的类没有 `__dict__`，实例属性**只能**是 `__slots__` 里声明的名字（可省内存，但代价是失去动态属性）。
- 类属性可以被实例「遮蔽」但不会被删除：`del a.x` 删的是实例属性，之后 `a.x` 又会看到类属性。

## 7. MRO 与 super

**MRO（Method Resolution Order，方法解析顺序）决定了「多继承时属性和方法到底用谁」，CPython 用 C3 线性化算法计算它。** `super` 不是「父类」，而是「MRO 链上的下一个类」。

**C3 线性化的直觉规则：**

1. 子类永远排在父类**前面**。
2. 多个父类的相对顺序按声明顺序**保持**。
3. 若出现矛盾（某类既要前又要后），该候选被丢弃，改选下一个。
4. 最终 MRO 以 `object` 结尾，且是**每个类恰好出现一次**的有序列表。

```python
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

print(D.__mro__)
# (<class 'D'>, <class 'B'>, <class 'C'>, <class 'A'>, <class 'object'>)
print([c.__name__ for c in D.mro()])   # ['D', 'B', 'C', 'A', 'object']
```

**钻石继承 + 协作式 `super`：**

```python
class A:
    def run(self):
        print('A')

class B(A):
    def run(self):
        print('B')
        super().run()      # MRO 链上的下一个：对 B 而言是 A

class C(A):
    def run(self):
        print('C')
        super().run()

class D(B, C):
    def run(self):
        print('D')
        super().run()      # D 的父类声明顺序是 B, C

D().run()
# 输出顺序：D → B → C → A
# 因为 D.__mro__ = (D, B, C, A, object)：
#   D.run → super() = B.run → B 里的 super() = C.run → C 里的 super() = A.run
```

**`super()` 在 Python 3 的隐式写法：**

```python
class Base:
    def __init__(self, x):
        self.x = x

class Child(Base):
    def __init__(self, x, y):
        super().__init__(x)      # 等价于 super(Child, self).__init__(x)
        self.y = y

# 为什么能省略参数：编译器为含 super() 的方法注入 __class__ 单元变量，
# super() 自动取「定义该方法的类」与「第一个参数（self）」。
```

**为什么用 `super()` 而不是直接 `Base.__init__(self)`：**

| 写法 | 多继承下的行为 | 结论 |
| --- | --- | --- |
| `Base.method(self)` | **硬编码**父类，MRO 中位于中间的类会被**跳过**，重复初始化风险 | 破坏协作，不推荐 |
| `super().method()` | 沿 MRO **依次**调用下一个，每个类只执行一次 | 支持协作式多继承，推荐 |

```python
class A:
    def __init__(self):
        print('A')

class B(A):
    def __init__(self):
        print('B')
        super().__init__()     # 正确：交给 MRO 下一个

class C(A):
    def __init__(self):
        print('C')
        super().__init__()

class D(B, C):
    def __init__(self):
        print('D')
        super().__init__()

D()   # D → B → C → A，每个只打印一次
```

**易错点：**

- `super()` 的语义是「**MRO 中当前类的下一个类**」，不是「当前类的直接父类」——在钻石继承里这点最关键。
- 多继承中如果某个类**故意不调用 `super()`**，MRO 就会被截断，后面的协作类不会执行，初始化可能残缺。
- 极端的继承顺序可能无法构造 MRO，Python 会抛 `TypeError: Cannot create a consistent method resolution order`。
- `super()` 用在**类方法**里传的是 `cls`，用在**实例方法**里传的是 `self`，两者不要混。

> 提示：调度顺序也可用 `D.mro()` 与 `D.__mro__` 查看；面试若问「C3 与深度优先的区别」，直接答「C3 保证子类优先且父类相对顺序稳定，避免了深度优先在钻石结构下的重复访问」。

## 8. 元类 metaclass

**一句话：类是对象，而「类的类」就是元类。默认情况下，所有类的元类都是 `type`。**

**核心认知链条：**

1. 在 Python 中，`class` 定义出来的东西也是**对象**（可以被赋值、传参）。
2. 那么「类对象」是谁创建的？→ 是它的**元类（metaclass）**。
3. 最基础的元类就是 **`type`**：`type(SomeClass)` 返回 `type`。
4. 所以 `metaclass=X` 就是「用 X 来造这个类」，而造类时会走 `X.__new__` / `X.__init__`。

```python
class Foo:
    pass

print(type(Foo))       # <class 'type'>
print(type(Foo()))     # <class 'Foo'>
print(Foo.__class__)   # <class 'type'>
print(isinstance(Foo, type))   # True（类本身也是 type 的实例）
```

**`type(name, bases, dict)` 动态创建类：**

```python
# 这三行与「class 语句」完全等价
Foo = type('Foo', (object,), {'x': 1, 'greet': lambda self: 'hi'})

f = Foo()
print(f.x)          # 1
print(f.greet())    # hi
print(type(Foo))    # <class 'type'>
```

**Python 2 与 3 的写法差异：**

| 版本 | 声明方式 |
| --- | --- |
| Python 2 | 类体内写 `__metaclass__ = Meta`（模块级的 `__metaclass__` 已废弃） |
| Python 3 | 类声明处写 `class Foo(metaclass=Meta):` |

**自定义元类的典型形态：**

```python
class Meta(type):
    def __new__(mcs, name, bases, namespace, **kwargs):
        print('正在创建类：', name)
        namespace.setdefault('created_by', 'Meta')
        return super().__new__(mcs, name, bases, namespace)   # 交给 type 真正造类

    def __init__(cls, name, bases, namespace, **kwargs):
        print('类初始化完成：', name)
        super().__init__(name, bases, namespace)

class Foo(metaclass=Meta):
    pass

print(Foo.created_by)   # Meta
print(type(Foo))        # <class '__main__.Meta'>
```

**典型用途①：注册表（自动收集子类）**

```python
registry = {}

class RegisterMeta(type):
    def __new__(mcs, name, bases, ns):
        cls = super().__new__(mcs, name, bases, ns)
        if name != 'Base':              # 基类本身不入册
            registry[name.lower()] = cls
        return cls

class Base(metaclass=RegisterMeta):
    pass

class Dog(Base): pass
class Cat(Base): pass

print(registry)   # {'dog': <class 'Dog'>, 'cat': <class 'Cat'>}
```

**典型用途②：ORM（把类属性声明变成表字段）**

```python
class Field:
    def __init__(self, name):
        self.name = name

class ModelMeta(type):
    def __new__(mcs, name, bases, ns):
        fields = {k: v for k, v in ns.items() if isinstance(v, Field)}
        cls = super().__new__(mcs, name, bases, ns)
        cls._fields = fields           # 收集字段，供建表/映射使用
        return cls

class Model(metaclass=ModelMeta):
    pass

class User(Model):
    id = Field('id')
    name = Field('name')

print(User._fields.keys())   # dict_keys(['id', 'name'])
```

**元类 vs 装饰器：**

| 维度 | 元类 | 类装饰器 |
| --- | --- | --- |
| 作用对象 | **类的创建过程**（连创建都能干预） | 已经创建好的类对象 |
| 能力 | 可修改 `bases`、`namespace`、拦截实例化、影响子类 | 只能修改/替换已存在的类 |
| 影响范围 | 该类**及其所有子类**（继承元类） | 仅被装饰的这一个类 |
| 复杂度 | 高，理解成本大，易过度设计 | 低，写法直观 |
| 建议 | 仅在「框架级」需求使用 | 业务里优先用装饰器 |

**易错点：**

- 元类冲突：如果父类元类是 `Meta1`、你想用 `Meta2`，则 `Meta2` 必须是 `Meta1` 的**子类**，否则抛 `TypeError: metaclass conflict`。
- 元类的 `__new__` 第一个参数是**元类自身**（约定写 `mcs`），返回值必须是「类对象」；不 `super().__new__` 就得不到真正的类。
- 不要为了「拦截实例化」上元类：那是元类 `__call__` 的活儿（见第 14 题），普通需求用 `__init_subclass__` 或类装饰器更简单。
- 「类也是对象」这一点别混淆：`type(Foo)` 是 `type`（元类），`type(Foo())` 是 `Foo`（类）。

## 9. 描述符

**描述符（descriptor）是「实现了 `__get__` / `__set__` / `__delete__` 中至少一个的类」，它被用作另一个类的类属性时，就能接管该属性的读取、赋值、删除。** `property`、`staticmethod`、`classmethod`、普通函数本质上**都是描述符**。

**协议方法：**

| 方法 | 作用 | 缺失时的行为 |
| --- | --- | --- |
| `__get__(self, obj, objtype=None)` | 读取 `obj.attr` | 走默认查找 |
| `__set__(self, obj, value)` | 赋值 `obj.attr = value` | 退化为写实例 `__dict__` |
| `__delete__(self, obj)` | 删除 `del obj.attr` | 退化为删实例 `__dict__` 项 |

**数据描述符 vs 非数据描述符（核心区分）：**

| 类型 | 定义 | 例子 | 优先级 |
| --- | --- | --- | --- |
| **数据描述符** | 定义了 `__set__` 或 `__delete__` | `property`、自定义校验器 | **高于实例 `__dict__`** |
| **非数据描述符** | 只定义了 `__get__` | 普通函数、`staticmethod`、`classmethod` | **低于实例 `__dict__`** |

**属性查找优先级（完整版）：**

```text
1) 数据描述符（类里定义、带 __set__）        ← 最高，能“压住”实例属性
2) 实例 __dict__
3) 非数据描述符（只带 __get__）
4) 普通类属性
5) __getattr__ → AttributeError
```

```python
class NonData:
    def __get__(self, obj, objtype=None):
        return 'non-data'

class Data:
    def __get__(self, obj, objtype=None):
        return 'data'
    def __set__(self, obj, value):
        print(f'set 被拦截：{value}')

class C:
    nd = NonData()    # 非数据描述符
    dt = Data()       # 数据描述符

c = C()
print(c.nd)           # non-data（类里没有同名实例属性时走描述符）
c.nd = 'instance'     # 非数据描述符优先级低 → 直接写进实例 __dict__
print(c.nd)           # instance（实例属性覆盖了非数据描述符）

print(c.dt)           # data
c.dt = 'x'            # 数据描述符优先级高 → 触发 __set__，不写实例 __dict__
print(c.dt)           # data（实例属性被数据描述符压住）
```

**自己写一个「带校验的描述符」：**

```python
class Positive:
    def __set_name__(self, owner, name):   # 3.6+：拿到属性名，便于报错信息
        self.name = name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self                     # 通过类访问（C.attr）时返回描述符本身
        return obj.__dict__.get(self.name)

    def __set__(self, obj, value):
        if value < 0:
            raise ValueError(f'{self.name} 不能为负')
        obj.__dict__[self.name] = value

class Order:
    price = Positive()
    count = Positive()

o = Order()
o.price = 10
o.count = 3
print(o.price, o.count)     # 10 3
try:
    o.price = -1
except ValueError as e:
    print(e)                # price 不能为负
```

**`property` / `staticmethod` / `classmethod` 都是描述符（面试常问）：**

```python
class C:
    @property
    def p(self):            # property 是数据描述符（实现了 __get__ 和 __set__）
        return 42

    @staticmethod
    def s():                # staticmethod 是非数据描述符，__get__ 返回原函数（不绑定 self）
        return 'static'

    @classmethod
    def c(cls):             # classmethod 是非数据描述符，__get__ 返回绑定 cls 的方法
        return cls.__name__

print(C.p)              # 42
print(C.s())            # static
print(C.c())            # C
```

```python
# 普通函数也是「非数据描述符」——这就是「方法」的由来
class C:
    def m(self):
        return 'm'

c = C()
print(C.m)               # <function C.m at 0x...>（类访问：函数本身）
print(c.m)               # <bound method C.m of ...>（实例访问：__get__ 绑定 self）
```

**易错点：**

- 描述符**只有在「类属性」位置**才生效；放在实例属性上（`self.x = Descriptor()`）不会被触发。
- 数据描述符之所以能「压住」实例 `__dict__`，是因为它在查找顺序里排第 1 位——这正是 `property` 能做「只读」的原因。
- `__get__` 中 `obj` 为 `None` 时表示「通过类访问」，此时应返回描述符本身（或类的说明），否则 `C.attr` 会拿到奇怪结果。
- 用描述符模拟 `property` 时注意：`__set__` 里要写 `obj.__dict__[self.name]` 而不是 `obj.__dict__[name]`，否则存不进/取不出。

## 10. property 与属性管理

**`property` 是「用描述符实现的数据封装」：把方法包装成属性，从而在「读、写、删」时插入逻辑（校验、派生计算、缓存）。**

**三种写法：**

```python
import math
from functools import cached_property

class Circle:
    def __init__(self, r):
        self._r = r                  # 约定：真实数据存在「带下划线」的私有属性里

    @property
    def r(self):                     # getter
        return self._r

    @r.setter
    def r(self, value):              # setter（同名装饰器）
        if value < 0:
            raise ValueError('半径不能为负')
        self._r = value

    @r.deleter
    def r(self):                     # deleter
        del self._r

    @property
    def area(self):                  # 只读派生属性：没有 setter
        return math.pi * self._r ** 2

c = Circle(2)
print(c.r, round(c.area, 2))         # 2 12.57
c.r = 3
print(c.r)                            # 3
try:
    c.r = -1
except ValueError as e:
    print(e)                          # 半径不能为负

try:
    c.area = 5                        # 无 setter → AttributeError
except AttributeError as e:
    print(e)                          # can't set attribute
```

**用 `property` 做「缓存 / 惰性计算」：**

```python
class Expensive:
    def __init__(self, n):
        self.n = n
        self._calls = 0

    @property
    def slow(self):                   # 普通 property：每次访问都重算
        self._calls += 1
        return sum(range(self.n))

    @cached_property
    def cached(self):                 # 首次计算后写入实例 __dict__，之后直接命中
        self._calls += 1
        return sum(range(self.n))

e = Expensive(1_000_000)
_ = e.slow; _ = e.slow                 # 计算两次
print(e._calls)                        # 2

e2 = Expensive(1_000_000)
_ = e2.cached; _ = e2.cached           # 只计算一次
print(e2._calls)                       # 1
print('cached' in e2.__dict__)         # True（缓存进了实例字典）
```

**`property` vs 直接暴露属性 vs `__getattr__`：**

| 方案 | 适用 | 代价 |
| --- | --- | --- |
| 直接公开属性 `self.x` | 简单数据类、无需校验 | 无法插入校验/派生逻辑，后期改接口会破坏调用方 |
| `property` | 需要校验、派生值、延迟计算、保持 API 稳定 | 每次访问有函数调用开销；代码略长 |
| `cached_property` | 计算昂贵、结果稳定、需要懒加载 | 依赖 `__dict__`（`__slots__` 类不可用）；缓存不会失效 |
| `__getattr__` | 动态/兜底属性 | 隐式、难调试、易与 `hasattr` 交互出问题 |

**为什么要用 `property`（面试要点）：**

1. **封装校验**：赋值时立刻检查合法性，杜绝「脏数据」。
2. **派生属性**：`area` 由 `r` 算出，无需手动同步，永远不会不一致。
3. **API 演进**：一开始是公开属性 `obj.x`，后来需要加逻辑，改成 `property` 后**调用方代码不用动**。
4. **只读控制**：只定义 getter 即可禁止赋值。

**易错点：**

- getter/setter 必须**同名**（都用 `@r.setter` 绑定到 `r`），否则 setter 不生效。
- 在 `__init__` 里用 `self.r = r` 会走 setter，**校验会生效**；若想绕过需直接写 `self._r = r`（这也是命名约定的意义）。
- `property` 与实例属性同名会死循环：`self.r = x` 在 `@r.setter` 里若又写 `self.r = x`，会无限递归。
- `cached_property` 要求类有 `__dict__`，**`__slots__` 类无法使用**；且缓存写入后不会自动失效，对象内部可变时需手动清理。

> 提示：`property` 是数据描述符，所以它能「压住」实例 `__dict__` 中的同名值；想手动清缓存，`del obj.__dict__['cached']` 即可。

## 11. 鸭子类型与多态

**鸭子类型（Duck Typing）：「如果它走起来像鸭子、叫起来像鸭子，那它就是鸭子」——关注对象「能做什么（行为）」，而不是「是什么类型」。**

**与静态类型的对比：**

| 维度 | 鸭子类型（动态） | 名义类型（静态，如 Java） |
| --- | --- | --- |
| 判定依据 | 有没有对应**方法/属性** | 是否继承/实现了某个**类型** |
| 检查时机 | **运行时** | 编译时 |
| 灵活度 | 高，无需公共基类 | 低，需显式声明接口 |
| 风险 | 传错对象要到运行才报错 | 编译期即可拦截 |

```python
def total(items):
    # 不关心 items 是 list/tuple/set/自定义容器，只要有 __iter__ 就能求和
    return sum(items)

print(total([1, 2, 3]))            # 6
print(total((1, 2, 3)))            # 6
print(total({1, 2, 3}))            # 6

class MyRange:
    def __init__(self, n): self.n = n
    def __iter__(self):
        return iter(range(self.n))

print(total(MyRange(4)))           # 6 → 自定义对象照样能用
```

**`isinstance` / `hasattr` / `callable` 的用途与取舍：**

```python
def call_twice(fn):
    if callable(fn):               # 只要求“可调用”
        fn(); fn()
    else:
        raise TypeError('需要一个可调用对象')

call_twice(lambda: print('hi'))

def describe(obj):
    print(isinstance(obj, (list, tuple)))    # 判断“是某类/某几类”
    print(hasattr(obj, '__len__'))           # 判断“有没有某个能力”

describe([1, 2])
# True
# True
```

| 手段 | 含义 | 建议 |
| --- | --- | --- |
| `hasattr(obj, 'x')` | 有没有属性/方法（会**吞掉**属性访问中的异常） | 判断「行为能力」，最符合鸭子类型 |
| `isinstance(obj, C)` | 是否是 C 或其子类实例（尊重继承） | 需要区分具体类型时用 |
| `callable(obj)` | 是否可调用（等价于有 `__call__`） | 判断回调 |
| `type(obj) is C` | 精确类型（**不考虑继承**） | 一般不用，破坏多态 |

**抽象基类 `abc`：给鸭子类型加「契约」**

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):        # 子类必须实现
        ...

class Circle(Shape):
    def __init__(self, r): self.r = r
    def area(self): return 3.14 * self.r ** 2

try:
    Shape()                # 抽象类不能实例化
except TypeError as e:
    print(e)               # Can't instantiate abstract class Shape with abstract method area

print(Circle(2).area())    # 12.56
```

- `ABC` 的价值：把「必须实现的方法」**显式声明**出来，实例化时立刻报错，而不是调用时才炸。
- 代价：比纯鸭子类型「重」，因为它引入了继承关系。

**协议 `typing.Protocol`：结构性检查（现代推荐）**

```python
from typing import Protocol, runtime_checkable

@runtime_checkable                  # 允许 isinstance 检查（需运行时则加）
class Sized(Protocol):
    def __len__(self) -> int: ...   # 只要“有 __len__”就满足协议

def show(x: Sized) -> int:
    return len(x)

print(show([1, 2, 3]))             # 3
print(isinstance([1, 2], Sized))   # True → 不继承自 Sized，靠结构匹配
print(isinstance(42, Sized))       # False
```

- `Protocol` 是「静态类型检查器（mypy）看得懂、又不需要显式继承」的接口描述。
- 配合 `@runtime_checkable` 可让 `isinstance` 也按「方法是否存在」判定。

**`__subclasshook__`：自定义 `isinstance` 的判定规则**

```python
from abc import ABC

class Flyer(ABC):
    @classmethod
    def __subclasshook__(cls, sub):
        return hasattr(sub, 'fly')      # 只要有 fly() 就算“会飞”

class Bird:
    def fly(self):
        return 'belly'

print(isinstance(Bird(), Flyer))         # True → 即使没继承 Flyer
```

**易错点：**

- `hasattr` 会**吞掉任何异常**（包括属性访问中抛出的非 `AttributeError`），在 `property` 内部有副作用时可能误判。
- 鸭子类型下「传什么都能跑」不等于「正确」：要在文档/测试中明确**需要哪些方法**，否则错误要到运行时才暴露。
- 用 `type(obj) is C` 判断对象类型会**破坏多态**（子类实例被拒绝），除非确实要排除子类。
- `ABC` 与 `Protocol` 定位不同：前者是「名义约束 + 运行时报错」，后者是「结构性约束 + 静态检查」，别混用。

## 12. 新式类与经典类、继承体系

**这是 Python 2 → 3 的历史遗留考点：Python 2 里存在「经典类（classic/old-style）」与「新式类（new-style）」两套体系，MRO 算法不同；Python 3 已统一为新式类。**

| 维度 | 经典类（Py2，不继承 `object`） | 新式类（Py2 继承 `object` / Py3 默认） |
| --- | --- | --- |
| 声明 | `class A:` | `class A(object):`（Py3 写 `class A:` 即可） |
| 顶层类型 | `types.ClassType`（`classobj`） | `type` |
| MRO 算法 | **深度优先 DFS**（有钻石重复问题） | **C3 线性化** |
| `super` | 不支持 | 支持 |
| `__slots__` / `property` / 描述符 | 不支持 | 支持 |
| `type(A) is type` | `False` | `True` |
| `A.__mro__` | 不存在 | 存在 |

**经典类 DFS 与新式类 C3 的关键差异（面试可举例）：**

```python
# —— Python 2 经典类的深度优先 ——
class A:            pass
class B(A):         pass
class C(A):         pass
class D(B, C):      pass

# 经典类 MRO（深度优先，从左到右，遇重复不剪枝）：
# D → B → A → C → A
# 问题：A 被访问了两次，且 C 排在 A 之后 —— 违反「子类应在父类之前」的直觉
```

```python
# —— Python 2 新式类 / Python 3 的 C3 线性化 ——
class A(object):    pass
class B(A):         pass
class C(A):         pass
class D(B, C):      pass

print(D.__mro__)
# (D, B, C, A, object)
# 每个类只出现一次，且 C 排在 A 之前，满足单调性
```

**对「属性和方法查找」的实际影响：**

```python
# 若 B、C 都覆盖了 run()，经典类与新式类的选择可能不同
class A:
    def run(self): return 'A'

class B(A):
    def run(self): return 'B'

class C(A):
    def run(self): return 'C'

class D(B, C):
    pass

print(D().run())          # Py3 新式类：'B'
# MRO = (D, B, C, A, object)，B 在 C 之前 → 用 B.run
# 若同样结构在 Py2 经典类下，也会先找 B（因为 DFS 先走 B 分支）；
# 差异真正暴露在「B 未定义、A 与 C 都定义」这类层级更深的场景：
```

```python
# 差异暴露示例：B 不定义 run，A、C 都定义
class D2(B, C):
    pass

# Py3 C3 的 MRO：(D2, B, C, A, object) → 找到 C.run（因为 C 在 A 之前）
# Py2 经典 DFS：(D2, B, A, C, A)         → 找到 A.run（DFS 先钻到最底）
```

**Python 3 的现状：**

- 所有类**隐式继承 `object`**，`class Foo:` 与 `class Foo(object):` 完全等价。
- 所有类都有 `__mro__` / `mro()`、支持 `super`、支持描述符与 `__slots__`。
- `object` 是所有类的根：`Foo.__mro__` 末尾必是 `object`。

```python
class Foo:
    pass

print(Foo.__bases__)      # (<class 'object'>,) —— 隐式基类
print(Foo.__mro__)        # (Foo, object)
print(issubclass(Foo, object))   # True
print(object in Foo.mro())       # True
```

**易错点：**

- 在 Python 3 里讨论「经典类」只作为历史知识：**不要**以为 Py3 还存在经典类。
- 「新式类 = 显式写 `(object)`」这个说法**只适用 Python 2**；Py3 不写也是新式类。
- C3 保证「单调性」，所以它比 DFS 更安全；出现 MRO 冲突时 `class D(B, C)` 会直接抛 `TypeError`，而不是给出错误顺序。
- `__bases__` 是**直接基类元组**，`__mro__` 是**完整线性化链**，两者概念不同，别答混。

## 13. 弱引用与 weakref

**弱引用（weak reference）指「不会增加对象引用计数」的引用：对象只被弱引用指向时，仍会被正常回收。** 它是「缓存」与「打破循环引用」的利器。

**核心 API：**

| API | 说明 |
| --- | --- |
| `weakref.ref(obj, callback=None)` | 创建弱引用；取值 `r()`，对象已死返回 `None` |
| `weakref.proxy(obj)` | 代理对象，像直接用原对象一样，对象已死访问会抛 `ReferenceError` |
| `weakref.WeakValueDictionary` | 值被弱引用的字典：值没有强引用时条目**自动消失** |
| `weakref.WeakKeyDictionary` | 键被弱引用的字典 |
| `weakref.WeakSet` | 元素被弱引用的集合 |
| `weakref.finalize(obj, fn)` | 更可靠的析构回调（优于 `__del__`） |

```python
import weakref

class Node:
    def __init__(self, name):
        self.name = name
    def __repr__(self):
        return f'Node({self.name})'

n = Node('n')
r = weakref.ref(n)
print(r() is n)          # True → 解引用拿到原对象

print(r())               # Node(n)
del n                    # 强引用没了
print(r())               # None → 对象已被回收

# 回调：对象被回收时触发
def on_die(ref):
    print('对象已被回收')

tmp = Node('tmp')
r2 = weakref.ref(tmp, on_die)
del tmp                  # 触发 on_die
```

**典型用途①：缓存（自动淘汰）**

```python
import weakref

class Image:
    def __init__(self, path):
        self.path = path
        self.pixels = b'x' * 1024      # 假装占用较大内存

cache = weakref.WeakValueDictionary()

def load(path):
    img = cache.get(path)              # 命中缓存
    if img is None:
        img = Image(path)
        cache[path] = img              # 只存弱引用：没有外部引用时自动移除
    return img

a = load('a.png')
print(cache.get('a.png'))              # Image 对象
del a                                  # 外部强引用消失
print(cache.get('a.png'))              # None → 条目被自动清理
```

**典型用途②：打破父子循环引用**

```python
import weakref

class Parent:
    def __init__(self, name):
        self.name = name
        self.children = []

class Child:
    def __init__(self, parent):
        self.parent = weakref.ref(parent)   # 反向引用用弱引用
        parent.children.append(self)

p = Parent('p')
c = Child(p)                                 # 父→子 强，子→父 弱
print(c.parent().name)                       # p
del p
print(c.parent())                            # None（父对象已被回收，无循环引用）
```

**哪些对象不能弱引用：**

```python
import weakref

for obj in ([], {}, (), set(), 1, 's', (i for i in range(3))):
    try:
        weakref.ref(obj)
        print(type(obj).__name__, '可弱引用')
    except TypeError as e:
        print(type(obj).__name__, '不可弱引用：', e)
# list / dict / tuple / set / int / str / generator 均不可弱引用
# 原因：这些内置类型没有 __weakref__ 槽位，无法记录弱引用列表
```

| 能否弱引用 | 说明 |
| --- | --- |
| 自定义类实例、函数、类、模块 | **可以**（默认带 `__weakref__`） |
| `list` / `dict` / `tuple` / `set` / `int` / `str` | **不可以**（无 `__weakref__`） |
| 自定义类若定义了 `__slots__` 且未加 `'__weakref__'` | **不可以** |
| `list`/`dict` 的**子类**（若无 `__slots__`） | 通常**可以**（子类实例默认有 `__dict__` 与 `__weakref__`） |

```python
import weakref

class MyList(list):        # 子类默认可弱引用
    pass

weakref.ref(MyList([1, 2]))   # 正常运行

class MyList2(list):
    __slots__ = ('x',)        # 定义了 __slots__ 且未声明 '__weakref__'
try:
    weakref.ref(MyList2())
except TypeError as e:
    print(e)                  # cannot create weak reference to 'MyList2' object
```

**`weakref.finalize` 优于 `__del__`：**

```python
import weakref

class Resource:
    def __init__(self, name):
        self.name = name
        weakref.finalize(self, Resource.cleanup, name)   # 也可在 __init__ 注册

    @staticmethod
    def cleanup(name):
        print(f'释放资源：{name}')

r = Resource('db-conn')
del r        # 对象被回收 → 回调执行
# 即使程序退出，finalize 注册的回调也会被调用
```

**易错点：**

- `weakref.proxy` 在目标已死时**访问属性会抛 `ReferenceError`**，而 `weakref.ref` 只是返回 `None`——使用前要判断。
- `WeakValueDictionary` 的「自动淘汰」依赖**值对象被回收**；若值仍有其他强引用，条目就会留存，别误以为它按时间过期。
- `__slots__` 类想被弱引用必须显式加 `'__weakref__'`，这是写元类/描述符时的常见坑。
- 弱引用**不能**用于打破「父对象持有子对象列表 + 子对象强引用父对象」的两端强引用，弱引用必须加在**其中一侧**才有意义。

## 14. Python 对象的创建过程

**`obj = Foo(1, 2)` 背后是一条清晰的链：`type.__call__` → `Foo.__new__` → `Foo.__init__`。**

**完整流程：**

```text
1. Foo(1, 2) 触发  Foo.__call__(1, 2)
   —— 该 __call__ 由「元类」提供（默认来自 type.__call__）
2. type.__call__ 内部：
   a. obj = Foo.__new__(Foo, 1, 2)      ← 分配并返回实例
   b. if isinstance(obj, Foo): Foo.__init__(obj, 1, 2)   ← 初始化
   c. return obj
```

```python
class Foo:
    def __new__(cls, *args, **kwargs):
        print('__new__ 被调用')
        return super().__new__(cls)      # 真正分配内存的是 object.__new__

    def __init__(self, value):
        print('__init__ 被调用')
        self.value = value

f = Foo(42)
# 输出：
# __new__ 被调用
# __init__ 被调用
print(f.value)                            # 42
```

**`__new__` vs `__init__`：**

| 维度 | `__new__` | `__init__` |
| --- | --- | --- |
| 类型 | **静态方法**（隐式），第一个参数是 `cls` | 实例方法，第一个参数是 `self` |
| 时机 | **先**执行，负责「创建」 | **后**执行，负责「初始化」 |
| 返回值 | **必须**返回实例（`super().__new__(cls)`） | 必须返回 `None`，否则报 `TypeError` |
| 是否一定调用 | 只有当 `__new__` 返回的实例是该类（或其子类）时，才接着调 `__init__` | 否则 `__init__` 不执行 |
| 典型场景 | 不可变类型子类化、单例、元类协作、返回其他类实例 | 设置属性、校验参数 |

```python
# 返回值决定 __init__ 是否执行
class OnlyNew:
    def __new__(cls):
        print('__new__')
        return 123               # 返回的不是 OnlyNew 实例
    def __init__(self):
        print('__init__ 不会执行')

print(OnlyNew())                 # 只打印 __new__，返回 123
```

**何时必须用 `__new__`（面试重点）：**

**① 子类化不可变类型（`int` / `str` / `tuple`）——因为它们的值在创建时就固定了**

```python
class PositiveInt(int):
    def __new__(cls, value):
        if value < 0:
            raise ValueError('必须为非负数')
        return super().__new__(cls, value)   # 把值交给 int.__new__

print(PositiveInt(5) + 1)                    # 6
try:
    PositiveInt(-1)
except ValueError as e:
    print(e)                                 # 必须为非负数
```

**② 单例模式**

```python
class Singleton:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    def __init__(self, value):
        self.value = value        # 注意：每次“创建”都会重新执行

a, b = Singleton(1), Singleton(2)
print(a is b, a.value)            # True 2 → 同一对象，value 被第二次调用覆盖
```

**③ 元类 `__call__` 拦截「实例化」**

```python
class Meta(type):
    def __call__(cls, *args, **kwargs):
        print('拦截实例化：', cls.__name__)
        obj = super().__call__(*args, **kwargs)   # 内部走 __new__ + __init__
        print('实例创建完成')
        return obj

class Foo(metaclass=Meta):
    def __init__(self, x):
        self.x = x

f = Foo(1)
# 拦截实例化： Foo
# 实例创建完成
print(f.x)                                        # 1
```

**`__init_subclass__`（3.6+）——比元类更轻的子类钩子**

```python
class Base:
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        print('新子类：', cls.__name__)

class Sub(Base):
    pass
# 新子类： Sub
```

**易错点：**

- `__init__` 只会返回 `None`；写了 `return self` 会抛 `TypeError: __init__() should return None`。
- `__new__` 里**不能**依赖实例属性（实例还没初始化），只能访问 `cls`。
- 单例用 `__new__` 实现时，`__init__` **每次访问都会重新执行**，若不想重复初始化需加标记位。
- `object.__new__` 在「类已定义 `__new__` 又定义 `__init__`」等场景下会校验多余参数，遇到 `__new__` 不接受参数时不要传多余实参。

> 提示：`__init_subclass__` 和 `__set_name__`（第 9 题）都是「用元类能做到、但有更简单替代」的典型，面试中被追问「必须用元类吗」时可以主动提这两个钩子。

## 15. 字节码与解释器执行

**Python 不是「逐字符解释」，而是「先编译成字节码（bytecode），再由 CPython 虚拟机逐条执行」。** `dis` 模块能把字节码可视化，这是分析性能与语义差异的利器。

**执行链路：**

```text
源码 .py
  → 词法/语法分析 → AST
  → 编译 → 代码对象 code object（含 co_code 等）
  → 写入 __pycache__/*.pyc 缓存（可选）
  → CPython 虚拟机（ceval）逐条执行字节码
```

**看一个函数被编译成了什么：**

```python
import dis

def add(a, b):
    return a + b

dis.dis(add)
# 输出（Python 3.11+）：
#   2           0 RESUME                   0
#   3           2 LOAD_FAST                0 (a)
#               4 LOAD_FAST                1 (b)
#               6 BINARY_OP                0 (+)
#               8 RETURN_VALUE
```

> 版本差异：Python 3.11 起算术运算统一为 `BINARY_OP`（`oparg` 表示运算符）；3.10 及以前是 `BINARY_ADD` / `BINARY_SUBTRACT` 等具体指令。Python 3.12 起还会把相邻的两次 `LOAD_FAST` 融合为一条 `LOAD_FAST_LOAD_FAST`（输出因此更短），以版本为准即可。

**代码对象（code object）里的关键属性：**

| 属性 | 含义 |
| --- | --- |
| `co_code` | 原始字节码（`bytes`，3.11+ 与 3.10 的编码不同） |
| `co_consts` | 常量元组（`None`、数字、字符串、嵌套 code 对象） |
| `co_names` | 全局名/属性名（如 `print`、`sum`） |
| `co_varnames` | 局部变量名 |
| `co_argcount` | 位置参数个数 |
| `co_flags` | 标志位（是否生成器、是否有 `*args` 等） |

```python
def demo(a, b):
    x = 10
    y = a + b
    return y * x

code = demo.__code__
print(code.co_varnames)   # ('a', 'b', 'x', 'y')
print(code.co_consts)     # (None, 10)
print(code.co_names)      # ()
print(code.co_code[:8])   # 原始字节码片段

dis.dis(demo)
```

**关键指令速查：**

| 指令 | 作用 |
| --- | --- |
| `LOAD_FAST` / `STORE_FAST` | 读写**局部变量**（最快，靠数组下标） |
| `LOAD_CONST` | 压入常量 |
| `LOAD_GLOBAL` / `LOAD_NAME` | 读全局/名字 |
| `LOAD_ATTR` / `STORE_ATTR` | 读写对象属性（走描述符协议） |
| `BINARY_OP`（3.11+） | 二元运算，`oparg` 编码 `+ - * / …` |
| `CALL` / `PRECALL`（3.11+） | 函数调用 |
| `RETURN_VALUE` | 返回栈顶值 |
| `POP_TOP` | 丢弃栈顶（表达式语句结束） |

**局部变量为什么快（`LOAD_FAST`）：**

```python
import dis

def local():
    x = 1
    return x

def global_lookup():
    return len([1, 2])       # len 是内置名 → LOAD_GLOBAL

dis.dis(local)
# LOAD_CONST 1 → STORE_FAST x → LOAD_FAST x → RETURN_VALUE（数组下标访问）

dis.dis(global_lookup)
# LOAD_GLOBAL len ...（需在全局/内置命名空间里查字典）
```

**`a += 1` 与 `a = a + 1` 对列表的区别（高频考点）：**

```python
import dis

lst = [1, 2]
alias = lst

lst += [3]          # 调 list.__iadd__ → 原地扩展，alias 也变
print(lst, alias)   # [1, 2, 3] [1, 2, 3]

lst = lst + [4]     # 创建新列表并重新绑定名字，alias 仍指向旧列表
print(lst, alias)   # [1, 2, 3, 4] [1, 2, 3]
```

```python
import dis

def inplace():
    a = [1]
    a += [2]         # INPLACE_ADD → 尝试 a.__iadd__ 原地修改
    return a

def newlist():
    a = [1]
    a = a + [2]      # 先算 BINARY_OP(+) 得到新对象，再重新绑定 a
    return a

dis.dis(inplace)
dis.dis(newlist)
# 3.11+ 中 inplace 用 BINARY_OP 12 (+=)，newlist 用 BINARY_OP 0 (+)
```

```python
# 元组没有 __iadd__，+= 会退化为「+ 后重新绑定」
t = (1, 2)
t += (3,)
print(t)             # (1, 2, 3) → 其实是新建元组

# 若 += 会重新绑定名字，闭包里会暴露一个经典陷阱
def outer():
    n = (1,)
    def inner():
        nonlocal n
        n += (2,)    # 需要 nonlocal，否则 UnboundLocalError（因为 += 会赋值）
    inner()
    return n
print(outer())       # (1, 2)
```

**`.pyc` 缓存机制：**

```text
项目/
├── module.py
└── __pycache__/
    ├── module.cpython-310.pyc     # 编译后的字节码缓存
    └── module.cpython-311.pyc     # 不同版本各存一份
```

| 点 | 说明 |
| --- | --- |
| 缓存位置 | `__pycache__/`（Python 3） |
| 命名 | `<模块名>.cpython-<版本>.pyc` |
| 失效判断 | 默认比对**源文件 mtime + size**；`compileall --invalidation-mode` 可改用**源码哈希**（更可靠、跨机器可复用） |
| 作用 | 跳过编译，加快启动；**不参与运行逻辑**，可安全删除 |
| 什么时候不生成 | 主脚本 `python main.py` 不写缓存；用 `-B` 或设置 `PYTHONDONTWRITEBYTECODE=1` 也会关闭 |

**易错点：**

- `dis` 的输出随 Python 版本变化很大（3.11 引入了自适应解释器与 `BINARY_OP`），面试里**说明版本**比背指令更重要。
- `+=` 与 `+` 的关键差异在**是否有 `__iadd__`（原地协议）**：有就地改，没有则退化为新建再绑定。
- `co_code` 是**字节码编码**，不是可读指令；要可读文本请用 `dis.Bytecode(func)` 或 `dis.dis`。
- `.pyc` 只是缓存，**删掉不会出错**；但若源码 mtime 被篡改（如某些构建工具保留时间戳），可能出现「改了代码不生效」的假象。
